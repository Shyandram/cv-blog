選擇影像系統，先看你要交付什麼。概念草圖、標籤必須保持原樣的產品照，以及文字必須完全正確的示意圖，需要不同的檢查。展示頁中最漂亮的一張圖，不一定回答你的問題。

本文比較文件記載的能力與部署選項，來源查核日期為 **2026 年 11 月 5 日**。本文沒有執行生成實驗，也不提供效能排名。列出的可下載版本是具體例子，不代表它們是最新模型。以下的確切版本、Muse 與評測連結於 **2026 年 11 月 6 日**補充查核。

## 先決定需要哪種操作

文生圖（text-to-image）從描述開始；影像編輯從既有影像與修改指令開始。局部重繪（inpainting）修改指定區域，通常以遮罩標示；向外延展（outpainting）則擴大畫布。參考影像可以引導外觀，但不保證精確保留原樣。實際支援哪些操作，取決於介面與選用的模型。[1, 4]

新插畫要看構圖與指令遵循。影像編輯還要檢查所有應保持不變的地方。海報必須在最終顯示尺寸下逐字閱讀；產品素材則要分別檢查形狀、標籤、比例與背景。

## 託管工具：先看工作流程

| 模型家族或產品 | 文件記載的用途 | 適合的首次試用 |
| --- | --- | --- |
| [OpenAI GPT Image](https://developers.openai.com/api/docs/guides/image-generation) | 透過 API 生成與編輯影像，支援的整合也可進行對話式編輯 [1] | 修改一個物件，並保留周圍場景 |
| [Gemini Image／Nano Banana](https://deepmind.google/models/gemini-image/) | Google 模型家族中的影像生成與編輯 [2] | 連續修改幾次，檢查主體特徵是否逐漸偏移 |
| [Midjourney 版本](https://docs.midjourney.com/hc/en-us/articles/32199405667853-Version) | 可明確選擇模型版本的影像創作 [3] | 依同一份需求產生概念，再比較精修其中一張所需的工作 |
| [Adobe Firefly](https://www.adobe.com/products/firefly.html) | 創意生成與編輯工具，包含 Adobe 與合作夥伴的模型 [4] | 在真正要使用素材的設計流程中完成作品 |
| [Meta Muse Image](https://dev.meta.ai/docs/image-generation) | `muse-image-1.0` 透過 Meta Model API 提供生成、編輯與多輪精修 [9] | 反覆進行參考圖編輯，檢查主體特徵與應保持不變的區域 |

這些是選型測試，不是某個模型家族必勝的主張。請記錄實際模型與版本：查核時 Midjourney 版本頁列出的預設為 V8.2，而預設值會改變。Firefly 也提供合作夥伴模型；在 Firefly 裡能選到的模型，不一定由 Adobe 訓練。[3, 4]

若想先開始、不管理 GPU 軟體，託管工具通常較方便。請確認匯出格式、編輯控制、帳號限制、輸入影像的處理方式，以及目前的商用條款。應用程式訂閱與 API 帳號可能提供不同權益。

### 把版本來源與輸出一起保存

查看供應商的模型目錄或 API 參考，不只記產品暱稱。[OpenAI 影像 API 參考](https://developers.openai.com/api/reference/resources/images/methods/generate)列出明確的影像模型識別碼與日期快照；`gpt-image-2.5-sunburst-2026-09-08` 就是一個可記錄的版本識別碼。Google 的 [Gemini 3.1 Flash Image 模型頁](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-image.md)則標明 `gemini-3.1-flash-image`（Nano Banana 2）。透過 Google 的[退役時程表](https://ai.google.dev/gemini-api/docs/deprecations.md)，分清這個穩定版識別碼、已退役的預覽版與較新的命名版本。別名、日期快照與產品介面名稱是不同的紀錄。[10, 11]

也可查看 [Microsoft MAI-Image-2.6](https://microsoft.ai/models/mai-image-2-6/)、[Grok Imagine Image 2.0](https://docs.x.ai/developers/models/grok-imagine-image-2.0) 與 [ByteDance Seedream 4.0](https://seed.bytedance.com/en/seedream4_0) 的確切發布頁。官方頁面提供能力與使用入口；仍應套用相同驗收表，不能從家族名稱推論品質或授權。這是精選版本連結，不是完整清單，也不宣稱它們是目前最新版本。[26, 27, 28]

## 開放權重：確認確切版本

| 可下載的例子 | 第一手來源確認的事 | 選擇時的意義 |
| --- | --- | --- |
| [Qwen-Image](https://huggingface.co/Qwen/Qwen-Image) | 模型卡標示 Apache-2.0，提供生成範例，並著重文字呈現 [5] | 把真正需要的繁體中文放進測試；支援某種語言不等於每個字都正確 |
| [FLUX.2 [klein] 4B](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B) | Black Forest Labs 的授權表列為 Apache-2.0 權重 [6, 12] | 授權選項與 9B 版本不同 |
| [FLUX.2 [klein] 9B](https://huggingface.co/black-forest-labs/FLUX.2-klein-9B) | 權重開放下載，但採非商用條款；商業部署需取得適當授權 [6, 12] | 不能把 4B 的授權套用到整個家族 |
| [Stable Diffusion 3.5 Large](https://huggingface.co/stabilityai/stable-diffusion-3.5-large) | 可下載模型，採 Stability AI Community License [7] | 必須閱讀該授權條件，不能當作 Apache-2.0 |
| [SDXL base 1.0](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0) | 有獨立模型卡與授權的 Stable Diffusion 發布版本 [13] | 確認流程所需的確切 base／refiner 元件 |
| [PixArt-Σ XL-2-1024-MS](https://huggingface.co/PixArt-alpha/PixArt-Sigma-XL-2-1024-MS) | 可下載的 diffusion Transformer 版本，附推論流程 [14] | 在自己的硬體上量測完整流程 |
| [HunyuanImage-3.0](https://huggingface.co/tencent/HunyuanImage-3.0) | Tencent 的生成權重與社群授權 [15] | 分清生成版本與 Instruct 版本 |
| [Janus-Pro-7B](https://huggingface.co/deepseek-ai/Janus-Pro-7B) | 可下載、整合理解與生成的研究版本 [16] | 把生成流程與影像理解分別測試 |

能否下載、原始碼的授權，以及某個權重版本的使用許可，是三件事。付費託管 API 也可能提供開放權重模型。請確認權重版本、額外元件，以及預定部署方式的條款；只有家族名稱還不夠。

編輯任務也可查看獨立的 [Qwen-Image-Edit-2509 模型卡](https://huggingface.co/Qwen/Qwen-Image-Edit-2509)；生成權重與編輯權重不能直接互換。[17]

## Muse 的兩種不同名稱

**Meta Muse Image** 是上表的託管影像生成／編輯產品線，模型目錄列出的識別碼為 `muse-image-1.0`。Muse Spark 與 Muse Wonder 在 Meta 目錄中扮演不同角色，僅有這些名稱不足以識別影像端點。[9]

**Google Research Muse（2023）** 則是研究專案 [Muse: Text-To-Image Generation via Masked Generative Transformers](https://muse-model.github.io/)。它以文字為條件預測被遮罩的離散影像 token，再平行精修。可搭配較早的遮罩影像生成方法 [MaskGIT 官方實作](https://github.com/google-research/maskgit)閱讀。引用的 Google Muse 專案是方法與論文資源，不能據此當作目前可呼叫的託管 API 或已提供下載的 Google Muse 權重。[18, 19]

機制與限制可接著讀 [ML 09：MaskGIT 與 Google Muse](/zh-tw/learn/ml/autoregressive-vision/#遮罩生成模型maskgit-與-muse)。引用歷史論文的速度或評測結果時，仍須保留當時的比較設定。

## ComfyUI 是工作台，不是模型

ComfyUI 提供以節點組成流程的介面與後端。流程圖串起載入、條件設定、生成與輸出操作；換模型，就會改變流程能產生的結果。它的生態系也包含選用的付費 API 節點，因此在本地開啟介面，不代表每一步都在本地執行。[8]

先從最小且受支援的流程開始。把流程圖、模型識別碼、軟體版本及設定和輸出一起保存。自訂節點應解決明確需求才加入，因為它除了增加功能，也增加可執行程式碼與相依項。匯出的流程有助於重現，但仍需要相容的模型與軟體。

估算本地硬體需求時，要看整條流程，不能只看主要權重檔案。文字編碼器、影像解碼、中間張量、輸出解析度與批次大小都會影響記憶體。降低精度或在裝置間搬移元件，會改變記憶體用量與速度。先採用文件記載的設定，測量最高記憶體用量與耗時，成功後再提高複雜度。

## 評測連結：先看各自量什麼

用排行榜建立候選清單，再開啟方法說明與確切模型／版本那一列。以下資源回答不同問題，分數不能互換。

| 資源 | 可提供的證據 | 比較前要確認 |
| --- | --- | --- |
| [GenEval](https://github.com/djghosh13/geneval)／[GenEval 2](https://github.com/facebookresearch/GenEval2) [20, 21] | 物件、計數、屬性與關係；GenEval 2 擴充組合能力的涵蓋範圍與評估方式 | 評測版本、偵測器／視覺問答評估模型，以及各能力的結果 |
| [T2I-CompBench／++](https://github.com/Karine-Huang/T2I-CompBench) [22] | 組合屬性與關係 | 使用哪個版本、類別及評估模型 |
| [DPG-Bench](https://github.com/TencentQQGYLab/ELLA#-dpg-bench) [23] | 透過內容問答檢查密集提示的對齊情況 | 提示集、影像取樣與評估設定 |
| [Arena 文生圖排行榜](https://arena.ai/leaderboard/image/text-to-image) [24] | 相對偏好排名與分類檢視 | 模型變體、評估日期、票數支持程度與不確定性 |
| [Artificial Analysis 影像模型](https://artificialanalysis.ai/image/models)與[方法說明](https://artificialanalysis.ai/methodology/image) [25] | 偏好品質、API 價格與生成時間 | 生成或編輯、供應商、設定及評測版本 |

偏好分數不能保證繁體中文字形正確，也不能保證編輯區域以外完全不變。抄錄結果時，請一起記錄查閱日期、模型識別碼、品質模式、解析度、提示修訂、樣本數與評估版本。供應商自述、獨立比較，以及自己的驗收試驗應分開記錄。[20–25]

## 用一張小型驗收表比較

使用相同需求、輸入素材、目標尺寸與花費上限。不同模型的專屬控制要記錄清楚；相同的隨機種子數字，不代表不同系統使用等價的隨機性。

| 試驗 | 要檢查什麼 |
| --- | --- |
| 有指定物件與位置的簡單場景 | 是否漏掉物件、空間關係是否正確、構圖是否合適 |
| 包含精確文字的海報 | 拼字、繁體中文字形、標點與可讀性 |
| 只修改選定物件的編輯 | 指定修改是否完成，其他區域是否意外改變 |
| 由參考圖引導的一組相關素材 | 主體特徵、風格一致性與有用的變化 |
| 放進最終應用的匯出檔 | 尺寸、需要時的透明背景，以及可見瑕疵 |

保留失敗輸出，不只保留最佳樣本。記錄生成費用、重試次數、編輯時間，以及各結果是否通過。**每份驗收素材的成本**應包含失敗嘗試；若沒有替人工修整計價，就另外列出工時。稍慢的系統若需要較少修補，也可能更適合。比較原則可參考[模型與評測指南](/zh-tw/blog/models-benchmarks-and-people/)。

## 實際的起步路徑

偶爾製作插畫，可先從託管介面與清楚需求開始。需要重複生產素材時，測試 API 或可儲存的流程。需要本地執行或客製化時，再依硬體與授權需求評估開放權重版本。文字或版面必須精確時，若傳統設計工具更容易控制，就把這些部分留在設計工具裡完成。

靜態影像通過驗收後，再把它當成有明確用途的動態素材輸入。接著可讀[影片生成模型怎麼選](/zh-tw/blog/choosing-video-generation-models/)；動作與時間上的一致性會帶來額外的失敗情況。
