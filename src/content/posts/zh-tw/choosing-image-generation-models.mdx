選擇影像系統，先看你要交付什麼影像。一張有說服力的概念草圖、標籤必須保持原樣的產品照，以及文字必須完全正確的示意圖，需要不同的檢查。展示頁中最漂亮的一張圖，不一定回答你的問題。

正文以不隨模型更新而過時的方式，說明能力與評估。具體的產品、模型 ID、開放權重的釋出與評測連結，都在[現行選項](#現行選項查核日期-2026-年-11-月-6-日)。本文沒有執行生成實驗，也不提供排名。

## 重點

- 先說清楚是哪一種操作：文生圖、指令式編輯、遮罩式局部重繪／向外延展、參考圖引導的生成，或結構控制的生成。系統之間的差異，更多來自操作類型，而不是整體「品質」。
- 目前多數系統在壓縮的潛在空間中，從雜訊逐步迭代；少數系統生成離散的影像 token。這些機制可以解釋常見的失敗，例如編輯時「應保持不變」的區域發生漂移。
- 依交付成果對應的能力軸評判系統：指令遵循、文字呈現、編輯保留度、主體一致性、解析度、控制力、速度與成本，以及使用權利。
- 自動指標與排行榜量測的範圍很窄：FID 比較分布，CLIP 類分數量測文字與影像的一致性，組合式評測計算物件與關係，偏好競技場量測品味。沒有任何一項能替你的用途背書。
- 用自己的需求與素材做一張小型驗收表，保留失敗的輸出，並比較每份驗收素材的成本。
- 檢查確切權重檔的授權與託管條款；發布的影像可考慮附上來源出處的中繼資料。

## 先決定需要哪種操作

| 操作 | 起點 | 典型用途 | 要檢查什麼 |
| --- | --- | --- | --- |
| 文生圖 | 一段文字描述 | 概念圖、插畫 | 構圖、物件數量、空間關係 |
| 指令式編輯 | 一張影像與一道指令 | 「把外套改成紅色」 | 要求的修改，*以及*所有應保持不變的部分 |
| 局部重繪／向外延展 | 影像加遮罩，或更大的畫布 | 移除物件；延伸背景 | 接縫、光線連續性、遮罩邊界 |
| 參考圖引導 | 一張或多張參考影像 | 一組作品中一致的角色或產品 | 主體特徵、比例，以及標誌之類的小細節 |
| 結構控制 | 草圖、邊緣圖、深度圖或姿態 | 版面必須精確的構圖 | 與控制訊號的吻合度 |
| 放大 | 低解析度影像 | 最終交付尺寸 | 憑空產生的細節、紋理瑕疵 |

名為「參考」的功能，依產品不同，可能指風格引導、保留主體特徵，或是邊界框架；請閱讀它的定義。結構控制是透過 ControlNet 之類的方法普及的：它在凍結的文生圖模型上加入一條可訓練的條件分支，讓邊緣圖、深度圖或姿態能引導版面。[1]

## 影像生成器如何運作（簡述）

**白話版。** 多數現代生成器從隨機雜訊開始，在你的文字引導下一步步去除雜訊，直到剩下一張影像。為了節省運算，它們處理的是影像的壓縮版本，最後再解碼。

**精確版。** *潛在擴散*（latent diffusion）先訓練一個自編碼器，把影像映射到較小的潛在格網，再於該潛在空間中訓練去雜訊網路，並透過交叉注意力以文字為條件；生成時，去雜訊器執行若干步，再解碼結果。[2] 許多近期的系統把卷積式去雜訊器換成 Transformer，並以*整流流*（rectified flow）訓練，這種公式化沿著一條直線連接資料與雜訊。[3] 另一類系統生成離散的影像 token，可逐一生成，也可平行預測被遮罩的 token，例如 Google Research 的 Muse。[4] 有些目前的產品在多模態語言模型的對話中生成並編輯影像，讓多輪編輯變得自然。本站的 [ML 08](/zh-tw/learn/ml/diffusion-flow-matching/#潛在擴散與擴散-transformer) 與 [ML 09](/zh-tw/learn/ml/autoregressive-vision/#遮罩生成模型maskgit-與-muse) 深入說明這些機制。

這些機制對選型的意義：

- **編輯是重新生成。** 常見的編輯做法，是對輸入影像加雜訊，再朝新指令去雜訊；加入的雜訊量，是在忠於原圖與自由改動之間取捨。[5] 這就是為什麼「不變」的區域可能漂移，也是為什麼以遮罩為基礎的局部重繪或專用的編輯模型能保留更多。
- **文字呈現因系統與文字而異。** 字母是小而精確的細節，有些釋出版本明確把文字呈現列為訓練重點（見現行選項中的 Qwen-Image）。請用你實際的文字與語言（包含繁體中文），在最終顯示尺寸下測試。
- **種子不可跨系統沿用。** 種子固定的是某個模型、取樣器與解析度的起始雜訊。在另一個系統或另一個版本中使用同一個種子，是不同的實驗。
- **步數與引導強度也是結果的一部分。** 步數較少較快；引導強度（guidance scale）在指令遵循與多樣性、自然度之間取捨（見 ML 08 的[無分類器引導](/zh-tw/learn/ml/diffusion-flow-matching/#無分類器引導cfg)）。每個輸出都要一併記錄這些設定。

## 能力軸與各自的測法

| 能力軸 | 意義 | 快速測試 |
| --- | --- | --- |
| 指令遵循 | 物件、數量、屬性與空間關係正確 | 「三個紅色杯子在一個藍色碗的左邊」：檢查數量與位置 |
| 文字呈現 | 字元、拼字、標點完全正確 | 你真正的標題，用你的語言，在最終尺寸下 |
| 編輯保留度 | 只有要求的區域改變 | 編輯一個物件；對其餘部分做差異比對 |
| 主體一致性 | 跨影像與跨編輯保持同一主體 | 同一個角色或產品的五個場景 |
| 風格範圍與控制 | 能否符合品牌風格或參考圖？ | 同一份需求，用三種指定風格 |
| 解析度與長寬比 | 原生尺寸；放大的品質 | 以你的交付尺寸與長寬比生成 |
| 速度與成本 | 在你的設定下，每張影像的時間與花費 | 在整個試用中量測，包含失敗的 |
| 權利與出處 | 權重授權、託管條款、內容憑證 | 閱讀授權檔與你預定用途的條款 |

## 評測與指標能告訴你什麼

**白話版。** 每個指標只檢查一項狹窄的性質。用它們來建立候選名單，不要用它們做決定。

- **FID（Fréchet Inception Distance）** 在預訓練網路的特徵空間中，比較大量生成影像與大量真實影像的統計量。它量測的是分布層級的真實感與多樣性，需要數千個樣本，且無法告訴你某一張影像是否符合它的提示。[6]
- **CLIP 類分數**（例如 CLIPScore）用預訓練的影像—文字模型，量測影像與文字之間的一致性；成本低，但與 FID 一樣只給出整體的分數，不適合檢查個別物件、數量或位置。[7, 8]
- **組合式評測**（由偵測器或問答模型評分的物件、數量、屬性與關係檢查）直接針對指令遵循；它們的分數取決於評測版本與評審模型。[8, 9, 10]
- **人類偏好排行榜**依成對投票為系統排名。它們反映整體吸引力，而不是精確的文字、編輯保留度或權利。[11, 12]

[ML 08 評估生成模型的小節](/zh-tw/learn/ml/diffusion-flow-matching/#評估生成模型)說明了 FID 及其後繼指標。不論來源為何，都要記錄評測版本、模型 ID、品質設定、解析度、樣本數與評估者，並把供應商自述的主張與獨立比較分開。

## 做一張小型驗收表

每個候選都使用相同的需求、輸入素材、交付尺寸與預算。

| 試驗 | 要檢查什麼 |
| --- | --- |
| 有指定物件與位置的簡單場景 | 缺少的物件、空間關係、構圖 |
| 包含精確文字的海報 | 拼字、繁體中文字形、標點、可讀性 |
| 只限於一個物件的編輯 | 要求的修改，以及其他地方意外的改變 |
| 由參考圖引導的一組相關素材 | 主體特徵、風格一致性、有用的變化 |
| 以最終格式匯出 | 尺寸、需要時的透明背景、可見的瑕疵 |

保留失敗的輸出，不只保留最好的樣本。記錄成本、重試、編輯時間，以及每項試驗是否通過。**每份驗收素材的成本**是全部花費（包含失敗）除以通過驗收的素材數；若沒有替人工修整計價，就另外列出。稍慢但需要較少修補的系統，整體可能更便宜。[模型評測指南](/zh-tw/blog/models-benchmarks-and-people/#一個數字能信任到什麼程度)說明了為什麼少數幾次試驗只能給出粗略的估計。

## 在本地執行模型

可下載的模型在一條*流程*（pipeline）中運作：文字編碼器、去雜訊器、影像解碼器，通常還有控制或放大用的額外元件。以節點為基礎的工作流程工具，讓你把這些元件串接起來並儲存整張流程圖，這是記錄一張影像如何產生的最佳方式。工具是工作台，不是模型：換了模型，同一張流程圖能產生的結果就不同；有些工具也提供付費的雲端節點，所以在本地開啟介面，不代表每一步都在本地執行。[13]

要估算整條流程的記憶體，而不只是主要的權重檔：文字編碼器、解碼器、中間張量、輸出解析度與批次大小都算在內。降低精度與在裝置之間搬移元件，是以記憶體換取速度。先從文件記載的設定開始，量測尖峰記憶體與耗時，只有在能解決明確需求時才加入自訂節點，因為它們會帶來可執行的程式碼與相依項。

## 權利與出處

影像模型和語言模型一樣有分層的條款：程式碼、權重與託管服務各自可能有不同的授權，同一個家族也可能混合寬鬆與非商業條款（見[授權的各層](/zh-tw/blog/models-benchmarks-and-people/#開放是每一層各自的性質)）。請檢查確切權重檔的授權，以及它需要的任何額外元件。若你要發布影像，可考慮附上出處中繼資料：C2PA 標準定義了內容憑證（Content Credentials），記錄內容來自何處、如何被編輯。[14]

## 實際的起步路徑

偶爾製作插畫，可先從託管介面與清楚的需求開始。需要重複生產素材時，測試 API 或可儲存的工作流程。需要本地執行或客製化時，再依硬體與授權需求評估開放權重的釋出版本。若傳統設計工具能提供更可靠的控制，就把精確的文字與版面留在設計工具中處理。靜態影像通過驗收後，再把它們當成動態素材的刻意輸入：接著讀[影片生成模型怎麼選](/zh-tw/blog/choosing-video-generation-models/)。
