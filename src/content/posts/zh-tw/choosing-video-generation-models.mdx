請依照要完成的鏡頭選擇影片模型。開場畫面漂亮還不夠：主體必須維持可辨識的樣貌，動作要完成，片段也要能接進前後剪輯。若還需要參考影像或分鏡，可以先讀[影像生成模型選擇](/zh-tw/blog/choosing-image-generation-models/)。

本文來源查核日期為 **2026 年 11 月 6 日**。這是依文件整理的選擇指南，不是重跑的評測，也不表示我們實測過每項產品。列出的版本是例子；開始專案前，仍要確認實際端點或權重。

## 先釐清手上有什麼素材

**文生影片（text-to-video）**從文字場景開始；**圖生影片（image-to-video）**加入影像，約束外觀或構圖；**影片轉換與編輯（video-to-video）**則沿用既有動態，修改指定部分。參考影像、起訖影格、片段延伸及聲音都是額外能力，支援情況會隨模型與介面改變。Veo、Luma 與 Runway 的文件列出不同組合。[1–3]

若商品形狀很重要，先用確認過的影像測試形狀能否在動態中維持；若必須保留演員原有的動作，應研究影片編輯；若只是探索氣氛鏡頭，文字可能已足夠。「參考」可能指引導身分、風格或邊界影格，不能假設這些功能可以互換。

## 託管服務的選項

| 模型家族或服務 | 文件中的方向 | 優先測試什麼 |
| --- | --- | --- |
| [Google Veo 3.1 GA](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/veo/3-1-generate) | 雲端模型 ID 為 `veo-3.1-generate-001` 與 `veo-3.1-fast-generate-001`；具原生聲音與時間控制 [1] [12] | 同時檢查動態、指定對白與聲畫同步 |
| [Gemini Omni 1.2 Flash](https://aistudio.google.com/docs/omni) | 以 `gemini-omni-1.2-flash` 透過 Interactions API 生成影片及進行對話式影片編輯 [11] | 連續編輯能否保留主體與先前確認的內容 |
| [Runway Gen-4.5、Aleph 2.0](https://docs.dev.runwayml.com/guides/models/) | 目錄 ID `gen4.5`、`gen4_turbo`、`aleph2` 對應不同生成／編輯模型 [2] | 實際端點接受的輸入，以及編輯時能否保留其他內容 |
| [Luma Ray 3.2](https://docs.agents.lumalabs.ai/guides/model/) | Luma Agents 的 `ray-3.2` 支援生成、編輯與重新構圖 [3] | 指定修改後，原鏡頭中不應改變的內容能否保留 |
| [Kling 4.0、Seedance 2.5](https://docs.dev.runwayml.com/guides/models/) | Runway 目錄中的例子為 `kling_4`、`seedance2_5`；先前變體使用不同 ID [2] | 參考素材類型、聲音、時長與各供應者條款 |
| [MiniMax H3、H3 Max](https://docs.dev.runwayml.com/guides/models/) | Runway 目錄 ID `hailuo3`、`h3_max` 提供其他託管候選 [2] | 實際端點的動態、聲音支援及驗收鏡頭成本 |

服務可以代管其他公司的模型，Runway API 目錄不代表全部模型都由 Runway 開發。同樣地，一般使用者介面與 API 也可能提供不同控制選項；請比較你真正要使用的產品。

**可用性也必須查核：**OpenAI 官方公告指出，Sora 網頁與 App 已於 2026 年 4 月 26 日停止服務，API 則於 2026 年 9 月 24 日停止服務。因此 Sora 適合放在歷史比較，不能列為本文的現行服務候選。[4]

**模型名稱與存取管道都要固定。**Google 現行影片文件指出，Gemini API 的 Veo 3.1 Preview 端點已於 2026 年 10 月 22 日停止服務，替代指南指定 `gemini-omni-1.2-flash`。上表另一個管道的雲端 GA Veo 端點仍有獨立文件與存取條件。只看 Veo 研究頁，無法確定可用的 Gemini API 端點。[11] [12]

**Muse 指哪一個？**Meta 的 [Muse Image／Muse Video 公告](https://ai.meta.com/blog/introducing-muse-image-muse-video-msl/)將 Muse Video 列為具原生聲音的預覽模型，也說明聲畫同步與快速動作的物理合理性仍有不足。這份公告日期為 2026 年 7 月 7 日；[目前的 Meta Model API 目錄](https://dev.meta.ai/docs/models)並未列出 Muse Video 生成端點，因此這裡不假設它有公開 API ID 或開放權重。[21] [22] Microsoft 的 [Muse／WHAM](https://www.microsoft.com/en-us/research/blog/introducing-muse-our-first-generative-ai-model-designed-for-gameplay-ideation/)則是另一個遊戲構思研究模型，生成遊戲畫面與控制器動作。[23]

## 開放權重與本地執行

| 發行家族 | 為什麼值得研究？ | 授權與維運 |
| --- | --- | --- |
| Wan2.2：[T2V-A14B](https://huggingface.co/Wan-AI/Wan2.2-T2V-A14B)、[I2V-A14B](https://huggingface.co/Wan-AI/Wan2.2-I2V-A14B)、[TI2V-5B](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B) | 分別提供文字、影像及文字／影像共同條件的權重 [5] | 儲存庫採 Apache-2.0；也要檢查所選權重與相依項 |
| HunyuanVideo 與 [HunyuanVideo-1.5](https://huggingface.co/tencent/HunyuanVideo-1.5) | 公開推論程式；1.5 發行區分 T2V、I2V 與蒸餾變體 [6] [13] | Tencent Hunyuan Community License 有自己的適用條件 [7] |
| [LTX-2 模型卡](https://huggingface.co/Lightricks/LTX-2)：`ltx-2-19b-dev`、`ltx-2-19b-distilled` | 公開聲音／影片推論與訓練工具；完整與蒸餾權重是不同選項 [8] [14] | 程式碼的 Apache-2.0 不取代模型授權；LTX-2 權重使用 Community License [9] |
| CogVideoX1.5：[5B T2V](https://huggingface.co/zai-org/CogVideoX1.5-5B)、[5B I2V](https://huggingface.co/zai-org/CogVideoX1.5-5B-I2V) | 提供明確區分文生影片與圖生影片的模型卡 [15] | 閱讀權重的 CogVideoX 授權；可以下載不代表採 Apache-2.0 |
| [Mochi 1 preview](https://huggingface.co/genmo/mochi-1-preview) | 可加入本地比較的另一個開放文生影片權重 [16] | 模型卡標示 Apache-2.0；結果紀錄應保留 preview 版本名稱 |

這些固定版本用來說明部署選項，不代表每個家族的最新版本。可以下載權重，不保證筆電能執行預定工作。記憶體與時間取決於解析度、生成影格數、精度、模型元件與執行環境。卸載到其他記憶體可以降低 GPU 記憶體壓力，卻可能增加傳輸與延遲。先從儲存庫支援的設定開始，再測量實際工作負載。

要重現下載版本，請保存模型卡網址**及其 revision／commit**、確切權重檔名、程式版本、精度／量化、取樣器與步數。蒸餾權重或量化轉換版本，應與完整發行版本分別實驗；只記錄家族名稱無法交代這些設定。

程式碼、權重、額外編碼器與託管服務是不同成果，也可能有不同條款。公開儲存庫不能直接證明所有商業用途或衍生成果散布都被允許。

## 看動態，不只看截圖

VBench 把影片品質拆成主體一致性、動作平順度、時間閃爍與空間關係等面向。它的價值是讓不同失敗模式看得見，而不是把所有偏好壓成一個漂亮數字。引用結果時，要確認評測版本、提示詞與評估設定。[10]

| 評測連結 | 提供什麼資訊 | 比較界線 |
| --- | --- | --- |
| [VBench 專案](https://vchitect.github.io/VBench-project/)與[官方排行榜](https://huggingface.co/spaces/Vchitect/VBench_Leaderboard) | 各面向的技術與語意品質，並提供評估程式 [10] [18] | 記錄選用的評測套件、任務與生成設定 |
| [VBench-2.0 論文](https://arxiv.org/abs/2503.21755)與[評估／提示詞指引](https://github.com/Vchitect/VBench/blob/master/VBench-2.0/README.md) | 人物忠實度、可控性、創意、物理與常識 [17] | 它與 VBench 是不同套件，分數不能直接互換 |
| Artificial Analysis [T2V](https://artificialanalysis.ai/video/leaderboard/text-to-video)／[I2V](https://artificialanalysis.ai/video/leaderboard/image-to-video) v2.1 與[方法說明](https://artificialanalysis.ai/methodology/video) | 盲測成對偏好、各評測的設定，以及分開的有聲／靜音評估 [19] [20] | 現行方法使用經驗證的私人評審；公開 Arena 投票不計入這些評測 |

保存排行榜日期、確切模型／供應者 ID、任務、聲音設定、解析度、影格率、時長、提示詞改寫與取樣預算。一起看信賴區間和失敗面向，再測試自己的鏡頭需求。有聲排行榜與靜音影片評測回答的問題不同；本文不把動態名次固定成結論，也沒有重跑這些分數。

自己的試驗可以用一份簡短檢查表：

- **指令：**要求的動作是否依正確順序發生？
- **連貫性：**臉孔、物件、衣著與背景是否保持一致？
- **動態：**接觸、遮擋與攝影機運動是否合理？
- **聲音：**若支援，對白與音效是否對應可見事件？
- **可剪輯性：**起點與終點能否接上前後鏡頭？

先以正常速度看完整段，再逐格檢查可疑轉折。不要讓清晰截圖掩蓋物件在中途變形的問題。原生聲音也不保證語音自然；Veo 官方文件本身就說明聲音一致性仍有待改善。[1]

## 實際可用的鏡頭流程

先寫鏡頭需求，包含主體、動作、攝影機運動、光線、構圖與必要聲音，並把必要條件和美感偏好分開。準備有權使用的參考素材，確認工具支援你預期的用途。

生成短草稿，檢查整段內容，每輪只改一個主要變因。商品鏡頭可先確認形狀與動態，再調整氣氛。保留提示詞、輸入素材、模型與版本、設定、輸出，以及淘汰原因。工具若提供隨機種子，可以一起記錄，但跨版本或執行環境時，不保證結果完全相同。

把驗收過的鏡頭放進剪輯軟體，再檢查切換處是否連貫。延伸一段影片，不會自動解決長故事的所有問題：人物狀態、畫面方向、光線與聲音仍要規劃。這是建議的試驗程序；本文沒有執行付費影片生成。

## 比較真正可用片段的成本

可以用**每秒驗收片段的成本**比較：全部生成支出（包含淘汰嘗試），除以實際接受並放入剪輯的時長。請說明是否包含放大、聲音、儲存與人工剪輯費用。若沒有任何片段通過，就應報告失敗，而不是提供誤導性的價格。

比較時維持相近的解析度、時長、來源素材、試驗預算與驗收條件；也要記錄排隊時間，不只看生成時間。新手可先用一項託管服務完成範圍明確的鏡頭；當客製化、資料位置或持續產量足以支持維運成本時，再研究本地權重。升級後重用相同試驗鏡頭，方法可參考[模型評估指南](/zh-tw/blog/models-benchmarks-and-people/)。
