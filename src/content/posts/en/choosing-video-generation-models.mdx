Choose a video model for the shot you need. A beautiful opening frame is not enough: the subject must remain recognizable, the action must finish, and the clip must fit the surrounding edit. Start with [image-generation selection](/en/blog/choosing-image-generation-models/) if you first need a reference image or storyboard.

Sources were checked on **6 November 2026**. This is a documented selection guide, not a reproduced benchmark or a claim that every listed product was tested. Named releases are examples; check the exact endpoint or checkpoint before starting a project.

## Decide what you already have

**Text-to-video** starts from a written scene. **Image-to-video** adds an image that constrains appearance or composition. **Video-to-video and editing** begin with existing motion and change selected aspects. Reference images, start/end frames, extensions, and audio are additional capabilities; support varies by model and interface. Veo, Luma, and Runway document different combinations. [1–3]

If the product's shape matters, begin with an approved image and test whether it survives motion. If an actor's existing movement matters, investigate video editing. For an exploratory mood shot, text alone may be sufficient. A feature called “reference” may guide identity, style, or a boundary frame: read its definition rather than assuming these are interchangeable.

**Availability matters:** OpenAI's official notice says the Sora web/app experiences ended on 26 April 2026 and the API ended on 24 September 2026. Sora belongs in historical comparisons, not this guide's current-service shortlist. [4]

**Pin the access surface as well as the model name.** Google's current video guide says the Gemini API's Veo 3.1 Preview endpoints were shut down on 22 October 2026; its replacement guide names `gemini-omni-1.2-flash`. The separate Cloud GA Veo endpoints above remain documented with their own access conditions. A Veo research page alone does not identify a working Gemini API endpoint. [11] [12]

**Which Muse?** Meta's [Muse Image / Muse Video announcement](https://ai.meta.com/blog/introducing-muse-image-muse-video-msl/) describes Muse Video as a preview with native audio, and identifies audio/video synchronization and fast-motion physics as remaining gaps. That announcement is dated 7 July 2026; the [current Meta Model API catalog](https://dev.meta.ai/docs/models) does not list a Muse Video generation endpoint, so no public API ID or open checkpoint is assumed here. [21] [22] Microsoft's [Muse / WHAM](https://www.microsoft.com/en-us/research/blog/introducing-muse-our-first-generative-ai-model-designed-for-gameplay-ideation/) is a separate gameplay-ideation research model that generates game visuals and controller actions. ## Open weights and local execution

| Release family | Why inspect it? | Licensing and operation |

| HunyuanVideo and [HunyuanVideo-1.5](https://huggingface.co/tencent/HunyuanVideo-1.5) | Public inference code; the 1.5 release distinguishes T2V, I2V and distilled variants [6] [13] | Tencent Hunyuan Community License has its own conditions [7] |
| [LTX-2 model card](https://huggingface.co/Lightricks/LTX-2): `ltx-2-19b-dev`, `ltx-2-19b-distilled` | Public audio/video inference and training tools; full and distilled checkpoints are different choices [8] [14] | Apache-2.0 code does not replace the separate model license; the LTX-2 weights have a Community License [9] |
| CogVideoX1.5: [5B T2V](https://huggingface.co/zai-org/CogVideoX1.5-5B), [5B I2V](https://huggingface.co/zai-org/CogVideoX1.5-5B-I2V) | Explicit text-to-video and image-to-video model cards [15] | Read the checkpoint's CogVideoX license; downloadable weights are not automatically Apache-2.0 |
| [Mochi 1 preview](https://huggingface.co/genmo/mochi-1-preview) | An additional open text-to-video checkpoint for a local comparison [16] | Model card identifies Apache-2.0; keep its preview status in the result record |

These fixed releases illustrate deployment options, not the newest release of every family. Downloadable weights do not guarantee that a laptop can run the intended workload. Memory and time depend on resolution, generated frame count, precision, model components, and runtime. Offloading can reduce GPU memory pressure while increasing transfers and latency. Start with the repository's supported configuration, then measure your target workload.

For a reproducible download, save the model-card URL **and its revision/commit**, exact checkpoint filename, code revision, precision/quantization, sampler and step count. A distilled checkpoint or a quantized conversion is a separate experiment from the full release; a family name does not specify those settings.

Treat code, weights, additional encoders, and hosted access as separate artifacts with separate terms. A public repository is not proof that every commercial use or derivative distribution is permitted.

## Judge motion, not just screenshots

VBench decomposes video quality into dimensions including subject consistency, motion smoothness, temporal flicker, and spatial relationships. Its value is showing different failure modes rather than compressing every preference into one attractive number. Check which benchmark version, prompts, and evaluation settings a result uses. [10]

| Benchmark link | What it contributes | Comparison boundary |
| --- | --- | --- |
| [VBench project](https://vchitect.github.io/VBench-project/) and [official leaderboard](https://huggingface.co/spaces/Vchitect/VBench_Leaderboard) | Dimension-level technical and semantic quality, with published evaluation code [10] [18] | Record the selected suite/task and generation settings |
| [VBench-2.0 paper](https://arxiv.org/abs/2503.21755) and [evaluation/prompt instructions](https://github.com/Vchitect/VBench/blob/master/VBench-2.0/README.md) | Human fidelity, controllability, creativity, physics and commonsense [17] | A different suite from VBench; its scores are not interchangeable with VBench totals |
| Artificial Analysis [T2V](https://artificialanalysis.ai/video/leaderboard/text-to-video) / [I2V](https://artificialanalysis.ai/video/leaderboard/image-to-video) v2.1 and [methodology](https://artificialanalysis.ai/methodology/video) | Blind pairwise preferences, with benchmark-specific settings and separate audio/silent evaluations [19] [20] | The current methodology uses validated private evaluators; public Arena votes do not count toward these benchmarks |

Save the leaderboard date, exact model/provider IDs, task, audio setting, resolution, frame rate, duration, prompt rewriting and sampling budget. Compare confidence intervals and failure dimensions, then test your own shot brief. A leaderboard with audio and a silent-video benchmark answer different questions; this article does not freeze a current ranking or reproduce their scores.

For your own trial, use a short review sheet:

- **Instruction:** Does the requested action occur in the right order?
- **Continuity:** Do faces, objects, clothing, and backgrounds remain consistent?
- **Motion:** Do contacts, occlusion, and camera movement remain plausible?
- **Sound:** If supported, do speech and effects match the visible event?
- **Editability:** Are the opening and ending usable beside the neighboring shots?

Watch the full clip at playback speed, then inspect suspicious transitions frame by frame. Do not let a sharp still frame conceal an object changing shape halfway through. Native audio is also not a guarantee of natural speech; Veo's own documentation describes ongoing audio-consistency limitations. [1]

## A practical shot workflow

Write a shot brief with subject, action, camera movement, lighting, framing, and required sound. Separate mandatory details from aesthetic preferences. Prepare reference assets you have permission to use, and confirm whether the selected tool supports their intended role.

Generate a short draft, review the whole sequence, and change one major variable per iteration. For a product shot, first establish shape and motion; refine atmosphere afterward. Save the prompt, input assets, model/version, settings, outputs, and rejection reasons. A seed, where supported, is useful metadata but does not promise identical results across changed versions or runtimes.

Assemble accepted shots in an editor and review continuity across cuts. Extending one clip does not automatically solve a longer story: character state, screen direction, lighting, and sound still need deliberate planning. This workflow is a proposed trial procedure; no paid generations were run for this article.

## Compare the cost of usable footage

Use **cost per accepted second**: all generation spending, including discarded attempts, divided by the duration actually accepted into the edit. State whether upscaling, audio, storage, and human editing are included. When no footage passes, report that failure rather than a misleading price.

Keep resolution, duration, source assets, trial budget, and acceptance rules comparable. Record waiting time as well as generation time. Begin with one hosted service for a bounded shot; investigate local weights when customization, data location, or sustained volume justifies operating them. Reuse the same trial shots after upgrades, following the [model-evaluation guide](/en/blog/models-benchmarks-and-people/).
