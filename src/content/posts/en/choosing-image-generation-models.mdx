Choose an image system by the image you need to deliver. A convincing concept sketch, a product photo with an unchanged label, and a diagram with exact text require different checks. The most attractive sample in a gallery may not answer your question.

This guide compares documented capabilities and deployment choices, with sources checked on **5 November 2026**. It does not report a generation experiment or a performance ranking. Named downloadable releases are concrete examples, not a claim that they are the latest models.

## First decide which operation you need

Text-to-image starts from a description. Image editing starts from an existing image and an instruction. Inpainting targets a region, often specified by a mask; outpainting extends the canvas. A reference image may guide appearance without guaranteeing exact preservation. The interface and selected model determine which operations are actually available. [1, 4]

For a new illustration, judge composition and instruction following. For an edit, also inspect everything that should remain unchanged. For a poster, read every character at the final display size. For a product asset, check shape, label, proportions, and the intended background separately.

## Hosted tools: start with the workflow

| Family or product | Documented role | A useful first trial |
| --- | --- | --- |
| OpenAI GPT Image | Generation and editing through APIs, including conversational editing through supported integrations [1] | Revise one object while preserving the surrounding scene |
| Gemini Image / Nano Banana | Image generation and editing within Google's model family [2] | Make a sequence of requested edits and check whether identity drifts |
| Midjourney | Image creation with explicit model-version selection [3] | Produce concepts for the same brief, then compare the effort needed to refine one |
| Adobe Firefly | Creative generation and editing tools, including Adobe and partner models [4] | Complete an asset in the design workflow where it will actually be used |

These are selection tests, not claims that one family wins them. Record the actual model and version: Midjourney's checked version page lists V8.2 as its default, and defaults change. Firefly is also an interface to partner models; a model available inside Firefly is not necessarily an Adobe-trained model. [3, 4]

A hosted tool is convenient when you want to start without managing GPU software. Check the export format, editing controls, account limits, input-image handling, and current commercial terms. An application subscription and an API account can have different entitlements.

## Open weights: inspect the exact release

| Downloadable example | What the primary source establishes | Selection implication |
| --- | --- | --- |
| Qwen-Image | Apache-2.0 model card with generation examples and a focus on text rendering [5] | Include your actual Traditional Chinese text in the trial; language support is not a guarantee of exact lettering |
| FLUX.2 [klein] 4B | Apache-2.0 weights in Black Forest Labs' license table [6] | A different licensing option from the 9B variant |
| FLUX.2 [klein] 9B | Open weights under non-commercial terms; commercial deployment requires appropriate licensing [6] | Do not apply the 4B license to the entire family |
| Stable Diffusion 3.5 Large | Downloadable model under the Stability AI Community License [7] | Read that license's conditions rather than treating it as Apache-2.0 |

Downloadability, source-code licensing, and permission to use a particular weight release are separate facts. A paid hosted API can also serve an open-weight model. Check the checkpoint, any additional components, and the terms for your intended deployment; the family name alone is insufficient.

## ComfyUI is the workbench, not the model

ComfyUI provides a node-based workflow interface and backend. A graph connects loading, conditioning, generation, and output operations; changing the model changes what the workflow can produce. Its ecosystem also includes optional paid API nodes, so a locally opened interface does not by itself prove that every operation is local. [8]

Use a minimal supported workflow first. Save the graph, model identifiers, software versions, and settings alongside the output. Add custom nodes only when they solve a clear need: they add executable code and dependencies as well as features. An exported workflow is useful evidence, but it still needs compatible models and software to run.

For local hardware, estimate the whole pipeline rather than only the main weight file. Text encoders, image decoding, intermediate tensors, output resolution, and batch size affect memory. Reduced precision and moving components between devices can change memory use and speed. Start with a documented configuration, measure peak memory and elapsed time, and increase complexity only after that works.

## Compare outputs with a small acceptance sheet

Use the same brief, input assets, intended dimensions, and spending limit. Keep model-specific controls documented; the same seed number does not create equivalent randomness across different systems.

| Trial | What to inspect |
| --- | --- |
| A simple scene with specified objects and positions | Missing objects, spatial relationships, and composition |
| A poster containing your exact text | Spelling, Traditional Chinese characters, punctuation, and legibility |
| An edit confined to a selected object | Requested change and unintended changes elsewhere |
| A reference-led set of related assets | Subject identity, style consistency, and useful variation |
| An export used in the final application | Dimensions, transparency if required, and visible artifacts |

Keep failed outputs, not only the best sample. Record generation cost, retries, editing time, and whether each result passes. **Cost per accepted asset** includes unsuccessful attempts; report human cleanup separately if you do not price it. A slightly slower system can be preferable if it produces usable assets with fewer repairs. See [the model and benchmark guide](/en/blog/models-benchmarks-and-people/) for comparison principles.

## A practical starting route

For occasional illustrations, begin with a hosted interface and a clear brief. For repeatable asset production, test an API or a saved workflow. For local operation or customization, evaluate an open-weight release against your hardware and licensing needs. Keep exact text or precise layout in a conventional design tool when that gives you more reliable control.

Once still images meet your acceptance checks, use them as deliberate inputs to motion work. Continue with [choosing video-generation models](/en/blog/choosing-video-generation-models/): motion and consistency over time introduce additional failure modes.
