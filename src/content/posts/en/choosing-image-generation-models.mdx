Choose an image system by the image you need to deliver. A convincing concept sketch, a product photo with an unchanged label, and a diagram with exact text require different checks. The most attractive sample in a gallery may not answer your question.

This guide compares documented capabilities and deployment choices, with sources checked on **5 November 2026**. It does not report a generation experiment or a performance ranking. Named downloadable releases are concrete examples, not a claim that they are the latest models. Exact-version, Muse and benchmark links below were expanded on **6 November 2026**.

## First decide which operation you need

Text-to-image starts from a description. Image editing starts from an existing image and an instruction. Inpainting targets a region, often specified by a mask; outpainting extends the canvas. A reference image may guide appearance without guaranteeing exact preservation. The interface and selected model determine which operations are actually available. [1, 4]

For a new illustration, judge composition and instruction following. For an edit, also inspect everything that should remain unchanged. For a poster, read every character at the final display size. For a product asset, check shape, label, proportions, and the intended background separately.

## Hosted tools: start with the workflow

| Family or product | Documented role | A useful first trial |
| --- | --- | --- |
| [OpenAI GPT Image](https://developers.openai.com/api/docs/guides/image-generation) | Generation and editing through APIs, including conversational editing through supported integrations [1] | Revise one object while preserving the surrounding scene |
| [Gemini Image / Nano Banana](https://deepmind.google/models/gemini-image/) | Image generation and editing within Google's model family [2] | Make a sequence of requested edits and check whether identity drifts |
| [Midjourney versions](https://docs.midjourney.com/hc/en-us/articles/32199405667853-Version) | Image creation with explicit model-version selection [3] | Produce concepts for the same brief, then compare the effort needed to refine one |
| [Adobe Firefly](https://www.adobe.com/products/firefly.html) | Creative generation and editing tools, including Adobe and partner models [4] | Complete an asset in the design workflow where it will actually be used |
| [Meta Muse Image](https://dev.meta.ai/docs/image-generation) | `muse-image-1.0` supports generation and editing through Meta Model API, including multi-turn refinement [9] | Repeat a reference-led edit and inspect subject identity and unchanged regions |

These are selection tests, not claims that one family wins them. Record the actual model and version: Midjourney's checked version page lists V8.2 as its default, and defaults change. Firefly is also an interface to partner models; a model available inside Firefly is not necessarily an Adobe-trained model. [3, 4]

A hosted tool is convenient when you want to start without managing GPU software. Check the export format, editing controls, account limits, input-image handling, and current commercial terms. An application subscription and an API account can have different entitlements.

### Save a versioned source with the output

Use the provider's model catalog or API reference, not only a product nickname. The [OpenAI image API reference](https://developers.openai.com/api/reference/resources/images/methods/generate) lists explicit image-model IDs and dated snapshots; `gpt-image-2.5-sunburst-2026-09-08` is one versioned identifier to record. Google's [Gemini 3.1 Flash Image model page](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-image.md) identifies `gemini-3.1-flash-image` (Nano Banana 2). Use Google's [retirement table](https://ai.google.dev/gemini-api/docs/deprecations.md) to distinguish that stable ID from retired preview IDs and inspect newer named releases. An alias, a dated snapshot and a product-interface name are different records. [10, 11]

Other concrete hosted releases worth checking are [Microsoft MAI-Image-2.6](https://microsoft.ai/models/mai-image-2-6/), [Grok Imagine Image 2.0](https://docs.x.ai/developers/models/grok-imagine-image-2.0), and [ByteDance Seedream 4.0](https://seed.bytedance.com/en/seedream4_0). Their official pages link model capabilities and access routes; apply the same acceptance sheet rather than inferring quality or licensing from the family name. These are selected release links, not an exhaustive list or a claim of newest availability. [26, 27, 28]

## Open weights: inspect the exact release

| Downloadable example | What the primary source establishes | Selection implication |
| --- | --- | --- |
| [Qwen-Image](https://huggingface.co/Qwen/Qwen-Image) | Apache-2.0 model card with generation examples and a focus on text rendering [5] | Include your actual Traditional Chinese text in the trial; language support is not a guarantee of exact lettering |

| [Stable Diffusion 3.5 Large](https://huggingface.co/stabilityai/stable-diffusion-3.5-large) | Downloadable model under the Stability AI Community License [7] | Read that license's conditions rather than treating it as Apache-2.0 |
| [SDXL base 1.0](https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0) | A separately identified Stable Diffusion release with its own model card and license [13] | Match the workflow's exact base/refiner requirements |
| [PixArt-Σ XL-2-1024-MS](https://huggingface.co/PixArt-alpha/PixArt-Sigma-XL-2-1024-MS) | A downloadable diffusion-transformer release with a documented inference pipeline [14] | Measure the complete pipeline on your hardware |
| [HunyuanImage-3.0](https://huggingface.co/tencent/HunyuanImage-3.0) | Tencent's generation checkpoint and its community license [15] | Keep the generation and Instruct variants distinct |
| [Janus-Pro-7B](https://huggingface.co/deepseek-ai/Janus-Pro-7B) | A downloadable unified understanding/generation research release [16] | Test its generation workflow separately from image understanding |

Downloadability, source-code licensing, and permission to use a particular weight release are separate facts. A paid hosted API can also serve an open-weight model. Check the checkpoint, any additional components, and the terms for your intended deployment; the family name alone is insufficient.

For editing, also inspect the separate [Qwen-Image-Edit-2509 model card](https://huggingface.co/Qwen/Qwen-Image-Edit-2509); a generation checkpoint and an editing checkpoint are not interchangeable. [17]

## Two different Muse names

**Meta Muse Image** is the hosted image-generation/editing line above; its model catalog identifies `muse-image-1.0`. Muse Spark and Muse Wonder occupy a different role in Meta's catalog, so their names alone do not identify an image endpoint. [9]

**Google Research Muse (2023)** is the research project [Muse: Text-To-Image Generation via Masked Generative Transformers](https://muse-model.github.io/). It predicts masked discrete image tokens with text conditioning and refines them in parallel. Read it with the [official MaskGIT implementation](https://github.com/google-research/maskgit), an earlier masked-image-generation method. The cited Google Muse project is a method/paper resource, not evidence of a currently callable hosted API or a downloadable Google Muse checkpoint. [18, 19]

For the mechanisms and their limitations, continue with [ML 09: MaskGIT and Google Muse](/en/learn/ml/autoregressive-vision/#masked-generative-models-maskgit-and-muse). A historical paper's reported speed or benchmark result should retain its original comparison setup.

## ComfyUI is the workbench, not the model

ComfyUI provides a node-based workflow interface and backend. A graph connects loading, conditioning, generation, and output operations; changing the model changes what the workflow can produce. Its ecosystem also includes optional paid API nodes, so a locally opened interface does not by itself prove that every operation is local. [8]

Use a minimal supported workflow first. Save the graph, model identifiers, software versions, and settings alongside the output. Add custom nodes only when they solve a clear need: they add executable code and dependencies as well as features. An exported workflow is useful evidence, but it still needs compatible models and software to run.

For local hardware, estimate the whole pipeline rather than only the main weight file. Text encoders, image decoding, intermediate tensors, output resolution, and batch size affect memory. Reduced precision and moving components between devices can change memory use and speed. Start with a documented configuration, measure peak memory and elapsed time, and increase complexity only after that works.

## Benchmark links: check what each measures

Use a leaderboard to form a shortlist, then open its methodology and the exact model/version row. The following resources answer different questions; their scores are not interchangeable.

| Resource | Useful evidence | What to check before comparing |
| --- | --- | --- |
| [GenEval](https://github.com/djghosh13/geneval) / [GenEval 2](https://github.com/facebookresearch/GenEval2) [20, 21] | Objects, counting, attributes and relations; GenEval 2 extends compositional coverage and its evaluator | Benchmark version, detector/VQA judge and per-skill results |
| [T2I-CompBench / ++](https://github.com/Karine-Huang/T2I-CompBench) [22] | Compositional attributes and relationships | Which benchmark edition, categories and evaluation model were used |
| [DPG-Bench](https://github.com/TencentQQGYLab/ELLA#-dpg-bench) [23] | Dense-prompt alignment through questions about requested content | Prompt set, image sampling and evaluator setup |
| [Arena text-to-image leaderboard](https://arena.ai/leaderboard/image/text-to-image) [24] | Relative preference rankings and category views | Model variant, evaluation date, vote support and uncertainty |
| [Artificial Analysis image models](https://artificialanalysis.ai/image/models) and [methodology](https://artificialanalysis.ai/methodology/image) [25] | Preference quality, API price and generation time | Generation versus editing, provider, settings and benchmark version |

A preference score does not certify exact Traditional Chinese lettering or preservation outside an edited region. Record the page's access date, model ID, quality mode, resolution, prompt revision, sample count and evaluator version with any copied result. Keep provider-reported claims separate from an independent comparison and your own acceptance trial. [20–25]

## Compare outputs with a small acceptance sheet

Use the same brief, input assets, intended dimensions, and spending limit. Keep model-specific controls documented; the same seed number does not create equivalent randomness across different systems.

| Trial | What to inspect |
| --- | --- |
| A simple scene with specified objects and positions | Missing objects, spatial relationships, and composition |
| A poster containing your exact text | Spelling, Traditional Chinese characters, punctuation, and legibility |
| An edit confined to a selected object | Requested change and unintended changes elsewhere |
| A reference-led set of related assets | Subject identity, style consistency, and useful variation |
| An export used in the final application | Dimensions, transparency if required, and visible artifacts |

Keep failed outputs, not only the best sample. Record generation cost, retries, editing time, and whether each result passes. **Cost per accepted asset** includes unsuccessful attempts; report human cleanup separately if you do not price it. A slightly slower system can be preferable if it produces usable assets with fewer repairs. See [the model and benchmark guide](/en/blog/models-benchmarks-and-people/) for comparison principles.

## A practical starting route

For occasional illustrations, begin with a hosted interface and a clear brief. For repeatable asset production, test an API or a saved workflow. For local operation or customization, evaluate an open-weight release against your hardware and licensing needs. Keep exact text or precise layout in a conventional design tool when that gives you more reliable control.

Once still images meet your acceptance checks, use them as deliberate inputs to motion work. Continue with [choosing video-generation models](/en/blog/choosing-video-generation-models/): motion and consistency over time introduce additional failure modes.
