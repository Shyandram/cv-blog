## The big picture

Two recognition systems can use exactly the same classifier and still behave very differently, because they describe the input differently. A texture histogram throws away where things are. A shape descriptor may ignore color. An embedding learned from web photos may quietly encode the background. Every representation keeps some variation and discards the rest, and the classifier can only use what was kept.

<Callout type="tip" title="Explain like I'm five">
Describe a toy to a friend so they can pick it out of a toy box. "It's red, round and the size of an orange" works. "It's made of atoms" is true but useless. Telling them all 500 things you can see is too much to remember. A good description is short and keeps exactly the clues that tell this toy apart from the others.
</Callout>

This chapter is about building that short, useful description. There are three ways to get one:

- **Selection** keeps a subset of the original measurements, for example 20 of 5,000 gene-expression levels. The kept features remain interpretable.
- **Extraction** computes new coordinates as functions of all measurements, for example the projection onto a few principal components.
- **Learning** estimates an extraction rule from data, often with a deep network ([ML 06](/en/learn/ml/ml-05-representation-learning/)). PCA is already a (very simple) learned extraction rule; the categories overlap.

Why bother, if a flexible classifier could use all the features? Three reasons. With a fixed number of training samples, adding weakly informative features can make a trained classifier *worse*, because each extra dimension adds parameters to estimate and room to overfit: the "curse of dimensionality" and the peaking phenomenon discussed by Theodoridis and Koutroumbas [1]. Fewer features are cheaper to measure, store and compute. And a small, meaningful feature set helps people understand what the classifier relies on. Guyon and Elisseeff list the same three motives in their classic introduction to feature selection [3]. The textbook background for this chapter is Theodoridis and Koutroumbas, Chapters 5–7 [1], and Bishop, Sections 4.1.4–4.1.6 and 12.1–12.4 [2]. For hand-designed image features, see also [IP 12](/en/learn/image-processing/dip-12-feature-extraction/).

## Feature selection

**In plain words.** Feature selection asks: which of the measurements I already have should I keep? You need a way to score features (or groups of features) and a way to search, because trying every subset is impossible.

With $D$ features there are $2^D - 1$ non-empty subsets: about $10^{30}$ for $D = 100$. Exhaustive search is out of the question except for tiny $D$. The approaches differ in how they score and how they search [3], [22], [23].

### Filter methods

A **filter** scores each feature (or subset) with a criterion computed directly from the data, independently of the final classifier, then keeps the best. Typical criteria are variance (drop near-constant features), a class-separation statistic such as the ANOVA $F$ statistic or the Fisher ratio (next section), correlation with the label, and the mutual information

$$
I(x_j; y) = \sum_{v}\sum_{c} p(x_j = v, y = c)\,\log\frac{p(x_j = v, y = c)}{p(x_j = v)\,P(y = c)} ,
$$

where $x_j$ is feature $j$ (discretized to values $v$), $y$ is the class label with values $c$, and $p$, $P$ are joint and marginal probabilities estimated from the training set. $I(x_j; y) = 0$ exactly when the feature and the label are statistically independent.

Filters are fast and classifier-agnostic, but univariate filters have two blind spots. **Redundancy**: two copies of the same good feature both score high, yet the second adds nothing. Peng, Long and Ding's mRMR criterion addresses this by rewarding relevance to the label while penalizing mutual information with already-selected features [6]. **Interactions**: two features can each be useless alone and decisive together. In the exclusive-or pattern $y = \mathbf{1}[x_1 > 0] \oplus \mathbf{1}[x_2 > 0]$, each feature on its own is independent of $y$, so every univariate filter discards both.

### Wrapper methods

A **wrapper** scores a candidate subset by training the actual classifier on it and measuring validation performance [4]. Because exhaustive search is impossible, wrappers use heuristics such as:

- **sequential forward selection**: start empty, repeatedly add the feature that most improves the validation score;
- **sequential backward elimination**: start with all features, repeatedly remove the least useful one;
- floating variants that may undo earlier steps [1].

Wrappers see interactions and redundancy through the classifier's eyes, but they are expensive (a full training run per candidate) and, because they try many subsets against the same validation data, they can overfit the validation set itself. Kohavi and John's paper that introduced the term is still the standard reference for these trade-offs [4].

### Embedded methods

An **embedded** method selects features as a side effect of training. The best-known example is the lasso, which adds an $\ell_1$ penalty to a linear model [5]:

$$
\hat w = \arg\min_w \ \frac{1}{2N}\sum_{n=1}^N \big(t_n - w^\top x_n\big)^2 + \lambda \lVert w\rVert_1, \qquad \lVert w\rVert_1 = \sum_{j=1}^D |w_j| ,
$$

with targets $t_n$, inputs $x_n$ and penalty strength $\lambda \ge 0$. The corners of the $\ell_1$ ball make many coordinates of $\hat w$ exactly zero, so the surviving coordinates are the selected features. The same idea applies to logistic regression for classification. Decision trees and their ensembles ([PR 04](/en/learn/pattern-recognition/pr-04-kernels-nonlinear-classifiers/), [PR 09](/en/learn/pattern-recognition/pr-09-ensembles-validation/)) also embed selection: a feature that never helps a split is never used.

### The selection-bias trap

Supervised selection uses the labels. If you select features on the full data set and *then* cross-validate only the classifier, the held-out folds have already influenced which features were chosen, and the error estimate is optimistic. Ambroise and McLachlan showed that this mistake made published gene-expression classifiers look nearly perfect; with selection performed inside each cross-validation fold, the error was no longer zero [7]. The code makes the effect concrete with features that are pure noise.

```python
import numpy as np
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(0)
X = rng.normal(size=(60, 5000))          # 60 samples, 5000 pure-noise features
y = rng.integers(0, 2, size=60)          # labels unrelated to X

# Wrong: select on all data, then cross-validate the classifier only.
X_sel = SelectKBest(f_classif, k=20).fit_transform(X, y)
wrong = cross_val_score(LogisticRegression(max_iter=1000), X_sel, y, cv=5)

# Right: selection is part of the model and is refitted in every fold.
model = make_pipeline(SelectKBest(f_classif, k=20),
                      LogisticRegression(max_iter=1000))
right = cross_val_score(model, X, y, cv=5)
print(f"selection outside CV: {wrong.mean():.2f}")
print(f"selection inside CV:  {right.mean():.2f}")
```

The labels are random, so no method can truly beat 50% accuracy. Selecting outside cross-validation reports 0.98. Putting the selector inside the pipeline reports 0.58, which is chance level up to the noise of a 60-sample estimate. The rule generalizes: every step that looks at labels (selection, supervised projection such as LDA, choosing the number of features) belongs inside the training procedure. Even unsupervised steps such as PCA and scaling should be fitted on training folds only, so that the procedure you evaluate is the procedure you will deploy.

## Evaluating features and feature subsets

**In plain words.** A good feature puts the classes far apart compared with how spread out each class is. Several formulas turn this idea into a number, from a simple per-feature ratio to criteria for whole subsets.

**Fisher's discriminant ratio** for a single feature compares the spread *between* class means with the spread *within* classes:

$$
\mathrm{FDR}_j = \frac{\sum_{c} P_c\,(\mu_{cj} - \mu_j)^2}{\sum_c P_c\,\sigma_{cj}^2},
$$

where $P_c$ is the proportion of class $c$, $\mu_{cj}$ and $\sigma^2_{cj}$ are the mean and variance of feature $j$ in class $c$, and $\mu_j$ is the overall mean [1]. (For two classes, Theodoridis and Koutroumbas write it as $(\mu_1-\mu_2)^2/(\sigma_1^2+\sigma_2^2)$; the idea is the same.)

For a **subset** of features, use the scatter matrices. With $x$ the feature vector restricted to the subset and $\mu_c$, $\mu$ the class and overall mean vectors,

$$
S_W = \sum_c P_c\,\Sigma_c, \qquad
S_B = \sum_c P_c\,(\mu_c - \mu)(\mu_c - \mu)^\top, \qquad
J = \operatorname{tr}\!\big(S_W^{-1} S_B\big),
$$

where $\Sigma_c$ is the covariance of class $c$, $S_W$ is the within-class scatter, $S_B$ is the between-class scatter, and $\operatorname{tr}$ is the trace. $J$ is large when class means are far apart relative to the within-class spread, measured in the directions that matter [1]. Unlike summing per-feature ratios, $J$ accounts for correlation between the features.

Two further criteria come from probability. The **Bhattacharyya distance** between two Gaussian classes $\mathcal N(\mu_1, \Sigma_1)$ and $\mathcal N(\mu_2, \Sigma_2)$ is

$$
B = \frac18(\mu_1-\mu_2)^\top\Big(\frac{\Sigma_1+\Sigma_2}{2}\Big)^{-1}(\mu_1-\mu_2) + \frac12\ln\frac{\big|\tfrac12(\Sigma_1+\Sigma_2)\big|}{\sqrt{|\Sigma_1|\,|\Sigma_2|}} ,
$$

with $|\cdot|$ the determinant. The first term measures mean separation; the second measures covariance difference. It gives an upper bound on the Bayes error for equal priors, $P_e \le \tfrac12 e^{-B}$ [1]. **Mutual information** with the label, introduced above, is the distribution-free counterpart.

The code compares single-feature scores with a subset criterion on the 13-feature wine data.

```python
import numpy as np
from sklearn.datasets import load_wine
from sklearn.preprocessing import StandardScaler

X, y = load_wine(return_X_y=True)
X = StandardScaler().fit_transform(X)
classes = np.unique(y)
mu = X.mean(axis=0)

# Per-feature Fisher ratio: between-class over within-class variance.
between = sum((y == c).mean() * (X[y == c].mean(0) - mu) ** 2 for c in classes)
within = sum((y == c).mean() * X[y == c].var(0) for c in classes)
fdr = between / within
print("top-3 features by Fisher ratio:", np.argsort(fdr)[::-1][:3],
      np.round(np.sort(fdr)[::-1][:3], 2))

def J(cols):  # scatter-matrix criterion trace(Sw^-1 Sb) on a feature subset
    Z = X[:, cols]
    m = Z.mean(0)
    Sw = sum((y == c).mean() * np.cov(Z[y == c].T, bias=True).reshape(len(cols), -1)
             for c in classes)
    Sb = sum((y == c).mean() * np.outer(Z[y == c].mean(0) - m, Z[y == c].mean(0) - m)
             for c in classes)
    return np.trace(np.linalg.solve(Sw, Sb))

top2 = list(np.argsort(fdr)[::-1][:2])
print("J(top-2 by ratio) =", round(J(top2), 2))
best_pair = max(((i, j) for i in range(13) for j in range(i + 1, 13)),
                key=lambda p: J(list(p)))
print("best pair by J:", best_pair, "J =", round(J(list(best_pair)), 2))
```

Features 6, 12 and 11 have the highest individual ratios (2.67, 2.38, 2.17). Yet the best *pair* by $J$ is features 6 and 9 ($J = 5.39$), not the top two individual features ($J = 4.93$): feature 12 overlaps in information with feature 6, while feature 9 complements it. This is the redundancy problem of univariate filters, seen in numbers.

All of these criteria are proxies. The final judge of a feature set is the cross-validated performance of the complete pipeline, estimated without leakage ([PR 09](/en/learn/pattern-recognition/pr-09-ensembles-validation/)).

## Principal component analysis

**In plain words.** PCA rotates the coordinate system so that the first axis points in the direction where the data vary most, the second in the direction of most remaining variation, and so on. Keeping only the first few axes gives the best low-dimensional summary in the least-squares sense. It never looks at the labels.

### Derivation

Let $x_1, \dots, x_N \in \mathbb{R}^D$ have mean $\bar x$ and covariance $\Sigma = \frac{1}{N-1}\sum_n (x_n - \bar x)(x_n - \bar x)^\top$. The variance of the data projected onto a unit vector $u$ is $u^\top \Sigma u$. Maximizing it subject to $u^\top u = 1$ with a Lagrange multiplier $\lambda$ gives

$$
\Sigma u = \lambda u ,
$$

so the best direction is an eigenvector of $\Sigma$, and the variance it captures is its eigenvalue $\lambda$. The first principal direction is the eigenvector with the largest eigenvalue; the next ones are the remaining eigenvectors in decreasing order of eigenvalue, each orthogonal to the previous ones [2], [8], [9]. Keeping the top $r$ directions also minimizes the mean squared reconstruction error, which equals the sum of the discarded eigenvalues $\sum_{i > r}\lambda_i$ [2].

In practice PCA is computed with the singular value decomposition (SVD) of the centered data matrix $X_c \in \mathbb{R}^{N\times D}$ (row $n$ is $x_n - \bar x$):

$$
X_c = U S V^\top, \qquad \lambda_i = \frac{s_i^2}{N-1}, \qquad Z = X_c V_r ,
$$

where $U$ and $V$ have orthonormal columns, $S = \operatorname{diag}(s_1, s_2, \dots)$ holds the singular values in decreasing order, $V_r$ contains the first $r$ columns of $V$ (the principal directions), and $Z \in \mathbb{R}^{N\times r}$ are the **scores**. The fraction $\lambda_i / \sum_k \lambda_k$ is the **explained variance ratio** of component $i$. To reconstruct, compute $\hat x = \bar x + V_r z$.

### Whitening

**Whitening** rescales each score to unit variance:

$$
z^{\text{white}}_{i} = \frac{z_i}{\sqrt{\lambda_i + \epsilon}} ,
$$

where $z_i$ is the score on component $i$, $\lambda_i$ is that component's variance from the training data, and $\epsilon \ge 0$ is a small constant that keeps tiny eigenvalues from blowing up. After whitening the training covariance is (approximately) the identity. This makes all directions equally loud, which helps some algorithms (ICA below, $k$-means, some neural networks) but also amplifies directions that were small because they were mostly noise. Whitening is a modeling choice, not a free improvement.

```python
import numpy as np
from sklearn.datasets import load_digits
from sklearn.decomposition import PCA

X, _ = load_digits(return_X_y=True)          # 1797 images of 8x8 = 64 pixels
Xc = X - X.mean(axis=0)
U, S, Vt = np.linalg.svd(Xc, full_matrices=False)
eigvals = S ** 2 / (len(X) - 1)               # variances along each direction
ratio = eigvals / eigvals.sum()
r = int(np.searchsorted(np.cumsum(ratio), 0.90) + 1)
print("components for 90% variance:", r)

Z = Xc @ Vt[:r].T                             # scores, N x r
X_hat = Z @ Vt[:r] + X.mean(axis=0)           # reconstruction
print("relative reconstruction error:",
      round(np.linalg.norm(X - X_hat) / np.linalg.norm(Xc), 3))

pca = PCA(n_components=r).fit(X)
assert np.allclose(pca.explained_variance_, eigvals[:r])
assert np.allclose(np.abs(pca.components_), np.abs(Vt[:r]))   # equal up to sign
Zw = Z / np.sqrt(eigvals[:r])                 # whitened scores
print("whitened covariance is identity:",
      np.allclose(np.cov(Zw.T), np.eye(r)))
```

Twenty-one of the 64 pixel dimensions hold 90% of the variance of the digits, and the reconstruction from them has a relative error of 0.31. The hand-written SVD agrees with scikit-learn up to the sign of each component (an eigenvector's sign is arbitrary). Figure 1 shows the cumulative curve and reconstructions.

### Variance is not class information

PCA ranks directions by variance, and variance is not the same as usefulness for classification. In Figure 2, a large nuisance variation (think lighting) dominates the first principal component, while the class difference lives in a direction with small variance. Projecting onto PC 1 keeps 96% of the variance and throws away essentially all the class information. A supervised projection (Fisher's LDA, next section) finds the useful direction immediately.

## Fisher's linear discriminant analysis

**In plain words.** LDA looks for the directions in which the class means are far apart *relative to* how spread out each class is. It uses the labels, so it finds directions that matter for classification, but it can produce at most one fewer direction than there are classes.

Fisher's criterion for a projection direction $v$ is the ratio of between-class to within-class scatter along $v$ [11]:

$$
J(v) = \frac{v^\top S_B v}{v^\top S_W v} ,
$$

with $S_W$ and $S_B$ as defined in the previous section. Setting the gradient to zero gives the **generalized eigenproblem**

$$
S_B v = \lambda S_W v ,
$$

and the best directions are the eigenvectors with the largest eigenvalues $\lambda$ (equivalently, eigenvectors of $S_W^{-1}S_B$ when $S_W$ is invertible) [1], [2]. For two classes there is a closed form, $v \propto S_W^{-1}(\mu_1 - \mu_2)$, which reappears as the Gaussian LDA classifier in [PR 03](/en/learn/pattern-recognition/pr-03-linear-models/).

**Why at most $K-1$ directions.** $S_B$ is a weighted sum of $K$ rank-one matrices $(\mu_c - \mu)(\mu_c - \mu)^\top$. The vectors $\mu_c - \mu$ are linearly dependent, because $\sum_c P_c(\mu_c - \mu) = 0$. So $S_B$ has rank at most $K - 1$, and at most $K-1$ eigenvalues are nonzero. Ten digit classes give at most nine discriminant directions, whatever the input dimension.

**When $S_W$ is singular.** With fewer samples than features (common with images), $S_W$ cannot be inverted. Standard fixes are to apply PCA first and then LDA in the reduced space, or to shrink $S_W$ toward a multiple of the identity (regularized LDA).

```python
from sklearn.datasets import load_digits
from sklearn.discriminant_analysis import LinearDiscriminantAnalysis as LDA
from sklearn.model_selection import cross_val_score
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

X, y = load_digits(return_X_y=True)
lda = LDA().fit(X, y)
print("discriminant directions for 10 classes:", lda.transform(X).shape[1])
for name, reducer in [("PCA", PCA(n_components=2)),
                      ("LDA", LDA(n_components=2))]:
    pipe = make_pipeline(StandardScaler(), reducer,
                         KNeighborsClassifier(n_neighbors=5))
    acc = cross_val_score(pipe, X, y, cv=5).mean()
    print(f"{name} to 2-D, then 5-NN: CV accuracy {acc:.3f}")
```

LDA returns nine directions for ten classes, as predicted. Squeezed to two dimensions, a 5-NN classifier on LDA coordinates reaches a cross-validated accuracy of 0.624, against 0.512 on the first two principal components. Because LDA uses labels, it sits inside the pipeline and is refitted in every fold. Figure 3 shows why: LDA pulls whole digit classes apart, while PCA mostly shows the directions of largest pixel variation.

## Kernel PCA

**In plain words.** Kernel PCA is PCA performed in the rich feature space of a kernel ([PR 04](/en/learn/pattern-recognition/pr-04-kernels-nonlinear-classifiers/)), without ever computing the features. It can unroll structures that no linear projection can.

Schölkopf, Smola and Müller showed that PCA in the feature space $\phi(x)$ only needs the kernel matrix $K_{ij} = k(x_i, x_j)$ [12]. Center it in feature space,

$$
\tilde K = K - \mathbf{1}_N K - K\mathbf{1}_N + \mathbf{1}_N K \mathbf{1}_N ,
$$

where $\mathbf{1}_N$ is the $N\times N$ matrix with every entry $1/N$. Solve the eigenproblem $\tilde K a_i = N\lambda_i a_i$ for coefficient vectors $a_i \in \mathbb{R}^N$, normalized so that $N\lambda_i\, a_i^\top a_i = 1$. The $i$-th kernel principal component of a point $x$ is then

$$
z_i(x) = \sum_{n=1}^N a_{in}\, \tilde k(x_n, x) ,
$$

where $\tilde k$ is the kernel centered in the same way. The cost is that of an $N\times N$ eigenproblem, and a new point needs $N$ kernel evaluations.

Kernel PCA is still unsupervised: it ranks components by variance in feature space, not by class separation. On the two-ring data, the first two RBF kernel components describe the *angle* around the rings and mix the classes; the third component describes the *radius* and separates them perfectly (Figure 4).

```python
import numpy as np
from sklearn.datasets import make_circles
from sklearn.decomposition import PCA, KernelPCA
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline

X, y = make_circles(n_samples=400, factor=0.4, noise=0.07, random_state=0)
Z = KernelPCA(n_components=4, kernel="rbf", gamma=2).fit_transform(X)
print("|corr(component, label)|:",
      np.round([abs(np.corrcoef(Z[:, i], y)[0, 1]) for i in range(4)], 3))

for name, reducer in [("linear PCA, 2 comps", PCA(n_components=2)),
                      ("kernel PCA, 3 comps", KernelPCA(n_components=3,
                                                        kernel="rbf", gamma=2))]:
    acc = cross_val_score(make_pipeline(reducer, LogisticRegression()),
                          X, y, cv=5).mean()
    print(f"{name} -> logistic regression: {acc:.3f}")
```

Only the third component correlates with the label (0.982; the others are below 0.05). A logistic regression on the two linear principal components cannot beat chance (0.432), while on three kernel components it is perfect (1.000).

## Independent component analysis

**In plain words.** At a party, two microphones each record a mixture of two voices. ICA tries to recover the individual voices from the mixtures alone, using the fact that the voices are statistically independent and not Gaussian.

ICA assumes the observed vector is a linear mixture of independent sources [13]:

$$
x = A s ,
$$

where $s = (s_1, \dots, s_M)$ are statistically independent, non-Gaussian source signals, $A$ is an unknown mixing matrix and $x$ are the observed signals. The goal is an unmixing matrix $W \approx A^{-1}$ such that $\hat s = W x$ has independent components. Why non-Gaussian? By the central limit theorem, mixtures tend to be "more Gaussian" than their sources, so maximizing the non-Gaussianity of $w^\top x$ finds a source. FastICA measures non-Gaussianity with approximations of negentropy and runs a fixed-point iteration after whitening the data [13]. Two ambiguities can never be resolved: the order of the sources and their scale (including sign).

The contrast with PCA is the point. PCA only makes the components *uncorrelated* (second-order statistics); ICA makes them *independent*, using higher-order statistics. If the sources were Gaussian, uncorrelated would already mean independent, and any rotation of the whitened data would be equally good, so ICA would fail.

```python
import numpy as np
from sklearn.decomposition import FastICA

t = np.linspace(0, 8, 2000)
S = np.c_[np.sin(3 * t),                      # source 1: sine
          np.sign(np.sin(5 * t)),             # source 2: square wave
          ((2 * t) % 2) - 1]                  # source 3: sawtooth
A = np.array([[1.0, 0.5, 0.3],
              [0.6, 1.0, 0.4],
              [0.4, 0.3, 1.0]])               # unknown mixing matrix
X = S @ A.T                                   # what the sensors record

S_hat = FastICA(n_components=3, whiten="unit-variance",
                random_state=0).fit_transform(X)
corr = np.abs(np.corrcoef(S.T, S_hat.T)[:3, 3:])
print(np.round(corr, 3))                      # one entry near 1 per row
```

Each true source matches exactly one recovered component with absolute correlation 0.999 or 1.000, and the off-diagonal matches are below 0.05. Figure 5 shows that PCA, applied to the same mixtures, returns uncorrelated signals that are still mixtures.

<Figure src={icaFig} alt="Four columns of three signals each: the true sine, square and sawtooth sources; three observed mixtures; three PCA components that still look mixed; three ICA components that match the sources." caption="Figure 5 — Blind source separation. PCA decorrelates the mixtures but does not unmix them; FastICA recovers the sine, square and sawtooth sources up to order and scale." />

**Non-negative matrix factorization** (NMF) is a related decomposition for non-negative data such as pixel intensities or word counts: it writes $X \approx WH$ with $W, H \ge 0$ elementwise. Because nothing can be subtracted, the factors tend to be additive "parts," as Lee and Seung showed for face images [14].

## Manifold learning

**In plain words.** Sometimes high-dimensional data lie on a curved, low-dimensional sheet, like a rolled-up poster. Manifold learning tries to unroll the sheet, keeping points that were neighbors along the sheet close together, without being fooled by points that are close in 3-D only because the sheet is rolled up.

The Swiss roll in Figure 6 is the standard example: a two-dimensional rectangle rolled up in three dimensions. PCA flattens it by projection and puts different layers of the roll on top of each other. Neighborhood-based methods do better:

- **Isomap** [15] builds a $k$-nearest-neighbor graph, estimates *geodesic* distances along the manifold as shortest-path lengths in the graph, and then finds low-dimensional coordinates whose Euclidean distances match those geodesic distances (classical multidimensional scaling).
- **Locally linear embedding** (LLE) [16] writes each point as a weighted combination of its neighbors, $x_n \approx \sum_{m \in \mathcal N(n)} W_{nm} x_m$ with $\sum_m W_{nm} = 1$, and then finds low-dimensional points $y_n$ that are reconstructed by the *same* weights.
- **t-SNE** [17] converts distances into neighbor probabilities $p_{ij}$ in the input (Gaussian, with a bandwidth set by a "perplexity" parameter) and $q_{ij}$ in the embedding (heavy-tailed Student-$t$), and minimizes the Kullback–Leibler divergence $\sum_{i \ne j} p_{ij}\log(p_{ij}/q_{ij})$. The heavy tails let well-separated groups spread out.
- **UMAP** [18] builds a weighted $k$-nearest-neighbor graph (a "fuzzy" topological representation) and optimizes a low-dimensional layout with a cross-entropy objective. It is typically faster than t-SNE and is often used for the same purpose.

<Figure src={manifoldFig} alt="A 3-D Swiss roll colored by position along the roll, and its 2-D embeddings: PCA overlaps layers; Isomap unrolls it into a rectangle; LLE unrolls it into a distorted fan; t-SNE breaks it into several separate pieces." caption="Figure 6 — The Swiss roll and four 2-D embeddings, colored by position along the roll. Isomap and LLE unroll it; PCA cannot; t-SNE keeps neighbors together but tears the continuous sheet into separate islands." />

One quantitative check is **trustworthiness**: the extent to which the $k$ nearest neighbors of each point in the embedding were also near neighbors in the input (1.0 is perfect).

```python
from sklearn.datasets import make_swiss_roll
from sklearn.decomposition import PCA
from sklearn.manifold import Isomap, LocallyLinearEmbedding, TSNE, trustworthiness

X, t = make_swiss_roll(n_samples=1000, noise=0.05, random_state=0)
methods = {
    "PCA": PCA(n_components=2),
    "Isomap": Isomap(n_neighbors=10, n_components=2),
    "LLE": LocallyLinearEmbedding(n_neighbors=12, n_components=2,
                                  random_state=0),
    "t-SNE": TSNE(n_components=2, perplexity=30, init="pca",
                  random_state=0),
}
for name, method in methods.items():
    Y = method.fit_transform(X)
    print(f"{name:7s} trustworthiness (k=10): "
          f"{trustworthiness(X, Y, n_neighbors=10):.3f}")
```

PCA scores 0.905; Isomap and t-SNE 0.999; LLE 0.996. Note what the number does *not* see: t-SNE scores as high as Isomap even though Figure 6 shows it tearing the roll into islands. Local neighborhoods are preserved; global structure is not.

### What an embedding picture can and cannot prove

These methods are mainly tools for looking at data. Three cautions follow from how they work [19]:

- **Cluster sizes and gaps are not meaningful by default.** t-SNE normalizes local densities, so a tight cluster and a diffuse one can look the same size, and distances between clusters may say little.
- **Results depend on settings.** Perplexity, number of neighbors, initialization and random seed all change the picture. Wattenberg, Viégas and Johnson's interactive article shows the same data producing very different t-SNE maps [19].
- **Two dimensions may not be enough.** A projection to 2-D must distort high-dimensional distances; well-separated islands in a picture are not proof of separate populations.

There is also a practical gap for classification: t-SNE and standard LLE learn coordinates for the training points only, with no natural rule for embedding a new point. Isomap, kernel PCA and UMAP provide out-of-sample transforms, but if a nonlinear embedding is part of a classifier, it must be fitted inside the training folds like any other step.

## Image and signal descriptors

**In plain words.** Before features were learned, people designed them by hand to measure exactly the properties they believed mattered: texture, edges, shape, frequency content. They remain useful as baselines and as interpretable checks.

Theodoridis and Koutroumbas devote two chapters to transform-based and application-specific features [1]; [IP 12](/en/learn/image-processing/dip-12-feature-extraction/) treats image descriptors in detail. Consider what each one keeps and what it is sensitive to:

| Descriptor | Preserves | Typical sensitivity |
| --- | --- | --- |
| Intensity histogram | Distribution of values | Loses spatial arrangement entirely |
| Co-occurrence (GLCM) statistics [20] | Pairwise intensity relations at an offset | Quantization levels and offset direction |
| Histogram of oriented gradients (HOG) [21] | Local edge directions in a grid of cells | Cropping, scale and alignment |
| Area, perimeter, compactness | Region geometry | Segmentation errors and resolution |
| Fourier/DCT coefficients | Frequency content | Alignment and which frequencies are kept |
| Wavelet coefficients | Location and scale of variation | Basis choice and boundary handling |

For a quantized image $I$ and an offset $\delta$, a gray-level co-occurrence matrix counts pairs $(I(p), I(p+\delta))$ over pixel positions $p$; normalized to probabilities $P(i,j)$, Haralick's texture features include contrast $\sum_{i,j}(i-j)^2P(i,j)$ and energy $\sum_{i,j}P(i,j)^2$ [20]. Always state the offset and the number of gray levels, because the numbers depend on both. For a segmented object with area $A$ and perimeter $P$, compactness $4\pi A/P^2$ equals 1 for an ideal continuous circle and is smaller for irregular shapes; pixel-based perimeter estimates distort it for small objects. Dalal and Triggs' HOG descriptor, built from normalized histograms of gradient orientation in small cells, was introduced for pedestrian detection and became one of the most widely used hand-designed image features [21].

For audio and other 1-D signals, features are computed on short windows in which the signal is approximately stationary: spectral energy in frequency bands, zero-crossing rate, and so on. The window length trades time resolution against frequency resolution.

### Code: one classifier, three feature sets

This example compares fixed feature strategies with the same classifier on the built-in digits data.

```python
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.decomposition import PCA
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=9)
transforms = {
    "all features": "passthrough",
    "24 PCA coordinates": PCA(n_components=24, random_state=9),
    "24 selected coordinates": SelectKBest(f_classif, k=24),
}
for name, transform in transforms.items():
    model = make_pipeline(
        StandardScaler(), transform, LogisticRegression(max_iter=1500))
    model.fit(Xtr, ytr)
    print(name, "test accuracy:", round(model.score(Xte, yte), 4))
```

All 64 pixels give 0.969 test accuracy, 24 principal components 0.956, and the 24 pixels with the best ANOVA $F$ scores 0.953. Here a reduction to about a third of the dimensions costs little accuracy. Some border pixels of the digits are constant, so the $F$ test warns about constant features; the warning reflects zero within-class variance, not leakage, and those pixels simply receive no useful score.

## Modern view

Feature engineering by hand has largely given way to learned representations, but the ideas of this chapter are everywhere in modern pipelines: deep features are selected, projected, whitened, visualized and evaluated with the same tools. Here is how the survey literature maps the field.

**Feature selection.** Guyon and Elisseeff's introduction [3] set the vocabulary (filters, wrappers, embedded methods), discussed feature construction, ranking and validation, and stressed that a feature can be useless alone and useful in combination. Chandrashekar and Sahin [23] provide a compact survey organized along the same filter/wrapper/embedded lines. Li et al. [22] revisit selection "from a data perspective": they group algorithms for conventional data into similarity-based, information-theoretic, sparse-learning-based and statistical methods, add methods for structured, heterogeneous and streaming data, and release an open-source repository for benchmarking. The leakage warning of Ambroise and McLachlan [7] remains the single most important practical lesson.

**PCA and its descendants.** Jolliffe and Cadima's review [10] explains PCA as an adaptive, data-defined technique and surveys its variants tailored to different data types. In modern deep learning, PCA survives as a diagnostic (how many directions carry most variance in a layer's activations) and as a preprocessing and initialization step, for example the PCA initialization recommended for t-SNE [26].

**Dimensionality reduction for visualization.** Espadoto et al. [24] ran a large quantitative survey of projection techniques: they characterized data sets, techniques and projection quality with several quantitative metrics (such as neighborhood and distance preservation), measured how the results depend on the technique and the data, and turned the observations into guidance for choosing a projection in a given context, with all code and results released as an open benchmark. Wang, Huang, Rudin and Shaposhnik [25] analyzed why t-SNE, UMAP and TriMAP behave as they do, focused on the trade-off between preserving local and global structure, and proposed PaCMAP to balance the two.

**Pitfalls of 2-D embeddings.** Single-cell biology, where t-SNE and UMAP are routine, produced the sharpest critiques. Kobak and Berens [26] gave a protocol for more faithful t-SNE maps: PCA initialization, a high learning rate and multi-scale similarities. Kobak and Linderman [27] showed that the better global structure often credited to UMAP comes largely from its initialization; with the same informative initialization, t-SNE preserves global structure similarly. Chari and Pachter [28] went further, arguing that extreme reduction to two dimensions inevitably distorts high-dimensional data and that such pictures should not be used for quantitative conclusions.

**Variance versus usefulness, revisited.** Figure 2's lesson reappears at scale in self-supervised learning. Balestriero and LeCun [29] argue that training a representation to reconstruct its input emphasizes high-variance components of the data, which are often less informative for perception tasks than low-variance details; reconstruction-trained features therefore need extra steps (such as fine-tuning) to be useful for classification. This is PCA's limitation, in a deep-learning setting.

**Open problems.** Selection with many correlated features and few samples remains unstable: different subsets can perform equally well, which complicates interpretation. Evaluating embeddings still lacks agreed metrics that capture both local and global fidelity [24], [25]. And for learned features, deciding which directions carry task-relevant rather than merely high-variance information is an active research question [29].

## Key takeaways

- Feature selection keeps original measurements; extraction builds new coordinates; learning fits the extraction rule from data. All three decide what the classifier can see.
- Filters are fast but miss interactions and redundancy; wrappers see them but cost more and can overfit validation data; embedded methods (lasso, trees) select during training.
- Any step that uses labels (selection, LDA, choosing the number of features) must be refitted inside each cross-validation fold. Selecting on the full data can report 98% accuracy on pure noise.
- Fisher ratio, $J = \operatorname{tr}(S_W^{-1}S_B)$, Bhattacharyya distance and mutual information score features; subsets must be scored jointly because of redundancy.
- PCA keeps maximum variance (eigenvectors of the covariance, computed by SVD); whitening equalizes variances. Variance is not class information.
- Fisher LDA solves $S_Bv = \lambda S_Wv$ and gives at most $K-1$ directions. Kernel PCA, ICA and NMF extend linear extraction to nonlinear, independent or non-negative structure.
- Isomap, LLE, t-SNE and UMAP are mainly visualization tools: their pictures depend on settings, and gaps between clusters are not proof of separate populations.

2. **The $K-1$ limit.** Prove that the between-class scatter $S_B$ of $K$ classes has rank at most $K-1$. What does this imply for LDA on a two-class problem?

<details>
<summary>Hint</summary>

$S_B = \sum_c P_c d_c d_c^\top$ with $d_c = \mu_c - \mu$, and $\sum_c P_c d_c = 0$, so the $K$ vectors $d_c$ span at most $K-1$ dimensions. With two classes, LDA gives a single direction, $v \propto S_W^{-1}(\mu_1-\mu_2)$.

</details>

3. **When 99% of the variance is not enough.** Describe a realistic imaging setup in which keeping 99% of the PCA variance discards the class signal. How would you detect the problem, and what would you do?

<details>
<summary>Hint</summary>

Large independent lighting or pose changes plus a small, consistent defect mark (Figure 2 in disguise). Detect it by comparing cross-validated accuracy with and without PCA, or by checking class separation (Fisher ratio) per component. Use a supervised projection, normalize the nuisance (for example illumination) first, or skip PCA.

</details>

4. **The XOR trap.** Generate $x_1, x_2$ uniform on $[-1,1]$ and eight irrelevant noise features, with $y = \mathbf{1}[x_1 > 0] \oplus \mathbf{1}[x_2 > 0]$. Rank all ten features with `f_classif` and with `mutual_info_classif`. Then run sequential forward selection with a decision tree. Which methods find $x_1$ and $x_2$?

<details>
<summary>Hint</summary>

Both univariate filters give $x_1$ and $x_2$ scores near zero, like the noise features, because each alone is independent of $y$. A wrapper that adds features one at a time can also struggle at the first step, for the same reason; a tree-based wrapper that evaluates pairs, or backward elimination starting from all features, finds them.

</details>

5. **Leakage, quantified.** In the selection-bias code, vary the number of noise features (100, 1,000, 5,000) and the number of samples (30, 60, 200). How does the "wrong" accuracy change? Explain the trend.

<details>
<summary>Hint</summary>

The optimism grows with the number of candidate features and shrinks with the number of samples: with more noise features, more of them correlate with the labels by chance in a small sample, and selecting the best 20 picks exactly those.

</details>

6. **Reading a t-SNE map.** Run t-SNE on the digits data with perplexity 5, 30 and 100, and with two random seeds each. Which features of the plots are stable (which digits are neighbors?) and which change (cluster sizes, gaps, positions)? What would you be willing to claim from one such plot?

<details>
<summary>Hint</summary>

Membership of local neighborhoods is quite stable; absolute positions, cluster areas and between-cluster distances are not. A defensible claim is "these points are locally similar in the input space," not "these two groups are far apart" or "this group is twice as diverse."

</details>
