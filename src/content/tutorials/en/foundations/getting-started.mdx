## The big picture

You do not need to finish every mathematical topic before touching an image. You do need to know what each operation assumes. The fastest way to learn is to start from a question you can test: "Why does blur remove an edge?", "Does a classifier still work on images from a new camera?", or "What changes when a model predicts the next token instead of a class?"

<Callout type="tip" title="Explain like I'm five">
Learning this subject is like learning to cook. A textbook explains the ingredients and techniques; a small experiment lets you taste what happens. Pick one dish, change one ingredient at a time, and write down what you notice before you try to cook a whole banquet. This site is the cookbook with the recipes arranged in a sensible order, and every recipe can be cooked in a small kitchen (a laptop CPU).
</Callout>

The site is organized into **eight tracks**. A track is an ordered sequence of tutorials on one theme. The numbering describes the role of each track, not a rule that you must complete one before entering another.

How they connect, in one paragraph: **Image Processing** treats an image as a signal and designs operations by hand. **Pattern Recognition** adds statistics and decision theory: given features, how should we decide, and how sure can we be? **ML/DL** replaces hand-designed features with learned ones and supplies the shared machinery (losses, optimization, architectures, generative models) used everywhere else. **DL for Vision** applies that machinery to concrete visual tasks, and its restoration and enhancement chapters lean on the image-formation ideas from Image Processing. **NLP** reuses the same probability, optimization and Transformer ideas with text as input. **Optimization** develops the modeling rules, constraints, duality and numerical methods behind estimation and training. **Information Theory** explains uncertainty, coding and communication limits; its entropy and divergence concepts connect classification, language modeling and compression.

## How a tutorial page works

Every tutorial follows the same layout, so once you know one page you know them all.

- **Level pill.** *Beginner*, *intermediate* or *advanced*. The ML math chapters and the first IP tutorials are beginner; the DL tutorials assume you already know CNNs and backpropagation.
- **Needs.** Under the title, a *Needs* line links the tutorials that the page assumes. Prerequisites are language independent, so the Chinese and English pages share them. If a *Needs* link is unfamiliar, read that page first, or at least its *Key takeaways*.
- **Track rail.** The left column lists every tutorial in the current track in order; *Previous* and *Next* links at the bottom follow the same order.
- **Sections.** Each tutorial opens with *What you'll learn* and an *Explain like I'm five* box, then develops each topic in two passes: a plain-language statement first, then the precise version with equations and code. It ends with *Key takeaways*, *Exercises* (hints are folded; try before you open them) and numbered *References*, cited in the text as [1], [2] and so on.
- **Notebook buttons.** A tutorial that has a companion notebook shows an **Open in Colab** pill next to its title and a **View notebook** link at the end. Currently [ML 03](/en/learn/ml/ml-03-convolutional-networks/) has one (convolution and image filtering).
- **Interactive demos.** Some pages embed a live 3×3 kernel editor or a before/after image slider. Both also live on the [Playground](/en/playground/) page.
- **Search and language.** The search page finds tutorials and blog posts in the language you are reading; the language switch in the header jumps to the same page in the other language. If a page has not been translated, the Chinese site shows the English version with a notice.

## Choose your entry route

Pick the description that fits you best. The routes overlap on purpose.

**If programming is new.** Learn Python functions, loops, list and array indexing, and basic plotting first. Then read [Images as Arrays](/en/learn/foundations/images-as-arrays/) and [IP 01](/en/learn/image-processing/dip-01-introduction/). Make a synthetic image, inspect its rows and columns, and explain why adding two `uint8` images can overflow. Continue with [IP 02](/en/learn/image-processing/dip-02-fundamentals/) and [IP 03](/en/learn/image-processing/dip-03-intensity-spatial-filtering/), which are written so that every equation has a matching NumPy line.

**If you can code but mathematics feels rusty.** Read [ML 01](/en/learn/ml/ml-01-introduction/) for the vocabulary of learning, then the three math chapters: [linear algebra](/en/learn/ml/ml-01a-linear-algebra/), [probability and information theory](/en/learn/ml/ml-01b-probability-information/) and [numerical computation](/en/learn/ml/ml-01c-numerical-computation/). They follow the "applied math" part of Goodfellow, Bengio and Courville [7] and pair each idea with a short NumPy check. Aim to be able to check matrix shapes, interpret a conditional probability and spot a numerically unstable calculation.

**If you know introductory probability and linear algebra.** Start [PR 01](/en/learn/pattern-recognition/pr-01-bayes-decisions/) for statistical decisions and classical methods, or [ML 02](/en/learn/ml/ml-02-neural-networks/) for learned representations. Return to the math chapters only when a derivation reveals a specific gap.

**If you already train neural networks.** Skim [ML 03](/en/learn/ml/ml-03-convolutional-networks/) and [ML 04](/en/learn/ml/ml-04-vision-transformers/), then pick an application chapter in DL for Vision, and pair it with [ML 10](/en/learn/ml/ml-10-evaluation-deployment/) on evaluation and deployment.

## Run the code

The website and the Python examples use separate environments. You can read the site without installing anything. To run the code you need Python; to preview the website itself you need Node.

### A Python environment for the tutorials

Create one dedicated virtual environment for all tutorials. Python 3.11 or newer is a practical starting point; check each package's requirements if you use a different version.

```bash
python3 -m venv .venv-study
source .venv-study/bin/activate
python -m pip install --upgrade pip
python -m pip install numpy scipy matplotlib scikit-learn scikit-image opencv-python PyWavelets jupyterlab
```

On Windows, activate with `.venv-study\Scripts\Activate.ps1` in PowerShell. The code blocks across the site import exactly these libraries (NumPy, SciPy, scikit-learn, scikit-image, OpenCV, PyWavelets) plus PyTorch for the neural-network chapters. Install PyTorch with the command produced by its [official installation selector](https://pytorch.org/get-started/locally/) [11]; choose the CPU build if you have no GPU. Every example on the site is sized to run on a laptop CPU in seconds to about a minute.

### Running a code block

Code blocks are **self-contained**: each one imports what it needs and builds its own data, usually synthetic arrays, the sample images in `skimage.data`, or the toy datasets in scikit-learn. Copy a block into a file and run it, or paste it into a notebook cell. Most blocks end with `assert` statements that check the claim made in the text; if an assertion fails, you have found either a version difference or a misunderstanding worth investigating.

A good habit is to change one thing and re-run: a kernel size, a learning rate, a random seed. The exercises suggest which knob to turn.

### Notebooks and Colab

A tutorial with a companion notebook has an **Open in Colab** button. Colab runs the notebook in your browser on a hosted machine, with NumPy, OpenCV, scikit-image and Matplotlib already installed, so nothing needs to be set up locally. To run the same notebook locally, download it from the **View notebook** link, then start `jupyter lab` inside the activated environment and open the file. The notebooks live in the repository's `notebooks/` folder.

### Previewing the website (optional)

```bash
npm run dev
```

## Your first CPU experiment

This complete example creates its own image, adds noise and smooths it. No download is needed.

```python
import numpy as np
import cv2

rng = np.random.default_rng(0)
clean = np.zeros((32, 32), dtype=np.float32)
clean[8:24, 8:24] = 1.0
noisy = clean + rng.normal(0, 0.1, clean.shape).astype(np.float32)
smooth = cv2.GaussianBlur(noisy, (5, 5), 1.0,
                          borderType=cv2.BORDER_REFLECT_101)
print("Shape and type:", smooth.shape, smooth.dtype)
print("Noise-region standard deviation:",
      noisy[:5, :5].std(), smooth[:5, :5].std())
print("Across the edge:", np.round(smooth[16, 5:12], 3))
assert smooth.shape == clean.shape
assert np.isfinite(smooth).all()
```

The output shows two effects. The standard deviation in the flat, all-background corner drops from about 0.074 to about 0.026: smoothing averages away noise. Across the edge at column 8, the values now ramp from about 0.04 to 0.93 over three or four pixels instead of jumping from 0 to 1: smoothing also spreads a sharp transition. A lower noise estimate therefore does not mean every important detail improved. [IP 03](/en/learn/image-processing/dip-03-intensity-spatial-filtering/) explains why, and Exercise 2 asks you to measure the trade-off.

## Choose one main textbook

Use one main book for continuity and a second one for a different explanation of the same idea. The links point to author or publisher pages, with access conditions as described there. This is a curated starting set, not a ranking.

| Need | Recommended book | How to use it |
|---|---|---|
| Mathematical preparation | Deisenroth, Faisal and Ong, *Mathematics for Machine Learning* [1] | start with linear algebra, matrix decompositions, vector calculus and probability; apply them through regression and PCA |
| Image operations | Gonzalez and Woods, *Digital Image Processing*, 4th ed. [2] | pair image fundamentals, spatial and frequency filtering, restoration and segmentation with the DIP track |
| Pattern Recognition, main text | Theodoridis and Koutroumbas, *Pattern Recognition*, 4th ed. [3] | follow classifier design, features and clustering; work the problems rather than only reading summaries |
| Pattern Recognition, companion | Bishop, *Pattern Recognition and Machine Learning* [4] | revisit the same topics through probability, latent variables and graphical models |
| A first modern DL text | Prince, *Understanding Deep Learning* [5] | connect diagrams, mathematics and the accompanying notebooks for networks and generative modeling |
| Another modern DL explanation | C. M. Bishop and H. Bishop, *Deep Learning: Foundations and Concepts* [6] | use its probabilistic presentation to strengthen the concepts behind architectures and training |
| DL foundations and reference | Goodfellow, Bengio and Courville, *Deep Learning* [7] | Part I (applied math) matches ML 01A–01C; later chapters cover optimization, CNNs, sequence models and representation learning |
| Computer vision beyond classification | Szeliski, *Computer Vision: Algorithms and Applications*, 2nd ed. [8] | connect image formation, motion, geometry, recognition and reconstruction |
| Probabilistic machine learning | Murphy, *Probabilistic Machine Learning: An Introduction* [9] | a modern, probability-first reference for the ML and PR tracks |
| NLP applications, main text | Hagiwara, *Real-World Natural Language Processing* [13] | follow the application workflow, text classification, sequence models, attention, pretrained models, training practices and deployment |
| NLP linguistic foundations, companion | McRoy, *Principles of Natural Language Processing* [14] | study syntax, grammars, semantics, discourse, retrieval, generation and translation alongside the corresponding NLP chapters |
| Language and text, supplementary | Jurafsky and Martin, *Speech and Language Processing*, 3rd-edition draft [10] | deepen selected topics in tokens, n-grams, classification, embeddings, Transformers and evaluation |
| Convex optimization | Boyd and Vandenberghe, *Convex Optimization* [15] | OPT 01–05 follow modeling and applications in Chapters 1–8; OPT 06–08 develop numerical methods in Chapters 9–11 and modern extensions |
| Information theory | Cover and Thomas, *Elements of Information Theory*, 2nd ed. [16] | follow entropy and typicality through source/channel coding, continuous variables, rate distortion, statistical decisions, universal coding and networks |

For the Pattern Recognition track, **Theodoridis and Koutroumbas [3] and Bishop's PRML [4] are the two core references**. Read Theodoridis for a systematic recognition pipeline, then compare Bishop's probabilistic treatment of the same problem. Their publication dates do not weaken Bayes decision theory or Gaussian models; turn to newer papers when the architecture, data scale or application has changed.

If you choose just one deep learning introduction, start with Prince [5] and use this site's math chapters as needed. Choose Bishop and Bishop [6] if you prefer a sustained probabilistic viewpoint. Goodfellow et al. [7] remains a valuable foundation, but its 2016 edition predates Transformers in vision, diffusion models and foundation models; the ML track covers those.

The NLP track uses **Hagiwara [13] and McRoy [14] as its two core books**. Hagiwara connects models to applications; McRoy supplies the linguistic and symbolic concepts needed to understand what a language system is trying to represent. Read both around the same problem: a classifier needs a data workflow, but a parser or dialogue system also needs an explicit account of linguistic structure. Newer papers supplement their 2021 editions.

For Optimization, use **Boyd and Vandenberghe [15]** to learn which problem transformations preserve convexity and what an optimality certificate means. For Information Theory, use **Cover and Thomas [16]** to distinguish an achievable construction from a bound that no construction can beat. These tracks extend the introductory mathematics in ML 01B–01C; their book chapter maps appear within each tutorial.

The Jurafsky and Martin draft changes over time; its current release is dated August 19, 2026 [10]. Record the release date when you make chapter notes, because chapter numbering can move between versions. Likewise, record textbook edition numbers so that exercise references stay reproducible.

## Read textbooks, surveys and papers differently

A **textbook** gives definitions and a coherent sequence. Re-derive one equation, run a tiny example and solve one exercise before moving on.

A **survey or review** gives a map of alternatives, assumptions and open questions. Each tutorial's *Modern view* section summarizes several. When you read one, make a table with the prediction target, learning objective, required data, compute and evaluation of each method it covers. Check its coverage date: "recent" means recent to its authors.

An **original paper** supplies one method and its evidence. Read the problem, the method, the experimental protocol and the limitations. Trace an important claim to the actual table or ablation that supports it. Knowing what changed relative to a fair baseline is more useful than knowing the method's name.

Keep a reading note with five entries: the question, the mathematical objects, the main assumption, the experiment that tests it, and one remaining doubt. The reference lists in each tutorial suggest focused next readings; you do not need to read every cited paper before running the code.

## A sequence of small milestones

1. **Represent data:** inspect an image and explain its axes, range and dtype.
2. **Transform data:** implement one filter, compare it with a library function and account for the boundaries.
3. **Make a decision:** fit a simple classifier with preprocessing learned only from the training data.
4. **Learn features:** train a small neural network and justify its loss and validation choice.
5. **Study a modern method:** reproduce a mechanism such as attention, masking or noising on synthetic data.
6. **Finish a small project:** report a baseline, independent test results, failure cases and limitations.

Move on when you can explain the previous milestone without copying its wording. A modest experiment with a clean comparison teaches more than a large model whose data and evaluation you cannot inspect.

## Key takeaways

- Eight tracks: Foundations, Image Processing, NLP, Pattern Recognition, ML/DL, DL for Vision, Optimization and Information Theory. They feed each other; none has to be finished before another is started.
- Each page's *Needs* line, level pill and track rail tell you where it sits; use them instead of reading everything in order.
- Choose an entry route by background and a learning path by goal; one tutorial per week with code and exercises is a sustainable pace.
- All code is self-contained and CPU sized; one Python environment with NumPy, SciPy, scikit-learn, scikit-image, OpenCV, PyWavelets and PyTorch covers the whole site.
- Pair each track with one main textbook and one companion, and read textbooks, surveys and papers for different purposes.

## Exercises

1. **Plan.** Pick an entry route, a learning path and a main textbook. Write the question your first experiment will answer and a concrete result that would count as progress.

<details>
<summary>Hint</summary>

Keep the question small enough to test on a CPU in one sitting, for example "How much does a 5×5 Gaussian blur reduce noise in flat regions, and how much does it widen an edge?" Progress is a number you can measure, not a feeling.

</details>

2. **Kernel sweep.** Change the smoothing example to kernel sizes 3, 5 and 9 (raise $\sigma$ with the kernel, for example 0.8, 1.0 and 2.0). Report the flat-region standard deviation and the number of pixels the edge takes to rise from 0.1 to 0.9.

<details>
<summary>Hint</summary>

Keep the random seed and the noisy image fixed so only the filter changes. Noise should fall and the edge width should grow together: that is the bias–variance trade-off of linear smoothing.

</details>

3. **Read a page's metadata.** Open [ML 02](/en/learn/ml/ml-02-neural-networks/). What is its level, what does its *Needs* line point to, and which tutorial comes next in the track rail?

<details>
<summary>Hint</summary>

The *Needs* line is right under the title. Follow it back until you reach a page whose prerequisites you already know; that chain is your personal reading order.

</details>

4. **Classify a source.** Select one reference from any tutorial and classify it as textbook, survey, original paper or software documentation. What question is that source best suited to answer?

<details>
<summary>Hint</summary>

A survey answers "what are the options and how do they compare?"; an original paper answers "does this specific change help, and under what protocol?"; documentation answers "what does this function actually compute?"

</details>

5. **Split by the right unit.** Sketch a training/validation/test split for a dataset containing many frames from each of 50 videos. Explain why splitting individual frames at random can be misleading.

<details>
<summary>Hint</summary>

Neighboring frames are nearly identical, so a random frame split puts near-duplicates in both training and test sets and inflates the test score. Split by video (or by recording session) instead.

</details>
