## The big picture

A CNN ([ML 03](/en/learn/ml/convolutional-networks/)) moves information through fixed local neighborhoods: a pixel learns about a distant pixel only after many layers. **Attention** lets every location decide, based on its current content, which other locations to read from, in a single step. To recognize a bird, a patch containing its head can directly consult a distant patch containing its wing.

<Callout type="tip" title="Explain like I'm five">
Imagine a classroom where each child holds one piece of a jigsaw puzzle. Each child asks a question about their piece ("I have a blue edge, who has sky?"), and every other child holds up a card describing their own piece. Each child listens most closely to the classmates whose cards best match the question, and updates their idea of what their piece shows. Then everyone does it again with the improved ideas. Attention is the listening rule. A Transformer repeats many rounds of listening, with a little thinking time in between.
</Callout>

The attention idea came from machine translation with recurrent networks: [ML 04](/en/learn/ml/recurrent-recursive-networks/) shows how it removed the single-vector bottleneck of encoder–decoder RNNs. The Transformer of Vaswani et al. [1] went further and removed recurrence entirely, building both encoder and decoder from attention and small per-token networks. The Vision Transformer (ViT) of Dosovitskiy et al. [2] applied the Transformer encoder almost unchanged to sequences of image patches. Bishop and Bishop [10] give a modern textbook treatment, and the surveys discussed in the Modern view [3], [11], [12] map the many vision variants. Afterwards, [DLCV 02](/en/learn/deep-learning/image-classification/) compares CNN and Transformer backbones for classification in practice, and [ML 06](/en/learn/ml/representation-learning/) shows how such backbones are pretrained without labels.

## Self-attention: queries, keys and values

**Plain version.** A query scores the available keys; normalized scores weight the values. This lets each token select content from the tokens it can access.

**Precise version.** Stack $N$ tokens as the rows of $X\in\mathbb{R}^{N\times D}$, where $D$ is the model width. Three learned matrices project them:

$$
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V,
$$

with $W_Q,W_K\in\mathbb{R}^{D\times d_k}$ and $W_V\in\mathbb{R}^{D\times d_v}$. **Scaled dot-product attention** [1] is

$$
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}_{\text{row}}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V=AV .
$$

$QK^\top$ is an $N\times N$ matrix of **scores**: entry $(i,j)$ is the dot product of query $i$ with key $j$, a measure of how relevant token $j$ is to token $i$. The row-wise softmax turns each row into nonnegative weights that sum to one, giving the **attention matrix** $A$. The output $Y=AV\in\mathbb{R}^{N\times d_v}$ has one row per token: row $i$ is $\sum_j A_{ij}v_j$, a weighted average of value vectors.

**Why three different projections?** If queries and keys were the same vector, every token would match itself most strongly, and relevance would be forced to be symmetric. Separate $W_Q$ and $W_K$ let "what I seek" differ from "what I offer" (an eye patch can seek a nose without being one), and a separate $W_V$ lets "what I offer" differ from "what I pass on".

**Why divide by $\sqrt{d_k}$?** If the components of a query and a key are independent with mean zero and variance one, their dot product $q\cdot k=\sum_{l=1}^{d_k}q_lk_l$ has mean zero and variance $d_k$. Without scaling, larger heads produce larger scores, the softmax saturates (almost all weight on one token), and its gradients become tiny. Dividing by $\sqrt{d_k}$ restores unit variance. It is a scale convention, not a normalization of each query to unit length.

**Content, not position, decides who talks to whom.** Unlike a convolution, whose weights are tied to relative positions, attention weights are computed from the data at run time. A related consequence: self-attention is **permutation-equivariant**. Shuffle the input tokens, and the outputs are shuffled in the same way, because nothing in the formula refers to token order. The snippet checks both the shapes and this symmetry.

```python
import torch

torch.manual_seed(0)
X = torch.randn(5, 8)                   # N=5, D=8
Wq, Wk, Wv = [torch.randn(8, 4) for _ in range(3)]
def attention(x):
    q, k, v = x @ Wq, x @ Wk, x @ Wv
    a = (q @ k.T / q.shape[-1]**.5).softmax(dim=-1)
    return a @ v, a
y, a = attention(X)
perm = torch.tensor([3, 0, 4, 1, 2])
yp, _ = attention(X[perm])
assert torch.allclose(a.sum(-1), torch.ones(5), atol=1e-6)
assert torch.allclose(yp, y[perm], atol=1e-5)
print("output shape:", tuple(y.shape))
```

This symmetry suits sets, but an image is not a set of patches: a face with its eyes below its mouth is not a face. Positional information, introduced below, breaks the symmetry.

## Multi-head attention

**Plain version.** Run several attention operations in parallel, each with its own smaller projections, so different heads can track different relationships (nearby texture, the same object, symmetric parts). Then concatenate their outputs and mix them.

**Precise version.** With $h$ heads, head $r$ has its own $W_Q^{(r)},W_K^{(r)},W_V^{(r)}\in\mathbb{R}^{D\times d_k}$, usually with $d_k=d_v=D/h$:

$$
\operatorname{head}_r=\operatorname{Attention}\!\left(XW_Q^{(r)},XW_K^{(r)},XW_V^{(r)}\right),\qquad
\operatorname{MHA}(X)=\big[\operatorname{head}_1,\dots,\operatorname{head}_h\big]\,W_O,
$$

where the brackets concatenate the $h$ outputs of width $D/h$ back to width $D$, and $W_O\in\mathbb{R}^{D\times D}$ mixes them. Because each head has width $D/h$, multi-head attention costs about the same as one full-width head, and its projections have $4D^2$ weights in total (plus biases). Heads are not guaranteed to learn human-readable roles; some are redundant and can be pruned.

The implementation below splits the projections into heads, computes the scores per head, concatenates and projects, and matches `nn.MultiheadAttention` exactly. It also shows a **causal mask**: setting forbidden scores to $-\infty$ before the softmax gives them exactly zero weight.

```python
import torch
from torch import nn

torch.manual_seed(0)
B, N, D, h = 2, 6, 16, 4
mha = nn.MultiheadAttention(D, num_heads=h, batch_first=True, bias=False)
X = torch.randn(B, N, D)

def multi_head(x):
    Wq, Wk, Wv = mha.in_proj_weight.chunk(3)          # each D x D (rows = outputs)
    q, k, v = x @ Wq.T, x @ Wk.T, x @ Wv.T              # B x N x D
    split = lambda t: t.view(B, N, h, D // h).transpose(1, 2)   # B x h x N x d_k
    q, k, v = split(q), split(k), split(v)
    scores = q @ k.transpose(-2, -1) / (D // h) ** 0.5  # B x h x N x N
    A = scores.softmax(dim=-1)
    heads = A @ v                                       # B x h x N x d_k
    concat = heads.transpose(1, 2).reshape(B, N, D)     # put the heads side by side
    return concat @ mha.out_proj.weight.T, A

ours, A = multi_head(X)
ref, _ = mha(X, X, X)
print("matches nn.MultiheadAttention:", torch.allclose(ours, ref, atol=1e-5))
print("attention tensor:", tuple(A.shape), "| parameters:",
      sum(p.numel() for p in mha.parameters()), "= 4 * D^2 =", 4 * D * D)

# Causal mask: query i may only read keys j <= i
causal = torch.triu(torch.ones(N, N, dtype=torch.bool), diagonal=1)   # True = forbidden
out_c, w_c = mha(X, X, X, attn_mask=causal)
print("no weight on the future:", torch.all(w_c[:, causal] == 0).item())
```

It prints `True`, an attention tensor of shape `(2, 4, 6, 6)` (batch, heads, queries, keys), `1024 = 4 * D^2 = 1024`, and `True` for the causal check. Production code can use `torch.nn.functional.scaled_dot_product_attention`, which dispatches to fused kernels when supported [7]. **Do not copy the Boolean mask unchanged:** `nn.MultiheadAttention` uses `True` for forbidden positions, while `scaled_dot_product_attention` uses `True` for allowed positions. Also pass `dropout_p=0.0` to the functional call during evaluation; it does not inspect a module's training flag. Check mask semantics and dropout explicitly when replacing the teaching implementation.

## Three ways to connect tokens

**Plain version.** Which tokens a query is allowed to read is part of the model's design, expressed as a mask on the score matrix.

| Mechanism | A query reads | Typical use |
|---|---|---|
| Bidirectional self-attention | All tokens of the same sequence | ViT and other image encoders |
| Causal (masked) self-attention | Itself and earlier positions only | Next-token generation, autoregressive image models |
| Cross-attention | Tokens from a different sequence | A decoder reading an encoder; image tokens reading text |

<Figure src={masksFig} alt="Three eight by eight matrices: fully blue for unrestricted attention, a lower-triangular blue region for the causal mask, and two blue blocks on the diagonal for two local windows." caption="Figure 1 — Attention masks: blue entries are allowed, white entries are forbidden. Causal generation also shifts its inputs by one position so a target cannot simply be copied." />

In **cross-attention**, queries come from one sequence $X$ and keys and values from another sequence $Z$: $Q=XW_Q$, $K=ZW_K$, $V=ZW_V$. The score matrix has shape $N_X\times N_Z$, and the output has one row per query. This is how the original Transformer decoder reads its encoder, how image captioners read image features, and how text-to-image diffusion models read a text prompt ([ML 08](/en/learn/ml/diffusion-flow-matching/)) without being autoregressive over image patches.

Attention weights are part of a computation, not automatically an explanation. A large weight can multiply an uninformative value, and the residual and MLP paths also shape the output.

## Positional information

**Plain version.** Content-only self-attention has no built-in position labels. Position embeddings, relative information or position-dependent masks supply structure.

**Sinusoidal encodings.** The original Transformer [1] adds a fixed vector $p_{pos}\in\mathbb{R}^D$ to the token at position $pos$:

$$
p_{pos,\,2i}=\sin\!\left(\frac{pos}{10000^{2i/D}}\right),\qquad
p_{pos,\,2i+1}=\cos\!\left(\frac{pos}{10000^{2i/D}}\right),\qquad i=0,\dots,\tfrac{D}{2}-1 .
$$

Each pair of dimensions $(2i,2i+1)$ is a point rotating around a circle at angular frequency $\omega_i=10000^{-2i/D}$, from fast (one radian per position) to very slow. Two properties follow from the angle-addition formulas. First, for any fixed offset $k$, $p_{pos+k}=p_{pos}R_k$ for a block-diagonal rotation $R_k$ that does not depend on $pos$; a linear layer can therefore learn to "look $k$ positions ahead". Second, $p_{m}\cdot p_{n}=\sum_i\cos\big(\omega_i(m-n)\big)$ depends only on the offset $m-n$ (Figure 2, middle).

<Figure src={posFig} alt="Left: a heatmap of sinusoidal encodings with position on the horizontal axis and 128 dimensions on the vertical axis, showing fast oscillations in low dimensions and slow ones in high dimensions. Middle: the dot product of position 20's encoding with all positions, peaking at 20 and falling off with distance. Right: a 14 by 14 grid colored by similarity of a 2-D row-plus-column encoding to a starred patch, brightest near the star and along its row and column." caption="Figure 2 — Sinusoidal positional encodings. Left: each dimension pair oscillates at its own frequency. Middle: similarity between encodings depends on the offset. Right: concatenating row and column encodings gives a 2-D encoding for a 14 × 14 patch grid." />

```python
import numpy as np

def sinusoidal(n_pos, D):
    pos = np.arange(n_pos)[:, None]
    omega = 1.0 / 10000 ** (np.arange(0, D, 2) / D)    # one frequency per sin/cos pair
    pe = np.zeros((n_pos, D))
    pe[:, 0::2] = np.sin(pos * omega)
    pe[:, 1::2] = np.cos(pos * omega)
    return pe, omega

pe, omega = sinusoidal(100, 16)
k = 7                                                 # a fixed offset
# block-diagonal rotation that maps p_pos to p_{pos+k}, the same for every pos
R = np.zeros((16, 16))
for i, w in enumerate(omega):
    c, s = np.cos(w * k), np.sin(w * k)
    R[2 * i:2 * i + 2, 2 * i:2 * i + 2] = [[c, -s], [s, c]]
print("p[pos+k] == p[pos] @ R for all pos:", np.allclose(pe[:-k] @ R, pe[k:]))
print("dot products depend only on offset:",
      np.isclose(pe[10] @ pe[17], pe[50] @ pe[57]))
```

Both checks print `True`.

**Other schemes.**

- **Learned absolute embeddings**: a trainable vector per position, as in ViT [2]. ViT's 1-D learned embeddings, indexed by raster order, worked about as well as explicitly 2-D ones; after training, embeddings of patches in the same row or column became similar, so the model learned the grid by itself. At a new resolution, the grid of embeddings is resized by 2-D interpolation before fine-tuning.
- **Relative position representations** (Shaw et al. [17]) add a learned term that depends on the offset $j-i$ to the score between tokens $i$ and $j$. Swin [5] adds a learned **relative position bias** table to each window's scores.
- **Rotary position embedding (RoPE)** (Su et al. [16]) rotates each query and key by an angle proportional to its position, using the same rotations as the sinusoidal code above. The score $q_m^\top k_n$ then depends on the positions only through $m-n$. RoPE is standard in large language models and increasingly used in vision with separate rotations for the two image axes.
- **No explicit encoding**: convolutions inside the network, as in CvT [19], or zero padding at borders can leak enough position information on their own.

## The Transformer block

**Plain version.** A block alternates two jobs. Attention lets tokens exchange information; a small MLP then processes each token on its own. Residual connections and normalization keep the stack stable.

**Precise version.** The **pre-norm** block used by ViT and most modern models is

$$
U=X+\operatorname{MHA}\!\big(\operatorname{LN}(X)\big),\qquad
Y=U+\operatorname{MLP}\!\big(\operatorname{LN}(U)\big),\qquad
\operatorname{MLP}(u)=W_2\,\operatorname{GELU}(W_1u+b_1)+b_2 .
$$

$\operatorname{LN}$ is **layer normalization** [14]: it standardizes each token's $D$ features to zero mean and unit variance, then applies a learned scale and shift; unlike BatchNorm, it does not depend on other samples in the batch. The MLP expands each token from $D$ to typically $4D$ hidden units, applies the GELU nonlinearity [26] ($\operatorname{GELU}(z)=z\,\Phi(z)$, where $\Phi$ is the standard normal CDF), and projects back. The residual additions mean each sub-layer only learns a correction, exactly as in ResNet.

<Figure src={blockFig} alt="A left-to-right block diagram: X, LayerNorm, multi-head self-attention, a plus node, LayerNorm, MLP with D to 4D to D and GELU, a plus node, Y; two curved orange arrows carry X around the attention branch and the intermediate result around the MLP branch to the plus nodes." caption="Figure 3 — A pre-norm Transformer block. Attention mixes information across tokens; the MLP transforms each token separately; residual paths (orange) carry the input around each branch." />

The original Transformer placed LayerNorm **after** each residual addition (post-norm). Xiong et al. [15] showed that with post-norm the gradients near the output are large at initialization, which is why it needs a learning-rate warm-up, whereas pre-norm keeps gradients well behaved and can train without one. So "a Transformer" is not fully specified until you say where the normalization goes. Counting weights per block: $4D^2$ for attention and $8D^2$ for the MLP, so about $12D^2$, two thirds of it in the MLP.

## The Vision Transformer (ViT)

**Plain version.** Cut the image into square patches, turn each patch into a vector, add position information, and feed the sequence to a standard Transformer encoder. Read the answer from a special extra token.

**Patchify.** For an image with $H\times W$ pixels and $C$ channels, and patch size $P$ dividing both $H$ and $W$, there are $N=HW/P^2$ patches. Flatten each into $x_i^{\text{patch}}\in\mathbb{R}^{P^2C}$ and project linearly:

$$
z_0=\big[\,x_{\text{cls}};\;x_1^{\text{patch}}E;\;\dots;\;x_N^{\text{patch}}E\,\big]+E_{\text{pos}},
$$

where $E\in\mathbb{R}^{P^2C\times D}$ is the learned **patch embedding**, $x_{\text{cls}}\in\mathbb{R}^D$ is a learned **class token** prepended to the sequence, and $E_{\text{pos}}\in\mathbb{R}^{(N+1)\times D}$ holds learned position embeddings. After $L$ blocks, a LayerNorm and a linear head applied to the class token's output give the logits. Averaging all patch outputs (mean pooling) is an equally common alternative to the class token.

<Figure src={patchFig} alt="The astronaut test image resized to 224 by 224 and overlaid with a seven by seven grid of white lines; on the right, the first twelve patches shown as a row of small tiles in raster order, followed by four numbered steps: cut into patches, flatten and multiply by E, add position embeddings and optionally a CLS token, and feed the N by D sequence to the encoder." caption="Figure 4 — Patchify. A 32-pixel grid is drawn for readability; ViT-Base uses 16 × 16 patches, which turn a 224 × 224 image into 196 tokens." />

A linear map applied to non-overlapping $P\times P$ patches is exactly a convolution with kernel size and stride both equal to $P$, which is how implementations write it:

```python
import torch
from torch import nn

torch.manual_seed(0)
B, C, H, W, P, D = 2, 3, 32, 32, 8, 48
x = torch.randn(B, C, H, W)

# 1) explicit: cut into P x P patches, flatten each, multiply by E
patches = x.unfold(2, P, P).unfold(3, P, P)                 # B, C, H/P, W/P, P, P
patches = patches.permute(0, 2, 3, 1, 4, 5).reshape(B, -1, C * P * P)   # B, N, P*P*C
E = torch.randn(C * P * P, D) * 0.02
tokens_explicit = patches @ E                                # B, N, D

# 2) the same linear map written as a convolution with kernel = stride = P
conv = nn.Conv2d(C, D, kernel_size=P, stride=P, bias=False)
conv.weight.data = E.T.reshape(D, C, P, P)
tokens_conv = conv(x).flatten(2).transpose(1, 2)             # B, N, D

print("tokens:", tuple(tokens_conv.shape), "| identical:",
      torch.allclose(tokens_explicit, tokens_conv, atol=1e-5))
```

It prints 16 tokens of width 48 and `True`.

**Sizes.** The standard configurations are ViT-Base (12 blocks, $D=768$, 12 heads, about 86 million parameters), ViT-Large (24 blocks, $D=1024$, 16 heads) and ViT-Huge (32 blocks, $D=1280$, 16 heads) [2]. "ViT-B/16" means Base with $16\times16$ patches. **Patch size is the main compute knob**: halving $P$ quadruples $N$ and multiplies the attention-score count by sixteen. Small patches keep fine detail; large patches are cheap but lose anything finer than the patch, which no later layer can recover.

**The data lesson.** Dosovitskiy et al. [2] found that ViT trained only on ImageNet-1k (about 1.3 million images) was somewhat worse than comparable ResNets, but when pretrained on ImageNet-21k (14 million) or JFT-300M (300 million) and then fine-tuned, it matched or exceeded them at lower pretraining cost. Their explanation is **inductive bias**: a CNN assumes locality and translation equivariance in every layer, whereas a ViT is local only within the patch embedding and must **learn** spatial relationships from data. Raghu et al. [18] compared the internal representations of ViTs and ResNets and found that ViTs have more uniform representations across layers, that their lower layers attend both locally and globally, and that learning local attention in early layers requires large-scale pretraining.

### Code: a tiny ViT trained on digits

This complete example trains a small ViT on the same $8\times8$ digits as the CNN in [ML 03](/en/learn/ml/convolutional-networks/), with $2\times2$ patches (16 tokens), a class token, learned positions and four pre-norm blocks. It runs on CPU in about half a minute.

```python
import copy
import numpy as np
import torch
from torch import nn
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

torch.manual_seed(0)
torch.set_num_threads(1)

class TinyViT(nn.Module):
    def __init__(self, img=8, patch=2, chans=1, D=64, depth=4, heads=4, classes=10):
        super().__init__()
        N = (img // patch) ** 2
        self.patch = nn.Conv2d(chans, D, kernel_size=patch, stride=patch)   # patchify + E
        self.cls = nn.Parameter(torch.zeros(1, 1, D))                       # [CLS] token
        self.pos = nn.Parameter(torch.randn(1, N + 1, D) * .02)             # learned positions
        layer = nn.TransformerEncoderLayer(D, heads, dim_feedforward=4 * D, dropout=0.1,
                                           activation="gelu", batch_first=True,
                                           norm_first=True)                 # pre-norm block
        self.blocks = nn.TransformerEncoder(layer, depth, enable_nested_tensor=False)
        self.norm, self.head = nn.LayerNorm(D), nn.Linear(D, classes)

    def forward(self, x):
        t = self.patch(x).flatten(2).transpose(1, 2)                         # B, N, D
        t = torch.cat([self.cls.expand(len(t), -1, -1), t], dim=1) + self.pos
        return self.head(self.norm(self.blocks(t))[:, 0])                    # read [CLS]

d = load_digits()
X = torch.tensor(d.images[:, None] / 16.0, dtype=torch.float32)
y = torch.tensor(d.target)
train, test = train_test_split(np.arange(len(y)), test_size=.2, stratify=d.target,
                               random_state=0)
train, val = train_test_split(train, test_size=.2, stratify=d.target[train], random_state=1)
model = TinyViT()
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.05)
best = (float("inf"), None)
for epoch in range(30):
    model.train()
    for idx in torch.tensor(train)[torch.randperm(len(train))].split(64):
        loss = nn.functional.cross_entropy(model(X[idx]), y[idx])
        opt.zero_grad(); loss.backward(); opt.step()
    model.eval()
    with torch.no_grad():
        v = nn.functional.cross_entropy(model(X[val]), y[val]).item()
    if v < best[0]:
        best = (v, copy.deepcopy(model.state_dict()))
model.load_state_dict(best[1]); model.eval()
with torch.no_grad():
    acc = (model(X[test]).argmax(1) == y[test]).float().mean().item()
print("parameters:", sum(p.numel() for p in model.parameters()))
print("best validation loss:", round(best[0], 4), "| held-out accuracy:", round(acc, 4))
```

On our run it uses about 202,000 parameters and reaches about 95% held-out accuracy, while the CNN in ML 03 reached about 96% with fewer than 10,000 parameters and the same split. On a small dataset, the CNN's built-in locality is worth a factor of twenty in parameters. This is the data lesson in miniature, not a verdict on large-scale performance.

## Training recipes: DeiT and beyond

**Plain version.** Much of the early gap between ViTs and CNNs on ImageNet-sized data turned out to be about training, not architecture.

DeiT (Touvron et al. [4]) trained ViTs competitively **on ImageNet-1k alone** using strong data augmentation (RandAugment, Mixup, CutMix, random erasing), heavy regularization (stochastic depth, label smoothing) and long schedules. It also introduced a **distillation token**: an extra learned token, like the class token, whose output is trained to match the predictions of a pretrained CNN teacher. The CNN's inductive bias is thus transferred through its predictions. DeiT III [27] later showed that a simpler, carefully tuned supervised recipe (a lightweight "3-Augment" scheme, simple cropping and a binary cross-entropy loss) makes plain ViTs stronger still. Steiner et al. [25] ran a large study of data, augmentation and regularization ("AugReg") and found that the right combination of augmentation, regularization and compute can match models trained on roughly ten times more data.

The general lesson, repeated in [ML 03](/en/learn/ml/convolutional-networks/)'s discussion of ConvNeXt: compare architectures only under matched data, augmentation, resolution, schedule and compute.

## Swin and hierarchical Transformers

**Plain version.** Global attention over thousands of tokens is expensive, and plain ViT keeps one coarse resolution throughout, which is awkward for detection and segmentation. Swin restricts attention to local windows, shifts the windows between layers so information still spreads, and merges patches to build a CNN-like pyramid.

**Windows.** Swin [5] partitions the token grid into non-overlapping windows of $M\times M$ tokens (typically $M=7$) and computes self-attention inside each window only. For an $h\times w$ token grid with $C$ channels, the paper gives the costs

$$
\Omega(\text{global MSA})=4hwC^2+2(hw)^2C,\qquad
\Omega(\text{window MSA})=4hwC^2+2M^2hwC,
$$

where $4hwC^2$ counts the four projections and the second term counts the score and weighting products. Global cost is quadratic in the number of tokens $hw$; window cost is linear for fixed $M$.

**Shifted windows.** With fixed windows, tokens in different windows would never interact. Swin alternates regular windows with windows displaced by $\lfloor M/2\rfloor$ tokens in each direction. A token near a window boundary at layer $\ell$ shares a window with tokens from neighboring windows at layer $\ell+1$, so information crosses boundaries (Figure 5). An efficient implementation cyclically shifts the feature map and uses a mask so that tokens wrapped from opposite edges do not attend to each other.

<Figure src={swinFig} alt="Left: an eight by eight token grid divided into four colored four by four windows. Middle: the same grid with window boundaries shifted by two tokens, giving nine regions of different sizes. Right: an eight by eight map in which the top-left four by four window is dark blue, an L-shaped band extending two more tokens right and down is light blue, and a red star marks one token near the window edge." caption="Figure 5 — Swin's regular and shifted windows on an 8 × 8 token grid. After two layers, information from the starred token reaches the dark window (layer ℓ) plus the light band added by the shifted windows (layer ℓ+1)." />

**Hierarchy.** Between stages, **patch merging** concatenates each $2\times2$ group of neighboring tokens and projects them linearly, halving the resolution and doubling the channels, as a strided convolution would. The four stages produce feature maps at $1/4$, $1/8$, $1/16$ and $1/32$ of the input resolution, the same pyramid a ResNet produces, so Swin can replace a CNN backbone in detection and segmentation frameworks. Each window also adds a learned **relative position bias** to its scores. Swin V2 [32] scaled the design up with residual post-normalization, scaled cosine attention and a continuous, log-spaced position bias that transfers better across window sizes and resolutions.

## Hybrid CNN–Transformer models

**Plain version.** Convolutions are good at local detail with little data; attention is good at long-range interaction. Hybrids use each where it helps.

- **Convolutional stem.** The original ViT paper already tested a "hybrid" in which the patches come from a ResNet feature map instead of raw pixels [2]; it helped at smaller compute budgets.
- **Convolutions inside attention.** CvT [19] uses a convolutional token embedding at each stage and depthwise-convolutional projections for queries, keys and values, which builds in locality and lets it drop explicit position embeddings.
- **Stacking by stage.** CoAtNet [20] places depthwise-convolution stages early, where resolution is high and local patterns dominate, and relative-attention stages later; it reports strong results across data scales because the convolutional stages supply inductive bias when data is limited.
- **Mobile hybrids.** MobileViT [28] inserts small Transformer blocks into a MobileNet-style network to add global context at mobile cost.
- **The reverse direction.** ConvNeXt (see [ML 03](/en/learn/ml/convolutional-networks/)) imported Transformer-era design choices into a pure CNN and matched Swin.

## Cost and efficient attention

**Plain version.** Global attention compares token pairs, so its pairwise work grows quadratically with token count. Efficiency methods reduce memory traffic, interactions or token count.

For $N$ tokens of width $D$, the score matrix costs about $N^2D$ multiply–adds per layer and the projections and MLP about $12ND^2$. A naive implementation stores an $N\times N$ matrix per head. Doubling the image height and width at a fixed patch size multiplies $N$ by four and the pairwise scores by sixteen.

<Figure src={costFig} alt="Relative pair-score counts at image sides 224, 448 and 896 with patch size 16: global attention grows to 256 times while 7 by 7 window attention grows to 16 times." caption="Figure 6 — Pair-score scaling, not a measured runtime. Projections, MLPs, memory traffic and kernel quality also determine latency." />

The main families:

- **Exact but faster.** FlashAttention [6] computes **exact** attention by tiling the computation so that blocks of queries, keys and values stay in fast on-chip memory, and never writes the full $N\times N$ matrix to slow GPU memory; FlashAttention-2 [29] improves the work partitioning further. The arithmetic is still quadratic; the memory is linear and wall-clock time drops substantially. PyTorch's `scaled_dot_product_attention` selects such kernels automatically when it can [7].
- **Restricted connectivity.** Windowed (Swin) or other sparse patterns reduce the number of pairs, at the price of needing several layers for global communication.
- **Fewer tokens.** Token Merging (ToMe) [21] gradually merges similar tokens inside a pretrained ViT using a fast matching step, increasing throughput without retraining. Larger patches, token pruning and pooling stages do the same more bluntly.
- **Smaller models.** Papa et al.'s survey [13] organizes efficient ViTs into compact architectures, pruning, knowledge distillation and quantization, and proposes an "Efficient Error Rate" metric to compare models across parameters, bits, FLOPs and size.

## State-space models and hybrids

**Plain version.** Instead of comparing every pair of tokens, carry a compact state through the sequence, as a recurrent network does ([ML 04](/en/learn/ml/recurrent-recursive-networks/)). The cost grows linearly with the number of tokens.

A simplified state-space recurrence over a token sequence is

$$
h_t=\bar A_t\,h_{t-1}+\bar B_t\,x_t,\qquad y_t=C_t\,h_t,
$$

where $h_t$ is a hidden state of fixed size, and $\bar A_t$, $\bar B_t$, $C_t$ are (discretized) state-space matrices. In **selective** models such as Mamba, the write/read coefficients and step sizes depend on input $x_t$; the underlying continuous transition can remain fixed while its discretization varies. Input selection and an affine state update permit a parallel scan [33]. An image has no natural one-dimensional order, so vision variants must choose **scan orders**: Vision Mamba (Vim) [30] scans the patch sequence forward and backward with position embeddings, and VMamba [31] scans along four directions over the 2-D grid. The Visual Mamba survey [8] reviews over 200 papers and identifies scanning as the critical design decision for vision.

A useful counterpoint is MambaOut [9] (CVPR 2025). Its authors argue that Mamba suits tasks with long sequences and causal (autoregressive) structure, and build MambaOut models by removing the state-space component while keeping the gated convolutional blocks. Their models outperform visual Mamba models on ImageNet classification, suggesting that Mamba is unnecessary there, while for detection and segmentation, which involve long token sequences, they find state-space models may still be worth exploring. The broader point is methodological: isolate the mechanism (attention, scan, convolution) from gating, normalization, training recipe and parameter budget before crediting a result to it.

### An image scan is an inductive bias

Mamba [33] supplies an efficient sequence operator; it does not choose an image geometry for us. Vim [30] uses a patch sequence, position embeddings and forward/backward processing. VMamba [31] instead places a four-route selective scan inside a hierarchical visual backbone. Neither label alone specifies receptive-field strength, resolution behavior or runtime. The state dimensions, routes, local operators and downsampling stages all matter.

For a fixed scan order, two adjacent pixels in the image may be many steps apart in the sequence. Conversely, the last pixel of one raster row and the first pixel of the next row become consecutive despite being far apart spatially. A local convolution can supply nearby evidence before the scan carries context farther. Multiple routes offer additional paths, but do not restore every geometric symmetry automatically. Position embeddings can also encode useful location while making transfer to a different grid a separate design problem.

A mathematical way to expose the choice is

$$
Y^{(r)}=P_r^{-1}\mathcal S_r(P_rX),\qquad
Y=\frac1m\sum_{r=1}^{m}Y^{(r)}.
$$

Here $X$ contains flattened image tokens, $r$ indexes one of $m$ routes, $P_r$ permutes tokens into that route, $\mathcal S_r$ applies its sequence recurrence, $P_r^{-1}$ restores image coordinates, and $Y$ averages the resulting features. This is a conceptual route-fusion model. A learned vision block can use different projections or fusion rules; averaging is chosen here to keep the experiment interpretable.

### CPU experiment: measure directional bias

The next example uses a single scalar state with the same decay on every route. It compares forward/backward raster scans with four raster/column routes, then rotates the input by 90 degrees, processes it and rotates the output back. Everything uses a synthetic $6\times6$ impulse; no weights or images are downloaded. This isolates ordering rather than reproducing a trained Vim or VMamba.

```python
import numpy as np

def scan_image(image, four=False):
    ids = np.arange(image.size).reshape(image.shape)
    row, col = ids.ravel(), ids.T.ravel()
    orders = [row, row[::-1]]
    if four:
        orders += [col, col[::-1]]
    outputs = []
    for order in orders:
        h = 0.0
        out = np.zeros(image.size)
        for i in order:
            h = 0.8 * h + 0.2 * image.ravel()[i]
            out[i] = h
        outputs.append(out.reshape(image.shape))
    return np.mean(outputs, axis=0)

image = np.zeros((6, 6))
image[1, 4] = 1.0
errors = []
for four in [False, True]:
    original = scan_image(image, four=four)
    rotated_back = np.rot90(scan_image(np.rot90(image), four=four), -1)
    error = np.max(np.abs(original - rotated_back))
    errors.append(error)
    print('four routes:', four, 'rotation discrepancy:', round(error, 6))
assert 0.0 < errors[1] < errors[0]
```

The maximum discrepancies are `0.063622` for two routes and `0.026738` for four. More routes reduce directional bias in this example, but the remaining discrepancy is nonzero. Rotating a raster path reverses one traversal axis; that path need not belong to the original four-route collection. Even shared coefficients and averaging therefore do not guarantee rotation equivariance. Learned directional projections, position information and local operations introduce further choices. Test the property you need instead of inferring it from “2-D scan.”

<Figure src={scanFig} alt="Impulse responses of two-route and four-route scalar image scans" caption="Figure 7 — The red outline marks the input impulse. Two raster routes spread context unevenly; adding column routes changes the influence map. These synthetic responses use the exact recurrence in the example, not learned attention maps or trained VMamba activations." />

The recurrence can have a global receptive field because information travels through the entire scan. This says a dependence is possible, not that its influence remains strong at every distance. With scalar decay $0.8$, the carried contribution decays by another factor of $0.8$ per intervening step. Selective transitions can change this retention, as derived in [ML 04](/en/learn/ml/recurrent-recursive-networks/), but training must still learn which information to preserve. Fine boundaries and small objects can be lost through state compression or downsampling even when distant context is available.

### What Mamba-2 changes, and how to evaluate it

Mamba-2 [34] reorganizes the selective sequence mixer around structured state-space duality and efficient chunk computation. It changes the transition structure and block parameter projections, rather than making an arbitrary image patch sequence equivalent to a Transformer. The causal structured coefficient matrix has an attention-like interpretation, but standard softmax attention retains different expressive and computational properties. An image application must still specify directions and fusion. The duality therefore answers a computation question; it does not remove the geometry question.

A fair vision comparison should separate three experiments: replace only the mixer inside a shared block; compare complete backbones under a matched training budget; and measure the deployed models on the target hardware. Keep data, augmentation, token resolution and downstream heads controlled. Record state size as well as parameter count, and measure latency and peak memory across image resolutions and batch sizes. A linear token-count term can coexist with expensive projections, route permutations and small-kernel overheads. GPU throughput claims do not follow from the Python loop above.

For dense tasks, inspect errors near boundaries, on small structures and across aspect ratios; for video, distinguish an offline bidirectional encoder from causal live processing. Include rotation/crop sensitivity and longer-grid evaluations rather than only in-distribution classification. MambaOut [9] supplies an important mixer-removal ablation. Its results support a task-dependent comparison, not a theorem that scans are unnecessary for every image problem. Xu et al. [8] organize visual Mamba work by backbones, scan mechanisms and image/video/point-cloud/multimodal applications. Their survey remains a 2024 preprint on the verified record. Its taxonomy is useful for selecting controlled experiments; the number of proposed variants does not establish a universal winner.

## Modern view

**Survey literature.** Khan et al. [3] (*ACM Computing Surveys*, 2022) start from the foundations (self-attention, large-scale pretraining, bidirectional encoding) and then survey Transformers across recognition, generative modeling, multimodal tasks such as visual question answering, video, low-level vision and 3-D analysis, closing with open problems. Han et al. [11] (*IEEE TPAMI*, 2023) organize vision Transformers by task (backbones, high- and mid-level vision such as detection and segmentation, low-level vision, video), and also cover efficient Transformer methods. Liu et al. [12] (*IEEE TNNLS*, 2024) review over a hundred visual Transformers for classification, detection and segmentation on images, point clouds and vision–language data, and suggest three future directions. For efficiency, Papa et al. [13] (*IEEE TPAMI*, 2024) is the most systematic. For state-space vision models, see Xu et al. [8]. Bishop and Bishop [10] provide the textbook derivations.

**State of the art, 2023–2026.** The plain ViT has become the default **foundation** backbone. ViT-22B [24] (ICML 2023) scaled a ViT to 22 billion parameters, with architectural changes (such as normalizing queries and keys) needed for stable training at that size. DINOv2 [23] (TMLR 2024) trained ViTs with self-supervision on a large curated image collection and produced general-purpose features that work frozen across classification, segmentation and depth estimation ([ML 06](/en/learn/ml/representation-learning/)). Darcet et al. [22] (ICLR 2024) found that large ViTs repurpose uninformative background patches as internal scratch space, producing high-norm artifact tokens in attention maps, and that adding a few extra **register tokens** removes the artifacts and improves dense predictions. Vision–language foundation models ([ML 10](/en/learn/ml/foundation-models/)) and diffusion Transformers ([ML 08](/en/learn/ml/diffusion-flow-matching/)) build on the same block. At the same time, hierarchical and hybrid designs remain common for dense, high-resolution tasks, modernized CNNs remain competitive under matched budgets (ML 03), and state-space and linear-attention models continue to be explored for very long token sequences such as video.

**Open problems.** Quadratic cost at high resolution and long video; the large data and compute appetite of plain ViTs; position encodings that generalize across resolutions and aspect ratios; interpreting attention without over-reading it; and fair, compute-matched comparisons between attention, convolution and state-space mechanisms.

## Key takeaways

- Queries and keys determine weights; values provide the content mixed by attention.
- Score scaling controls magnitude under variance assumptions; it does not guarantee unit variance for arbitrary learned inputs.
- Masks constrain information access, while positional signals distinguish arrangements that content-only attention cannot.
- Transformer blocks alternate token mixing and per-token transformations, with residual paths and normalization.
- ViT, shifted windows and convolutional hybrids make different choices about locality, resolution and training requirements.
- FlashAttention reduces memory traffic for exact attention; windows, token reduction and state-space scans alter computation or context access.

## Paper guides

These guides are optional. Start with the question and original figure, then unfold the evidence, design analysis and reading checkpoint.

### ViT — image patches and the role of pretraining scale

#### Question and thesis

Can a largely standard Transformer learn useful image representations from a sequence of patches? Dosovitskiy et al. show that it can, with pretraining scale playing a central role [2]. Read patch tokenization, self-attention and residual blocks first. The thesis is not that convolution is always inferior: the paper explicitly investigates how data availability changes the comparison.

#### Method and figure

<Figure src={paperMlVit} alt="Flattened patches become token embeddings with positional information; the Transformer processes their sequence, and a class token feeds the classification head." caption="Source: Dosovitskiy et al., ICLR 2021 manuscript, arXiv:2010.11929v2. Figure 1, PDF p. 3. Flattened patches become token embeddings with positional information; the Transformer processes their sequence, and a class token feeds the classification head. [2]" />

Figure 1 starts with a grid of non-overlapping image patches. Flatten each patch, apply a shared learned linear projection, prepend a learnable class token, and add positional embeddings. For an image whose dimensions are divisible by the patch width,

$$
N=HW/P^2.
$$

Here $H$ and $W$ are image height and width in pixels, $P$ is the square patch width, and $N$ is the number of image tokens before adding the class token. The projection maps patch contents to the Transformer hidden width. Position embeddings supply spatial information that a sequence of content vectors alone does not identify.

The encoder alternates attention and multilayer transformations with normalization and residual connections. The final class-token representation goes to the classification head. Smaller patches increase token count, which changes attention cost even when the original image dimensions stay fixed.

#### Evidence

Figure 3 compares pretraining on ImageNet, ImageNet-21k and JFT-300M. Relative performance changes with the data regime: large ViT models are less competitive when pretrained on less data, while extensive pretraining supports strong transfer. Table 2 reports transfer results with fine-tuning variability. Read the pretraining dataset and compute columns together with downstream accuracy; differing resources prevent treating every row as an isolated architecture comparison.

#### Design analysis

Convolution builds in locality and weight sharing across positions. ViT retains a patch-based input structure but relies more heavily on data to learn useful spatial relationships. The data-scale study is therefore part of the explanation, not a secondary implementation detail. Also distinguish changing model width from changing patch size: both affect cost, but only the latter directly changes the number of input tokens at fixed resolution.

#### Reading checkpoint

Halve the patch width while keeping image size fixed. Determine how the number of image tokens changes, then reason about the pairwise attention matrix. Point to where spatial order enters Figure 1, and explain why an attention visualization alone does not establish a causal explanation of the prediction.

#### Limits and next step

Strong large-scale transfer does not guarantee a favorable small-data or low-compute result. Classification evidence also does not by itself establish dense prediction performance. Continue with [ML 06](/en/learn/ml/representation-learning/) representation learning and compare supervised pretraining with SimCLR's training objective: similar downstream use can arise from different learning signals.
