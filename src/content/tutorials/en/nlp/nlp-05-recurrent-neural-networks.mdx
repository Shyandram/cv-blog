## The big picture

A language model assigns probabilities to text by predicting the next token from the text before it. This chapter builds two such models and compares them under one evaluation contract. The first, an n-gram model, predicts the next token using a small piece of the preceding text. Its probability table is directly inspectable: we can trace a prediction to training counts and see exactly which earlier words the model ignores. This makes it a useful first language model, a controlled baseline, and a way to understand the statistical problems that more elaborate models also face. The second, a recurrent neural network (RNN), replaces the table with a learned state that is updated after every token, so its prediction can in principle depend on the entire prefix.

<Callout type="tip" title="Explain like I'm five">
Imagine a notebook recording what people say next. One page records what follows “cat”; another records what follows “the cat.” When you need a guess, you open the matching page and count the examples. Longer page headings give you more context, but many pages may be nearly empty. Smoothing reserves a little room for words that have not yet appeared on that page. A recurrent network works differently: instead of a notebook with a page for every heading, it keeps a short running summary in its head and rewrites that summary after each word it hears.
</Callout>

## 1. Three meanings of “n-gram”

An n-gram is a contiguous sequence of $n$ tokens. The tokens may be words, subwords or characters; the chosen tokenization determines what is counted. In the word-token sequence `a cat sleeps`, the unigrams are `a`, `cat`, `sleeps`; the bigrams are `a cat`, `cat sleeps`; and the trigram is `a cat sleeps`.

Do not confuse these three uses:

| Use | Object stored or predicted | What it tells us |
| --- | --- | --- |
| N-gram occurrence | A contiguous token tuple | A local piece of a particular sequence |
| Document feature | The number or presence of a tuple in a document | Evidence supplied to a classifier or retrieval model |
| N-gram language model | A normalized next-token distribution for each retained history | Probabilities used to score or generate a sequence |

A document bigram feature such as `not ready` can help a classifier distinguish an operational status. It does not, by itself, specify the probability of `ready` after `not`: we still need competing next-token counts and a normalization rule. Likewise, the probability of a phrase depends on the sentence context under a language model, while a feature count usually pools all of its occurrences within the document.

In a language model, the order $n$ includes the token being predicted. A bigram uses **one previous token**, not two; a trigram uses two. Sentence boundaries require a consistent convention. A beginning marker supplies initial context, and an end marker is a predicted outcome that represents stopping. The examples never predict the beginning marker. Keeping it in the prediction vocabulary would allocate probability to an event that our sentence format does not allow.

## 2. Exact factorization, limited history

Predicting one token at a time can represent a sequence probability exactly. Throwing away older context is the modeling assumption, rather than a consequence of probability theory.

$$
p(x_1,\ldots,x_T)=\prod_{t=1}^{T}p(x_t\mid x_{\lt t}),\qquad
p_n(x_1,\ldots,x_T)=\prod_{t=1}^{T}p_n(x_t\mid h_t^{(n)}).
$$

Here $x_t$ is the token at position $t$; $T$ counts predicted positions, including an end marker when used; $x_{\lt t}$ is the complete prefix; $n$ is the n-gram order; $h_t^{(n)}$ is the suffix containing at most the previous $n-1$ tokens, with beginning markers where needed; and $p_n$ denotes the limited-history model. The first equality is the chain rule. The second defines a model whose predictions depend only on the retained suffix. It need not equal the true sequence distribution.

| Order | Context before predicting `sleeps` in `a cat sleeps` | Conditional distribution |
| --- | --- | --- |
| Unigram, $n=1$ | Empty history | $p_1(\text{sleeps})$ |
| Bigram, $n=2$ | `cat` | $p_2(\text{sleeps}\mid\text{cat})$ |
| Trigram, $n=3$ | `a cat` | $p_3(\text{sleeps}\mid\text{a cat})$ |

An empty history is still a valid context: the unigram model uses the same next-token distribution everywhere. A bigram makes finer distinctions, but it must pool all prefixes ending in the same token. A trigram can separate prefixes whose last two tokens differ. None of these guarantees that the retained context contains the information needed by a linguistic dependency.

### A worked count comparison

The following invented corpus intentionally makes the article informative: examples beginning with `the` end in `sleeps`, and examples beginning with `a` end in `eats`. This is a controlled statistical pattern, not a claim about English. The example fits three orders independently with the same vocabulary and smoothing strength.

```python
from collections import Counter, defaultdict

train = ["the cat sleeps", "the dog sleeps", "a cat eats", "a dog eats"]
START, END, UNK = "<s>", "</s>", "<unk>"
vocab = sorted({w for s in train for w in s.split()} | {END, UNK})
alpha = 0.2
models = {}
for order in (1, 2, 3):
    rows = defaultdict(Counter)
    for sentence in train:
        tokens = [START] * (order - 1) + sentence.split() + [END]
        for t in range(order - 1, len(tokens)):
            history = tuple(tokens[t-order+1:t])
            rows[history][tokens[t]] += 1
    models[order] = rows

def probability(order, history, word):
    row = models[order].get(tuple(history), {})
    return (row.get(word, 0) + alpha) / (sum(row.values()) + alpha * len(vocab))

for order, rows in models.items():
    for history in rows:
        assert abs(sum(probability(order, history, w) for w in vocab) - 1) < 1e-10
print("vocabulary size:", len(vocab))
print("unigram P(eats):", round(probability(1, (), "eats"), 3))
print("bigram P(eats | cat):", round(probability(2, ("cat",), "eats"), 3))
print("trigram P(eats | a cat):", round(probability(3, ("a", "cat"), "eats"), 3))
print("trigram P(eats | the cat):", round(probability(3, ("the", "cat"), "eats"), 3))
print("unseen-history P(eats):", round(probability(3, (UNK, "cat"), "eats"), 3))
assert probability(3, ("a", "cat"), "eats") > probability(3, ("the", "cat"), "eats")
assert abs(probability(3, (UNK, "cat"), "eats") - 1 / len(vocab)) < 1e-10
```

Output:

```text
vocabulary size: 8
unigram P(eats): 0.125
bigram P(eats | cat): 0.333
trigram P(eats | a cat): 0.462
trigram P(eats | the cat): 0.077
unseen-history P(eats): 0.125
```

After `cat`, the bigram count table contains one `eats` and one `sleeps`. Both article choices feed that same table. The trigram tables separate the two observations: `a cat` has one observed `eats`, while `the cat` has none. The trigram can therefore express the distinction, but each of its tables has only one observation. More detailed conditioning gives less evidence per context on this corpus.

The unseen history has no outgoing counts. Additive smoothing makes its distribution uniform over all eight prediction tokens. This is a complete probability distribution, yet it discards useful information that the final token `cat` does occur in training. Interpolation with a lower-order distribution can retain that evidence. Normalization and useful generalization are different properties.

## 3. From counts to normalized probabilities

To estimate a distribution, count each history–target event in training, then divide by the history's outgoing total. Two details make the result reproducible: which symbols are predicted and which contexts count as distinct.

$$
\widehat p(w\mid h)=\frac{c(h,w)}{c(h)},\qquad
c(h)=\sum_{v\in V}c(h,v),\qquad c(h)\gt0.
$$

Here $h$ is a retained history; $w$ is a candidate next token; $V$ is the prediction vocabulary; $v$ ranges over its members; $c(h,w)$ is the number of training transitions from $h$ to $w$; $c(h)$ is their total; and $\widehat p$ is the maximum-likelihood estimate. For a trigram, $h$ is a two-token tuple; for a unigram, it is the empty tuple. The estimate is undefined when the history has never occurred.

Why does the observed relative frequency solve the likelihood problem? For one history, a distribution maximizing $\sum_w c(h,w)\log p(w\mid h)$ subject to probabilities summing to one has its positive-count probabilities proportional to the counts. The normalizing constraint then divides by $c(h)$. Different histories can be fitted independently because a count table does not share parameters across them.

This simplicity creates two distinct problems. An **unseen transition** has an observed history but a target never counted after it, producing probability zero. An **unseen history** has no count table at all, making the unsmoothed ratio undefined. Smoothing can handle both within a fixed vocabulary. It cannot produce the spelling of a word that the vocabulary has replaced with an unknown marker.

Additive smoothing adds a small positive count to every possible target:

$$
p_\alpha(w\mid h)=\frac{c(h,w)+\alpha}{c(h)+\alpha|V|}.
$$

Here $p_\alpha$ is the smoothed distribution; $c(h,w)$ and $c(h)$ are transition and outgoing-history counts; $w$ is the candidate token; $h$ is the retained history; $V$ is the prediction vocabulary; $|V|$ is its size; and $\alpha\gt0$ is the amount added to each candidate count. Summing the numerator over the vocabulary gives exactly the denominator. Even an unobserved history has a defined distribution: all candidates receive probability $1/|V|$.

The vocabulary size matters as much as the count added to one candidate. With a large vocabulary, allocating $\alpha$ to every token can absorb substantial total probability. A parameter that works for this tiny word vocabulary should not be transferred unchanged to a much larger one without validation.

### Code: train, score and sample a bigram model

This complete example needs no downloads or GPU. The corpus is invented for teaching; its test sentences are separate from training. Every test word absent from the training vocabulary maps to the same unknown token.

```python
from collections import Counter, defaultdict
import math
import random

train = [
    "the cat sleeps", "the dog sleeps", "the cat runs",
    "the dog runs", "a cat eats", "a dog eats",
    "the bird sings", "a bird sleeps",
]
test = ["the cat eats", "a dog runs", "the bird sleeps", "a robot runs"]
START, END, UNK = "<s>", "</s>", "<unk>"
words = {w for sentence in train for w in sentence.split()}
vocab = sorted(words | {END, UNK})       # START is context, never predicted
alpha = 0.2
counts = defaultdict(Counter)
unigrams = Counter()

def encode(sentence):
    return [w if w in words else UNK for w in sentence.split()] + [END]

for sentence in train:
    tokens = [START] + encode(sentence)
    for h, w in zip(tokens, tokens[1:]):
        counts[h][w] += 1
        unigrams[w] += 1

def bigram(h, w):
    row = counts.get(h, {})
    return (row.get(w, 0) + alpha) / (sum(row.values()) + alpha * len(vocab))

def unigram(h, w):
    return (unigrams[w] + alpha) / (sum(unigrams.values()) + alpha * len(vocab))

def perplexity(sentences, probability):
    nll, n = 0.0, 0
    for sentence in sentences:
        tokens = [START] + encode(sentence)
        for h, w in zip(tokens, tokens[1:]):
            nll -= math.log(probability(h, w))
            n += 1
    return math.exp(nll / n)

for h in [START] + vocab:
    assert abs(sum(bigram(h, w) for w in vocab) - 1) < 1e-10
print("unigram test perplexity:", round(perplexity(test, unigram), 3))
print("bigram test perplexity:", round(perplexity(test, bigram), 3))
assert UNK in encode(test[-1])

rng = random.Random(7)
h, sample = START, []
for _ in range(20):                     # cap length for this demonstration
    w = rng.choices(vocab, weights=[bigram(h, v) for v in vocab])[0]
    if w == END:
        break
    sample.append(w)
    h = w
print("sample:", " ".join(sample))
```

Output:

```text
unigram test perplexity: 10.382
bigram test perplexity: 3.573
sample: a bird sings
```

The assertions check that every conditional distribution sums to one and that "robot" maps to the unknown token. The bigram model is far less "surprised" by the test sentences than the unigram model, because word order carries information. Sampling can still produce awkward strings: positive probability is not a guarantee of grammaticality. The length cap only stops the demonstration; it does not change the probabilities used for scoring.

### Distinguish smoothing from longer memory

Smoothing addresses missing observations within the chosen representation. It does not restore discarded history. After either “the technician did not repair the” or “the technician repaired the,” a bigram sees only `the`. It assigns the same next-token distribution even if the earlier words would make different continuations appropriate. Increasing the corpus can estimate that shared distribution more accurately while leaving the equality intact.

Additive smoothing also has an exact mixture interpretation. For a context with a positive observed count:

$$
p_\alpha(w\mid h)=\lambda_h\widehat p(w\mid h)+(1-\lambda_h)\frac1{|V|},\qquad
\lambda_h=\frac{c(h)}{c(h)+\alpha|V|},\qquad
\widehat p(w\mid h)=\frac{c(h,w)}{c(h)}.
$$

Here $p_\alpha$ is the smoothed distribution, $h$ is the retained history, $w$ is a candidate token, $c(h,w)$ is its observed transition count, $c(h)\gt0$ is the total outgoing count, $\widehat p$ is the unsmoothed estimate, $\alpha\gt0$ is the smoothing parameter, $|V|$ is vocabulary size and $\lambda_h$ is the weight on observations. A context with zero count uses the uniform distribution directly.

The same smoothing parameter changes rare contexts more than frequent ones. As context count grows, the observed evidence receives more weight; as smoothing grows, probability moves toward the uniform distribution. This explains why a held-out curve can improve initially and then worsen: protecting unseen transitions eventually also dilutes useful observed distinctions. Choose the parameter with validation data rather than the final test set.

A tokenizer and unknown-token rule are part of this experiment. Mapping several unseen words to one marker pools their probabilities. A lower perplexity after that mapping can partly reflect an easier prediction alphabet. It does not show that the model can identify those original words.



### Interpolate evidence from several history lengths

When a long context is rare, shorter contexts often have more observations. Interpolation combines their complete distributions instead of assigning every unseen continuation the same probability.

$$
p_{\mathrm{mix}}(w\mid u,v)=
\lambda_3 p_3(w\mid u,v)+\lambda_2 p_2(w\mid v)+\lambda_1 p_1(w),
\qquad \lambda_i\geq0,\quad \sum_{i=1}^{3}\lambda_i=1.
$$

Here $u,v$ are the two most recent tokens; $w$ is the next token; $p_3,p_2,p_1$ are normalized trigram, bigram and unigram distributions; $p_{\mathrm{mix}}$ is their mixture; and $\lambda_i$ is the nonnegative weight assigned to order $i$. Each component must be defined for the queried history, for example by smoothing. Summing over candidate tokens gives one because each component sums to one and the weights also sum to one.

For the unseen context in our small comparison, a mixture can use the observed bigram after `cat` even though the full two-token context is missing. Fixed mixture weights are easy to inspect; history-dependent weights can assign more trust to well-supported longer histories. Choose the weights on validation text. Deciding them after inspecting the final test perplexity makes that score part of model selection.

Interpolation differs from simply substituting a shorter history only when a transition is missing. Such back-off rules must also account for the probability already allocated to observed transitions, so that the complete distribution stays normalized. Chen and Goodman's comparative study examines smoothing choices and their empirical behavior [4]. Our additive and mixture examples expose the mechanics rather than implementing every estimator in that study.

## 4. What held-out perplexity measures

Scoring measures how much probability a model gives the observed targets. A good score means that these particular token sequences were relatively unsurprising under a particular tokenizer and vocabulary; it does not establish factual accuracy or understanding.

$$
\mathcal L=-\frac1N\sum_{j=1}^{N}\log p(w_j\mid h_j),\qquad
\operatorname{PPL}=\exp(\mathcal L)=
\left(\prod_{j=1}^{N}\frac1{p(w_j\mid h_j)}\right)^{1/N}.
$$

Here $N$ is the number of scored token positions; $j$ indexes those positions across the evaluated sentences; $w_j$ is the observed target; $h_j$ is its permitted history; $p$ is the evaluated model; $\mathcal L$ is mean negative log likelihood in nats per token; and $\operatorname{PPL}$ is perplexity. The product form shows that perplexity is the geometric mean of reciprocal target probabilities. It is not the count of plausible continuations at every position.

If every observed target receives probability $1/K$, perplexity equals $K$, where $K$ is the number of equally likely choices in that hypothetical distribution. Actual predictions are not uniform: one difficult target can contribute a large log loss while many easy targets contribute little. Reporting only an average can conceal concentrated failure on rare names or unfamiliar domains. Inspect losses by word frequency and sentence type as well.

The bigram code counts the end marker, which makes stopping part of both the training problem and the evaluation. It excludes the beginning marker. Its unigram and bigram results are comparable because the test text, tokenization, unknown mapping and number of scored positions match. A comparison across word and character tokenizers has different units. Even the same raw sentence can yield a different score denominator and prediction alphabet.

Train, validation and test text have separate roles. Training determines vocabulary and counts; validation selects order and smoothing; test evaluates the chosen pipeline once. A held-out spelling absent from training must follow the fixed unknown rule. Rebuilding the vocabulary with test text silently changes the experiment. Repeated sentences or material copied across splits can also make memorized local continuations look like generalization.

## 5. Generation, stopping and the memory ceiling

Generation repeatedly samples from a normalized next-token distribution, appends the sampled token to the history and stops when the end marker appears. Scoring instead supplies the observed history from the text being evaluated. The same probability tables support both procedures, but one examines supplied text while the other produces a stochastic trajectory.

The demonstrated sample `a bird sings` is one draw with a fixed random seed. It is not a representative quality estimate. Examine several independently seeded trajectories and report both local errors and unusually long sequences. A length cap guarantees that a program stops running; if the cap fires before the end marker, the displayed sequence is truncated rather than a model-generated completed sentence.

Choosing the most probable next token at each step gives a deterministic greedy trajectory. It does not generally maximize the probability of the entire sequence: a locally attractive token may lead to poor later continuations. Conversely, sampling preserves distributional variety but may choose low-probability transitions. Generation choices therefore answer a different question from whether the model assigns good probabilities to held-out text.

### A failure that more training cannot remove

Consider `the robot near the cabinets is` and `the robots near the cabinet are`. Agreement depends on the head of the subject, rather than simply the immediately preceding noun. If the relevant head lies outside the retained suffix, the model pools examples that require different agreement choices. More observations can improve the pooled estimate, but cannot make that estimate depend on a token outside the model's input.

For any two prefixes with the same final $n-1$ tokens, an n-gram model's next-token distributions must be identical. This is an architectural equality, not an empirical tendency. Increase $n$ and the ceiling moves farther away, while the number of possible histories and the sparsity of their count tables increase. Shared neural representations can connect similar contexts, but their actual behavior still requires testing; merely replacing a table does not establish that an agreement dependency was learned.

## 6. A recurrent language model

**Plain version.** An n-gram model looks the history up in a table. A recurrent language model reads the history one token at a time and keeps a fixed-size vector, the hidden state, that it updates after each token. The next-token distribution is computed from that state, so the model is no longer forced to forget everything older than $n-1$ tokens.

Elman's simple recurrent network introduced this idea of a state fed back as input at the next step [6]; Mikolov and colleagues showed that a recurrent network trained as a word-level language model could beat strong smoothed n-gram baselines for speech recognition [7]. Keep the chain rule from section 2 exactly as it was. Only the conditional distribution changes. For a token sequence $x_1,\ldots,x_T$ with a beginning marker $x_0$:

$$
\begin{aligned}
\mathbf h_t&=\tanh\!\left(W_x\,\mathbf e(x_{t-1})+W_h\,\mathbf h_{t-1}+\mathbf b\right),\qquad \mathbf h_0=\mathbf 0,\\
\mathbf z_t&=W_o\,\mathbf h_t+\mathbf c,\\
p_\theta(x_t=v\mid x_{\lt t})&=\operatorname{softmax}(\mathbf z_t)_v=\frac{\exp z_{t,v}}{\sum_{u\in V}\exp z_{t,u}}.
\end{aligned}
$$

Here $\mathbf e(x)\in\mathbb R^{d}$ is the embedding of token $x$ (a row of a learned table, as in NLP 04); $\mathbf h_t\in\mathbb R^{m}$ is the hidden state after reading $x_0,\ldots,x_{t-1}$; $W_x\in\mathbb R^{m\times d}$, $W_h\in\mathbb R^{m\times m}$ and $\mathbf b\in\mathbb R^{m}$ are the recurrent parameters; $W_o\in\mathbb R^{|V|\times m}$ and $\mathbf c\in\mathbb R^{|V|}$ map the state to one score $z_{t,v}$ per vocabulary item $v$; $V$ is the prediction vocabulary and $u$ ranges over it; $\theta$ collects all parameters; and $\tanh$ acts element by element. This is the same recurrence as in ML 03A, written with an embedding as input and a softmax over the vocabulary as output.

Three consequences follow directly from the equations.

- **Unbounded conditioning, bounded memory.** $\mathbf h_t$ is a function of the whole prefix, so two prefixes that share their last $n-1$ tokens can receive different predictions. But $\mathbf h_t$ has only $m$ numbers. The model must learn what to keep; nothing guarantees that it keeps the information a particular dependency needs.
- **Shared parameters.** The same $W_x$, $W_h$ and $W_o$ are used at every position. The parameter count does not grow with context length, whereas the number of possible n-gram histories grows as $|V|^{n-1}$.
- **Generalization through similarity.** Similar tokens receive similar embeddings, and similar prefixes can produce similar states. An unseen history no longer falls back to a uniform row: it is mapped to some state, and the prediction made from that state can reuse what similar histories taught the model.

### The training loss is next-token cross-entropy

Training minimizes the same quantity that section 4 used for evaluation, now as a differentiable function of $\theta$:

$$
\mathcal L(\theta)=-\frac1N\sum_{j=1}^{N}\log p_\theta(x_j\mid x_{\lt j}),\qquad
\operatorname{PPL}=\exp\mathcal L,\qquad
\text{bits per token}=\frac{\mathcal L}{\ln 2}.
$$

Here $N$ is the number of supervised target positions (padding and other ignored positions excluded), $x_j$ is the observed target at position $j$, $x_{\lt j}$ is its prefix, and $\ln 2$ converts nats to bits. The per-position term is the cross-entropy between the one-hot target and the model's softmax distribution; [IT 01](/en/learn/information-theory/entropy-mutual-information/) develops cross-entropy and its link to coding length. Character-level work often reports bits per character instead of perplexity; the two carry the same information.

Two implementation details carry over from the count model. First, **shift by one**: the input sequence is $x_0,\ldots,x_{T-1}$ and the target sequence is $x_1,\ldots,x_T$. Feeding a position's own token as both input and target creates a trivial copying shortcut. Second, **teacher forcing**: during training each step receives the observed previous token, not the model's own earlier sample. At generation time, the model's samples become its inputs, so errors can feed on themselves. Training loss and sampling behavior therefore need separate checks, exactly as section 5 argued for the n-gram model.

## 7. Training through time: what gradients can reach

**Plain version.** Unrolling the recurrence turns the model into a very deep network with tied weights. Gradients from a prediction must travel back through every intermediate step to reach the token that should have influenced it. Over long distances they tend to shrink to almost nothing or, less often, blow up.

Backpropagation through time (BPTT) applies ordinary backpropagation to the unrolled graph and sums the gradient contributions for each shared weight [8]. The sensitivity of a later state to an earlier one is an ordered product of one-step Jacobians:

$$
\frac{\partial \mathbf h_t}{\partial \mathbf h_s}=\prod_{k=s+1}^{t}\operatorname{diag}\!\big(1-\mathbf h_k^{2}\big)\,W_h ,
$$

where $s\lt t$ are positions, $\mathbf h_k^2$ squares each element, and $\operatorname{diag}(\cdot)$ builds a diagonal matrix from the $\tanh$ derivatives. When the factors are typically smaller than one in norm, the product decays exponentially with distance $t-s$ (vanishing gradients); when they are larger, it can grow exponentially (exploding gradients). Bengio, Simard and Frasconi analyzed why learning long-term dependencies with gradient descent is hard [9]; Pascanu, Mikolov and Bengio revisited the problem and popularized clipping the gradient norm as the remedy for explosions [10]. ML 03A derives these results in full and measures them.

What does this mean for language? Return to the agreement example from section 5: in `the robots near the cabinet are`, the verb depends on `robots`, four words back, and the intervening noun points the other way. A plain RNN *can* represent a state that remembers the plural subject, but the training signal that would teach it to do so must survive the trip from `are` back to `robots`. At the word level that is a few steps; at the character level the same dependency spans roughly twenty steps. A model can therefore have enough capacity for a dependency and still fail to learn it, which is a different failure from the n-gram's architectural ceiling.

## 8. Gated cells: LSTM and GRU

**Plain version.** Gated cells add a memory path that is updated mainly by addition and controlled by learned switches. Information, and gradient, can then pass across many steps without being squashed at every one.

The long short-term memory (LSTM) cell of Hochreiter and Schmidhuber [11], with the forget gate added by Gers, Schmidhuber and Cummins [12], keeps a cell state $\mathbf c_t$ next to the hidden state:

$$
\mathbf c_t=\mathbf f_t\odot\mathbf c_{t-1}+\mathbf i_t\odot\tilde{\mathbf c}_t,\qquad
\mathbf h_t=\mathbf o_t\odot\tanh(\mathbf c_t).
$$

Here $\mathbf f_t$, $\mathbf i_t$ and $\mathbf o_t$ are the forget, input and output gates (vectors in $(0,1)^m$ computed by sigmoid layers from the current input and $\mathbf h_{t-1}$), $\tilde{\mathbf c}_t$ is a $\tanh$ candidate computed the same way, and $\odot$ is element-wise multiplication. Along the cell path, $\partial\mathbf c_t/\partial\mathbf c_{t-1}$ is approximately $\operatorname{diag}(\mathbf f_t)$: no weight matrix, no squashing. When a forget gate stays near one, a value written at the plural subject can survive until the verb.

The gated recurrent unit (GRU) of Cho and colleagues [13] merges cell and hidden state and uses two gates:

$$
\mathbf h_t=\mathbf z_t\odot\mathbf h_{t-1}+(1-\mathbf z_t)\odot\tilde{\mathbf h}_t,
$$

where $\mathbf z_t\in(0,1)^m$ is the update gate and $\tilde{\mathbf h}_t$ is a candidate state computed with a reset gate. (Some sources swap the roles of $\mathbf z_t$ and $1-\mathbf z_t$.) The full gate equations, a from-scratch LSTM step checked against PyTorch, and parameter counts are in ML 03A. For language modeling the practical summary is: LSTMs and GRUs train far more reliably than plain $\tanh$ RNNs, neither dominates the other across tasks, and gating eases rather than removes the difficulty of very long dependencies.

## 9. Stacked and bidirectional recurrent networks

**Plain version.** Recurrent layers can be stacked so that a higher layer reads the state sequence of the layer below. Running a second network right to left gives each position a view of its future too, which is useful for labeling text but forbidden for predicting the next token.

A **stacked** (deep) RNN feeds $\mathbf h^{(\ell)}_1,\ldots,\mathbf h^{(\ell)}_T$ from layer $\ell$ as the input sequence of layer $\ell+1$, and the softmax reads the top layer. Two to four layers are common in recurrent language models; dropout between layers is the usual regularizer [16].

A **bidirectional** RNN runs one network forward and one backward and concatenates their states, $\mathbf h_t=[\overrightarrow{\mathbf h}_t;\overleftarrow{\mathbf h}_t]$ [14]. The backward state at position $t$ has read $x_{t+1},\ldots,x_T$. That is ideal for tagging, where the whole sentence is given and the label of a word may depend on words to its right; it is the main encoder of [NLP 06](/en/learn/nlp/sequence-labeling/). It is *wrong* for a left-to-right language model: if the state used to predict $x_t$ has seen $x_t$, the loss rewards copying and the perplexity becomes meaningless. A useful sanity check for any language model is that changing a future token leaves every earlier prediction unchanged.

## 10. Character-level language models

**Plain version.** The prediction unit can be a character instead of a word. The vocabulary becomes tiny and no spelling is ever unknown, but sequences become several times longer and the model must learn spelling before it can learn grammar.

Character-level RNNs were popular demonstrations of what recurrent networks learn; Graves showed that LSTMs trained on characters can generate long, locally coherent text and handwriting [15]. The tradeoffs compared with word or subword units are concrete:

| Choice | Vocabulary | Unknown inputs | Sequence length | Long-range cost |
| --- | --- | --- | --- | --- |
| Words | Large; rare words need an unknown marker | Mapped to one marker; spelling lost | Shortest | Fewest steps between related words |
| Subwords (NLP 01) | Medium, fixed by the tokenizer | Split into known pieces | Medium | Medium |
| Characters | Tiny alphabet | Any spelling over the alphabet | Longest | Many steps between related words |

Two cautions follow from the evaluation rules in section 4. First, character perplexity and word perplexity have different units; a character model with perplexity 11 is not "better" than a word model with perplexity 3.6, because each counts a different number of predictions over a different alphabet. To compare across units, convert both to total negative log likelihood (or bits) for the same raw text. Second, a fixed character alphabet still needs a policy for symbols outside it, such as accented letters or emoji. Decide it before looking at held-out text.

## 11. Sampling and temperature

**Plain version.** A trained model gives a probability for every next token. To generate, we draw one, append it, and repeat. A temperature setting makes the draw more cautious or more adventurous without retraining.

For logits $\mathbf z_t$ and temperature $\tau\gt0$, sample from

$$
q_\tau(v)=\frac{\exp(z_{t,v}/\tau)}{\sum_{u\in V}\exp(z_{t,u}/\tau)}.
$$

Here $v$ and $u$ range over the vocabulary $V$, $z_{t,v}$ is the model's score for $v$ at step $t$, and $q_\tau$ is the sampling distribution. $\tau=1$ samples from the model's own distribution; $\tau\to0$ approaches greedy selection of the highest-scoring token; $\tau\gt1$ flattens the distribution and gives more weight to unlikely tokens. Temperature changes only the generation procedure. It does not change the probabilities used to compute perplexity, so a model's held-out score is the same at every temperature.

Generation adds stopping rules, length limits and search strategies such as beam search and nucleus sampling. Those belong to [NLP 08](/en/learn/nlp/seq2seq-transformers/) and [NLP 09](/en/learn/nlp/language-modeling-transformers/). One warning applies already: a sample is a single random trajectory. Judge a model by held-out likelihood and task checks, and use samples to look for qualitative failure patterns, not to rank models.

## 12. Practical training, then a complete experiment

### The training checklist

**Plain version.** Most failed recurrent language models fail for mundane reasons: padding counted as text, gradients that explode, states leaking between unrelated documents, or a model selected on the test set. Each has a standard remedy.

- **Packing a corpus into streams.** For a continuous text, cut the token stream into $B$ equal parallel streams and lay them out as a $B\times n$ matrix. Each training step reads the next $T$ columns. Every position is a real token, so no padding is needed. Stream $b$ continues exactly where it stopped in the previous window.
- **Padding and masking.** When examples are separate sentences of different lengths, pad them to a common length and keep a Boolean mask. The mask must remove padded positions from the loss (otherwise the model is rewarded for predicting padding) and, for bidirectional encoders, from the state updates; PyTorch's `pack_padded_sequence` does the latter. NLP 06 implements both in a tagger.
- **Truncated BPTT.** Backpropagating through thousands of steps costs memory linear in the length. Instead, carry the hidden state from one window of $T$ steps to the next but *detach* it, so the forward pass still sees the whole past while gradients flow back at most $T$ steps.
- **Gradient clipping.** If the gradient norm $\lVert\mathbf g\rVert$ exceeds a threshold $\kappa$, rescale it to $\kappa\,\mathbf g/\lVert\mathbf g\rVert$ [10]. This keeps the update direction and caps its length.
- **Regularization and early stopping.** Dropout on non-recurrent connections [16] and weight decay limit memorization; select the epoch with the lowest *validation* perplexity, then report test perplexity once.
- **Fair baselines.** Melis, Dyer and Blunsom found that carefully tuned standard LSTMs outperformed several more elaborate recent architectures once all were given comparable hyperparameter search [17]. The same principle applies at small scale: tune the n-gram baseline on the same validation data before claiming that the neural model wins.

### Code: a character-level LSTM against an interpolated n-gram

The text is the opening of Chapter I of Lewis Carroll's *Alice's Adventures in Wonderland* (1865), which is in the public domain; it was copied from Project Gutenberg eBook #11 [24] with italic underscores removed, curly quotes straightened and em dashes written as `--`, then lowercased. Paragraphs 1–7 are training data, paragraph 8 is validation and paragraph 9 is the test set. The alphabet is fixed in advance, before the held-out text is inspected. Both models condition each held-out character on all earlier text. The n-gram baseline interpolates smoothed unigram, bigram and trigram character distributions exactly as in section 3, with weights and smoothing chosen on validation. The LSTM is trained three times with different seeds, because a single run on so little data can mislead. The whole script runs on a CPU in well under a minute and downloads nothing.

```python
from torch import nn

    ' it written up somewhere."',

paras = [p.lower() for p in PARAGRAPHS]
train = "\n".join(paras[:7]) + "\n"     # paragraphs 1-7: fit parameters
valid = paras[7] + "\n"                 # paragraph 8: choose settings
test = paras[8] + "\n"                  # paragraph 9: report once
ALPHABET = "\n !\"'(),-.:;?abcdefghijklmnopqrstuvwxyz"  # fixed in advance
V = len(ALPHABET)
assert set(train + valid + test) <= set(ALPHABET)
print("characters train/valid/test:", len(train), len(valid), len(test))
print("letters never seen in training:", sorted(set(valid + test) - set(train)))

# ---- Baseline: interpolated character n-grams (orders 1-3) ----
def count(order):
    rows = defaultdict(Counter)
    for t in range(len(train)):
        rows[train[max(0, t - order + 1):t]][train[t]] += 1
    return rows

tables = {k: count(k) for k in (1, 2, 3)}

def p_add(k, history, ch, alpha):
    row = tables[k].get(history[len(history) - k + 1:] if k > 1 else "", {})
    return (row.get(ch, 0) + alpha) / (sum(row.values()) + alpha * V)

def ngram_ppl(prefix, target, lams, alpha):
    full, nll = prefix + target, 0.0
    for pos in range(len(prefix), len(full)):
        h = full[max(0, pos - 2):pos]
        p = sum(l * p_add(k, h, full[pos], alpha) for k, l in zip((1, 2, 3), lams))
        nll -= math.log(p)
    return math.exp(nll / len(target))

grid = [(l1, l2, round(1 - l1 - l2, 2)) for l1 in (0.1, 0.2, 0.3)
        for l2 in (0.2, 0.3, 0.4, 0.5) if l1 + l2 < 1]
best_cfg = min(((ngram_ppl(train, valid, lams, a), lams, a) for lams in grid
                for a in (0.01, 0.1, 0.5)), key=lambda r: r[0])
ng_valid, ng_lams, ng_alpha = best_cfg
ng_test = ngram_ppl(train + valid, test, ng_lams, ng_alpha)
print(f"n-gram  weights={ng_lams} alpha={ng_alpha}  "
      f"valid PPL={ng_valid:.2f}  test PPL={ng_test:.2f}")

tri_alpha = min((0.01, 0.1, 0.5), key=lambda a: ngram_ppl(train, valid, (0, 0, 1), a))
tri_test = ngram_ppl(train + valid, test, (0, 0, 1), tri_alpha)
print(f"trigram only  alpha={tri_alpha}  test PPL={tri_test:.2f}")

# ---- Character-level LSTM language model ----
stoi = {c: i for i, c in enumerate(ALPHABET)}
encode = lambda s: torch.tensor([stoi[c] for c in s])

class CharLSTM(nn.Module):
    def __init__(self, vocab, emb=24, hidden=96, dropout=0.3):
        super().__init__()
        self.emb = nn.Embedding(vocab, emb)
        self.rnn = nn.LSTM(emb, hidden, batch_first=True)
        self.drop = nn.Dropout(dropout)
        self.out = nn.Linear(hidden, vocab)

    def forward(self, x, state=None):
        h, state = self.rnn(self.emb(x), state)
        return self.out(self.drop(h)), state

def lstm_ppl(model, prefix, target):
    model.eval()
    with torch.no_grad():
        ids = encode(prefix + target).unsqueeze(0)
        logits, _ = model(ids[:, :-1])          # condition on all earlier text
        nll = nn.functional.cross_entropy(logits[0, len(prefix) - 1:],
                                          ids[0, len(prefix):])
    model.train()
    return math.exp(nll.item())

def train_lstm(seed, epochs=80, B=16, T=48):
    torch.manual_seed(seed)
    model = CharLSTM(V)
    opt = torch.optim.Adam(model.parameters(), lr=3e-3, weight_decay=1e-4)
    ids = encode(train)
    n = (len(ids) - 1) // B                     # B parallel streams of n characters
    X, Y = ids[:n * B].view(B, n), ids[1:n * B + 1].view(B, n)  # targets shifted by one
    history, best = [], (float("inf"), None, 0)
    for epoch in range(1, epochs + 1):
        state, total, steps = None, 0.0, 0
        for i in range(0, n, T):
            if state is not None:               # truncated BPTT: keep values, cut graph
                state = tuple(s.detach() for s in state)
            logits, state = model(X[:, i:i + T], state)
            loss = nn.functional.cross_entropy(logits.reshape(-1, V),
                                               Y[:, i:i + T].reshape(-1))
            opt.zero_grad()
            loss.backward()
            nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            opt.step()
            total, steps = total + loss.item(), steps + 1
        v = lstm_ppl(model, train, valid)
        history.append((epoch, math.exp(total / steps), v))
        if v < best[0]:                         # early stopping on validation only
            best = (v, copy.deepcopy(model.state_dict()), epoch)
    model.load_state_dict(best[1])
    return model, best, history

runs = {}
for seed in (0, 1, 2):
    m, best, hist = train_lstm(seed)
    runs[seed] = (m, hist, lstm_ppl(m, train + valid, test))
    print(f"LSTM seed={seed}  best epoch={best[2]}  valid PPL={best[0]:.2f}  "
          f"test PPL={runs[seed][2]:.2f}")
mean_test = sum(r[2] for r in runs.values()) / len(runs)
print(f"LSTM mean test PPL over 3 seeds: {mean_test:.2f}")
assert mean_test < tri_test
model = runs[0][0]

# ---- Sampling at several temperatures ----
def sample(prompt, tau, length=80, seed=1):
    g = torch.Generator().manual_seed(seed)
    model.eval()
    with torch.no_grad():
        logits, state = model(encode(prompt).unsqueeze(0))
        out = prompt
        for _ in range(length):
            probs = torch.softmax(logits[0, -1] / tau, dim=-1)
            nxt = torch.multinomial(probs, 1, generator=g)
            out += ALPHABET[nxt.item()]
            logits, state = model(nxt.view(1, 1), state)
    return out.replace("\n", " / ")

for tau in (0.5, 1.0, 1.5):
    print(f"tau={tau}:", sample("alice ", tau))

# ---- Same last two characters, different earlier context ----
def next_dist(prefix):
    model.eval()
    with torch.no_grad():
        logits, _ = model(encode(prefix).unsqueeze(0))
    return torch.softmax(logits[0, -1], dim=-1)

a, b = "alice was beginning to get ", "the rabbit-hole went "
assert a[-2:] == b[-2:]                     # a trigram sees only these two
def ngram_dist(prefix):
    return torch.tensor([sum(l * p_add(k, prefix[-2:], c, ng_alpha)
                             for k, l in zip((1, 2, 3), ng_lams)) for c in ALPHABET])

tv = lambda p, q: 0.5 * (p - q).abs().sum().item()
print("total variation, n-gram:", round(tv(ngram_dist(a), ngram_dist(b)), 3),
      " LSTM:", round(tv(next_dist(a), next_dist(b)), 3))
```

### Reading the results

**The baseline matters.** A single trigram with additive smoothing reaches a test perplexity of 13.37, and every LSTM run beats it. The interpolated n-gram, tuned on the same validation paragraph, reaches 11.24, while the three LSTM runs reach 12.09, 11.05 and 11.30 (mean 11.48). On 2,633 training characters the recurrent model is roughly level with a well-smoothed count model and clearly better than a poorly smoothed one. This is the small-data version of the point made by Melis and colleagues [17]: an improvement claimed against an untuned baseline may vanish against a tuned one. Neural language models pull ahead as data grows, because shared representations can exploit many weak regularities that sparse tables cannot pool; Jozefowicz and colleagues document how far recurrent language models improved with large corpora and models [19]. Our experiment is far too small to show that regime, and it does not need to: it shows how to make the comparison honestly.

**Seeds matter.** The spread across seeds (11.05 to 12.09) is larger than the gap between the mean LSTM and the n-gram. With one seed, we could have reported either "the LSTM wins" or "the LSTM loses". Report several runs, or a confidence interval over held-out documents, whenever differences are this small.

**The validation curve shows memorization.** In Figure 4, training perplexity keeps falling far below the validation value. The model is learning the specific training paragraphs. Early stopping picks epochs 39–43; without it, the final epoch would be considerably worse on held-out text.

**Units.** These are per-character perplexities over a 39-symbol alphabet; $\log_2 11.24\approx3.49$ bits per character for the n-gram. They cannot be compared with the word-level values of section 3 (for example 3.573), which count different events over a different vocabulary.

**The memory ceiling, measured.** The final lines compare next-character distributions after `alice was beginning to get ` and `the rabbit-hole went `, two prefixes whose last two characters agree. The interpolated trigram must give identical distributions (total variation 0.0), exactly as section 5 proved. The LSTM's distributions differ (total variation 0.197), because its state depends on the earlier characters. This confirms that the recurrent model *uses* longer context. Whether it uses it *well* is a separate question, which held-out perplexity and targeted tests answer.

**Samples.** At $\tau=0.5$ the sample repeats frequent fragments such as `she was` and `of the`; at $\tau=1.0$ word shapes appear with many misspellings; at $\tau=1.5$ the output breaks into rare punctuation and random letters. A character model trained on fewer than three thousand characters has learned frequent letter sequences, spaces and some short words. It has not learned English. These are single draws with one seed, so read them as illustrations of the temperature effect rather than as quality estimates.

## Modern view

**Survey perspective.** Jurafsky and Martin's August 2026 draft retains a dedicated n-gram chapter, organized around probabilistic prediction, estimation, evaluation, generation and smoothing [3]. It is a useful conceptual bridge: readers can inspect local counts before encountering models that share learned representations. Chen and Goodman's smoothing comparison explains why the estimator matters in addition to the history length [4]. These sources serve different purposes: the textbook develops the model, while the empirical study compares ways to allocate probability with sparse evidence. Tiezzi and colleagues' 2024 survey reviews why recurrent processing has returned in the Transformer era [20]. It frames two trends under one umbrella of recurrence: models that mix Transformer and recurrent ideas to avoid the quadratic cost of self-attention, and deep state-space models that act as a special class of linear RNNs. Its main open problem is learning from streams whose length is not known in advance, which connects sequence modeling to lifelong online learning.

**What recurrent language models achieved.** From Mikolov's RNN language model [7] to large-scale LSTM language models [19] and carefully regularized LSTMs [18], recurrent networks were the strongest general-purpose language models until Transformers replaced them for most large-scale work. Merity and colleagues' AWD-LSTM study shows how much of that strength came from regularization and optimization choices rather than from new cell designs [18]; Melis and colleagues reached a similar conclusion through controlled hyperparameter search [17].

**2023–2026.** Recurrence has returned in new forms aimed at the cost of attention over long contexts. RWKV reformulates a Transformer-like model so it can be trained in parallel and run as an RNN at inference [21]. Mamba uses input-dependent (selective) state-space updates computed with a parallel scan [22]. xLSTM revisits the LSTM with exponential gating and new memory structures [23]. These models keep the property that made RNN language models attractive: a fixed-size state, so generation cost per token does not grow with context length. They also inherit the question raised in section 7: a fixed-size state must decide what to forget. ML 03A covers the state-space side in more detail.

**Evaluation.** Chang and colleagues' 2024 survey organizes large-language-model evaluation around what, where and how to evaluate [5]. It covers task behavior and evaluation methods beyond token prediction. Applied here, a lower perplexity should be accompanied by the task checks that matter: spelling recovery, agreement, meaning preservation or an appropriate stopping rule. The practical role of an n-gram baseline in a 2023–2026 workflow is to make a question measurable. Does a more elaborate model improve held-out predictions under the same tokenization? Does it distinguish two prefixes that the chosen n-gram history must merge? Does its added memory and latency improve the downstream result? Answer with matched experiments rather than comparing unmatched scores or assuming that a longer context is always used effectively.

**Open problems.** Open problems include sparse evidence after domain changes, probabilities for new names, and interactions between tokenization and measured difficulty. Character or subword tokens change the tradeoff between vocabulary coverage and sequence length. Longer histories, whether held in a table or in a recurrent state, offer more information but create harder estimation and credit-assignment problems. Choose the prediction unit and retained history together, and state their limits before interpreting a result.

## Key takeaways

- An n-gram occurrence or document feature is not automatically a normalized language model; order $n$ uses $n-1$ preceding tokens, while the chain rule itself does not require limited memory.
- Smoothing protects unobserved events, and interpolation reuses shorter-history evidence; neither can recover history that the model discarded.
- Perplexity comparisons need matching prediction units, unknown mapping and boundary conventions; character and word perplexities are not comparable.
- A recurrent language model replaces the count table with a learned state that depends on the whole prefix, with parameters shared across positions.
- BPTT gradients shrink or grow with distance; clipping handles explosions, and LSTM or GRU gating eases vanishing gradients without removing the difficulty of long dependencies.
- Bidirectional RNNs suit labeling, not left-to-right language modeling.
- Practical training needs shifted targets, masks or packed streams, truncated BPTT, clipping, regularization and validation-based early stopping.
- On tiny data, a tuned interpolated n-gram can match an LSTM; compare against tuned baselines and report several seeds.

## Paper guides

These optional guides connect the chapter to original papers. Read the challenge and figure first, then unfold the method, evidence and limitations.

### Seq2Seq — Sequence to Sequence Learning with Neural Networks

#### Challenge

A recurrent tagger can emit one label per input token, but translation may reorder words and produce a different number of tokens. Sutskever, Vinyals and Le show that an encoder and a separate decoder can learn such variable-length mappings [25]. Their thesis is that deep LSTMs, trained on suitable sequence arrangements, can translate through a fixed-dimensional sentence representation. Read this chapter's recurrent state, LSTM gates and teacher forcing first.

#### Method

<Figure src={paperSeq2seq} alt="Original recurrent encoder reading ABC and decoder generating WXYZ and an end token" caption="Source: Sutskever et al., NeurIPS 2014 author manuscript, Figure 1, PDF p. 2. The input and output can have different lengths. The end token separates encoding from generation and later ends the output; the experimental models reverse source order, not target order. [25]" />

The encoder consumes the source and passes its final representation to a decoder. The decoder predicts a distribution over the next target token, then continues until an end-of-sequence token. The probability of a target sequence factors as

$$
p(y\mid x)=\prod_{t=1}^{T'}p(y_t\mid v,y_{<t}),\qquad v=\operatorname{Encoder}(x).
$$

Here $x$ is the source sequence, $v$ its fixed-dimensional encoder representation, $y$ the target sequence including its end token, $T'$ the target length, and $y_{<t}$ the earlier target tokens. Each factor is the decoder's next-token probability. Training maximizes this probability using the known target prefix; inference must use previously generated tokens instead.

Read Figure 1 from left to right: the input updates a recurrent state, then output generation reuses the accumulated information. The actual system uses distinct encoder and decoder LSTMs and four recurrent layers. Reversing only the source brings many corresponding source–target words closer along the computation path. It does not remove recurrence or give the decoder direct access to every source state. Beam search retains several partial hypotheses but remains an approximate search.

#### Results

Table 1 evaluates WMT'14 English→French on ntst14. A five-model reversed-input ensemble with beam size 12 obtains 34.81 BLEU, compared with the reported phrase-based baseline's 33.30. This is an ensemble result, not a single LSTM score. Table 2's 36.5 instead comes from rescoring the baseline's 1000-best candidates with an ensemble. Candidate rescoring and generating translations from scratch are different tasks and must not share one unlabeled “best score.”

#### Ablations

The single forward-input LSTM scores 26.17 BLEU and the single reversed-input LSTM 30.59, both with beam size 12 in Table 1. This directly supports the importance of sequence arrangement in that training setup. Increasing ensemble size and changing beam width have separate effects: the five-model ensemble scores 33.00 with beam 1 and 34.50 with beam 2. Do not attribute all of the final gain to reversal or assume a wider beam always yields a proportionate benefit.

#### Conclusion

The central abstraction is conditional sequence generation: an encoder summarizes one sequence and a decoder unfolds another. Trace where information about the first input word must travel before the first output is predicted. Then read the [Bahdanau guide in NLP 08](/en/learn/nlp/seq2seq-transformers/papers/bahdanau-attention--jointly-learning-to-align-and-translate/) to see how attention gives the decoder repeated access to source representations.

#### Problems

A fixed representation can lose details, especially as inputs grow or differ from training examples. Source reversal eases some dependencies; it does not eliminate the bottleneck. Training with correct prefixes differs from inference with imperfect generated prefixes. Vocabulary limits, approximate decoding and data-specific word order also constrain the reported results. This paper establishes a useful architecture, not a guarantee that arbitrary long sequences can be faithfully compressed.
