## The big picture

**Natural language processing (NLP)** builds systems that work with human language: finding documents, labeling a complaint, recognizing names, translating, answering a question or generating a response. These tasks share representations, but they need different outputs and different evaluation.

A vision model receives pixels; a text model receives a sequence of discrete symbols. Both can use embeddings, attention and shared pretrained representations, which is why so much of the machinery in the [ML track](/en/learn/ml/ml-04-vision-transformers/) carries over. Language brings its own difficulties: one word can have several meanings, changing word order can reverse a statement, and a perfectly fluent sentence can assert something false.

<Callout type="tip" title="Explain like I'm five">
A language model plays a guessing game: after "please open the", what comes next? "Door" is a good guess, "banana" is a bad one. It learns which continuations are likely from lots of examples. To play, it first has to chop text into pieces it knows (tokens) and turn each piece into a list of numbers (an embedding). A helpful assistant needs more than the guessing game, though: it must also follow the request, find the right information and check that its answer is actually supported.
</Callout>

Always start with a task definition. "Understand reviews" could mean classifying sentiment, extracting product defects or summarizing common complaints. Write down the expected input, output and acceptable errors before choosing a model.

## Text as data

**Plain version.** A computer stores text as a sequence of character codes. Before a model can use it, we must decide what the units are and give each unit a number. Those decisions are part of the model.

McRoy's data-structure view is useful here [39]: a string, token sequence, annotation table, tree and graph answer different questions. A string preserves what the user wrote. A token sequence chooses units for computation. An annotation table attaches labels to spans. A syntax tree records grouping, while a relation graph records links between entities or events. Converting everything immediately into one dense vector loses the interfaces needed to explain an extraction or align a translation.

Language also has several levels. **Morphology** concerns meaningful pieces within words, such as a plural ending. **Syntax** concerns combinations and dependencies. **Semantics** concerns what is asserted, questioned or referred to. **Pragmatics** concerns what a speaker intends in a setting. **Discourse** concerns connections across sentences and turns. These are useful distinctions rather than a promise that every application needs a separate module for every level.

Consider the invented message “Can you move it to Friday?” Tokenization reveals words, but “it” needs conversational context; “Friday” needs a reference date; and the grammatical question probably expresses a request. A classifier may label the message as rescheduling while still being unable to carry out the change. Separate recognition from execution. A structured output can record the intent, unresolved referent, candidate date and evidence spans before another component asks for the missing detail.

An annotation contract states the unit being labeled, the permitted labels, boundary rules, treatment of ambiguous cases and the evidence that annotators may inspect. For sentiment, does the label describe the speaker's opinion, the mentioned product or the whole message? “The delivery was awful but the camera is excellent” has different answers under those definitions. Ambiguity in the task specification can produce disagreement that additional model capacity cannot repair.

### Characters, Unicode and normalization

Text is stored as Unicode code points, encoded as bytes (usually UTF-8, where one code point takes one to four bytes). A visible character can contain several code points, so character counts, code-point counts and byte counts need not agree. The same visible string can have more than one representation; for example, an accented letter can be one precomposed code point or a base letter plus a combining accent. **Unicode normalization** (such as NFC) maps canonically equivalent forms to a common form under the Unicode specification [42]. Other normalization choices are modeling decisions with costs:

- Lowercasing merges "Apple" (company) and "apple" (fruit), and "US" and "us".
- Removing punctuation erases question marks, decimal points and emoticons.
- Stripping accents changes meaning in many languages.

Keep the original text, document every transformation, and for a pretrained model use exactly the normalization it was trained with.

### Tokens, types and vocabularies

A **token** is one occurrence in a sequence; a **type** is a distinct vocabulary entry. The string "a cat and a dog" has five whitespace tokens and four types. A **token ID** is an index into the vocabulary: it is a name, not a quantity, so ID 7 is not "more" than ID 3.

Whitespace splitting is a useful teaching baseline for English, but punctuation, contractions, code, URLs and languages written without spaces need more care. Chinese text cannot generally be segmented into words by splitting on spaces, and even deciding where a "word" ends is a linguistic question with more than one answer. This is one reason modern systems learn their units from data.

## Tokenization: words, characters and subwords

**Plain version.** Whole words make the vocabulary huge and leave new words unknown. Single characters make sequences very long. Subwords sit in between: common words stay whole, rare words are spelled out from smaller reusable pieces.

### The open-vocabulary problem

With a word vocabulary, every word not seen in training becomes a single unknown token such as `<unk>`, which loses all information about it. A character or byte vocabulary never has unknowns, but makes sequences several times longer, and attention cost grows quickly with length. Mielke et al. review this trade-off from pre-neural to neural methods and conclude that there is no single solution for all applications [5].

### Byte-pair encoding (BPE)

Sennrich et al. adapted **byte-pair encoding** to neural machine translation so that rare and unseen words could be represented as sequences of subword units [2]. Training is a greedy loop:

1. Start with a vocabulary of single characters, with an end-of-word marker so merges respect word boundaries.
2. Count every adjacent symbol pair in the corpus, weighted by word frequency.
3. Merge the most frequent pair into a new symbol, and add it to the vocabulary.
4. Repeat until the vocabulary reaches the desired size.

To tokenize new text, apply the learned merges in the order they were learned.

```python
from collections import Counter

corpus = ("low low low low low lower lower newest newest newest newest newest "
          "newest widest widest widest").split()
# Start from characters; "_" marks the end of a word so merges respect boundaries.
words = Counter(tuple(w) + ("_",) for w in corpus)

def pair_counts(words):
    pairs = Counter()
    for symbols, freq in words.items():
        for a, b in zip(symbols, symbols[1:]):
            pairs[a, b] += freq
    return pairs

def merge(words, pair):
    out = Counter()
    for symbols, freq in words.items():
        s, i = [], 0
        while i < len(symbols):
            if i + 1 < len(symbols) and (symbols[i], symbols[i + 1]) == pair:
                s.append(symbols[i] + symbols[i + 1]); i += 2
            else:
                s.append(symbols[i]); i += 1
        out[tuple(s)] += freq
    return out

merges = []
for step in range(10):
    pairs = pair_counts(words)
    best = max(pairs, key=lambda p: (pairs[p], p))   # most frequent; ties broken by symbol order
    merges.append(best)
    words = merge(words, best)
print("merges:", [a + b for a, b in merges])

def tokenize(word):                   # apply the learned merges in order
    symbols = list(word) + ["_"]
    for pair in merges:
        symbols = list(merge(Counter({tuple(symbols): 1}), pair))[0]
    return symbols

for w in ["lowest", "newer", "wider"]:
    print(w, "->", tokenize(w))
```

Output:

```text
merges: ['t_', 'st_', 'est_', 'ow', 'low', 'west_', 'ne', 'newest_', 'low_', 'wi']
lowest -> ('low', 'est_')
newer -> ('ne', 'w', 'e', 'r', '_')
wider -> ('wi', 'd', 'e', 'r', '_')
```

The word "lowest" never occurs in the corpus, yet it is represented by two meaningful pieces, `low` and the suffix `est_`. "newer" and "wider" fall back to smaller pieces because their endings were never frequent enough to merge. No word is ever unknown, because single characters are always in the vocabulary. Production tokenizers often run BPE over **bytes** instead of characters, so that any input, including emoji and unseen scripts, can be encoded with a fixed base vocabulary of 256 symbols.

### WordPiece

**WordPiece** was introduced by Schuster and Nakajima for Japanese and Korean voice search [3] and became widely known through Google's neural machine translation system, which divided words into a limited set of common sub-word units ("wordpieces") to handle rare words [4]. WordPiece grows its vocabulary with merges like BPE, but instead of the most frequent pair it picks the pair with the highest score $\mathrm{freq}(ab)/\bigl(\mathrm{freq}(a)\,\mathrm{freq}(b)\bigr)$, which favors pairs whose parts rarely appear apart; and it keeps only the final vocabulary, not an ordered list of merges [37]. A piece that continues a word is written with a `##` prefix, so "unbelievable" might appear as `un`, `##believ`, `##able` [37]. BERT's released models use a WordPiece vocabulary [16].

### Unigram language model and SentencePiece

Kudo's **unigram language model** tokenizer works in the opposite direction: start from a large candidate vocabulary, assign each piece a probability, and repeatedly remove the pieces whose loss hurts the corpus likelihood least [6]. Because it defines a probability for every possible segmentation, it can also *sample* different segmentations of the same word during training, a regularizer Kudo called **subword regularization** [6]. **SentencePiece** is a library that trains BPE or unigram models directly from raw text, treating whitespace as an ordinary symbol (displayed as `▁`) so that no language-specific pre-tokenizer is needed and the original text can be recovered exactly [7].

Toolkits such as Hugging Face Tokenizers organize the whole process as a pipeline of normalization, pre-tokenization, the subword model and post-processing (for example adding special tokens such as a classification token) [8].

**Practical rules.** For a pretrained model, always load its own tokenizer and special-token conventions; replacing the tokenizer while keeping the embedding table changes what every ID means. When training a new tokenizer, fit it on the training partition only. Token counts differ between languages for the same content, which affects both cost and the context length available.

## Word embeddings

**Plain version.** Give every word a short list of numbers so that words used in similar contexts get similar lists. "You shall know a word by the company it keeps": cats and kittens both drink milk and chase things, so their vectors end up close.

### From one-hot vectors to dense vectors

A **one-hot** vector for word $i$ has length $|V|$ (the vocabulary size) with a single 1 in position $i$. Every pair of distinct one-hot vectors is equally far apart, so they encode no similarity. An **embedding table** $E\in\mathbb R^{|V|\times d}$ replaces token ID $i$ with its row $E_i$, a dense vector of dimension $d$ (typically hundreds). Multiplying a one-hot vector by $E$ selects that row, which is why an embedding layer is just a lookup.

### Counting contexts: PPMI and SVD

The **distributional** approach builds vectors from co-occurrence counts. Let $C_{wc}$ count how often context word $c$ appears within a small window around word $w$. **Pointwise mutual information** compares this with what independence would predict:

$$
\mathrm{PMI}(w,c)=\log\frac{P(w,c)}{P(w)\,P(c)},\qquad
\mathrm{PPMI}(w,c)=\max\bigl(\mathrm{PMI}(w,c),0\bigr),
$$

where $P(w,c)=C_{wc}/\sum C$ and $P(w)$, $P(c)$ are the corresponding marginals. Positive PMI (PPMI) keeps only associations stronger than chance. A truncated singular value decomposition of the PPMI matrix then yields dense vectors.

```python
import numpy as np

sentences = """the cat drinks milk . the dog drinks water . a cat chases a mouse .
a dog chases a cat . the kitten drinks milk . the puppy drinks water .
a kitten chases a ball . a puppy chases a ball . the car needs fuel .
the truck needs fuel . a car drives on the road . a truck drives on the road .""".split(".")
tokens = [s.split() for s in sentences if s.strip()]
vocab = sorted({w for s in tokens for w in s})
idx = {w: i for i, w in enumerate(vocab)}

# 1) Co-occurrence counts within a +-2 word window.
C = np.zeros((len(vocab), len(vocab)))
for s in tokens:
    for i, w in enumerate(s):
        for j in range(max(0, i - 2), min(len(s), i + 3)):
            if j != i:
                C[idx[w], idx[s[j]]] += 1

# 2) Positive pointwise mutual information.
total = C.sum()
pw, pc = C.sum(1, keepdims=True) / total, C.sum(0, keepdims=True) / total
with np.errstate(divide="ignore"):
    pmi = np.log((C / total) / (pw * pc))
ppmi = np.maximum(pmi, 0)

# 3) Truncated SVD gives dense 8-dimensional embeddings.
U, S, _ = np.linalg.svd(ppmi)
E = U[:, :8] * S[:8]
E /= np.linalg.norm(E, axis=1, keepdims=True)

def nearest(word, k=3):
    sims = E @ E[idx[word]]
    order = [vocab[i] for i in np.argsort(-sims) if vocab[i] != word]
    return [(w, round(float(sims[idx[w]]), 2)) for w in order[:k]]

for w in ["cat", "puppy", "truck", "milk"]:
    print(w, "->", nearest(w))
```

Output:

```text
cat -> [('kitten', 0.96), ('puppy', 0.88), ('dog', 0.88)]
puppy -> [('dog', 1.0), ('kitten', 0.98), ('cat', 0.88)]
truck -> [('car', 1.0), ('needs', 0.6), ('the', 0.47)]
milk -> [('water', 0.97), ('a', 0.62), ('chases', 0.51)]
```

Animals cluster with animals and vehicles with vehicles, learned from twelve sentences and no labels. Note "milk" and "water" are nearly identical: both are things that are drunk in this corpus. Embedding similarity measures **shared contexts**, which often but not always matches similar meaning; antonyms such as "hot" and "cold" also share contexts.

### word2vec and GloVe

Mikolov et al. made embedding learning fast enough for billions of words with simple log-linear models: **CBOW** predicts a word from its context and **skip-gram** predicts context words from a word [9]. The follow-up paper introduced **negative sampling** and subsampling of frequent words [10]. For a word $w$ and an observed context word $c$, skip-gram with negative sampling maximizes

$$
\log\sigma\bigl(\mathbf u_c^\top\mathbf v_w\bigr)+\sum_{k=1}^{K}\mathbb E_{c_k\sim P_n}\Bigl[\log\sigma\bigl(-\mathbf u_{c_k}^\top\mathbf v_w\bigr)\Bigr],
$$

where $\mathbf v_w$ is the word's input vector, $\mathbf u_c$ the context's output vector, $\sigma$ the logistic sigmoid, and $c_1,\dots,c_K$ are $K$ "negative" words drawn from a noise distribution $P_n$. The model learns to tell real (word, context) pairs from random ones.

Pennington et al.'s **GloVe** fits vectors directly to global co-occurrence counts $X_{ij}$ with a weighted least-squares objective [11]:

$$
J=\sum_{i,j}f(X_{ij})\bigl(\mathbf w_i^\top\tilde{\mathbf w}_j+b_i+\tilde b_j-\log X_{ij}\bigr)^2,
$$

where $\mathbf w_i,\tilde{\mathbf w}_j$ are word and context vectors, $b_i,\tilde b_j$ biases, and $f$ a weighting function that limits the influence of very rare and very frequent pairs. Count-based (PPMI–SVD, GloVe) and prediction-based (word2vec) methods turn out to be closely related; both factorize a matrix of co-occurrence statistics in different ways.

**fastText** extended skip-gram by representing each word as a bag of character $n$-grams, so vectors can be built for words never seen in training [12].

### Static versus contextual

A **static** embedding gives "bank" the same vector in "river bank" and "bank account". **Contextual** representations compute a different vector for each occurrence from its sentence. ELMo produced such vectors from the internal states of a deep bidirectional language model and improved six NLP tasks when added to existing models [13]. Every model in the rest of this chapter is contextual.

## Language models

**Plain version.** A language model assigns a probability to a sequence by predicting one token at a time from the tokens before it.

### The chain rule and n-grams

For tokens $w_1,\ldots,w_T$, the chain rule of probability gives

$$
p(w_1,\ldots,w_T)=\prod_{t=1}^{T}p(w_t\mid w_1,\ldots,w_{t-1}).
$$

This identity is exact. An **n-gram** model approximates the history by its last $n-1$ tokens; a **bigram** model ($n=2$) uses only the previous token. A start marker `<s>` serves as context for the first word, and an end marker `</s>` is predicted to represent the sentence boundary.

Let $c(h,w)$ count how often $w$ follows context $h$ in training, and let $V$ be the prediction vocabulary. The maximum-likelihood estimate $c(h,w)/\sum_v c(h,v)$ assigns probability zero to any unseen pair, and a single zero makes the whole sentence impossible. **Additive smoothing** with $\alpha>0$ fixes this:

$$
p(w\mid h)=\frac{c(h,w)+\alpha}{\sum_{v\in V}c(h,v)+\alpha|V|}.
$$

Additive smoothing is intentionally simple; better smoothing methods (interpolation and back-off with lower-order models) and neural models share statistical strength more effectively.

### Code: train, score and sample a bigram model

This complete example needs no downloads or GPU. The corpus is invented for teaching; its test sentences are separate from training. Every test word absent from the training vocabulary maps to the same unknown token.

```python
from collections import Counter, defaultdict
import math
import random

train = [
    "the cat sleeps", "the dog sleeps", "the cat runs",
    "the dog runs", "a cat eats", "a dog eats",
    "the bird sings", "a bird sleeps",
]
test = ["the cat eats", "a dog runs", "the bird sleeps", "a robot runs"]
START, END, UNK = "<s>", "</s>", "<unk>"
words = {w for sentence in train for w in sentence.split()}
vocab = sorted(words | {END, UNK})       # START is context, never predicted
alpha = 0.2
counts = defaultdict(Counter)
unigrams = Counter()

def encode(sentence):
    return [w if w in words else UNK for w in sentence.split()] + [END]

for sentence in train:
    tokens = [START] + encode(sentence)
    for h, w in zip(tokens, tokens[1:]):
        counts[h][w] += 1
        unigrams[w] += 1

def bigram(h, w):
    row = counts.get(h, {})
    return (row.get(w, 0) + alpha) / (sum(row.values()) + alpha * len(vocab))

def unigram(h, w):
    return (unigrams[w] + alpha) / (sum(unigrams.values()) + alpha * len(vocab))

def perplexity(sentences, probability):
    nll, n = 0.0, 0
    for sentence in sentences:
        tokens = [START] + encode(sentence)
        for h, w in zip(tokens, tokens[1:]):
            nll -= math.log(probability(h, w))
            n += 1
    return math.exp(nll / n)

for h in [START] + vocab:
    assert abs(sum(bigram(h, w) for w in vocab) - 1) < 1e-10
print("unigram test perplexity:", round(perplexity(test, unigram), 3))
print("bigram test perplexity:", round(perplexity(test, bigram), 3))
assert UNK in encode(test[-1])

rng = random.Random(7)
h, sample = START, []
for _ in range(20):                     # cap length for this demonstration
    w = rng.choices(vocab, weights=[bigram(h, v) for v in vocab])[0]
    if w == END:
        break
    sample.append(w)
    h = w
print("sample:", " ".join(sample))
```

Output:

```text
unigram test perplexity: 10.382
bigram test perplexity: 3.573
sample: a bird sings
```

The assertions check that every conditional distribution sums to one and that "robot" maps to the unknown token. The bigram model is far less "surprised" by the test sentences than the unigram model, because word order carries information. Sampling can still produce awkward strings: positive probability is not a guarantee of grammaticality. The length cap only stops the demonstration; it does not change the probabilities used for scoring.

### Loss and perplexity

For $N$ predicted tokens (here including the end markers), the average negative log-likelihood and **perplexity** are

$$
\mathcal L=-\frac1N\sum_{i=1}^{N}\log p(w_i\mid h_i),
\qquad
\operatorname{PPL}=\exp(\mathcal L),
$$

where $h_i$ is the context of the $i$-th predicted token. Perplexity is the size of a uniform choice that would be equally surprising: a model that spreads probability evenly over 11 symbols has perplexity 11. Lower perplexity means the model assigned more probability to *this* tokenized test set. It does not measure factual correctness, helpfulness or successful retrieval. Perplexities computed with different tokenizers are not comparable, because the number and kind of predicted events $N$ changes.

### Neural language models

Bengio et al. replaced count tables with a neural network that learns a distributed representation for each word together with the probability function, so unseen word combinations made of similar words can still receive high probability [14]. This "learn the embedding and the predictor together" idea underlies every model below.

## From RNNs to Transformers

**Plain version.** An n-gram model forgets everything beyond a few words. A recurrent network carries a memory along the sentence. Attention lets every word look directly at every other word. The Transformer is built almost entirely from attention.

### Recurrent networks and LSTMs

A **recurrent neural network** (RNN) reads one token embedding $\mathbf x_t$ at a time and updates a hidden state:

$$
\mathbf h_t=\tanh\bigl(W\mathbf h_{t-1}+U\mathbf x_t+\mathbf b\bigr),\qquad
p(w_{t+1}\mid w_{\le t})=\operatorname{softmax}(V\mathbf h_t),
$$

where $W$, $U$, $V$ and $\mathbf b$ are learned. In principle $\mathbf h_t$ summarizes the whole prefix. In practice, gradients through many steps vanish or explode, so plain RNNs struggle with long dependencies. The **long short-term memory** (LSTM) adds a cell state with multiplicative input, forget and output gates that let information and gradients flow over long spans [15]. [ML 03a](/en/learn/ml/ml-03a-recurrent-recursive-networks/) covers these architectures in detail.

### Sequence-to-sequence and attention

Sutskever et al. mapped an input sequence to an output sequence with two LSTMs: an **encoder** compresses the source sentence into a fixed-length vector, and a **decoder** generates the target from it [17]. Bahdanau et al. argued that this fixed-length vector is a bottleneck and let the decoder (soft-)search over all encoder states at every output step [18]. This was **attention**: a learned, input-dependent weighted average of the source representations.

### The Transformer

Vaswani et al. dropped recurrence entirely [19]. Each layer applies **scaled dot-product attention** followed by a position-wise feed-forward network, with residual connections and normalization. For a sequence of $T$ vectors stacked in $X\in\mathbb R^{T\times d}$:

$$
Q=XW_Q,\quad K=XW_K,\quad V=XW_V,\qquad
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\Bigl(\frac{QK^\top}{\sqrt{d_k}}+M\Bigr)V,
$$

where $W_Q,W_K,W_V$ are learned projections, $d_k$ is the key dimension, and $M$ is a **mask** whose entries are $0$ where attention is allowed and $-\infty$ where it is forbidden. Row $t$ of the softmax is a probability distribution saying how much token $t$ reads from every other token. Several such "heads" run in parallel. Because attention ignores order, **positional information** is added to the embeddings. Every position is processed in parallel, which made training on very large corpora practical.

```python
import numpy as np

rng = np.random.default_rng(0)
T, d = 5, 8                                   # 5 tokens, 8-dimensional embeddings
X = rng.normal(size=(T, d))                   # token embeddings (+ positions)
Wq, Wk, Wv = (rng.normal(size=(d, d)) / np.sqrt(d) for _ in range(3))

def attention(X, causal):
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    scores = Q @ K.T / np.sqrt(d)             # (T, T) query-key similarities
    if causal:                                # position t may only look at <= t
        scores = np.where(np.tri(T, dtype=bool), scores, -np.inf)
    w = np.exp(scores - scores.max(axis=1, keepdims=True))
    w /= w.sum(axis=1, keepdims=True)         # softmax over keys
    return w @ V, w

out, w = attention(X, causal=True)
print(np.round(w, 2))

# Changing the LAST token must not change any earlier causal output...
X2 = X.copy(); X2[-1] += 5.0
out2, _ = attention(X2, causal=True)
print("causal: earlier outputs unchanged:", np.allclose(out[:-1], out2[:-1]))
# ...but in a bidirectional encoder every position can see it.
b1, _ = attention(X, causal=False); b2, _ = attention(X2, causal=False)
print("bidirectional: earlier outputs unchanged:", np.allclose(b1[:-1], b2[:-1]))
```

Output:

```text
[[1.   0.   0.   0.   0.  ]
 [0.88 0.12 0.   0.   0.  ]
 [0.42 0.29 0.29 0.   0.  ]
 [0.28 0.24 0.29 0.19 0.  ]
 [0.34 0.06 0.24 0.11 0.26]]
causal: earlier outputs unchanged: True
bidirectional: earlier outputs unchanged: False
```

The causal weights are lower-triangular: the first token can only read itself, the last can read everything. The two checks prove the property that makes next-token training valid: in a causal model, no position can see the future, so all next-token predictions in a sentence can be trained in parallel without cheating.

### Three ways to use a Transformer

- A **causal decoder** predicts the next token from its prefix; it can generate text. GPT models are decoders.
- A **bidirectional encoder** reads left and right context at once; it is suited to understanding tasks such as classification and tagging, but cannot directly generate left to right. BERT is an encoder.
- An **encoder–decoder** encodes a source sequence bidirectionally and generates a target causally, reading the source through **cross-attention**. Translation and summarization fit this pattern; T5 uses it.

## Pretrained language models

**Plain version.** First teach a big model general language skills from huge amounts of unlabeled text, then adapt it to your task with a little labeled data, or simply by describing the task in words.

- **GPT** (Radford et al., 2018) showed that generative pre-training of a Transformer language model on unlabeled text, followed by discriminative fine-tuning on each task, gave large gains on language-understanding benchmarks [20].
- **BERT** (Devlin et al.) pretrains a deep bidirectional encoder with a **masked language model** objective: some input tokens are hidden or replaced, and the model predicts the original tokens from both sides of the context. Adding one output layer and fine-tuning gave new state-of-the-art results on eleven tasks [16]. A masked LM does not assign a normalized left-to-right probability to whole sentences; it is a representation learner.
- **T5** (Raffel et al.) casts every task, including classification, as text-to-text generation with an encoder–decoder, and systematically compares pre-training objectives, architectures, data sets and transfer approaches [21].
- **GPT-3** (Brown et al.) scaled an autoregressive model to 175 billion parameters and showed that it can often perform new tasks **few-shot**, from a handful of examples placed in the prompt and without any gradient updates [22]. Kaplan et al. had found that language-model loss falls as a power law in model size, data and compute over many orders of magnitude [23].
- **Instruction following.** Ouyang et al. fine-tuned GPT-3 on labeler-written demonstrations and then with reinforcement learning from human rankings of outputs (RLHF), producing InstructGPT; in human evaluations, outputs of the 1.3B-parameter InstructGPT were preferred to those of the 175B GPT-3 [24]. Preference is not a certificate of factual correctness.
- **Retrieval-augmented generation** (RAG) supplies selected external passages to a generator, so answers can draw on documents that change after training [25]. Retrieval can still return irrelevant or outdated text, and a generator may ignore it, so check retrieval coverage and whether each final claim is supported by the cited passage.

Adaptation options trade data, compute and control: a frozen encoder with a small classifier, full fine-tuning, parameter-efficient adapters (covered in [ML 09](/en/learn/ml/ml-09-foundation-models/)), and prompting without any parameter update.

### A classical baseline you should always run

Many text tasks do not need generation at all. Bag-of-words or **TF–IDF** features with logistic regression are a fast CPU baseline: each document becomes a sparse vector of weighted word counts, and a linear classifier predicts $p(y\mid x)$. The TF–IDF weight of term $t$ in document $d$ is

$$
\operatorname{tfidf}(t,d)=\operatorname{tf}(t,d)\cdot\log\frac{N}{\operatorname{df}(t)},
$$

where $\operatorname{tf}(t,d)$ counts $t$ in $d$, $N$ is the number of training documents and $\operatorname{df}(t)$ the number containing $t$ (libraries add smoothing and normalization). Bag-of-words loses order, which matters for negation.

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline

train = [
    ("the battery is good", 1), ("good screen and good sound", 1),
    ("the camera is great", 1), ("great value , works well", 1),
    ("the battery is not good", 0), ("not great , the screen broke", 0),
    ("the sound is bad", 0), ("bad camera and bad battery", 0),
    ("works well , not bad at all", 1), ("not good , not worth it", 0),
]
test = ["the screen is not good", "the sound is not bad", "great battery"]
texts, labels = zip(*train)

for name, ngrams in [("unigrams", (1, 1)), ("uni+bigrams", (1, 2))]:
    clf = make_pipeline(TfidfVectorizer(ngram_range=ngrams, token_pattern=r"\S+"),
                        LogisticRegression(C=10.0))
    clf.fit(texts, labels)                    # vocabulary + IDF fitted on train only
    probs = clf.predict_proba(test)[:, 1]
    print(f"{name:12s}", [f"{t!r}: {p:.2f}" for t, p in zip(test, probs)])
```

Output (probability of a positive review):

```text
unigrams     ["'the screen is not good': 0.43", "'the sound is not bad': 0.11", "'great battery': 0.61"]
uni+bigrams  ["'the screen is not good': 0.20", "'the sound is not bad': 0.18", "'great battery': 0.56"]
```

Adding bigram features lets the model learn that "not good" is negative, so that test sentence drops from 0.43 to 0.20. But "not bad" is still judged negative: it appears only once in training, too rarely to outweigh "bad". Local n-grams patch some order effects; contextual models learn them from far more data. On real tasks, a well-tuned TF–IDF baseline is sometimes surprisingly hard to beat and always cheap to run.

## Evaluating NLP systems

**Plain version.** Measure the task you actually care about, on data the model has never seen, with the same protocol for every system.

### Splits and leakage

Related emails, duplicated articles and messages from one conversation can leak across a random split. Split by document family, conversation, author or time when that matches deployment. Fit vocabularies, TF–IDF statistics and tokenizers on training data only, and record dataset versions and deduplication rules ([ML 10](/en/learn/ml/ml-10-evaluation-deployment/) treats leakage and confidence intervals in depth). For web-scale pretrained models, an additional risk is **contamination**: public test sets may have appeared in the pretraining data.

### Metrics by task

| Task | Useful measurements | An error to inspect |
|---|---|---|
| Classification | Macro-F1, per-class recall, calibration | Rare categories collapsed into the majority |
| Entity extraction | Span-level precision and recall | Correct entity words with wrong boundaries |
| Language modeling | Held-out log-loss/perplexity under one tokenizer | Poor rare-word coverage or leaked context |
| Translation, summarization | BLEU, ROUGE, plus human judgment | Valid paraphrases scored as errors |
| Retrieval | Recall at a cutoff, ranking metrics | The supporting passage never reaches the generator |
| Open-ended generation | Task correctness, evidence support, abstention | Fluent but unsupported assertions |

**BLEU** compares a candidate translation with reference translations through modified $n$-gram precisions $p_n$ (each candidate $n$-gram counted at most as often as it appears in a reference) [26]:

$$
\mathrm{BLEU}=\mathrm{BP}\cdot\exp\Bigl(\sum_{n=1}^{N}w_n\log p_n\Bigr),\qquad
\mathrm{BP}=\begin{cases}1,&c\gt r\\ e^{\,1-r/c},&c\le r\end{cases}
$$

where $w_n$ are weights (usually $1/N$ with $N=4$), $c$ is the candidate length and $r$ the reference length; the brevity penalty BP stops very short outputs from scoring high precision. **ROUGE** is a family of recall-oriented overlap measures for summarization, such as ROUGE-N ($n$-gram recall against references) and ROUGE-L (longest common subsequence) [27]. Both reward surface overlap: a correct paraphrase can score low, and a fluent sentence with one wrong fact can score high.

**Benchmarks** bundle tasks. GLUE collected diverse existing natural-language-understanding tasks, some with very little training data, plus a hand-crafted diagnostic test suite, to encourage models that share knowledge across tasks [28]. For large language models, Chang et al. organize evaluation around what to evaluate, where (which benchmarks) and how (automatic metrics versus human judgment) [32]. Whatever the metric, define a human-evaluation rubric before looking at system outputs, record which evaluators saw which examples, and report latency, memory and truncation of long inputs alongside quality.

## Language meets vision

**Plain version.** The same Transformer that reads word tokens can read image patches. Train a text model and an image model to agree on which caption goes with which picture, and you get a shared space where words and images can be compared. Connect an image encoder to a language model, and you get an assistant that can talk about pictures.

- **Images as tokens.** The Vision Transformer splits an image into fixed-size patches, embeds each patch like a word, and applies a standard Transformer encoder; with large-scale pretraining it matched strong convolutional networks [29]. [ML 04](/en/learn/ml/ml-04-vision-transformers/) develops this in detail.
- **Contrastive image–text learning.** CLIP trains an image encoder and a text encoder on 400 million image–caption pairs to predict which caption goes with which image, and transfers zero-shot to new classification tasks by comparing an image with text prompts such as "a photo of a dog" [30]. For a batch of $B$ pairs with normalized embeddings $\mathbf i_k$ and $\mathbf t_k$, the loss is a symmetric cross-entropy over the similarity matrix $S_{jk}=\mathbf i_j^\top\mathbf t_k/\tau$ with temperature $\tau$:

$$
\mathcal L=-\frac1{2B}\sum_{k=1}^{B}\Bigl[\log\frac{e^{S_{kk}}}{\sum_j e^{S_{kj}}}+\log\frac{e^{S_{kk}}}{\sum_j e^{S_{jk}}}\Bigr].
$$

Here $\mathcal L$ is the contrastive loss, $B$ is the number of paired examples, $k$ indexes a matching pair, $j$ indexes candidate matches, $S_{jk}$ is the image–text similarity score, $\mathbf i_j$ and $\mathbf t_k$ are normalized image and text vectors, $\tau>0$ is the temperature, and $e$ is the exponential base.

- **Vision–language assistants.** LLaVA connects a pretrained vision encoder to a large language model and instruction-tunes the combination on multimodal instruction-following data generated with a language-only model [31]. [ML 09](/en/learn/ml/ml-09-foundation-models/) places these models among other foundation models.
- **Shared factorization.** Text generation and image generation by next-token prediction use exactly the same chain rule as the bigram model above, applied to different tokens; see [ML 08](/en/learn/ml/ml-08-autoregressive-vision/).

The practical consequence for a vision practitioner is that tokenization, embeddings, masks, pretraining objectives and evaluation pitfalls learned here apply directly to image and video models on the rest of this site, including the [deep-learning track](/en/learn/deep-learning/dl-01-deep-learning-for-image-processing/).

## Modern view

**Surveys.** Mielke et al. trace the history of open-vocabulary modeling and tokenization, from word-level models through hybrids of words and characters to learned subword segmentation and byte-level processing, and argue that no single granularity suits all applications [5]. Qiu et al. survey pre-trained models for NLP with a taxonomy along four perspectives and discuss how to adapt them to downstream tasks [33]. Bommasani et al. introduced the term **foundation models** for models trained on broad data at scale and adaptable to many tasks, and analyzed their capabilities, technical principles, applications and societal risks [34]. Zhao et al.'s continually updated survey of large language models is organized around pre-training, adaptation tuning, utilization and capacity evaluation [35]. Minaee et al. review prominent LLM families (GPT, LLaMA, PaLM), techniques to build and augment LLMs, datasets and evaluation metrics [36]. Chang et al. survey LLM evaluation by what, where and how to evaluate [32].

**State of the field, 2023–2026.** The dominant recipe is a large decoder-only Transformer pretrained on next-token prediction over web-scale text, followed by instruction tuning and preference-based post-training, often combined with retrieval [22], [24], [25], [35], [36]. Subword tokenizers (BPE or unigram, frequently byte-level) remain standard [5]. Models increasingly accept images and other modalities through encoders connected to the language model [30], [31]. Scaling studies guide how compute is split between model size and data [23].

**Multilingual pipelines.** Liu and Fu organize their 2024 survey around development, deployment, applications and societal impact [40]. This extends the application viewpoint beyond an English-only training set: audit language coverage, preprocessing and serving behavior together. Wang et al.'s 2024 multilingual safety study provides an empirical reason to evaluate each supported language independently [41]. A translated instruction does not establish that a model has the same behavior in both languages.

**Open problems.**

- *Factuality and grounding.* Fluent output can be unsupported; measuring and enforcing evidence support remains difficult.
- *Evaluation.* Contamination of public benchmarks, sensitivity to prompt wording, and the cost and reliability of human judgment all complicate comparisons [32].
- *Tokenization.* Token counts differ across languages and scripts, which affects cost, context length and fairness; character- and byte-level alternatives trade this against sequence length [5].
- *Efficiency.* Attention cost grows with sequence length; long documents and long conversations strain memory and latency.
- *Low-resource languages.* Most data, benchmarks and tools still focus on a few high-resource languages.

## Key takeaways

- Tokenization and normalization define the prediction problem; a pretrained model must always be used with its own tokenizer.
- Subword tokenizers (BPE, WordPiece, unigram/SentencePiece) give an open vocabulary with manageable sequence lengths.
- Embeddings place words used in similar contexts close together; static vectors cannot separate senses, contextual models can.
- A language model factorizes a sequence probability by the chain rule; perplexity measures fit to a tokenized test set, not truth or usefulness.
- RNNs carry memory step by step; attention lets every token read every other token; the mask decides what is allowed, which is what separates GPT-style decoders from BERT-style encoders.
- Pretraining plus adaptation (fine-tuning, prompting, instruction tuning, retrieval) is the modern recipe, but a TF–IDF baseline is still worth running.
- Overlap metrics such as BLEU and ROUGE are useful but blind to paraphrase and factual errors; evaluate the task you need on clean, leak-free splits.
- The same tokens-embeddings-attention machinery powers ViT, CLIP and vision–language assistants, linking this track to the rest of the site.
