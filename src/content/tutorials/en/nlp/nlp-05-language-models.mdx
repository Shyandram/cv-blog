## The big picture

A language model assigns probabilities to text under a specified context. That simple definition connects spelling completion, sentence generation and reusable contextual representations, but these uses do not share the same output contract. Predicting a likely continuation is different from verifying a factual answer. A fluent continuation may reflect common text patterns while being unsuitable for a particular task.

Hagiwara develops language modeling in Chapter 5, attention and Transformers in Chapter 8, and pretrained-model adaptation in Chapter 9 [1]. McRoy's Chapter 6 emphasizes language-model evaluation through tasks, including grammaticality, sentiment, similarity and inference [2]. This chapter connects the probability model to those practical evaluations. We train only a tiny synthetic model; large pretrained systems are discussed through verified primary papers and surveys.

<Callout type="tip" title="Explain like I'm five">
Imagine a guessing game where you see the beginning of a sentence and guess the next word. A causal model can look only at the words already shown. A masked-word exercise lets you see words on both sides of a hidden word. Both teach patterns, but seeing the answer later in the sentence would be cheating in the first game.
</Callout>

Three decisions organize the subject. The training objective determines what is predicted. The attention pattern determines which input positions are visible. The deployment procedure determines how predictions become user-facing output. Keep these separate when comparing models. A change in sampling temperature changes the output distribution; it does not change which facts were learned or verify the resulting claim.

## Causal sequence probability

**Plain version.** A sequence probability can be built by predicting each token from earlier tokens. The complete sequence is available during training, but each prediction must still obey that visibility rule.

Using the probability chain rule:

$$
p_\theta(x_1,\ldots,x_T)=\prod_{t=1}^{T}p_\theta(x_t\mid x_{\lt t}).
$$

Here $x_t$ is the token at position $t$; $T$ is the sequence length; $x_{\lt t}$ is the prefix before $t$; and $\theta$ denotes model parameters. A beginning token can supply an explicit context for the first ordinary token, and an end token lets the model assign probability to stopping. The chain rule is exact; the learned conditional distributions are approximations to the data-generating process.

For a corpus with $N$ supervised token positions, the mean negative log likelihood is:

$$
\mathcal L_{\mathrm{causal}}=-\frac{1}{N}\sum_{n=1}^{N}\log p_\theta(x_n\mid c_n).
$$

Here $\mathcal L_{\mathrm{causal}}$ is the training objective; $n$ indexes valid prediction positions across examples; $x_n$ is the target token; $c_n$ is its allowed prefix; and $N$ excludes padding and any other positions intentionally left unsupervised. Natural logarithms express this loss in nats per token. A batch average that includes padding changes the objective and can reward predicting artificial padding symbols.

Teacher forcing uses the observed prefix when predicting each training token. It permits parallel evaluation of all positions when the architecture enforces a causal mask. At generation time, the prefix contains earlier generated tokens instead. Errors can then affect later predictions. The training objective and rollout behavior therefore require separate diagnostics, even when the same model weights are used.

Shift the input and target by one position. If the full sequence is beginning, the, robot, moves, end, the model input is beginning, the, robot, moves and the targets are the, robot, moves, end. Predicting each input token from its own unshifted representation would create a shortcut unrelated to next-token prediction. The code below makes the shift explicit.

## Masked and conditional objectives

**Plain version.** Not every pretrained language model predicts the next token. A masked objective uses surrounding context, while a conditional generator predicts an output sequence from a separate input.

BERT's masked language objective hides selected input positions and predicts their original tokens using bidirectional context [3]. A simplified description is:

$$
\mathcal L_{\mathrm{mask}}=-\frac{1}{|M|}\sum_{i\in M}\log p_\theta(x_i\mid\widetilde{\mathbf x}).
$$

Here $M$ is the set of supervised masked positions; $|M|$ is its size; $x_i$ is the original token; and $\widetilde{\mathbf x}$ is the corrupted input sequence. The tilde indicates corruption, not an independently sampled document. This expression describes the masked prediction component; it does not reproduce every detail of the original BERT training procedure.

A masked predictor is useful for contextual representations, classification and span-oriented tasks. Its loss is not automatically the log probability of an ordinary left-to-right sequence. Multiplying predictions that each use both sides of the sentence does not generally yield the same normalized joint distribution as a causal factorization. Consequently, masked-objective scores and causal perplexities are not directly interchangeable.

Conditional sequence generation instead writes:

$$
p_\theta(\mathbf y\mid\mathbf x)=\prod_{t=1}^{U}p_\theta(y_t\mid y_{\lt t},\mathbf x).
$$

Here $\mathbf x$ is the source sequence; $\mathbf y$ is the target sequence; $U$ is target length including any end token; and $y_{\lt t}$ is the target prefix. The source can be visible in full while the target remains causal. T5 organizes many NLP tasks in a text-to-text framework and studies transfer learning with a Transformer encoder–decoder [4].

These distinctions guide model choice. A sentence classifier may use a bidirectional encoder because the complete sentence is available. A streaming continuation must exclude future output tokens. Translation can use the entire source after it arrives, but simultaneous translation needs a more restrictive source visibility contract. The task's available information should determine the mask, rather than choosing a mask because a particular model name is familiar.

## Context representations and position

**Plain version.** Attention compares token representations, and position information tells it where those tokens occur. A token's identity alone does not say whether it is the subject or the final word.

For a learned embedding and position table:

$$
\mathbf h_i^{(0)}=E[x_i]+P[i].
$$

Here $\mathbf h_i^{(0)}\in\mathbb R^d$ is the initial representation at position $i$; $E$ is a token embedding table; $E[x_i]$ selects the row for token $x_i$; $P$ is a learned position table; $P[i]$ selects the position row; and $d$ is representation width. The example uses this simple learned-position design. Other positional designs exist, but the code does not need them to demonstrate causal prediction.

A learned position table also imposes a maximum supported position. Giving a sequence beyond that range is not an ordinary longer input; it is an invalid lookup. Record context limits in the serving contract. Extending the table or changing positional behavior is a model change that should be evaluated, rather than assumed to preserve performance on longer documents.

Contextual representations are computed from token and position inputs through the network. The same token can therefore have different representations in different sentences. This supports reuse across tasks, but reuse requires the matching tokenizer, vocabulary and preprocessing rules. An embedding row has meaning only relative to the model's token IDs. Swapping in a different tokenizer without adapting weights can turn apparently valid numbers into unrelated symbols.

## Scaled dot-product attention

**Plain version.** Each position asks which other positions contain useful information. Attention converts those comparisons into weights and combines the corresponding value vectors.

For one attention head:

$$
Q=HW_Q,\quad K=HW_K,\quad V=HW_V,\qquad
A=\operatorname{softmax}_{\mathrm{row}}\left(\frac{QK^\top}{\sqrt{d_k}}+B\right),\quad O=AV.
$$

Here $H\in\mathbb R^{T\times d}$ contains input representations; $W_Q,W_K\in\mathbb R^{d\times d_k}$ are learned query and key projections; $W_V\in\mathbb R^{d\times d_v}$ is the value projection; $Q,K,V$ are projected matrices; $d_k$ and $d_v$ are key and value widths; $B\in\mathbb R^{T\times T}$ is an additive visibility mask; $A$ contains row-normalized attention weights; and $O\in\mathbb R^{T\times d_v}$ is the output. The softmax is applied separately to each query row. This is the mechanism introduced in the Transformer paper [5].

For causal self-attention, $B_{ij}=0$ when $j\leq i$ and $B_{ij}=-\infty$ otherwise. Here $i$ is the query position and $j$ is the candidate key position. With shifted targets, the current input position is an allowed prefix token, so the diagonal remains visible. A fully bidirectional self-attention layer permits every real input position, although padding can still be blocked.

<Figure src={maskFig} alt="Causal attention permits a triangular set of token positions while bidirectional attention permits all real tokens" caption="Figure 1 — Visibility is part of the task definition. Rows are querying positions and columns are the positions they may read." />

The scale factor prevents dot products from growing simply because the key vector has more dimensions under common initialization assumptions. It does not turn attention weights into calibrated semantic importance. A large weight indicates a large contribution within this computation, after learned projections. It is not a proof that the attended token caused the final answer or supports the generated statement.

Multi-head attention performs several learned projections and combines their outputs. The original Transformer also uses residual connections, normalization and position-wise feedforward layers [5]. Our tiny model keeps one head and one block to make shapes inspectable. It preserves the central visibility and residual mechanisms without claiming to match a production language model's architecture or training recipe.

Direct attention score storage grows quadratically with sequence length. Specialized implementations can avoid materializing every intermediate matrix, but the modeling question remains which positions need to interact. For this teaching example the sequence is tiny, so clarity matters more than kernel speed. In deployment, benchmark memory and latency under the actual context lengths rather than extrapolating from a short sentence.

## A runnable causal model

**Plain version.** A tiny model can learn a synthetic language pattern and still generalize poorly to unseen combinations. We also test a property that low loss alone cannot establish: future tokens must not influence earlier predictions.

The following standalone CPU example uses invented fixed-length sentences. Train and test sentences differ, while every ordinary vocabulary item is present in training. The code uses no padding, pretrained weights or dataset downloads. It is intentionally a mechanism experiment rather than a language benchmark.

The implementation uses AdamW for optimization [11], the GELU activation in the feedforward block [12], and layer normalization before attention and the feedforward transformation [13]. These choices define this small experiment, rather than reproduce every detail of the original Transformer. Keep them fixed when studying the causal mask so a change in optimization or activation does not confound the comparison.

```python
import math
import torch
from torch import nn
from torch.nn import functional as F

torch.manual_seed(11)
torch.set_num_threads(1)
train_text = [
    'the red robot moves', 'the blue robot waits',
    'a red sensor waits', 'a blue sensor moves',
    'the red sensor moves', 'a blue robot waits',
]
test_text = ['a red robot moves', 'the blue sensor waits']
vocab = ['<bos>', '<eos>'] + sorted(set(' '.join(train_text).split()))
index = {word: i for i, word in enumerate(vocab)}
def encode(rows):
    return torch.tensor([[index[w] for w in ['<bos>'] + s.split() + ['<eos>']] for s in rows])
train, test = encode(train_text), encode(test_text)

class TinyCausalModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.token = nn.Embedding(len(vocab), 16)
        self.position = nn.Embedding(5, 16)
        self.norm1, self.norm2 = nn.LayerNorm(16), nn.LayerNorm(16)
        self.q, self.k, self.v = [nn.Linear(16, 16, bias=False) for _ in range(3)]
        self.output = nn.Linear(16, 16)
        self.ff = nn.Sequential(nn.Linear(16, 32), nn.GELU(), nn.Linear(32, 16))
        self.head = nn.Linear(16, len(vocab))
    def forward(self, ids):
        length = ids.shape[1]
        h = self.token(ids) + self.position(torch.arange(length))
        z = self.norm1(h)
        scores = self.q(z) @ self.k(z).transpose(-1, -2) / math.sqrt(16)
        blocked = torch.ones(length, length, dtype=torch.bool).triu(1)
        weights = scores.masked_fill(blocked, float('-inf')).softmax(dim=-1)
        h = h + self.output(weights @ self.v(z))
        h = h + self.ff(self.norm2(h))
        return self.head(h)

model = TinyCausalModel()
optimizer = torch.optim.AdamW(model.parameters(), lr=0.01)
def loss(rows):
    logits = model(rows[:, :-1])
    return F.cross_entropy(logits.reshape(-1, len(vocab)), rows[:, 1:].reshape(-1))
initial = loss(train).item()
for _ in range(180):
    optimizer.zero_grad()
    objective = loss(train)
    objective.backward()
    optimizer.step()
model.eval()
with torch.no_grad():
    train_nll, test_nll = loss(train).item(), loss(test).item()
    original = train[:1, :-1]
    changed = original.clone()
    changed[0, -1] = index['blue']
    gap = (model(original)[:, :-1] - model(changed)[:, :-1]).abs().max().item()
assert train_nll < initial and gap < 1e-6
print('initial/train/test NLL:', *(round(x, 3) for x in [initial, train_nll, test_nll]))
print('held-out perplexity:', round(math.exp(test_nll), 3))
print('future-token perturbation gap:', gap)
```

The initial, final training and held-out losses are printed by your run. The assertion checks that training loss decreases; it does not require held-out loss to improve by any specified amount. The held-out sentences combine familiar words in combinations excluded from training. A large train–test gap demonstrates that learning the observed patterns does not establish compositional generalization.

The future-token perturbation test changes the final input token and compares all earlier logits. Causal attention should make that change invisible to earlier predictions. This test targets the exact visibility contract. Passing it does not establish every form of data isolation: duplicated documents across splits, vocabulary construction from forbidden test data or future metadata can still create other leakage.

The model has no dropout, so evaluation mode does not alter a stochastic layer here. We call it explicitly because the training/evaluation distinction is essential in realistic models. The loss function flattens batch and position dimensions while retaining vocabulary as the class dimension. If those axes are accidentally exchanged, a program can run while optimizing the wrong prediction problem.

Each sequence has the same length, and the position table covers the five model-input positions. These details remove padding and truncation from the toy experiment. Extending to variable-length data requires separate attention and loss masks. An attention mask controls what representations may read; a loss mask controls which target positions contribute to the objective. They solve different problems and should be tested independently.

## Perplexity and meaningful comparison

**Plain version.** Perplexity summarizes held-out token prediction. Its value depends on what counts as a token and which positions are evaluated.

For mean negative log likelihood $\mathcal L$:

$$
\mathrm{PPL}=\exp(\mathcal L).
$$

Here $\mathrm{PPL}$ is perplexity and $\exp$ is the natural exponential; $\mathcal L$ uses natural logarithms over the same evaluated token positions. Lower perplexity means that the model assigns higher average probability to observed tokens under that evaluation contract. It is not a direct measure of factual correctness, helpfulness or grammaticality.

Compare perplexities only under compatible tokenization and input conventions. A word can be one token in one vocabulary and several in another. The mean loss per token then describes a different unit. Also record whether beginning and end markers are scored, how documents are segmented, the context length and whether evaluation windows overlap. Recounting duplicated target positions changes the weighting.

Keep evaluation documents independent of training documents and their derivatives. Splitting adjacent passages of one document across partitions can expose style, facts and nearly identical wording. For a time-dependent application, use an appropriate chronological split and retain the document version. A held-out name or phrase does not by itself prove the surrounding document is independent.

McRoy's benchmark perspective reminds us to assess task behavior in addition to sequence prediction [2]. A classifier needs category performance; an extractor needs spans and supported relations; a generator needs meaning preservation and omissions. A model with lower perplexity can fail a critical task distinction, such as changing “did not move” to “moved.” Match the evaluation to the user's actual outcome.

## Pretraining, adaptation and prompting

**Plain version.** Pretraining learns broad representations or continuation patterns. Adaptation changes behavior for a task; prompting changes the supplied input without necessarily changing weights.

Supervised task adaptation minimizes a task-specific loss over labeled examples. A classifier can attach a head to a pretrained representation; a conditional generator can learn the desired response format. Continued language-model training on domain text changes the distribution modeled, but does not automatically teach the application's label policy. Domain familiarity and task instruction are distinct forms of adaptation.

In-context examples appear inside the input. They can demonstrate format or behavior without updating parameters during that request. Their usefulness depends on selection, ordering and compatibility with the task. Examples that contain private answers or test labels can invalidate evaluation. A prompt that happens to perform well on development cases must still be frozen before the final test.

Low-Rank Adaptation, or LoRA, freezes a base weight matrix and trains a constrained update [6]:

$$
W'=W+BA.
$$

Here $W\in\mathbb R^{m\times n}$ is the frozen matrix; $A\in\mathbb R^{r\times n}$ and $B\in\mathbb R^{m\times r}$ are learned factors; $r$ is the chosen rank; and $W'$ is the effective adapted matrix. This simplified expression omits optional scaling. Fewer trainable parameters can reduce adaptation cost, but do not remove the need for representative labels, data isolation or task evaluation.

Save the base-model version, tokenizer, adaptation weights and configuration together. An adaptation trained against one base checkpoint is not guaranteed to work on another checkpoint with the same family name. For comparison, report which parameters changed and which data were used. “Fine-tuned” alone gives too little information to reproduce the result.

## Instructions and preferences

**Plain version.** Learning to follow a task instruction and learning which response people prefer are related but different training signals. Neither is a direct truth guarantee.

The InstructGPT paper studies supervised instruction examples followed by preference-based training with human feedback [7]. This distinguishes a base continuation model from one adapted toward requested behavior. The source of preferences matters: annotators follow a policy, and that policy may balance helpfulness, formatting and other goals. A preferred response can still contain a factual error.

Direct Preference Optimization, or DPO, uses preferred and rejected responses with a reference policy [8]. A representative objective is:

$$
\mathcal L_{\mathrm{DPO}}
=-\log\sigma\!\left(
\beta\left[
\log\frac{\pi_\theta(y^+\mid x)}{\pi_{\mathrm{ref}}(y^+\mid x)}
-\log\frac{\pi_\theta(y^-\mid x)}{\pi_{\mathrm{ref}}(y^-\mid x)}
\right]\right).
$$

Here $x$ is the prompt; $y^+$ and $y^-$ are the preferred and rejected response sequences; $\pi_\theta$ is the trainable policy; $\pi_{\mathrm{ref}}$ is a fixed reference policy; $\beta$ is a positive scale parameter; $\sigma$ is the logistic sigmoid; and $\mathcal L_{\mathrm{DPO}}$ is the loss for one preference pair. Sequence probabilities are products over response-token conditionals; prompts are context rather than supervised response tokens.

The objective increases the preferred response's relative likelihood compared with the rejected response, measured against the reference. It assumes the preference pair is useful training evidence. If a dataset rewards confident unsupported answers, optimizing the objective can reinforce that behavior. Evaluation should therefore include source support, uncertainty and task-specific failure cases beyond aggregate preference wins.

This equation is a reading aid rather than an invitation to train preference models on the tiny corpus. Small synthetic exercises cannot establish large-model alignment. The lesson is to identify the training signal and its limits. Instruction compliance, preference agreement and factual support are separate properties that need separate evidence.

## Decoding changes the output distribution

**Plain version.** A trained model produces scores. A decoder decides whether to choose the strongest token or sample alternatives.

For logit $z_v$ and positive temperature $\tau$:

$$
q_\tau(v)=\frac{\exp(z_v/\tau)}{\sum_{u\in V}\exp(z_u/\tau)}.
$$

Here $v$ is a candidate token; $V$ is the vocabulary; $u$ indexes candidates in the denominator; $z_v$ is the model's unnormalized score; $\tau$ is temperature; and $q_\tau$ is the resulting sampling distribution. Lower temperature concentrates mass around high-scoring tokens; higher temperature spreads it. Greedy selection chooses a maximum-score token rather than sampling.

<Figure src={temperatureFig} alt="Temperature changes probabilities of four synthetic token candidates without changing their original logits" caption="Figure 2 — Temperature changes a sampling distribution over fixed synthetic logits. More concentrated output is not automatically more correct." />

Generation also needs a stopping policy and a length budget. A model may stop too early or continue with redundant content. These are output errors relative to a task contract. We develop conditional search, summary constraints and translation evaluation in [NLP 08](/en/learn/nlp/nlp-08-generation-deployment/). Here, record the decoding configuration whenever you compare model responses.

Repeated samples can reveal variability, but agreement among samples is not an independent verification of a claim. They share the same model and often the same training biases. A retrieval or tool result can supply external evidence, provided its source and permissions are checked. That connection motivates the next chapter.

## A reproducible language-model experiment

**Plain version.** A result is useful when someone can tell exactly which text, tokens and decisions produced it. Record the experiment as a contract rather than only saving a weight file.

Begin with the document split and its reason. A random split may be suitable for independent synthetic sentences, while a support assistant might require customer-separated or chronological documents. Write down whether vocabulary construction is an allowed use of unlabeled development text. In the toy experiment, the vocabulary comes only from training sentences, and the test combinations were chosen to contain known words. This isolates a narrow combination-generalization question.

Next record the tokenization, sequence boundaries, target shift, maximum context and loss denominator. The code scores every next-token target including the end token, and does not score the beginning token as a target. These small details make the reported perplexity interpretable. If another run excludes stopping predictions or weights each sentence equally regardless of length, its number answers a different question.

Finally separate selection from reporting. Choose architecture, training length and decoding behavior on development data when the goal is a fair final test. The code fixes its short training budget as a teaching demonstration and makes no competitive claim. A production comparison needs a declared selection procedure, repeated runs where instability matters, and a held-out set inspected only after those choices are frozen.

Save enough information to explain a failure: preprocessing version, model configuration, seed, permitted input context and output settings. Keep sensitive raw documents under appropriate access controls rather than copying them into an unrestricted log. A compact record with a document identifier and version can support reproducibility without making every reader a recipient of the underlying text.

## Modern view

**Plain version.** Contemporary language modeling combines pretraining, adaptation, evaluation and system integration. Surveys are useful when they clarify these separate choices rather than compressing everything into one model ranking.

Zhao and colleagues' survey, revised through 2026 and published in Frontiers of Computer Science, organizes large language models through pretraining, adaptation, utilization and capability evaluation [9]. This framework helps distinguish more training data from instruction tuning or a different usage pattern. Chang and colleagues' evaluation survey separates questions about what to evaluate, where to evaluate and how to evaluate [10]. Together they motivate a task-specific evaluation plan rather than relying on a single general score.

Keep the taxonomy distinct from a universal performance claim. A causal decoder, a bidirectional encoder and an encoder–decoder offer different interfaces and information visibility. The original BERT and T5 papers illustrate these alternatives [3, 4]. The appropriate comparison depends on whether the user needs token spans, a class label, a retrieved passage or generated text. A compact specialized model can be a better engineering choice when it satisfies the task with lower latency and simpler review.

Open problems include contamination of evaluation sets, long-context robustness, multilingual coverage, stable uncertainty and the relationship between instruction following and source-grounded correctness. A larger context window permits more input; it does not establish that all relevant parts are used reliably. A longer answer may look complete while omitting the source's crucial qualification.

For practical study, maintain four reports: the sequence-prediction contract, task-level quality, challenge-case errors and resource cost. Keep a final held-out set separate from model selection, prompt selection and decoding selection. When the application changes, revise the contract and evaluation before comparing new checkpoints. The probability model is a powerful component, but the complete language application remains a designed and tested system.

## Key takeaways

- Causal prediction uses earlier tokens; masked prediction can use both sides of selected positions.
- Attention visibility and supervised-loss masking serve different purposes.
- Shift targets explicitly and test that future tokens cannot change earlier logits.
- Perplexity comparisons require compatible tokenization and evaluation positions.
- Pretraining, domain adaptation, task tuning and prompting are distinct operations.
- Preference learning does not replace factual-support evaluation.
- Decoding configuration is part of every reproducible generation result.
