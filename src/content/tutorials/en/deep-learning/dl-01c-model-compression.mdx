## The big picture

A trained network is usually bigger and slower than it needs to be for one particular job on one particular device. **Model compression** is the set of techniques that remove that slack after (or during) training, and **efficient inference** is the engineering that makes the smaller model actually run faster on real hardware. The two are different, and most disappointments in this area come from confusing them.

<Callout type="tip" title="Explain like I'm five">
Imagine moving from a big house into a small flat. You can throw away things you never use (pruning). You can fold your clothes more tightly so the same clothes take less space (quantization). You can ask a friend who already lives in a small flat to show you which few things really matter, and copy their choices (distillation). Or you can buy foldable furniture in the first place (designing a small network). But the removal company charges by the weight of the boxes and the number of trips, not by how neatly you wrote the list. In the same way, a computer cares about how many bytes it must carry and whether it has the right tools to open the boxes, not about how small your model looks on paper.
</Callout>

**Why it matters.** Most deployed vision models run under a budget (a phone camera, a 60-frames-per-second factory line, a battery-powered robot), and compression decides whether a model fits it. It also changes the model: a quantized or pruned network is a different function that can fail where the original did not. Hence one rule for the whole chapter: **measure the cost on the target device and the accuracy after compression, on deployment data**.

## What "cost" means

**Plain version.** "Small" and "fast" each have several meanings. A model with fewer parameters may not use less memory while it runs, and a model with fewer operations may not finish sooner. Before compressing anything, decide which number your budget is about, and measure that number on the device that matters.

### Six numbers that are not the same

Six numbers describe what running a network costs:

- **Parameters** $P$: the number of learned values. With $b$ bits each, the weights take $P\,b/8$ bytes on disk and in memory. Pruning and quantization reduce this.
- **Multiply–accumulates (MACs)** or **FLOPs**: the arithmetic per image. One MAC is one multiplication plus one addition, usually counted as 2 FLOPs; libraries disagree, so state which you report. A $k \times k$ convolution from $C_{\text{in}}$ to $C_{\text{out}}$ channels on an $H' \times W'$ output costs $k^2 C_{\text{in}} C_{\text{out}} H' W'$ MACs ([ML 11](/en/learn/ml/ml-10-evaluation-deployment/#counting-operations)).
- **Memory traffic**: the bytes moved between main memory and the arithmetic units. Weights, input activations and output activations all have to be read or written at least once.
- **Peak memory**: the largest amount of memory alive at one time during a forward pass (weights plus the activations still needed). For high-resolution restoration networks it can be dominated by activations rather than weights.
- **Latency**: wall-clock time for one input, end to end, on the target device. This is what a camera pipeline or a user feels.
- **Throughput**: images per second when many are processed together. Large batches raise throughput but not single-image latency.

Dehghani et al. showed that these cost indicators can disagree and that reporting only one of them can lead to wrong conclusions about which model is more efficient [1]. Compression makes the disagreement worse, because each technique attacks a different number: pruning attacks parameters and MACs, quantization attacks bytes, and neither automatically attacks latency.

### Arithmetic intensity and the roofline

**Plain version.** A chip has two speed limits: how fast it can multiply, and how fast it can fetch numbers from memory. A layer that does a lot of arithmetic on each number it fetches hits the first limit; a layer that fetches a lot and multiplies little hits the second. Shrinking the arithmetic of a layer that is stuck on the second limit does almost nothing.

**Precise version.** The **roofline model** of Williams, Waterman and Patterson [2] bounds the attainable speed of a computation by

$$
\text{attainable speed} = \min\bigl(\pi,\; \beta \cdot I\bigr),
\qquad
I = \frac{\text{operations}}{\text{bytes moved}},
$$

where $\pi$ is the peak arithmetic rate of the device (here in MACs per second), $\beta$ its memory bandwidth (bytes per second) and $I$ the **arithmetic intensity** of the computation (MACs per byte). The intensity at which the two limits meet, $I^\ast = \pi / \beta$, is the **ridge point**: below it the layer is **memory-bound**, above it **compute-bound**. A simple time estimate for one layer is

$$
t \approx \max\!\left(\frac{\text{MACs}}{\pi},\; \frac{\text{bytes}}{\beta}\right).
$$

The snippet applies this to a few layers on a **made-up** accelerator (4 TMAC/s, 100 GB/s; real devices differ), assuming every weight, input and output value crosses memory exactly once. Real kernels reuse caches and overlap transfers, so treat the numbers as an idealized sketch.

```python
# A made-up accelerator: 4 TMAC/s peak compute, 100 GB/s memory bandwidth.
PEAK_MACS, BANDWIDTH = 4e12, 100e9

def layer(kind, C=64, H=56, W=56, batch=1):
    """MACs and bytes moved, if weights, inputs and outputs each cross memory once."""
    if kind == "conv 3x3":
        weights, macs = 9 * C * C, 9 * C * C * H * W
    elif kind == "depthwise 3x3":
        weights, macs = 9 * C, 9 * C * H * W
    elif kind == "pointwise 1x1":
        weights, macs = C * C, C * C * H * W
    elif kind == "linear 2048x2048":
        weights, macs, C, H, W = 2048 * 2048, 2048 * 2048, 2048, 1, 1
    acts = 2 * C * H * W                                  # one input and one output tensor
    return batch * macs, weights + batch * acts

for kind, batch, nbytes in [("conv 3x3", 1, 4), ("depthwise 3x3", 1, 4), ("pointwise 1x1", 1, 4),
                            ("depthwise 3x3", 1, 1), ("linear 2048x2048", 1, 4), ("linear 2048x2048", 64, 4)]:
    macs, values = layer(kind, batch=batch)
    traffic = values * nbytes
    t_compute, t_memory = macs / PEAK_MACS, traffic / BANDWIDTH
    bound = "compute" if t_compute > t_memory else "memory"
    print(f"{kind:17s} batch {batch:2d} {8 * nbytes:2d}-bit: {macs / 1e6:7.1f} M MACs, "
          f"{macs / traffic:5.1f} MACs/byte, ~{max(t_compute, t_memory) * 1e6:6.1f} us ({bound}-bound)")
print(f"ridge point: {PEAK_MACS / BANDWIDTH:.0f} MACs/byte")
```

Three lessons recur later. First, the depthwise layer has 64 times fewer MACs than the dense $3 \times 3$ convolution but is estimated to be only about 1.8 times faster, because it is memory-bound (the arithmetic behind the warning in [DLCV 01B](/en/learn/deep-learning/dl-01b-building-blocks/#bottlenecks-inverted-residuals-and-depthwise-separable-convolutions) that MACs are not latency). Second, storing that layer in 8 bits instead of 32 cuts its estimated time by 4 without changing a single MAC: for memory-bound layers, quantization helps by moving fewer bytes. Third, the batch-64 linear layer does 64 times the work of the batch-1 layer in about the same time, because its weights are read once and reused, so throughput at a large batch says little about latency at batch 1.

### Measuring honestly

Follow the latency protocol in [ML 11](/en/learn/ml/ml-10-evaluation-deployment/#a-latency-protocol) (fixed and reported device, runtime, precision, batch size, resolution and threads; warm-up; percentiles; synchronization on GPUs) and the end-to-end checklist in [DLCV 03A](/en/learn/deep-learning/dl-03a-real-time-detection/#speed-a-measurement-checklist). Compression adds three rules of its own:

1. **Compare against a fair dense baseline**: a dense model of the same size, trained with the same budget. Liu et al. found that, for the structured pruning methods they examined, training the pruned architecture from scratch matched or beat fine-tuning the pruned weights [3]; Blalock et al. reviewed 81 pruning papers and found that inconsistent baselines and metrics made most comparisons impossible [4].
2. **Measure accuracy after export, on the runtime you ship.** The exported, quantized, fused graph is a different numerical program from the one you trained.
3. **Report a trade-off curve, not one point.** Accuracy against latency (and memory) for several compression levels shows whether a method moves the whole curve or just picks a different point on it.

## Pruning

**Plain version.** Many weights of a trained network are close to zero and contribute little. Pruning sets them to exactly zero and removes them. Removing scattered single weights gives the most freedom in what to remove but needs special software to run faster; removing whole channels gives a genuinely smaller network that runs faster anywhere, with less freedom in what to remove.

### What gets removed

Write the parameters of a network as a vector $\boldsymbol\theta \in \mathbb{R}^{N}$. Pruning chooses a binary **mask** $\mathbf{m} \in \{0, 1\}^{N}$ and uses $\mathbf{m} \odot \boldsymbol\theta$ instead of $\boldsymbol\theta$, where $\odot$ is elementwise multiplication. The **sparsity** is the fraction of zeros,

$$
s = 1 - \frac{\lVert \mathbf{m} \rVert_0}{N},
$$

where $\lVert \mathbf{m} \rVert_0$ counts the nonzero entries of the mask. What differs between methods is the **granularity** of the mask:

- **Unstructured** (fine-grained): any single weight may be removed. This gives the most freedom in choosing what to remove, but the result is a dense-shaped tensor full of scattered zeros. Li et al. point out that such irregular sparsity does not reduce the cost of convolutional layers much unless sparse convolution libraries are available [5].
- **Structured** (coarse-grained): whole filters, channels, attention heads or blocks are removed. Removing output channel $j$ of a convolution also removes input channel $j$ of the next layer, so both tensors shrink and stay dense. Li et al. prune whole filters together with their connecting feature maps for exactly this reason: the result runs with ordinary dense matrix libraries [5].
- **Semi-structured**: a fixed small pattern that hardware can exploit. NVIDIA's sparse Tensor Cores support **2:4 sparsity**, in which every group of four consecutive weights has at least two zeros; the paper reports twice the math throughput of the dense units for this pattern [6].

### Which weights: magnitude and other criteria

The simplest and still most common criterion is **magnitude**: remove the weights with the smallest $|\theta_i|$. It can be applied per layer (remove the same fraction of each layer) or globally (one threshold for the whole network; layers with many small weights then lose more). For structured pruning, the magnitude of a group is used instead: Li et al. rank filters by the sum of absolute weights ($\ell_1$ norm) of each filter [5]. **Network slimming** adds an $\ell_1$ penalty on the scale factors $\gamma$ of the batch-normalization layers during training, which pushes the scales of unimportant channels towards zero, and then removes the channels with the smallest $|\gamma|$ [7]. Many other criteria exist (gradient-based, second-order, data-driven); Hoefler et al. survey them [8].

Structured pruning has one trap that unstructured pruning does not: **coupled channels**, such as the channels on both sides of a residual addition, which must be removed together. Fang et al.'s DepGraph finds such groups automatically from the computational graph [9].

### Prune, fine-tune, repeat

Removing weights changes the function, so pruning is followed by training. Han et al. described the standard three-step recipe: train the network to learn which connections are important, prune the unimportant ones, and retrain the remaining weights; on ImageNet they reported reducing AlexNet's parameters from 61 million to 6.7 million and VGG-16's from 138 million to 10.3 million without accuracy loss [10]. Their Deep Compression pipeline added quantization and Huffman coding on top of pruning [11].

Pruning is often spread over several smaller steps, each followed by some training, instead of one large cut. Zhu and Gupta's **gradual** schedule raises the sparsity from zero to its target during training, quickly at first and more slowly near the end [12]. They also compared large-sparse models with small-dense models of the same memory footprint and found the large-sparse ones consistently more accurate across the architectures they tested [12].

### Code: unstructured and structured pruning of a small MLP

The snippet trains a 64–256–128–10 MLP on scikit-learn's digits, then prunes it in two ways: by removing the smallest weights in every layer, and by removing whole hidden units (the smallest $\ell_1$ norm of incoming weights, in both hidden layers). Each pruned model is fine-tuned for 10 epochs, re-applying the mask after every optimizer step. At the end, the most heavily pruned structured model is sliced into a genuinely smaller dense network.

```python
import copy, warnings
import numpy as np
from sklearn.datasets import load_digits
from sklearn.exceptions import ConvergenceWarning
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier
warnings.filterwarnings("ignore", category=ConvergenceWarning)

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X / 16.0, y, test_size=0.3, random_state=0, stratify=y)
base = MLPClassifier(hidden_layer_sizes=(256, 128), max_iter=300, random_state=0).fit(Xtr, ytr)
print(f"dense: {sum(w.size for w in base.coefs_)} weights, test accuracy {base.score(Xte, yte):.3f}")

def fine_tune(net, masks, epochs=10):
    order_rng = np.random.default_rng(0)
    for _ in range(epochs):
        order = order_rng.permutation(len(Xtr))
        for i in range(0, len(Xtr), 128):
            net.partial_fit(Xtr[order[i:i + 128]], ytr[order[i:i + 128]])   # one Adam step
            for w, m in zip(net.coefs_, masks):
                w *= m                                                     # keep pruned weights at zero

def unstructured_masks(net, sparsity):          # smallest |w| in each layer -> 0
    return [np.abs(w) > np.quantile(np.abs(w), sparsity) for w in net.coefs_]

def structured_masks(net, keep):                # drop hidden units with the smallest L1 norm of incoming weights
    masks = [np.ones_like(w) for w in net.coefs_]
    for l in range(len(net.coefs_) - 1):
        norms = np.abs(net.coefs_[l]).sum(axis=0)
        dead = np.argsort(norms)[: int(round((1 - keep) * norms.size))]
        masks[l][:, dead] = 0                   # incoming weights of the unit ...
        masks[l + 1][dead, :] = 0               # ... and its outgoing weights
    return masks

for name, make, levels in [("remove weights", unstructured_masks, [0.8, 0.9, 0.95]),
                           ("keep units", structured_masks, [0.5, 0.25, 0.125])]:
    for level in levels:
        net = copy.deepcopy(base)
        masks = make(net, level)
        for w, m in zip(net.coefs_, masks):
            w *= m
        before = net.score(Xte, yte)
        fine_tune(net, masks)
        kept = int(sum(m.sum() for m in masks))
        print(f"{name} {level:6.1%}: {kept:5d} weights left, "
              f"accuracy {before:.3f} -> {net.score(Xte, yte):.3f} after fine-tuning")

# The last structured model is a genuinely smaller dense network: slice out the live units.
alive = [masks[l].any(axis=0) for l in range(2)]
small_W = [net.coefs_[0][:, alive[0]], net.coefs_[1][alive[0]][:, alive[1]], net.coefs_[2][alive[1]]]
small_b = [net.intercepts_[0][alive[0]], net.intercepts_[1][alive[1]], net.intercepts_[2]]
h = Xte
for l, (w, b) in enumerate(zip(small_W, small_b)):
    h = h @ w + b if l == 2 else np.maximum(h @ w + b, 0)
print("sliced shapes:", [w.shape for w in small_W],
      "| same predictions:", bool((h.argmax(1) == net.predict(Xte)).all()))
```

Output (toy results):

```text
dense: 50432 weights, test accuracy 0.980
remove weights  80.0%: 10087 weights left, accuracy 0.909 -> 0.974 after fine-tuning
remove weights  90.0%:  5044 weights left, accuracy 0.563 -> 0.954 after fine-tuning
remove weights  95.0%:  2523 weights left, accuracy 0.170 -> 0.885 after fine-tuning
keep units  50.0%: 17024 weights left, accuracy 0.887 -> 0.981 after fine-tuning
keep units  25.0%:  6464 weights left, accuracy 0.550 -> 0.980 after fine-tuning
keep units  12.5%:  2720 weights left, accuracy 0.402 -> 0.957 after fine-tuning

```

What to read from it. **Fine-tuning does most of the work**: removing 90% of the weights drops accuracy to 0.563, and ten epochs bring it back to 0.954. **Structured pruning produced a real network** of shape 64–32–16–10 that any library runs as ordinary dense matrices. And at about 2,500 remaining weights the small dense network (0.957) beat the large sparse one (0.885), the opposite of Zhu and Gupta's finding on large models [12]: our network is so over-parameterized for an 8 × 8 digit task that making it narrower costs almost nothing. Do not generalize from this toy in either direction.

### The lottery ticket hypothesis

**Plain version.** If a pruned network can be this small, why not train the small network directly? Frankle and Carbin found that, in their experiments, a randomly reinitialized pruned network trained worse, but the same sparse network **reset to its original initial weights** trained as well as the full one. They proposed that large networks contain such lucky sparse subnetworks ("winning tickets") from the start.

The tickets are found by **iterative magnitude pruning**: train, prune the smallest-magnitude weights, reset the survivors to their initial values, and repeat; on small MNIST and CIFAR-10 networks this consistently found tickets at 10–20% of the original size or less [13]. At ImageNet scale, the weights had to be reset to their values from early in training rather than to initialization [14], and Liu et al. reported that with a well-tuned learning rate the ticket initialization brought no gain over random initialization in their experiments [3]. The practical lesson is modest: the hypothesis is about which sparse networks are trainable, not a cheaper way to compress (finding a ticket costs several full trainings).

## Quantization

**Plain version.** A network trained in 32-bit floating point does not need that precision to make good predictions. Quantization stores weights, and often activations, as small integers (8 bits, sometimes 4) together with a few scale factors. That cuts memory by 4 to 8 times and, on hardware with integer arithmetic, also speeds up computation. The difficulty is that a small grid of values has to cover both the many small numbers and the few very large ones.

### Uniform affine quantization

The most common scheme, because it permits efficient fixed-point arithmetic [15], maps a real value $x$ to an integer $q$ and back [16]:

$$
q = \operatorname{clip}\!\left(\operatorname{round}\!\left(\frac{x}{s}\right) + z,\; q_{\min},\; q_{\max}\right),
\qquad
\hat{x} = s\,(q - z),
$$

where $s > 0$ is the **scale** (the step between neighbouring representable values), $z$ the integer **zero point** (the integer that represents the real value 0 exactly), $[q_{\min}, q_{\max}]$ the integer range of a $b$-bit format (for example $[0, 255]$ for unsigned 8-bit or $[-127, 127]$ for a symmetric signed format), $\operatorname{round}$ rounding to the nearest integer, $\operatorname{clip}$ clamping into the range, and $\hat{x}$ the dequantized approximation of $x$. For a real range $[x_{\min}, x_{\max}]$ that contains 0, a common choice is

$$
s = \frac{x_{\max} - x_{\min}}{q_{\max} - q_{\min}},
\qquad
z = q_{\min} - \operatorname{round}\!\left(\frac{x_{\min}}{s}\right).
$$

**Symmetric** quantization fixes $z = 0$ and uses a signed range. Exact representation of 0 matters because zero padding and ReLU outputs produce many exact zeros [15]. Two kinds of error arise: **rounding error**, at most $s/2$ for values inside the range, and **clipping error** for values outside it. A larger range reduces clipping but makes $s$, and therefore the rounding error, larger [15]. [ML 11](/en/learn/ml/ml-10-evaluation-deployment/#quantization) has a tested implementation and the error-versus-bits curve.

### Why integer kernels can factor out the scales

**Plain version.** Integers are only useful if the expensive part of a layer, the long sum of products, can run entirely in integers. With one scale per weight row and one per activation tensor, the scales can be pulled out of the sum and applied once at the end.

For one output $y_i = \sum_j W_{ij} x_j$ of a linear layer (a convolution is the same sum over a patch), quantize the weights symmetrically with one scale $s_{w,i}$ per output channel, $W_{ij} \approx s_{w,i}\,q^{w}_{ij}$, and the inputs affinely with scale $s_x$ and zero point $z_x$, $x_j \approx s_x (q^{x}_j - z_x)$. Then

$$
y_i \approx s_{w,i}\, s_x \sum_{j} q^{w}_{ij}\,\bigl(q^{x}_j - z_x\bigr),
$$

where the sum involves only integers and is accumulated in a 32-bit integer register, and the single product $s_{w,i} s_x$ is applied once per output. This is why per-channel scales for weights are cheap (one factor per output channel), while per-channel scales for **activations** are not: they would sit inside the sum and require rescaling the accumulator for each input channel [15]. It is also why a common choice is symmetric weights and asymmetric activations: an asymmetric weight zero point would add a data-dependent term to every output [15]. Biases are typically kept as 32-bit integers [16].

```python
import numpy as np

rng = np.random.default_rng(0)
W = rng.normal(0, 0.2, size=(16, 256))              # a layer: 16 outputs, 256 inputs
x = rng.normal(0.3, 1.0, size=256)                  # input activations (not centred at 0)

# Weights: symmetric int8, one scale per output channel (zero point 0).
s_w = np.abs(W).max(axis=1) / 127
W_q = np.round(W / s_w[:, None]).astype(np.int8)

# Activations: affine uint8 with a scale and an integer zero point.
lo, hi = min(x.min(), 0.0), x.max()
s_x = (hi - lo) / 255
z_x = int(np.round(-lo / s_x))
x_q = np.clip(np.round(x / s_x) + z_x, 0, 255).astype(np.uint8)
print("activation scale:", round(s_x, 5), "| zero point:", z_x)

# Integer-only inner products, accumulated in int32, then one rescale per output.
acc = W_q.astype(np.int32) @ (x_q.astype(np.int32) - z_x)
y_int = s_w * s_x * acc
y_ref = W @ x
print("max |integer result - float result|:", np.abs(y_int - y_ref).max().round(4))
print("relative error:", (np.linalg.norm(y_int - y_ref) / np.linalg.norm(y_ref)).round(4))
print("largest |accumulator|:", np.abs(acc).max(), "| int16 limit:", 2**15 - 1)
```

Output:

```text
activation scale: 0.01967 | zero point: 117
max |integer result - float result|: 0.0495
relative error: 0.0083
largest |accumulator|: 83167 | int16 limit: 32767
```

The integer path reproduces the float result to within about 1%. The accumulator reaches 83,167, far beyond what 16 bits can hold, which is why accelerators keep 32-bit accumulators even when inputs are 8-bit [15]. Before the next layer, the 32-bit result is converted back to 8 bits ("requantized") with the next layer's scale.

*Optional: [Requantization with a fixed-point multiplier](#requantization-with-a-fixed-point-multiplier) (in the Supplementary notes). How Jacob et al. turn the combined real-valued scale into an integer multiply and a bit shift, so that no floating-point operation is left at inference.*

### Granularity and range setting

**Granularity** is how many values share one scale: one per tensor, one per output channel, or one per small group of consecutive weights. Finer granularity fits the grid to each group's own range. **Range setting** (or calibration) is how $[x_{\min}, x_{\max}]$ is chosen [15]:

- **Min-max**: the observed minimum and maximum. No clipping, but one outlier stretches the grid for everyone.
- **Percentile**: ignore a small fraction of the most extreme values.
- **MSE**: search for the range that minimizes $\lVert x - \hat{x} \rVert^2$ on representative data, trading clipping against rounding.

Weights are known in advance and need no data. Activations depend on the input, so their ranges are estimated by running a small **calibration set** of unlabeled images through the network; Nagel et al. note that 500 to 1,000 unlabeled images are usually enough [15].

*Optional: [Choosing the clipping range: min-max, percentile and MSE](#choosing-the-clipping-range-min-max-percentile-and-mse) (in the Supplementary notes). A tested comparison showing that the best rule changes with the bit width: at 8 bits keep the outliers, at 4 bits clip them.*

### What breaks: outliers, folded batch norm and activations

**Plain version.** Quantization fails when one shared scale must cover values of very different sizes. The large values force a coarse grid, and the many small values all round to the same few integers.

The classic vision example is MobileNetV2. Nagel et al. showed that the weight ranges of different output channels of one of its depthwise-separable layers differ so much that one set of quantization parameters cannot serve the whole tensor; with batch normalization folded and 8-bit per-tensor quantization, the ImageNet top-1 accuracy of their model fell from 71.72% to 0.12% [17]. Their fix needs no data or training: because $\operatorname{ReLU}(c\,t) = c\,\operatorname{ReLU}(t)$ for $c > 0$, an output channel of one layer can be scaled down and the matching input channel of the next layer scaled up without changing the function (**cross-layer equalization**). After replacing ReLU6 by ReLU, which has this property, equalization and bias absorption brought the model to 70.92% at 8 bits [17].

Our toy reproduces the mechanism. We take the trained MLP and rescale one hidden unit by 100 (and the next layer's weights by 1/100). The float network computes exactly the same function, but its activation and weight ranges now contain one huge channel.

```python
import warnings
import numpy as np
from sklearn.datasets import load_digits
from sklearn.exceptions import ConvergenceWarning
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier
warnings.filterwarnings("ignore", category=ConvergenceWarning)

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X / 16.0, y, test_size=0.3, random_state=0, stratify=y)
net = MLPClassifier(hidden_layer_sizes=(256, 128), max_iter=300, random_state=0).fit(Xtr, ytr)

def q_weight(w, bits, per_channel):     # symmetric: one scale per output unit, or one per tensor
    qmax = 2 ** (bits - 1) - 1
    m = np.abs(w).max(axis=0, keepdims=True) if per_channel else np.abs(w).max()
    return np.clip(np.round(w * qmax / m), -qmax, qmax) * m / qmax

def q_act(a, hi, bits):                 # post-ReLU activations: grid on [0, hi], zero point 0
    s = hi / (2 ** bits - 1)
    return np.clip(np.round(a / s), 0, 2 ** bits - 1) * s

def run(Ws, bs, X, wbits=None, abits=None, his=None, per_channel=True, record=None):
    h = X
    for l, (w, b) in enumerate(zip(Ws, bs)):
        h = h @ (q_weight(w, wbits, per_channel) if wbits else w) + b
        if l < len(Ws) - 1:
            h = np.maximum(h, 0)
            if record is not None:
                record.append(h)
            if abits:
                h = q_act(h, his[l], abits)
    return h

acc = lambda logits: (logits.argmax(1) == yte).mean()
for c in [1, 100]:
    Ws = [w.copy() for w in net.coefs_]
    bs = [b.copy() for b in net.intercepts_]
    Ws[0][:, 0] *= c; bs[0][0] *= c; Ws[1][0, :] /= c   # same function: ReLU(c*t) = c*ReLU(t)
    calib = []
    run(Ws, bs, Xtr[:100], record=calib)                 # 100 training images calibrate the ranges
    minmax = [a.max() for a in calib]
    pct99 = [np.percentile(a, 99) for a in calib]
    print(f"unit 0 scaled by {c}: float {acc(run(Ws, bs, Xte)):.3f} | "
          f"W8A8 {acc(run(Ws, bs, Xte, 8, 8, minmax)):.3f} | "
          f"W8A4 {acc(run(Ws, bs, Xte, 8, 4, minmax)):.3f} | "
          f"W8A4 clipped {acc(run(Ws, bs, Xte, 8, 4, pct99)):.3f} | "
          f"W4 per-tensor {acc(run(Ws, bs, Xte, 4, per_channel=False)):.3f} | "
          f"W4 per-channel {acc(run(Ws, bs, Xte, 4)):.3f}")
```

Output (toy results; "W8A4" means 8-bit weights and 4-bit activations):

```text
unit 0 scaled by 1: float 0.980 | W8A8 0.980 | W8A4 0.978 | W8A4 clipped 0.978 | W4 per-tensor 0.983 | W4 per-channel 0.980
unit 0 scaled by 100: float 0.980 | W8A8 0.980 | W8A4 0.163 | W8A4 clipped 0.980 | W4 per-tensor 0.102 | W4 per-channel 0.978
```

The two networks are the same function, yet with one outlier channel, 4-bit min-max activations collapse to 0.163 and 4-bit per-tensor weights to 0.102. Clipping the activation range at the 99th percentile (0.980) and per-unit weight scales (0.978) both fix it. Here clipping happens to cost nothing; when the outlier channel carries real information it does, which is why methods that move or isolate outliers exist.

The same pattern, at larger scale, drives quantization research for Transformers: Dettmers et al. found systematic outlier feature dimensions in large language models and kept them in 16-bit [18], and SmoothQuant moves the difficulty from activations to weights with an equivalent per-channel rescaling, the same family of idea as cross-layer equalization [19].

### Post-training quantization and quantization-aware training

**Plain version.** You can quantize a finished model with a little calibration data (fast, no labels), or you can train the model while it "feels" the rounding, so that it learns weights that survive it (slower, more accurate at low bit widths).

**Post-training quantization (PTQ)** takes a trained float model and converts it using only a small calibration set. Nagel et al.'s recommended pipeline is: cross-layer equalization, symmetric weight and asymmetric activation quantizers (per-channel weights if the hardware supports it), MSE-based weight ranges, then **AdaRound** (a learned choice between rounding each weight up or down [20]) if calibration data is available, analytical bias correction otherwise, and finally activation range setting [15].

**Quantization-aware training (QAT)** inserts "fake quantization" (quantize, then immediately dequantize) into the forward pass and trains as usual. The difficulty is that $\operatorname{round}$ has zero gradient almost everywhere. The **straight-through estimator** (STE) [21] treats rounding as the identity in the backward pass. For the symmetric quantizer $\hat{x} = s\,\operatorname{clip}(\operatorname{round}(x/s), q_{\min}, q_{\max})$ this gives

$$
\frac{\partial \hat{x}}{\partial x} \approx
\begin{cases}
1, & q_{\min} \le x/s \le q_{\max},\\
0, & \text{otherwise},
\end{cases}
$$

so gradients pass unchanged through values inside the range and stop at clipped values [15]. The float "shadow" weights are updated, and the forward pass always uses their quantized version.

When to use which: in the white paper's experiments PTQ was sufficient for 8-bit weights and activations (within 0.7% of float for every model tested), while lower bit widths, and 4-bit activations in particular, needed QAT; networks with depthwise-separable layers remained the hardest even with QAT [15].

*Optional: [Beyond round-to-nearest: AdaRound, BRECQ and LSQ](#beyond-round-to-nearest-adaround-brecq-and-lsq) (in the Supplementary notes). Three refinements: learning whether to round each weight up or down, reconstructing whole blocks, and learning the scale itself during QAT.*

### Mixed precision and other number formats

Not all layers are equally sensitive, so **mixed-precision quantization** gives different layers different bit widths: HAWQ chooses them from second-order (Hessian) information [22], HAQ from latency and energy feedback of a hardware simulator, finding that the best policies differ between edge and cloud accelerators [23]. Integers are not the only option: 8-bit floating-point encodings (E4M3 and E5M2) [24] spend bits on an exponent, which tolerates a wider range of magnitudes at the cost of fewer steps.

Do not confuse this with **mixed-precision training** ([DLCV 01A](/en/learn/deep-learning/dl-01a-training-practice/#mixed-precision-and-loss-scaling)), which keeps a 32-bit master copy of the weights and computes in 16-bit to speed up training. Mixed-precision quantization is about the deployed model.

## Knowledge distillation

**Plain version.** Train a small **student** to imitate a large **teacher**, not only the correct labels. The teacher's full output (which wrong classes it considers plausible) and its intermediate features carry more information per example than a label does, so the student learns more from the same images.

The response-based loss of Hinton et al., with temperature $T$ and the $T^2$ factor, is derived and tested in the [DLCV 01 Supplementary notes](/en/learn/deep-learning/dl-01-deep-learning-for-image-processing/notes/knowledge-distillation-learning-from-a-teachers-soft-answers/) and summarized in [ML 11](/en/learn/ml/ml-10-evaluation-deployment/#knowledge-distillation) [25]; we do not repeat it. In one line: the student minimizes $(1-\alpha)\,\mathrm{CE}(y, \sigma(\mathbf{z})) + \alpha\,T^2\,\mathrm{CE}(\sigma(\mathbf{v}/T), \sigma(\mathbf{z}/T))$, where $\mathbf{z}$ and $\mathbf{v}$ are the student and teacher logits, $y$ the label, $\sigma$ the softmax, $\mathrm{CE}$ cross-entropy and $\alpha \in [0, 1]$ the weight of the soft term. Hinton et al. show that matching logits, as Ba and Caruana did by regressing them with an L2 loss [26], is the high-temperature limit of this loss [25].

### Code: distilling the toy MLP into an 8-unit student

The teacher is the 50,432-weight MLP from the pruning snippet. The student has one hidden layer of 8 units (592 weights) and is trained by full-batch gradient descent, once on labels only and twice with the distillation loss.

```python
import warnings
import numpy as np
from sklearn.datasets import load_digits
from sklearn.exceptions import ConvergenceWarning
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier
warnings.filterwarnings("ignore", category=ConvergenceWarning)

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X / 16.0, y, test_size=0.3, random_state=0, stratify=y)
teacher = MLPClassifier(hidden_layer_sizes=(256, 128), max_iter=300, random_state=0).fit(Xtr, ytr)
h = Xtr
for l, (w, b) in enumerate(zip(teacher.coefs_, teacher.intercepts_)):   # teacher logits
    h = h @ w + b if l == 2 else np.maximum(h @ w + b, 0)
z_teacher = h

def softmax(z, T=1.0):
    e = np.exp((z - z.max(axis=1, keepdims=True)) / T)
    return e / e.sum(axis=1, keepdims=True)

def train_student(T, alpha, hidden=8, steps=500, lr=0.2, seed=0):
    """64 -> 8 -> 10 ReLU network, full-batch gradient descent on the distillation loss."""
    rng = np.random.default_rng(seed)
    W1, b1 = rng.normal(0, np.sqrt(2 / 64), (64, hidden)), np.zeros(hidden)
    W2, b2 = rng.normal(0, np.sqrt(1 / hidden), (hidden, 10)), np.zeros(10)
    Y, p_T = np.eye(10)[ytr], softmax(z_teacher, T)
    for _ in range(steps):
        a = np.maximum(Xtr @ W1 + b1, 0)
        z = a @ W2 + b2
        # gradient of (1-alpha)*CE(y, softmax(z)) + alpha*T^2*CE(p_T, softmax(z/T)) w.r.t. z
        g = ((1 - alpha) * (softmax(z) - Y) + alpha * T * (softmax(z, T) - p_T)) / len(Xtr)
        ga = (g @ W2.T) * (a > 0)
        W2 -= lr * a.T @ g;  b2 -= lr * g.sum(0)
        W1 -= lr * Xtr.T @ ga; b1 -= lr * ga.sum(0)
    return (np.maximum(Xte @ W1 + b1, 0) @ W2 + b2).argmax(1)

print(f"teacher: {sum(w.size for w in teacher.coefs_)} weights, accuracy {teacher.score(Xte, yte):.3f}")
for T in (1, 4):
    print(f"mean top probability of the teacher on training images at T = {T}: "
          f"{softmax(z_teacher, T).max(axis=1).mean():.3f}")
for name, T, alpha in [("labels only", 1, 0.0), ("distill, T = 1", 1, 0.5), ("distill, T = 4", 4, 0.5)]:
    accs = [(train_student(T, alpha, seed=s) == yte).mean() for s in range(5)]
    print(f"student (592 weights), {name:14s}: accuracy {np.mean(accs):.3f} +/- {np.std(accs):.3f} over 5 seeds")
```

Output (toy results):

```text
teacher: 50432 weights, accuracy 0.980
mean top probability of the teacher on training images at T = 1: 0.998
mean top probability of the teacher on training images at T = 4: 0.787
student (592 weights), labels only   : accuracy 0.936 +/- 0.025 over 5 seeds
student (592 weights), distill, T = 1: accuracy 0.936 +/- 0.025 over 5 seeds
student (592 weights), distill, T = 4: accuracy 0.954 +/- 0.006 over 5 seeds
```

Distillation at $T = 4$ raised the student's mean accuracy from 0.936 to 0.954 and made it much less dependent on the random seed. At $T = 1$ it changed nothing, and the second line says why: on its own training images the teacher is almost certain (mean top probability 0.998), so its soft targets are practically the labels. The temperature is what exposes the teacher's opinion about the wrong classes. The effect is small and specific to this toy; it is the mechanism, not the number, that transfers.

### Feature and attention distillation

The teacher's intermediate representations can be imitated too. **FitNets** train a thin, deep student so that one of its middle layers (the "guided" layer), passed through a small learned **regressor**, predicts a middle layer of the teacher (the "hint" layer); the regressor is needed because the two layers have different widths, and the authors use a convolutional regressor to keep its size manageable [27]. **Attention transfer** imitates where the teacher's features are active rather than the features themselves: for a feature map $A \in \mathbb{R}^{C \times H \times W}$ it forms a spatial map

$$
F(A) = \sum_{c=1}^{C} \lvert A_c \rvert^{p},
$$

where $A_c$ is channel $c$ and $p \ge 1$ an exponent (the paper also studies $p = 1$ and a max over channels), and trains the student to match the $\ell_2$-normalized maps of the teacher at several depths [28]. Because $F(A)$ has no channel dimension, teacher and student widths need not match. Gou et al. organize the field by what is transferred (responses, features, relations between examples or layers) and how (offline from a fixed teacher, online, or self-distillation) [29].

### What decides whether distillation helps

- **Teacher and student must see the same input.** Beyer et al. found that distillation works best when teacher and student receive the identical augmented view of each image ("consistent" teaching), when augmentation is aggressive, and when training is very long ("patient"); inconsistent setups plateaued lower in their experiments [30].
- **A better teacher is not always a better teacher.** Cho and Hariharan found that larger, more accurate teachers often did not produce better students, attributed this to mismatched capacity, found multi-step distillation through intermediate-size models ineffective, and reported that stopping the teacher's training early mitigated the problem [31].
- **Distillation is a training method, not a compression of an existing model**: it needs a training run, data, and a student architecture chosen in advance. DeiT, for example, trains a vision Transformer with an extra distillation token that learns from a convolutional teacher ([DLCV 02](/en/learn/deep-learning/dl-02-image-classification/#deit-training-vits-on-imagenet-alone)) [32].

## Low-rank factorization

**Plain version.** A big weight matrix often contains much less information than its size suggests. Writing it as the product of two thin matrices replaces one large layer by two small ones, with far fewer weights and operations.

Any $m \times n$ matrix $W$ has a singular value decomposition $W = U \Sigma V^\top$, where $U$ ($m \times m$) and $V$ ($n \times n$) have orthonormal columns and $\Sigma$ is diagonal with the singular values $\sigma_1 \ge \sigma_2 \ge \dots \ge 0$. Keeping the $r$ largest gives the best rank-$r$ approximation in the Frobenius norm ([ML 01A](/en/learn/ml/ml-01a-linear-algebra/#the-best-low-rank-approximation)):

$$
W \approx A B, \qquad A = U_{:, 1:r}\,\Sigma_{1:r,1:r} \in \mathbb{R}^{m \times r}, \qquad B = V_{:, 1:r}^\top \in \mathbb{R}^{r \times n},
$$

where $U_{:,1:r}$ is the first $r$ columns of $U$ and $r$ the chosen **rank**. The layer $x \mapsto W x$ becomes two layers $x \mapsto A(Bx)$ with $r(m + n)$ weights instead of $mn$, which saves weights and MACs only if $r \lt mn/(m+n)$. For a convolution with kernel $W \in \mathbb{R}^{C_{\text{out}} \times C_{\text{in}} \times k \times k}$, reshape it to a $C_{\text{out}} \times (C_{\text{in}} k^2)$ matrix and factorize: $B$ becomes a $k \times k$ convolution with $r$ output channels and $A$ a $1 \times 1$ convolution back to $C_{\text{out}}$ channels. Denton et al. exploited such linear structure in convolutional filters to speed up convolutional layers about twofold on CPU and GPU with accuracy within 1% [33]; Jaderberg et al. built filter bases that are rank-1 in the spatial domain (a $k \times 1$ followed by a $1 \times k$ filter) [34]; Zhang et al. extended low-rank acceleration to very deep networks for classification and detection, minimizing the reconstruction error of each layer's nonlinear responses rather than of its weights [35].

```python
import warnings
import numpy as np
from sklearn.datasets import load_digits
from sklearn.exceptions import ConvergenceWarning
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier
warnings.filterwarnings("ignore", category=ConvergenceWarning)

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X / 16.0, y, test_size=0.3, random_state=0, stratify=y)
net = MLPClassifier(hidden_layer_sizes=(256, 128), max_iter=300, random_state=0).fit(Xtr, ytr)
(W1, W2, W3), (b1, b2, b3) = net.coefs_, net.intercepts_

U, S, Vt = np.linalg.svd(W2, full_matrices=False)       # W2 is 256 x 128
energy = np.cumsum(S**2) / np.sum(S**2)
for r in [4, 8, 16, 32, 128]:
    A, B = U[:, :r] * S[:r], Vt[:r]                     # W2 ~ A @ B: a 256->r and an r->128 layer
    h = np.maximum(np.maximum(Xte @ W1 + b1, 0) @ A @ B + b2, 0)
    acc = ((h @ W3 + b3).argmax(1) == yte).mean()
    print(f"rank {r:3d}: {A.size + B.size:5d} weights instead of {W2.size} "
          f"({energy[r - 1]:.0%} of the squared singular values), accuracy {acc:.3f}")
```

Output (toy results):

```text
rank   4:  1536 weights instead of 32768 (29% of the squared singular values), accuracy 0.620
rank   8:  3072 weights instead of 32768 (47% of the squared singular values), accuracy 0.978
rank  16:  6144 weights instead of 32768 (58% of the squared singular values), accuracy 0.981
rank  32: 12288 weights instead of 32768 (72% of the squared singular values), accuracy 0.981
rank 128: 49152 weights instead of 32768 (100% of the squared singular values), accuracy 0.980
```

Rank 8 keeps the accuracy with less than a tenth of the layer's weights, although it keeps only 47% of the squared singular values. The Frobenius error of the weights is a poor guide to the error of the task: what matters is what the layer does to the inputs it actually sees, which is why Zhang et al. minimize response error instead [35]. The last line shows the break-even rule: at full rank the factorized form has more weights than the original, because $128 > 256 \cdot 128 / 384 \approx 85$. Splitting one layer into two also adds a memory round trip for the intermediate result, so on a memory-bound device the latency saving is smaller than the MAC saving.

## Designing small from the start

**Plain version.** Instead of shrinking a big network after training, you can choose an architecture that is small and hardware-friendly from the beginning, either by hand (efficient blocks) or by search. In practice the two approaches are combined: a well-designed small network is then quantized, and sometimes pruned or distilled.

The main hand-designed families are covered elsewhere and only listed here: **depthwise-separable convolutions** and inverted residuals (MobileNet [36], MobileNetV2 [37]; derivation and cost in [DLCV 02](/en/learn/deep-learning/dl-02-image-classification/#mobilenet-factorize-the-convolution) and [ML 03](/en/learn/ml/ml-03-convolutional-networks/#efficient-cnns-separate-spatial-filtering-from-channel-mixing)), **compound scaling** of depth, width and resolution (EfficientNet [38]; [DLCV 02](/en/learn/deep-learning/dl-02-image-classification/#efficientnet-scale-depth-width-and-resolution-together)), and the block-by-block cost arithmetic in [DLCV 01B](/en/learn/deep-learning/dl-01b-building-blocks/#bottlenecks-inverted-residuals-and-depthwise-separable-convolutions). The roofline view from the start of this chapter is the right lens for all of them: a block is efficient on a device if it does enough arithmetic per byte for that device and has fast kernels there.

### Re-parameterization: train rich, deploy plain

**Structural re-parameterization** trains a block with several parallel linear branches and merges them into one convolution for deployment. RepVGG trains blocks with a $3 \times 3$ convolution, a $1 \times 1$ convolution and an identity branch, each followed by batch normalization, and deploys a plain stack of $3 \times 3$ convolutions and ReLUs [39]. The folding is derived and checked numerically in the [DLCV 03A Supplementary notes](/en/learn/deep-learning/dl-03a-real-time-detection/notes/folding-a-re-parameterized-block-into-one-convolution/) and, for enhancement networks, in the [DLCV 09C.1 Supplementary notes](/en/learn/deep-learning/dl-05a-lightweight-enhancement/notes/structural-re-parameterization-step-by-step/).

Re-parameterization interacts with quantization. The YOLOv6 report states that, because of its heavy use of re-parameterized blocks, earlier PTQ techniques failed to produce good results; in its version 1.0, YOLOv6-S fell from 42.4 to 35.0 COCO val AP under 8-bit PTQ, and to 40.9 when trained with RepOptimizer, which narrowed the activation distribution [40]. The merged kernel adds branches with very different ranges, which is exactly the situation per-tensor quantization handles worst.

### Neural architecture search

**Plain version.** Neural architecture search (NAS) lets an algorithm choose layer types, widths and kernel sizes, scoring candidates by accuracy and, in its hardware-aware form, by measured latency on the target device.

Elsken et al. describe every NAS method by three choices: the **search space** (which architectures are allowed), the **search strategy** (how candidates are proposed) and the **performance estimation strategy** (how a candidate is scored without training it fully) [41]. Three ideas matter for compression:

- **Weight sharing makes search affordable.** The original reinforcement-learning approach trained each proposed architecture separately [42]; ENAS lets all candidates share the weights of one large graph [43], DARTS relaxes the discrete choice into a continuous one optimized by gradient descent [44], and Once-for-All trains one network from which sub-networks of different depth, width, kernel size and resolution are extracted for different devices without retraining [45].
- **Search for measured latency, not FLOPs.** MnasNet puts latency measured on real phones into the objective [46]; ProxylessNAS searches directly on the target task and hardware [47]; FBNet's differentiable search is motivated by the same observation that FLOPs do not always reflect latency [48].
- **Keep a random baseline.** Li and Talwalkar found random search with early stopping at least as good as ENAS on the two benchmarks they used [49].

## Deployment: from a small model to a fast one

**Plain version.** A compressed model becomes fast only after a compiler or runtime turns it into a few large, fused operations with kernels that support its number format and sparsity pattern. Speed claims from papers often assume support that your device does not have.

### Operator fusion and batch-norm folding

Each separate operation reads its input from memory and writes its output back. **Operator fusion** merges consecutive operations (convolution, bias, batch normalization, activation) into one kernel so that intermediate results stay in fast on-chip memory; from the roofline viewpoint, it raises arithmetic intensity by removing memory round trips. The most common fusion is **batch-norm folding**: at inference, batch normalization [50] with learned scale $\gamma_c$, shift $\beta_c$, running mean $\mu_c$ and variance $\sigma_c^2$ is an affine map per output channel $c$, so it can be absorbed into the preceding convolution,

$$
W'_c = \frac{\gamma_c}{\sqrt{\sigma_c^2 + \epsilon}}\,W_c,
\qquad
b'_c = \frac{\gamma_c}{\sqrt{\sigma_c^2 + \epsilon}}\,(b_c - \mu_c) + \beta_c,
$$

where $W_c$ and $b_c$ are the kernel and bias of output channel $c$ and $\epsilon$ a small constant. A tested NumPy version is in the [DLCV 03A Supplementary notes](/en/learn/deep-learning/dl-03a-real-time-detection/notes/folding-a-re-parameterized-block-into-one-convolution/). For compression, notice the factor $\gamma_c / \sqrt{\sigma_c^2 + \epsilon}$: it differs from channel to channel, so folding can spread the per-channel weight ranges apart, which is one reason MobileNetV2 was hard to quantize per tensor [17]. On device, batch normalization is folded before quantization, so the folded weights are what the integer kernel sees, and QAT has to simulate the folding correctly [15].

### Integer kernels and runtime support

Quantization speeds up inference only if the runtime has integer (or low-precision) kernels for every operation in the graph. [ML 11](/en/learn/ml/ml-10-evaluation-deployment/#code-weight-only-int8-latency-and-export) shows a weight-only int8 model that is four times smaller but *slower*, because it converts weights back to float on every call. In a real deployment, check: does the target support per-channel weight scales (not all hardware does [15]); which operators fall back to float (each fallback adds a dequantize and a quantize); and whether the runtime keeps the graph in integers between layers. The export and runtime tools themselves (ONNX, ONNX Runtime, TensorRT, `torch.export`) are described in [ML 11](/en/learn/ml/ml-10-evaluation-deployment/#export-and-inference-runtimes).

### Why paper speed-ups shrink on devices

- **FLOPs are not the bottleneck.** A method that removes 90% of the MACs of memory-bound layers barely changes their time (Figure 1).
- **Sparsity needs kernels.** Unstructured sparsity speeds up only with sparse kernels for that pattern on that device [5], [8]; 2:4 sparsity has dedicated hardware on some GPUs [6]; structured pruning needs nothing special.
- **Batch size.** Throughput at a large batch is not latency at batch 1 (the linear-layer example above).
- **The rest of the pipeline.** Pre-processing, post-processing such as NMS ([DLCV 03A](/en/learn/deep-learning/dl-03a-real-time-detection/#export-reduced-precision-and-re-parameterization)), resizing and data transfer do not shrink when the network does.
- **Unsupported operators.** A single operator without a low-precision kernel can force conversions that cost more than they save.

## Compressing vision models: what is sensitive

**Plain version.** Different parts of a vision model react very differently to compression. Layers with few weights per channel, outputs that must be numerically precise (box coordinates, pixel values), and activations whose range changes from image to image are the usual weak points.

### Classification backbones

Networks built from depthwise-separable layers are the hardest common backbones to quantize. With 4-bit weights and 8-bit activations, per-tensor PTQ cost MobileNetV2 and EfficientNet-lite about 2.5 and 4.2 points of ImageNet top-1 in Nagel et al.'s experiments, which they attribute likely to the depthwise-separable convolutions; per-channel scales recovered 2.8 points for EfficientNet-lite [15]. Layers whose weight ranges differ strongly across channels are the first candidates for per-channel scales or higher precision, and a per-layer sensitivity test (quantize one layer at a time and measure the drop, as in Exercise 5) finds the others quickly.

### Detectors

Detectors predict continuous box coordinates and scores, and both suffer from coarse grids. In the white paper, EfficientDet-D1 reached 40.08 COCO mAP in float and 38.29 with 8-bit PTQ, but only 0.31 with 4-bit per-tensor weights (35.08 per-channel); QAT brought the 4-bit-weight results to 35.34 and 36.75 [15]. Re-parameterized detectors such as YOLOv6 need quantization-friendly training (above) [40]. Because strict-IoU accuracy is what coarse box coordinates hurt first, check AP at high IoU thresholds after quantizing, not only AP at IoU 0.5 ([DLCV 03A](/en/learn/deep-learning/dl-03a-real-time-detection/#export-reduced-precision-and-re-parameterization)).

Distillation also needs care for detectors. Wang et al. found that applying ordinary distillation to a detector gave only minor gains, and instead had the student imitate the teacher's features at locations near objects, estimated from the anchors; this improved students on KITTI, Pascal VOC and COCO in their experiments [51].

### Dense prediction and restoration

For super-resolution, denoising and enhancement the output is an image, and every quantization error can become visible. Two properties make these networks harder than classifiers. First, many restoration networks remove batch normalization; Li et al. found that this leaves activations with a much larger dynamic range, which breaks quantization schemes that assume normalized activations, and proposed learning a max scale per layer (PAMS) [52]. Second, Hong et al. observed that in super-resolution networks each channel has a different activation distribution, which also changes with the input image, and proposed channel-wise distribution-aware quantization (DAQ) [53]. So calibrate on images like the deployment content (dark scenes for a low-light model), evaluate at full resolution with the metrics of [DLCV 09](/en/learn/deep-learning/dl-04-image-restoration/#evaluation-metrics), and inspect smooth gradients, where banding appears first. The NTIRE efficient super-resolution challenges rank runtime, FLOPs and parameters in separate tracks under a fixed PSNR threshold [54] ([DLCV 09A](/en/learn/deep-learning/dl-04a-super-resolution/#efficiency)); [DLCV 09C.1](/en/learn/deep-learning/dl-05a-lightweight-enhancement/) covers efficient enhancement networks.

### Vision Transformers and diffusion models

In vision Transformers, the activations after softmax and GELU are far from Gaussian, which PTQ4ViT handles with two ranges per such tensor [55]; Liu et al. add a ranking loss so that quantized attention keeps the order of the attention scores [56]. Diffusion models add a time dimension: the same denoising network runs at many noise levels, and its activation distributions change with the time step. Q-Diffusion identifies this, together with bimodal activations in shortcut layers, as the key difficulty and uses time-step-aware calibration [57]; PTQ4DM studies the same multi-time-step calibration problem [58]. Large segmentation foundation models are compressed by distillation: MobileSAM distills the large image encoder of the Segment Anything Model [59] into a small one ("decoupled distillation") [60], and EfficientSAM pre-trains small encoders to reconstruct SAM's features [61].

## Modern view

### What the surveys say

- **General compression.** Cheng et al. divide the field into four categories: parameter pruning and quantization, low-rank factorization, transferred/compact convolutional filters, and knowledge distillation, and discuss each category's advantages and drawbacks [62]. Menghani organizes efficient deep learning into five areas: compression techniques, learning techniques (such as distillation), automation (hyper-parameter optimization and architecture search), efficient architectures, and infrastructure (software and hardware), and adds a practitioner's guide [63].
- **Quantization.** Gholami et al. survey quantization from the basics (uniform and non-uniform quantizers, range calibration, granularity, fine-tuning) to advanced topics (integer-only inference, mixed precision, hardware-aware and distillation-assisted quantization, extreme low-bit quantization) [64]; Nagel et al.'s white paper is the practical companion, with tested PTQ and QAT pipelines and a debugging workflow [15].
- **Pruning and sparsity.** Hoefler et al. distill more than 300 papers on sparsity for inference and training, including how to obtain real speed-ups on hardware [8]. Cheng, Zhang and Shi organize pruning by universal or specific speed-up, when to prune, how to prune, and fusion with other compression techniques, and cover pruning of large language and multimodal models [65]. Blalock et al. remain the cautionary reference on how pruning results are reported [4].
- **Distillation.** Gou et al. categorize distillation by knowledge type, training scheme, teacher–student architecture and algorithm [29]; Wang and Yoon focus on vision and on why distillation works [66].
- **Architecture search.** Elsken et al. provide the three-dimension taxonomy used above [41]; White et al., writing after more than 1,000 NAS papers, give a taxonomy of search spaces, algorithms and speed-up techniques together with benchmarks and best practices [67].

### The state of the art, 2023–2026

- **Low-bit weights for very large models.** Weight-only quantization to 3–4 bits with error-compensating rounding (GPTQ [68]) or activation-aware protection of salient channels (AWQ [69]) became standard for large Transformers; [ML 11](/en/learn/ml/ml-10-evaluation-deployment/#quantization) introduces both. SmoothQuant made 8-bit weights and activations practical for language models by migrating outliers from activations to weights [19].
- **Generative vision models at 4 bits.** After Q-Diffusion [57], SVDQuant quantizes both weights and activations of large diffusion models to 4 bits by moving activation outliers into the weights and absorbing the weight outliers with a small high-precision low-rank branch, fused into the low-bit kernel to avoid extra memory traffic; it combines two techniques of this chapter, low-rank factorization and quantization [70].
- **Floating-point 8-bit formats** (E4M3, E5M2) as an alternative to int8 for both training and inference [24].
- **Distilled foundation models.** Small students of large vision foundation models, such as MobileSAM and EfficientSAM for segmentation [60], [61], and the distilled DINOv2 backbones discussed in [DLCV 02](/en/learn/deep-learning/dl-02-image-classification/#dino-and-dinov2-self-distillation).
- **Structural pruning for any graph.** DepGraph-style dependency analysis makes channel pruning applicable to CNNs, Transformers and other architectures with one method [9].
- **Challenge-driven efficient restoration**, where runtime, FLOPs and parameters are scored separately [54].

### Open problems

- **Predicting device speed.** FLOPs and parameters still dominate papers, but only measured latency on the target matters, and it depends on kernels, memory and batch size [1].
- **Fair comparisons.** Baselines of equal size and training budget, multiple seeds and full trade-off curves are still often missing [4], [3].
- **Low-bit activations.** 4-bit weights are increasingly routine; 4-bit activations, especially in networks with depthwise layers, attention and time-varying distributions, still cost accuracy [15], [57].
- **What compression changes beyond accuracy.** Average accuracy can hide changes on rare classes, shifted inputs or calibration; measuring these after compression is still not standard practice.
- **Compression of restoration and generative models**, where the error is visible in the output and no single metric captures it.

## Key takeaways

- Parameters, MACs, memory traffic, peak memory, latency and throughput are different numbers; decide which one your budget is about and measure it on the target device, end to end.
- The roofline view explains most surprises: memory-bound layers (depthwise, batch-1 linear layers) gain little from fewer MACs and much from fewer bytes.
- Pruning needs fine-tuning. Unstructured sparsity gives the most freedom in what to remove but needs sparse kernels; structured pruning yields smaller dense layers that run fast anywhere; 2:4 sparsity is a hardware-supported middle ground.
- Uniform affine quantization stores integers plus scales; per-channel weight scales are cheap, per-channel activation scales are not. Outliers, folded batch norm and depthwise layers are where it breaks.
- Use PTQ first (8 bits usually suffices for vision models); use QAT with the straight-through estimator when you need 4 bits or when PTQ fails.
- Distillation helps when the teacher's outputs carry information beyond the labels: use a temperature, give teacher and student the same views, train long, and do not assume a bigger teacher is better.
- Low-rank factorization and efficient design attack the architecture; their savings only become speed if the resulting layers run efficiently on the device.
- Compare every compressed model against a dense model of the same size trained just as carefully, and evaluate after export on the runtime you ship.

### N:M semi-structured sparsity

This note describes the 2:4 pattern used by sparse GPU hardware and what it costs compared with unstructured pruning.

In **N:M sparsity**, every group of $M$ consecutive weights (along the input dimension of a matrix multiplication) contains at most $N$ nonzeros; 2:4 is the case supported by NVIDIA's sparse Tensor Cores, which the authors report doubles the math throughput of the dense units for this pattern [6]. Only the two nonzero values of each group are stored, plus 2 bits of metadata per stored value giving its position within the group; for 16-bit values this stores a group of four in 36 bits instead of 64, about 44% less [6]. Their workflow is train dense, prune to 2:4 by removing the two smallest-magnitude weights of every group, then retrain with the same optimizer and schedule while keeping the pattern fixed [6]. Because the constraint is local, pruning can lose some relatively large weights; the authors show that permuting input channels before pruning can preserve more weight magnitude, although for most networks they tested this was not needed [6].

The snippet measures that cost on a random matrix: 2:4 must drop a large weight whenever its group of four contains three large ones, which unstructured pruning at the same 50% would keep.

```python
import numpy as np

rng = np.random.default_rng(0)
W = rng.normal(size=(256, 512))

def prune_2_4(W):
    """Keep the two largest |w| in every group of four consecutive weights along a row."""
    groups = W.reshape(W.shape[0], -1, 4)
    order = np.argsort(np.abs(groups), axis=-1)                # positions sorted by magnitude
    mask = np.ones_like(groups, dtype=bool)
    np.put_along_axis(mask, order[..., :2], False, axis=-1)     # drop the two smallest
    return (groups * mask).reshape(W.shape)

W_24 = prune_2_4(W)
W_un = W * (np.abs(W) > np.median(np.abs(W)))                    # unstructured, also 50%
kept = lambda V: (V**2).sum() / (W**2).sum()
print("zeros: 2:4", (W_24 == 0).mean(), "| unstructured", (W_un == 0).mean())
print(f"squared magnitude kept: 2:4 {kept(W_24):.3f} | unstructured {kept(W_un):.3f}")
print("every group of four has exactly two nonzeros:",
      bool(((W_24.reshape(256, -1, 4) != 0).sum(-1) == 2).all()))
```

Output:

```text
zeros: 2:4 0.5 | unstructured 0.5
squared magnitude kept: 2:4 0.867 | unstructured 0.928
every group of four has exactly two nonzeros: True
```

For a random Gaussian matrix, the 2:4 pattern keeps 86.7% of the squared weight magnitude against 92.8% for unstructured pruning at the same sparsity; retraining is what closes the accuracy gap. Edge cases: the pattern applies along the reduction dimension, so for a convolution the groups run over input channels times kernel positions as laid out by the kernel; and the speed-up appears only in the matrix-multiplication part of a layer, on hardware and libraries that support it.

### Pruning coupled channels

This note lists the dependency rules that decide which channels must be pruned together, the main source of bugs in structured pruning.

When output channel $j$ of a layer is removed, every tensor that consumes or produces channel $j$ must change consistently. The rules for common vision blocks:

- **Sequential convolutions.** Removing output channel $j$ of convolution $\ell$ removes row $j$ of its kernel and bias, the matching entries of any batch normalization after it ($\gamma_j$, $\beta_j$, $\mu_j$, $\sigma_j^2$), and input channel $j$ of convolution $\ell + 1$. This is what the pruning snippet does for an MLP.
- **Residual additions.** In $y = x + F(x)$, channel $j$ of $x$ and channel $j$ of $F(x)$ are added, so they form one group: channel $j$ can only be removed from the block input, the last layer of $F$, the block output and every later block that shares the same residual stream, all at once. The importance of the group must be judged jointly, for example by summing the norms of all its members. Internal channels of $F$ (the middle of a bottleneck) are free.
- **Depthwise convolutions.** Input channel $j$ and output channel $j$ are the same filter, so removing one removes the other, which couples the preceding and following $1 \times 1$ layers.
- **Concatenation.** After $\operatorname{concat}(a, b)$, channel indices of $b$ are offset by the width of $a$; removing a channel of $a$ shifts the indices of $b$ in the next layer's input.
- **Attention heads.** Removing a head removes its query, key and value projections and the matching input slice of the output projection.

Fang et al.'s DepGraph builds these groups automatically from the computational graph and showed that even a simple norm-based criterion works well once the grouping is right, on ResNe(X)t, DenseNet, MobileNet and vision Transformers among other architectures [9]. A practical check after any structured pruning: export the pruned model, run it on a batch, and compare with the masked (not yet sliced) model; identical outputs, as in the snippet, prove that the slicing respected every dependency.

### The gradual pruning schedule

This note gives Zhu and Gupta's sparsity schedule in full and shows how its parameters shape a pruning run.

The sparsity at training step $t$ is [12]

$$
s_t = s_f + (s_i - s_f)\left(1 - \frac{t - t_0}{n\,\Delta t}\right)^{3},
\qquad t \in \{t_0,\; t_0 + \Delta t,\; \dots,\; t_0 + n\Delta t\},
$$

where $s_i$ is the initial sparsity (usually 0), $s_f$ the final sparsity, $t_0$ the training step at which pruning starts, $\Delta t$ the number of training steps between two pruning updates, and $n$ the number of pruning updates. At each update, the weights of every layer are sorted by magnitude and the smallest are masked until the layer reaches sparsity $s_t$; masked weights receive no gradient updates, and once $s_f$ is reached the masks no longer change [12].

**Worked example.** With $s_i = 0$, $s_f = 0.9$, $t_0 = 2{,}000$, $\Delta t = 1{,}000$ and $n = 10$, pruning runs from step 2,000 to step 12,000. After one update ($t = 3{,}000$) the sparsity is $0.9\,(1 - 0.9^3) \approx 0.244$; after five updates ($t = 7{,}000$) it is $0.9\,(1 - 0.5^3) = 0.7875$, already 87.5% of the target; the last five updates add only the remaining 0.11. The cubic shape removes many weights while the network is still very redundant and slows down as fewer, more important weights remain.

**Choices it leaves to you.** The authors report that varying $\Delta t$ between 100 and 1,000 training steps had a negligible effect on final quality, but that pruning while the learning rate is already very small makes it hard for training to recover; they schedule pruning in the regime where the learning rate is still reasonably high, so the pruning schedule must be chosen together with the learning-rate schedule [12]. Training must also continue for a while after $t_0 + n\Delta t$ so that the last cut can be repaired.

### Requantization with a fixed-point multiplier

This note explains how an integer-only network passes results from one layer to the next without any floating-point operation.

After the integer sum of products, a layer must produce its output as 8-bit integers for the next layer, which has its own scale $s_y$ and zero point $z_y$. Jacob et al. write the real product $r_3 = r_1 r_2$ of two quantized matrices, with $r_\alpha = s_\alpha (q_\alpha - z_\alpha)$ for $\alpha = 1, 2, 3$, as [16]

$$
q_3^{(i,k)} = z_3 + M \sum_{j=1}^{N} \bigl(q_1^{(i,j)} - z_1\bigr)\bigl(q_2^{(j,k)} - z_2\bigr),
\qquad
M = \frac{s_1 s_2}{s_3},
$$

where $q_\alpha^{(i,j)}$ is entry $(i,j)$ of quantized matrix $\alpha$, $N$ the inner dimension, and $M$ the only non-integer quantity. Because $M$ depends only on the scales, it is computed offline. They found $M$ empirically always in $(0, 1)$ and write it as [16]

$$
M = 2^{-n} M_0, \qquad M_0 \in [0.5, 1),
$$

with $n$ a non-negative integer. $M_0$ is stored as the 32-bit integer nearest to $2^{31} M_0$, which is at least $2^{30}$ and therefore keeps at least 30 bits of relative accuracy; multiplication by $M_0$ becomes an integer multiplication, and multiplication by $2^{-n}$ a bit shift with correct round-to-nearest behaviour [16].

A worked example: with $s_1 = 0.02$, $s_2 = 0.05$ and $s_3 = 0.4$, $M = 0.0025$. The power of two that brings it into $[0.5, 1)$ is $2^{8} = 256$: $0.0025 \cdot 256 = 0.64$, so $n = 8$ and $M_0 = 0.64$, stored as $\operatorname{round}(0.64 \cdot 2^{31}) = 1{,}374{,}389{,}535$. Two pitfalls: the bit shift must round, not truncate, or a systematic negative bias appears in every layer; and the result must be clamped to the 8-bit range after adding $z_3$ (a fused ReLU is often implemented by this same clamp). Per-channel weight scales simply give one $(M_0, n)$ pair per output channel.

### Choosing the clipping range: min-max, percentile and MSE

This note compares three ways of choosing the quantization range and shows that the best one depends on the bit width.

With range $[x_{\min}, x_{\max}]$ and $b$ bits, the step is $s = (x_{\max} - x_{\min})/(2^b - 1)$. Values inside the range have rounding error up to $s/2$; values outside are clipped to the ends. The three common rules [15]:

- **Min-max**: $x_{\min} = \min x$, $x_{\max} = \max x$. No clipping error; the step is set by the extremes.
- **Percentile**: the ends are low and high percentiles of the calibration values. A fixed fraction of values is clipped.
- **MSE**: choose the ends that minimize $\frac{1}{n}\sum_i (x_i - \hat{x}_i)^2$ on calibration data, usually by grid search. For the last layer of a classifier, Nagel et al. note that a cross-entropy criterion on the logits can be better than MSE, because only the order of the few largest logits matters [15].

```python
import numpy as np

rng = np.random.default_rng(0)
x = rng.laplace(0, 1, 20_000)             # heavy-tailed, like many activations
x[:4] = 40.0                               # four rare outliers

def quantize(x, lo, hi, bits):
    s = (hi - lo) / (2**bits - 1)
    z = np.round(-lo / s)
    return s * (np.clip(np.round(x / s) + z, 0, 2**bits - 1) - z)

def mse(lo, hi, bits):
    return np.mean((quantize(x, lo, hi, bits) - x) ** 2)

shrink = np.linspace(0.05, 1.0, 39)       # candidate ends: a fraction of the min and of the max
for bits in (8, 4):
    p_lo, p_hi = np.percentile(x, [0.05, 99.95])
    errors = {(a, b): mse(a * x.min(), b * x.max(), bits) for a in shrink for b in shrink}
    a, b = min(errors, key=errors.get)
    print(f"{bits}-bit MSE: min-max {mse(x.min(), x.max(), bits):.5f} | "
          f"percentile {mse(p_lo, p_hi, bits):.5f} | "
          f"MSE search {errors[a, b]:.5f} on [{a * x.min():.1f}, {b * x.max():.1f}]")
```

Output:

```text
8-bit MSE: min-max 0.00299 | percentile 0.21929 | MSE search 0.00295 on [-8.3, 40.0]
4-bit MSE: min-max 0.66333 | percentile 0.29765 | MSE search 0.26366 on [-4.4, 12.0]
```

At 8 bits the grid is fine enough to cover the outliers: min-max is essentially optimal, and the percentile rule, which clips the four outliers from 40 to about 7, is 70 times worse in MSE. At 4 bits the grid is so coarse that covering the outliers ruins everything else: min-max becomes the worst rule and the MSE search clips the upper end at 12. Two edge cases: MSE on the tensor is only a proxy for the task loss, so very rare but important values (for example a bright highlight in an image) may deserve more weight than MSE gives them; and ranges estimated on a calibration set that does not match deployment data (daytime images for a night-time camera) clip the values that matter most.

### Beyond round-to-nearest: AdaRound, BRECQ and LSQ

This note describes three methods that improve on the basic recipe of "choose a range, round to the nearest grid point".

**AdaRound** questions the rounding step itself. Rounding every weight to its nearest grid point minimizes the error of each weight separately, but not the error of the layer's output, because the errors of different weights interact through the inputs. Nagel et al. approximate the task loss with a Taylor expansion, which turns the up-or-down decision for every weight into a binary optimization problem; they simplify it to a layer-wise loss on the layer's output and solve a soft relaxation on a small amount of unlabeled data. They report 4-bit weights for ResNet-18 and ResNet-50 within 1% of float accuracy without fine-tuning [20]. Each weight still moves to one of its two neighbouring grid points, so the stored format does not change.

**BRECQ** reconstructs blocks instead of single layers: it quantizes a network block by block and optimizes each quantized block so that its output matches the output of the float block. From an analysis of the second-order error, the authors argue that blocks balance cross-layer dependencies against overfitting to the small calibration set, and they add mixed precision based on approximate sensitivities [71].

**LSQ** applies to quantization-aware training. Instead of setting the scale $s$ of each quantizer from statistics, it makes $s$ a trainable parameter and estimates its gradient through the quantizer, scaled so that the step size learns at a suitable pace relative to the weights. The authors report ImageNet models with weights and activations at 2, 3 or 4 bits, and 3-bit models that reach the full-precision baseline [72]. A pitfall shared by all learnable quantizer parameters: Nagel et al. note that with SGD-type optimizers their learning rate must be lowered relative to the other parameters, which adaptive optimizers such as Adam avoid [15].

## Paper guides

These guides are optional: each walks through one paper the chapter builds on — the problem it poses, the idea, what it showed and what to check when you read it.

### The Lottery Ticket Hypothesis (Frankle and Carbin, ICLR 2019)

**The problem.** Pruning can remove most weights of a trained network, yet the resulting sparse architectures were reported to train badly from scratch. If small networks suffice at the end, why do we need large ones at the start? [13]

**The idea.** Train a network, prune the smallest-magnitude weights, and reset the surviving weights to the values they had **at initialization**, keeping the mask. Train this sparse network in isolation and compare it with the full network. Iterate (iterative magnitude pruning), removing a fixed fraction of the remaining weights in each round [13].

**What it showed.** For fully connected networks on MNIST and convolutional networks (Conv-2/4/6, variants of VGG) on CIFAR-10, the reset subnetworks ("winning tickets") matched the original test accuracy at 10–20% of the weights or less, learned faster than the original above that size, and lost this ability when randomly reinitialized. Iterative pruning found smaller tickets than one-shot pruning. For the deeper ResNet-18 and VGG-19 the method needed learning-rate warm-up to find tickets at higher learning rates [13].

**How to read it.** The main plots show two quantities against the percentage of weights remaining: the iteration of minimum validation loss (the authors' proxy for learning speed, from an early-stopping criterion) and the test accuracy at that iteration. Each curve is an average over several trials, and the comparison that carries the argument is winning ticket versus the same mask with random reinitialization, not ticket versus dense network. Note the architectures and their per-layer pruning rates in the setup table: convolutional and fully connected layers are pruned at different rates [13].

**Limits.** All experiments are on small datasets; finding a ticket costs several full trainings, so it is not a cheaper compression method; the follow-up by Frankle et al. found that at ImageNet scale the weights must be rewound to an early training iteration rather than to initialization [14]; and Liu et al. reported that, with a tuned learning rate, winning-ticket initialization did not beat random initialization in their structured-pruning experiments [3].

**Why it matters here.** It reframed pruning as a question about trainability: what makes a sparse network trainable, and when during training the important structure is decided.

### A White Paper on Neural Network Quantization (Nagel et al., 2021)

**The problem.** Quantization is essential for efficient inference on fixed-point hardware, but practitioners face many interacting choices (symmetric or asymmetric, per-tensor or per-channel, range setting, PTQ or QAT), and published methods are hard to combine [15].

**The idea.** Start from how a fixed-point accelerator computes a matrix multiplication (8-bit inputs, 32-bit accumulators, requantization), derive which quantization choices are cheap on such hardware, and then assemble two tested pipelines: one for PTQ and one for QAT, plus a debugging workflow for models that still fail [15].

**What it showed.** In its experiments, the PTQ pipeline kept 8-bit weights and activations within 0.7% of float for all tested vision and language models; 4-bit weights with PTQ were within about 1% for ResNets and InceptionV3 but cost more for models with depthwise-separable layers, where per-channel quantization helped. The QAT pipeline brought 4-bit weights and 8-bit activations close to float for most models, while 4-bit activations remained hard for MobileNetV2, EfficientNet-lite, DeepLabV3 and especially EfficientDet-D1 [15].

**How to read its tables.** "W4A8" means 4-bit weights and 8-bit activations. The range-setting ablations quantize only weights (with float activations) or only activations (with float weights), so they isolate one source of error at a time. The PTQ results average over 5 runs and the QAT results over 3; DeepLabV3 is scored in mIoU on Pascal VOC, EfficientDet-D1 in mAP on COCO, and the classifiers in ImageNet top-1, so differences in different rows are not on one scale. Look for the per-tensor versus per-channel columns: they show which models are limited by channel range imbalance.

**Limits.** The paper considers one bit width for all layers (no mixed precision), uniform integer formats only, and mainly models from before 2021; Transformers appear through BERT, for which a few activations had to stay in 16 bits under PTQ [15].

**Why it matters here.** It is the most direct source for the practical rules in this chapter: symmetric weights and asymmetric activations, per-channel weights when the hardware allows, MSE range setting, cross-layer equalization for depthwise networks, PTQ first and QAT when PTQ is not enough.
