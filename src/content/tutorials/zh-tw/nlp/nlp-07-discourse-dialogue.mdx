## 先看全貌

對話是持續改變的共同問題。最新一句可能替換原請求、指向較早物件，或修正系統解讀。只理解每句話不夠；系統還要追蹤誰說了什麼、哪些仍不確定，以及參與者實際接受了哪個提案。

<Callout type="tip" title="用最簡單的話說">
想像幫朋友選兩個不同顏色的盒子。朋友先說「藍色那個」，再說「其實要另一個」，最後說「對，就是那個」。你得記得現場有哪些盒子、選擇怎樣改變，以及「對」確認什麼。重複一句好聽的話很容易，拿對盒子卻需要把對話脈絡保持清楚。
</Callout>

## 1. 篇章把意義連到句子之外

篇章（discourse）是跨子句或句子組織的語言；連貫性是讓這些部分能一起理解的關係。關係可以明說，例如使用「因為」，也可以依上下文推論。系統必須區分來源陳述的關係與只是因相鄰而被暗示的關係。

例如「幫浦變熱了。操作員停止了它。」介紹事件、行動者與物件指涉，可能暗示對升溫的回應，卻不一定證明升溫造成停止。加上「因為」就改變明說的關係。摘要器加入這個詞是在增加主張，不只是改善文筆。

可以用圖 $G=(V,E)$ 表示篇章，其中 $V$ 包含文字片段或命題，$E$ 包含帶類型關係。關係可表示解釋、對比、時間順序、詳述或指涉。這是建模選擇，不是每種篇章相依都能放進單一樹。實體指涉可能連接不同局部主題單位中的遠距片段。

首先應問操作性問題：應用必須保留哪些關係？事故查詢需要事件時間、實體身分、否定與證據連結；對話導師還需要學習者的問題與未解的誤解。當一般篇章標籤的錯誤能連到應用結果時，它才具有實際價值。

語法與篇章提供不同線索。語法主詞可能突出，最近討論的實體可能仍顯著，明確轉移主題也可能改變偏好的指涉對象。它們是線索，不是普遍規則。偏好最近提及的模型，在對話刻意回到較早物件時可能失敗。

McRoy [2] 提供連貫性、指涉與互動意義管理的概念基礎。實作時，除了圖或擷取命題，也要保留來源位移與原話。錯誤解讀應能回溯證據，後來修正則能替換解讀，而不用刪掉原始紀錄。

## 2. 提及、先行詞與共指

提及（mention）是指向實體、事件或概念的文字區段；先行詞（antecedent）是協助解讀後續提及的較早表達；共指（coreference）把指向相同實體的提及分組。措辭相似不保證身分相同，兩個不同幫浦都可能叫「備用幫浦」。

Lee 等人的區段式共指模型，可替一個提及的可能先行詞評分 [3]。抽象形式為：

$$
p(a_i=j\mid d)=\frac{\exp s(i,j,d)}{\sum_{k\in A_i}\exp s(i,k,d)}.
$$

其中 $d$ 是文件或對話；$i$ 索引當前提及；$A_i$ 是包含空選項的候選先行詞集合；$a_i$ 是選到的先行詞變數；$s(i,j,d)$ 是學得相容性分數。空選項讓提及可以引入新實體或暫不連結。刪除候選會改變模型能考慮的範圍。

模型既要偵測提及，也要連結。較早實體區段若已被丟掉，後續只改善剩餘候選分數也找不回它。診斷時應分開偵測召回與連結準確率。任務系統連到錯誤裝置，可能比漏掉不相關提及更重要。

以下手寫基準使用明確相容性與新近性，刻意保持小型以揭露失敗。裝置類別由資料提供，程式不會依姓名或社會刻板印象推測屬性。

```python
entities = [
    {"id": "pump_a", "category": "device", "turn": 1},
    {"id": "valve_b", "category": "device", "turn": 2},
    {"id": "operator", "category": "person", "turn": 2},
]
def candidates(category):
    return [e for e in entities if e["category"] == category]
def recent(category):
    choices = candidates(category)
    return max(choices, key=lambda e: e["turn"])["id"] if choices else None
print("Recency baseline for it:", recent("device"))
assert recent("device") == "valve_b"
# In a synthetic annotation, the speaker meant the earlier pump.
intended = "pump_a"
assert recent("device") != intended
# A cautious application preserves ambiguity instead of hiding the choice.
possible = {e["id"] for e in candidates("device")}
resolution = next(iter(possible)) if len(possible) == 1 else None
assert resolution is None and possible == {"pump_a", "valve_b"}
```

基準選最近的相容實體，人工設定的說話意圖卻指較早幫浦。重點不是新近性毫無用處，而是線索無法每次都確定身分。「你指 Pump A 還是 Valve B？」這種澄清能明確保留不確定性。

上下文還包含指示語（deixis）：這個、這裡、現在等表達，依賴說話者、地點、時間或介面選取。應把相關情境與話語一起存。缺少原介面選取的書面逐字稿，可能無法解出「這個裝置」。系統拒絕輸入無法支持的推論，不應被一律判錯。

評估也依標註政策而異。有些語料只連實體，有些包含事件指涉或聯想關係。要決定是否允許空連結、如何標歧義。分數只在此定義下可解讀。本章使用明確合成實體 ID，讓預期範圍可見。

## 3. 回合、行為與共享狀態

對話回合是參與者在交談某時點的貢獻，可以是請求、回答、修正、確認或澄清。同一表面詞依待回答問題而有不同功能：「週二」可能提供日期，也可能修正原日期。

任務導向對話狀態儲存繼續任務所需資訊。設備查詢的欄位可包含裝置、時間區間、測量項目與輸出語言。值應連同來源回合、信心與狀態儲存。未知、明確不存在與不適用，不能全部壓成同一個空字串。

狀態更新可寫成：

$$
s_t=U(s_{t-1},o_t,r_t),\qquad a_t=\pi(s_t).
$$

其中 $s_t$ 是回合 $t$ 後的狀態；$o_t$ 是觀察話語或擷取對話行為；$r_t$ 指出說話者與其他回合脈絡；$U$ 是更新規則；$a_t$ 是下一系統動作；$\pi$ 是狀態到動作的政策。狀態不一定是單一確定紀錄，政策也不一定直接生成文字。

提案與已接受狀態應分開。使用者可以要求選項、檢視再改變。系統建議出現在逐字稿，不代表成為使用者偏好。同樣地，引述文件寫「替換 Pump A」是證據內容，不是當前使用者指令。

修正需要範圍。「其實要 Pump B」可只換裝置而保留時間；「重新開始」可能清除整個任務；「不是昨天」否定值卻未必提供替代。生成器寫回覆前，狀態追蹤器應先表示這些差別。

多方對話還有權責問題。某人的偏好未必覆蓋另一人的指令。共享任務要說明誰能確認變更，哪些事實是觀察而非偏好。說話者標籤、時間戳與對話 ID 屬於資料模型，不只是逐字稿裝飾。

## 4. 信念狀態與有效澄清

話語含糊時，信念狀態（belief state）能保留多個解讀，系統再選擇動作、檢索更多證據或提問。機率最高的解讀不會自動適合執行，因為錯誤後果很重要。

簡單貝氏更新為：

$$
b_t(h)=\frac{p(o_t\mid h)b_{t-1}(h)}{\sum_{h'}p(o_t\mid h')b_{t-1}(h')}.
$$

其中 $h$ 是候選解讀；$b_{t-1}(h)$ 是先前機率；$o_t$ 是新觀察；$p(o_t\mid h)$ 是該解讀下的觀察概似；分母對候選 $h'$ 正規化。簡化更新假設固定假說空間與已指定觀察模型。任務變動需要轉移模型或明確修正操作，不能反覆把每句話當獨立證據。

```python
import numpy as np

hypotheses = ["pump_a", "pump_b", "unknown"]
prior = np.array([0.48, 0.48, 0.04])
ambiguous_likelihood = np.array([0.6, 0.5, 0.2])
posterior = prior*ambiguous_likelihood
posterior /= posterior.sum()
print("After ambiguous evidence:", dict(zip(hypotheses, posterior.round(3))))
action = "clarify" if posterior.max() < 0.9 else "query"
assert action == "clarify"
# A second synthetic observation explicitly names Pump B.
named_likelihood = np.array([0.02, 0.95, 0.03])
updated = posterior*named_likelihood
updated /= updated.sum()
print("After explicit naming:", dict(zip(hypotheses, updated.round(3))))
assert updated[1] > 0.9
assert np.isclose(updated.sum(), 1)
```

概似是教學設定，不是校準模型分數或量測的人類行為。學得系統需要驗證校準與分布轉移下的不確定性。保留未知假說，也避免封閉清單假裝每個真實請求都指已知裝置。

<Figure src={belief} alt="合成的 Pump A、Pump B 與未知信念機率，呈現先驗、含糊觀察後與明確命名後的變化" caption="圖 1 — 信念狀態保留歧義，直到額外證據改變決策。機率為教學設定，不主張具有實證校準。" />

決策理論政策最小化期望損失：$a^*=\operatorname*{arg\,min}_a\sum_h b_t(h)L(a,h)$。其中 $a$ 遍歷允許動作，$L(a,h)$ 是解讀 $h$ 為真時執行動作 $a$ 的代價。提問有成本，但查錯裝置可能成本更高。固定信心門檻只是示範捷徑，不是普遍最佳規則。

應問能區分重要不確定性的問題。只有裝置含糊時，不要再問已確定時間。如果結構不支援請求，就說明限制，不問無關細節。澄清應改變可行下一步，而不是只延長交談。

資訊增益與任務效用不同。某問題可能降低不相關偏好的不確定性，裝置仍未解決。要量測答案是否讓任務正確繼續。反覆澄清也可能令人挫折，因此恢復成功與互動成本要一起評估。

## 5. 含修正測試的確定性狀態追蹤器

對狹義任務，結構化追蹤器是有用基準，揭露語言理解與動作選擇的契約。下面消費的是已擷取事件，不主張能理解任意自然語言。

狀態儲存選定欄位與修訂編號。任何接受的欄位變更，都讓先前確認失效。確認只對明確展示給使用者的版本有效，避免舊的「是」授權新變更提案。

```python
from copy import deepcopy

initial = {"device": None, "period": None, "revision": 0, "confirmed": None}
def update(state, event):
    result = deepcopy(state)
    kind = event["kind"]
    if kind == "set":
        slot, value = event["slot"], event["value"]
        allowed = {"device": {"pump_a", "pump_b"}, "period": {"today", "yesterday"}}
        if slot not in allowed or value not in allowed[slot]:
            raise ValueError("Unsupported slot or value")
        if result[slot] != value:
            result[slot] = value
            result["revision"] += 1
            result["confirmed"] = None
    elif kind == "confirm":
        if event["revision"] != result["revision"]:
            raise ValueError("Confirmation refers to an old proposal")
        if any(result[k] is None for k in ["device", "period"]):
            raise ValueError("Cannot confirm incomplete state")
        result["confirmed"] = result["revision"]
    else:
        raise ValueError("Unsupported event")
    return result
s1 = update(initial, {"kind": "set", "slot": "device", "value": "pump_a"})
s2 = update(s1, {"kind": "set", "slot": "period", "value": "today"})
s3 = update(s2, {"kind": "confirm", "revision": 2})
s4 = update(s3, {"kind": "set", "slot": "device", "value": "pump_b"})
print("Before correction:", s3)
print("After correction:", s4)
assert initial["device"] is None
assert s3["confirmed"] == 2 and s4["confirmed"] is None
try:
    update(s4, {"kind": "confirm", "revision": 2})
except ValueError:
    pass
else:
    raise AssertionError("Stale confirmation was accepted")
```

複製保留先前狀態，方便檢查與測試。真實系統也需要事件 ID，避免重複傳遞把更新套兩次。要區分重複觀察與文字碰巧相同的新修正，保存來源回合與剖析事件，才能追溯語言理解或狀態邏輯錯誤。

欄位缺少不等於否定。「沒有發生故障」填入故障狀態，未提故障則仍未知。使用者撤回值時，追蹤器要明確清除或修訂。只附加逐字稿卻不解讀狀態，會同時保留舊新值；沒有狀態，後續檢索可能任取其一。

允許值有限，讓基準涵蓋範圍清楚。通用系統可使用學得欄位擷取與開放詞彙，但仍要驗證單位、結構與來源。模型信心不能代替合法值。擷取到狀態更新介面應測試格式錯誤、不支援與矛盾事件。

## 6. 上下文視窗、摘要與持續記憶

長逐字稿含有比下一回覆需要更多的資訊。截斷可能移除仍有效限制，摘要可能改作用範圍或確定性。記憶應保留仍相關內容，區分已接受狀態與歷史建議。

可把上下文分為近期回合、結構化任務狀態與檢索證據。近期回合支持局部指涉與語氣；狀態保留已接受欄位及未解問題；證據支持事實主張。角色不同，摘要不能把未驗證模型回覆升格為權威證據。

有用記憶包含值、來源、時間、範圍與狀態。範圍可限一次請求、一場對話或持續偏好。修正應更新有效紀錄，保留先前痕跡。持續儲存需要刻意政策，不能假定使用者提過的每個細節都永久影響未來對話。

可寫成 $m=(v,p,\tau,\sigma,q)$，其中 $v$ 是值、$p$ 是來源、$\tau$ 是時間、$\sigma$ 是範圍、$q$ 是提議、接受或撤回等狀態。這是應用結構而非標準語言形式，目的在讓解讀與檢索可稽核。

滑動視窗可能只留「是」，卻刪了被確認的提案；摘要可能留某裝置，卻漏掉它已被另一裝置替換。應用合成對話測兩者，將重建狀態與明確事件紀錄比較，不只看回覆是否連貫。

檢索舊回合有幫助，但相似度不足。很相似的舊請求可能時間不對或值已撤回。先按對話、參與者與有效狀態過濾，再用檢索分數。保留舊例與當前指令的差別，避免意外重啟已完成任務。

多語對話的正規化與翻譯可能改指涉或禮貌。原話要讓合格覆核者可取得。把繁體中文對話整理成英文摘要可以有用，但需測地域詞、否定與說話者身分。記憶品質是語言任務的一部分，不只是儲存最佳化。

## 7. 任務對話與開放交談

任務導向對話有明確結果：形成查詢、完成類似預約的紀錄、找正確觀察或產生指定報告。開放交談的目標較不明確，接受回覆也更多。兩者都需要一致性，成功標準卻不同。

模組化任務系統分開理解、狀態追蹤、政策、證據存取與文字實現，讓錯誤容易定位。端到端系統可整合這些功能，但仍要測出錯狀態與措辭問題的差別。Hagiwara 的對話序列模型閱讀 [1] 是起點，綜述 [4,5] 則描述更廣設計家族。

回覆生成可寫成 $p_\theta(u_t\mid h_t,s_t,e_t)$，其中 $u_t$ 是下一話語、$h_t$ 是選定歷史、$s_t$ 是任務狀態、$e_t$ 是證據、$\theta$ 是模型參數。條件分布說明生成器收到什麼，不保證它遵守每個欄位或證據。

任務政策可選澄清、查詢、解釋或拒絕不支援操作，再由生成器說出這個動作。這讓對話流暢度不決定查詢是否準備好。合法動作與結構有限時，確定性政策可能是很強的基準。

開放交談受益於彈性語言，但角色風格不能覆蓋事實一致性。系統可能很吸引人，卻編造過去互動，或暗示未發生的動作已完成。對話主張要對實際紀錄檢查，外部主張則對證據檢查，兩者不同。

應用也需要明確完成條件。交付報告可結束任務，對話則能開新任務。應記錄轉換，避免舊確認與欄位默默套用。沿用裝置偏好可能合理，沿用無關操作授權卻不合理。

## 8. 工具邊界與有證據的動作報告

工具連接的對話系統產生可由軟體執行的提案。提案、執行與結果是不同事件。「我查了資料庫」應由成功查詢結果支持，不能只是模型生成了查詢描述。

工具學習研究討論基礎模型規劃、選工具、組參數及使用回饋 [6]。應用只應透過明確結構暴露允許操作，執行前驗證工具與參數，再把結果狀態及證據 ID 加入狀態。這是把一般介面正確性套到語言控制器。

唯讀證據也可能含命令文字。操作手冊可引用指令，檢索對話可含另一人的請求；它們仍是來源內容，不應更新當前使用者任務或擴大允許操作。角色與來源標籤必須穿過檢索與摘要而保留。

合成查詢助理只有確定裝置與時間才能形成提案。系統可展示待處理提案並問缺失資訊。結果要區分成功、沒有匹配觀察與執行錯誤。全部寫成一般流暢答案，會抹掉理解實際過程需要的資訊。

重試也要有狀態。重試唯讀查詢可能合理，重複改外部狀態的操作可能產生第二次效果。記錄請求 ID 與執行狀態，讓軟體邊界強制語意；不能只靠模型記得動作已執行。

本章不執行外部工具，狀態示例停在提案追蹤。真實部署要把提案驗證器與結果解讀分開測，不與語言生成混為一談。[生成與部署章](/zh-tw/learn/nlp/nlp-08-generation-deployment/) 繼續說明版本契約與工作量測。

## 9. 評估完整對話，不只一個回覆

看起來正確的回覆可能隱藏錯欄位、過期記憶或未執行動作。評估應跨完整對話量測中間狀態與最終任務。Deriu 等人的綜述 [4] 說明任務對話、開放交談與互動問答為何需要不同方法。

對指定欄位集合 $J$，定義精確狀態準確率：

$$
A_{\mathrm{state}}=\frac{1}{N}\sum_{t=1}^{N}\mathbf1\{\hat s_{t,j}=s_{t,j}\text{ for every }j\in J\}.
$$

其中 $N$ 是評估回合數；$s_{t,j}$ 是回合 $t$ 的參考欄位 $j$；$\hat s_{t,j}$ 是預測值；$\mathbf1$ 在全部選定欄位匹配時為一，否則為零。嚴格指標揭露大量空值或簡單欄位平均所隱藏的錯誤。要指定欄位集合與未知值處理。

```python
reference = [
    {"device": "pump_a", "period": None},
    {"device": "pump_a", "period": "today"},
    {"device": "pump_b", "period": "today"},
]
predicted = [
    {"device": "pump_a", "period": None},
    {"device": "pump_a", "period": "today"},
    {"device": "pump_a", "period": "today"},
]
slots = ["device", "period"]
joint = sum(all(p[j] == r[j] for j in slots)
            for p, r in zip(predicted, reference))/len(reference)
slot_accuracy = sum(p[j] == r[j] for p, r in zip(predicted, reference)
                    for j in slots)/(len(reference)*len(slots))
print("Exact state accuracy:", joint)
print("Per-slot accuracy:", slot_accuracy)
assert joint == 2/3 and slot_accuracy == 5/6
# The final device is wrong despite many correct fields.
assert predicted[-1]["device"] != reference[-1]["device"]
```

任務成功應檢查最終所求，不只看長度或親切風格。本例要求裝置、時間與證據正確，並尊重修正；另報不受支持動作主張與未解指涉。短對話若查錯裝置，不是有效率的成功。

人類評估要展示足夠歷史、指定判斷工作。只看最後回覆，無法判斷是否尊重修正。應隱藏／隨機化系統身分，定義錯誤類型並保留歧見。Schmidtova 等人 [7] 說明明確幻覺定義與方法報告為何重要。

當相關使用者或事故造成洩漏時，按對話與群組切分。相鄰回合不能散落訓練與測試。加入主題切換、重名、含糊代名詞、修正、過期確認及工具失敗等挑戰。記錄是否由使用者模擬器產生；模擬成功是該模擬器下的證據，不自動代表人類可用性。

使用同一對話配對比較，並在對話層級回報不確定性。回合彼此相依，大量回合不等於相同數量獨立測試。也要評估修復：系統能否認出誤解、問有效問題，再恢復正確結果。

## 現代觀點

當代閱讀地圖連接語言結構、系統設計與評估。來源查證至 2026 年 10 月 4 日，標明發表日期與手稿狀態，不把所有來源當成同樣新。

**Ni 等人的系統性綜述 [5]** 發表在 Artificial Intelligence Review 的 2023 卷，依模型與系統類型整理深度學習對話。任務導向與開放領域的區分，解釋為何一個回覆指標不能描述所有對話。本章綜合是先依實際目標選評估，再檢查目標依賴的狀態與證據失敗。

**Deriu 等人的評估綜述 [4]** 區分任務對話、開放交談與互動問答，把人工和自動評估對應其結構。實務重點是同時量測元件及結果：話語品質好仍可能任務失敗，嚴格欄位匹配則可能忽略無益澄清策略。

**Qin 等人的工具學習綜述 [6]** 發表於 2024，整理基礎模型、工具、規劃與回饋互動，提醒我們除了文字品質，也檢查參數構造與結果使用。應用層級結論是明確維持提案、執行與證據狀態。工具擴大能嘗試什麼，不免除驗證嘗試或報告真實結果。

**Schmidtova 等人的 2025 人類評估綜述 [7]** 記錄幻覺定義與評估差異。對話中要區分與歷史不一致、無支持外部主張，以及錯誤動作報告。它們需要不同證據，也可能需要不同覆核者。公開標註指南才讓分數可解讀及重現。

| 系統責任 | 有用表示 | 揭露失敗的測試 |
|---|---|---|
| 指涉 | 提及、候選、實體 ID | 兩個相容裝置與含糊代名詞 |
| 任務追蹤 | 欄位、修訂、來源回合 | 先確認後再修正 |
| 不確定性 | 替代解讀或信念狀態 | 裝置不明後再明確命名 |
| 記憶 | 來源、範圍、狀態 | 撤回後仍檢索到舊值 |
| 工具控制 | 已驗證提案與執行狀態 | 查詢失敗或重複而未編造成功 |
| 回覆 | 選定動作、狀態、證據 | 流暢文字改了數值或指涉 |
| 評估 | 完整對話、明訂錯誤類型 | 欄位準確率高但最終任務錯 |

當前設計愈來愈結合彈性生成與明確狀態、檢索和工具介面。綜述支持這張圖的不同部分；表格是教學綜合，不是新標準架構。模型可改善語言彈性，狀態邏輯仍是小型確定元件。假定所有責任都要共同學習前，先比較模組化基準。

開放問題包括長上下文指涉、任務變更下校準、多語修正、過期記憶、可靠工具結果解讀與可擴充人類評估。更多上下文能找回證據，也能加入過期或矛盾材料。應測記憶選擇與狀態，而非把長視窗當完整解方。

下一研究問題應夠狹窄才能評估：「明確修訂能否阻擋過期確認？」或「澄清能否恢復含糊裝置指涉，又不重問已知欄位？」保留完整對話軌跡與成功條件，才能把展示變成可檢查的證據。

## 重點整理

- 篇章需要孤立句意之外的實體指涉、關係與範圍。
- 提及偵測與先行詞選擇是不同共指錯誤來源。
- 對話狀態區分提案、接受值、修正與確認。
- 信念保留歧義，澄清應解決影響任務的不確定性。
- 記憶需要來源、時間、範圍與狀態，並保留撤回。
- 工具提案、執行與觀察結果必須維持不同事件。
- 依明確證據，跨完整對話評估狀態、修復與最終結果。
