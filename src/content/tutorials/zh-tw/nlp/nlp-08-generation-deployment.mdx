## 先看全貌

語言應用必須選擇說什麼、清楚表達，並支持說出的內容，這是不同責任。可讀句子可能描述錯事件，正確句子也可能漏掉使用者需要的警告。部署增加第四項責任：結果必須可預期地抵達，並留下足夠上下文讓人追查失敗。

<Callout type="tip" title="用最簡單的話說">
想像寫一張科學實驗小紙條給朋友。先選重要觀察，再整理順序讓朋友知道誰做什麼，最後寫句子。若把「沒有移動」變成「移動」，字再漂亮也寫錯了。有用的生成器要讓紙條更好讀，同時保留實驗意義。
</Callout>

## 1. 選模型前先定義生成問題

生成是產生內容與形式都符合任務的序列。輸入可為文件、表格、來源語句、對話歷史或檢索段落，輸出可是一句或結構報告。選擇改變建模問題，也改變什麼算錯誤。

條件序列模型寫成：

$$
p_\theta(y\mid x,c)=\prod_{t=1}^{T}p_\theta(y_t\mid y_{\lt t},x,c).
$$

其中 $x$ 是來源輸入；$c$ 是要求語言或格式等任務脈絡；$y=(y_1,\ldots,y_T)$ 是含結束詞元的輸出；$y_{\lt t}$ 是 $t$ 前的詞元；$\theta$ 是學得參數。分解描述分布，不保證取樣輸出獲得來源支持。

先用普通語言寫契約。設備報告可寫：「給定附時間戳的觀察，用兩句描述目前溫度及任何明確記錄的故障，保留裝置名稱、單位、數字與否定。」它揭露「好好摘要」這種無限制指令掩蓋的遺漏和矛盾，也指出確定性基準能處理的欄位。

分開三種操作。**內容選擇**選使用者相關觀察；**句子規劃**決定順序、分組與指代表達；**文字實現**把計畫寫成合語法文字。McRoy [2] 提供語言基礎。神經系統可在內部合併，但仍需分別測試責任。

來源若有高溫、稍後正常溫度及明確沒有故障，選最高值與選最新值會產生不同報告。語法流暢不會決定該用哪個規則。要記錄描述目前狀態、極端事件，還是整段軌跡；時間與範圍屬於輸入契約。

輸入結構狹窄時，模板是有用基準，可完全控制允許主張，方便定位失敗。限制也清楚：無法自然涵蓋任意關係、指涉或篇章。應量測涵蓋，不把模板視為天生不足。新增彈性解決已記錄的基準失敗時，學得生成器才有明確價值。

## 2. 擷取式摘要：在預算內選證據

擷取式摘要選來源句子，抽象式摘要可改寫或融合。擷取讓來源清楚，但仍可能因缺上下文、時間衝突或未解代名詞而誤導。選「它故障了」卻沒有先行詞，即使每個字都出自來源，仍是篇章錯誤。

假設文件有候選句 $s_1,\ldots,s_n$，句 $i$ 用單位向量 $v_i$ 表示，使用者查詢用單位向量 $q$ 表示。簡單相關分數是 $r_i=v_i^\top q$。為避免重複，可用最大邊際相關性（maximal marginal relevance，MMR）[3]：

$$
i^*=\operatorname*{arg\,max}_{i\notin S}\left[\lambda r_i-(1-\lambda)\max_{j\in S}v_i^\top v_j\right].
$$

其中 $S$ 是已選句索引；$i^*$ 是下一索引；$\lambda\in[0,1]$ 平衡相關與相似已選句；$S$ 為空時，最大相似度定義零。向量長度為一，所以內積是餘弦相似度。這是貪婪選擇規則，不是摘要品質全域最佳的證明。

以下用二元詞指示讓決策可檢查，四句皆為合成。移除少數功能詞能降低語法支配程度，卻也可能移除重要區別。未研究影響前，不應直接將此分詞器用於一般文字。

```python
import re
import numpy as np

sentences = [
    "Pump A temperature reached 80 C during the test.",
    "The test recorded Pump A temperature at 80 C.",
    "Pump A vibration triggered a shutdown warning.",
    "The technician replaced a label on the cabinet.",
]
query = "pump temperature vibration shutdown"
stop = {"a", "the", "at", "on", "during"}
def tokens(text):
    return set(re.findall(r"[a-z0-9]+", text.lower())) - stop
vocab = sorted(set().union(*(tokens(s) for s in sentences), tokens(query)))
def vector(text):
    v = np.array([w in tokens(text) for w in vocab], dtype=float)
    return v / max(np.linalg.norm(v), 1e-12)
V = np.stack([vector(s) for s in sentences])
q = vector(query)
relevance, similarity = V @ q, V @ V.T
selected = []
for _ in range(2):
    redundancy = similarity[:, selected].max(axis=1) if selected else np.zeros(4)
    score = 0.55 * relevance - 0.45 * redundancy
    score[selected] = -np.inf
    selected.append(int(np.argmax(score)))
print("Selected indices:", selected)
print("Summary:", " ".join(sentences[i] for i in sorted(selected)))
assert len(set(selected)) == 2
assert 2 in selected and not ({0, 1} <= set(selected))
```

選到的兩句包含停機與一個溫度句，避免幾乎重複的觀察。選後排序索引可恢復來源順序：選擇順序量測邊際價值，呈現順序則要支持理解。本例沒有學得參數，因此沒有訓練洩漏；學得相關性模型需要自己的訓練／驗證／測試程序。

<Figure src={selection} alt="四個合成設備句子的餘弦相似度矩陣，及顯示兩個所選句的相關性與重複度圖" caption="圖 1 — 擷取基準把取捨顯示出來。相似溫度句競爭有限摘要空間，停機句則提供不同內容。" />

真實預算通常限制詞元而非句數。整句分詞長度能放進剩餘預算，才能加入。沒有句子放得下時，回傳較短摘要或另做改寫；默默截句可能刪掉條件或否定。多文件摘要應把近似重複報告分組，避免多份副本假裝獨立證據。

重複只是其中一個限制。事故摘要可能要求至少一個後果句、全部重要數值，以及明確的未解分歧標記。把它們寫成內容計畫限制最容易檢查。高相關分數不能補償必需警告被刪，應保留來源 ID 與時間戳。

## 3. 抽象式生成與條件序列學習

改寫模型能融合觀察、提高可讀性，也能編造來源未建立的連接。「溫度高，因此幫浦故障」若來源只記同時事件，就新增因果。應先依受支持命題建立目標，再把流暢文字當最終結果。

序列到序列學習將輸入映成輸出 [4]；編碼器產生來源表示，解碼器逐詞元預測，注意力讓解碼器在預測時讀不同來源位置 [5]。[語言模型章](/zh-tw/learn/nlp/nlp-05-language-models/) 討論架構；這裡關心輸出如何與任務契約互動。

訓練通常提供正確的先前目標詞元，稱為教師強制 [4]。詞元損失為：

$$
\mathcal L(\theta)=-\frac{1}{M}\sum_{b=1}^{B}\sum_{t=1}^{T_b}m_{bt}\log p_\theta(y_{bt}\mid y_{b,\lt t},x_b).
$$

其中 $B$ 是例數；$T_b$ 是範例 $b$ 填補後的目標長度；$m_{bt}$ 對真實目標為一、填補為零；$M=\sum_{b,t}m_{bt}$ 是真實詞元數；$x_b$、$y_{bt}$、$y_{b,\lt t}$ 分別是來源、目前目標與參考前綴。使用自然對數。遮罩從損失移除填補，不會自動從計算移除。

仔細檢查位移。解碼器輸入從起始詞元開始，目標從第一個輸出詞元開始；目標含結束符號讓模型學停止。填補與結束必須分開，否則可能獎勵錯誤停止。不同長度文件批次要記錄按詞元或例子平均，因為它們給長文件不同權重。

推論時解碼器讀自己的預測，錯名字或否定可改變後續機率。低教師強制損失未量測完整回饋，因此要評估生成序列與參考條件概似。摘要檢查命題是否受支持，翻譯檢查完整來源意義是否保留。

資料建構往往比小架構調整更重要。使用未來事件寫的目標摘要，不適合部署於事件之前。翻譯對若默默修正數字，就訓練模型改數字。來源版本、指南與目標來源要一起保留，按文件、對話或事件分組切分，防止近重複跨訓練測試。

注意力可診斷計算存取，不能證明事實。詞元讀到正確證據仍能表達相反意思。驗證要看輸出主張、來源實體、關係及範圍。狹義結構任務可讓生成器說出已驗證計畫；自由文字的驗證不完整，應明說限制。

## 4. 解碼選序列，不提供保證

訓練分布不指定唯一答案。貪婪解碼選最高下一詞元，束搜尋保留數個部分序列，取樣則按可能經溫度調整的分布抽詞。這些控制搜尋與變化，不會讓無支持內容變可靠。

候選序列分數為：

$$
\ell(y\mid x)=\sum_{t=1}^{T}\log p_\theta(y_t\mid y_{\lt t},x).
$$

其中 $\ell$ 是完整序列對數機率；$T$ 包含結束詞元；其他符號同前。原始對數機率中，每個新增詞元都貢獻非正項，因此可能偏好短序列。長度調整改搜尋目標，應說明形式並在驗證資料調整，不能默默加入。

微型條件模型有兩個競爭起始詞，展示選最佳下一詞不一定得到最佳完整序列。機率為實驗設定，不由語言資料估計。

```python
import math

table = {
    (): {"safe": 0.55, "close": 0.45},
    ("safe",): {"stop": 0.51, "wait": 0.49},
    ("close",): {"valve": 0.99, "door": 0.01},
}
def next_probs(prefix):
    return table.get(prefix, {"<eos>": 1.0})
def decode(width):
    beams = [((), 0.0)]
    for _ in range(3):
        candidates = []
        for seq, score in beams:
            if seq and seq[-1] == "<eos>":
                candidates.append((seq, score))
                continue
            for token, prob in next_probs(seq).items():
                candidates.append((seq + (token,), score + math.log(prob)))
        beams = sorted(candidates, key=lambda pair: pair[1], reverse=True)[:width]
    return beams[0]
greedy, beam = decode(1), decode(2)
print(greedy[0], round(math.exp(greedy[1]), 4))
print(beam[0], round(math.exp(beam[1]), 4))
assert greedy[0] == ("safe", "stop", "<eos>")
assert beam[0] == ("close", "valve", "<eos>")
assert beam[1] > greedy[1]
```

完整機率為 0.2805 與 0.4455，束搜尋在人工樹中找到較可能序列。這只說明模型機率。若 close valve 與來源指令矛盾，更好的機率搜尋仍會答錯。搜尋品質與任務正確需要分開量測。

溫度取樣定義為 $p_i^{(\tau)}=\exp(z_i/\tau)/\sum_j\exp(z_j/\tau)$。其中 $z_i$ 是詞元 $i$ 的 logit，$j$ 遍歷詞彙，$\tau\gt0$ 是溫度。低溫集中高分詞，但事實錯誤也可能最高分，因此降低隨機不會移除它。

要明訂輸出限制、停止規則及達上限後的行為，截斷翻譯不能當完整結果。解碼參數與模型一起記錄，讓評估可重現。確定報告可能更重視重現而非風格多樣，創作則可能需要多樣建議，但證據敏感主張仍要驗證。

## 5. 翻譯跨形式保留意義

翻譯是具強內容限制的條件生成：保留來源意義，同時產生自然目標語言。詞序、形態、慣用語與隱含上下文，使它不只是逐詞替換。McRoy 翻譯討論 [2] 可搭配 Hagiwara 序列到序列材料 [1]。

應分開評估**充分性（adequacy）**——來源意義是否保留——與**流暢度（fluency）**——目標是否自然。流暢譯文可能漏例外、反轉否定或改行動者；字面翻譯則可能保技術內容卻不自然。可接受平衡取決於用途，必須在選模型或指標前指定。

結構基準可以完整保留事件紀錄，只改文字實現。紀錄若有裝置、值、單位、時間與故障狀態，先驗欄位再選目標模板。這是受控資料到文字，不是通用翻譯器；它能隔離實現、擷取及解讀的錯誤。

通用翻譯器可用詞彙表保術語，仍要在上下文測試。必需詞可能存在，卻附錯實體；保留數字也不夠，因為值可能重新分配。可測「Pump A 比 Pump B 熱」、「閥門可能保持關閉」、「中午前未偵測到故障」等關係。最小改動揭露比較、模態、否定與時間是否被尊重。

語言標籤與正規化屬於契約。繁體與簡體是不同輸出要求；廣泛語言標籤不指定書寫系統、地域術語與標點。存來源前不要破壞性轉換，應並存原文與正規化輸入，讓覆核者追查誤譯。

低資源情況的不確定性可能來自訓練涵蓋有限，而非輸入含糊。報告應記錄領域、方言、文字系統與語言對。短產品描述驗證不代表長技術指令也成立。覆核者不能讀兩語就無法直接評充分性，要使用合格雙語覆核並說明缺口。

## 6. 評估詞語、主張與讀者結果

單一自動分數無法總結所有生成品質。詞彙重疊容易重現又便宜，但一個小詞改動就能反轉意思。自動指標應按指定程序比較，再檢查應用真正在乎的錯誤維度。

BLEU 使用截限 n-gram 精確率與短度懲罰評翻譯 [6]；ROUGE 包含偏召回的摘要重疊量測 [7]。它們比較候選與參考，不證明語意等價或來源支持。報分數要指定版本、分詞、聚合與參考集合；句層級與語料層級數字行為未必相同。

簡單 unigram 召回檢查：

$$
R_1=\frac{\sum_w\min(c_{\mathrm{ref}}(w),c_{\mathrm{hyp}}(w))}{\sum_w c_{\mathrm{ref}}(w)}.
$$

其中 $w$ 遍歷詞型；$c_{\mathrm{ref}}(w)$、$c_{\mathrm{hyp}}(w)$ 是參考與候選詞頻；分母是參考詞元數。它示範 ROUGE 式的一個部分，以下最小實作沒有重現完整套件的每項前處理或聚合。

```python
import re
from collections import Counter

def words(text):
    return re.findall(r"[a-z0-9]+", text.lower())
def overlap_recall(reference, hypothesis):
    ref, hyp = Counter(words(reference)), Counter(words(hypothesis))
    return sum((ref & hyp).values()) / sum(ref.values())
reference = "Pump A is operating at 30 C."
contradiction = "Pump A is not operating at 30 C."
score = overlap_recall(reference, contradiction)
print("Unigram recall:", score)
assert score == 1.0
assert ("not" in words(reference)) != ("not" in words(contradiction))
```

矛盾句保留所有參考詞，因此召回 1.0。精確率會懲罰多出的詞，但小懲罰仍不能表達否定反轉的重要性。這是受控反例，不表示重疊指標永不與人類判斷相關，而是說明必須配合對意義敏感的檢查。

設備應用可分別計**無支持主張**、**必需主張遺漏**、**數值關係錯誤**與**未解指涉**。它們是專案自訂錯誤類別。每類都要給標註者正反例，包含缺證據與矛盾證據。少說可能減無支持，卻漏關鍵資訊，因此兩種方向都要回報。

COMET 等學得指標 [8] 使用訓練表示與人類品質監督評翻譯，可捕捉字面重疊以外差別，但帶有自己的版本、訓練分布與語言涵蓋。輸出只是在那些條件下的量測，應測應用重要的否定、數量與術語錯誤。

人工評估要隱藏系統身分、隨機呈現、保留來源並指定決策。先請覆核者標無支持陳述，再判整體實用；總偏好可能獎勵風格而漏罕見關鍵錯誤。應報誰覆核、涵蓋哪些語言領域與如何處理歧見，小型裁決挑戰集合則與一般流量樣本分開。

聚合要以有意義單位。同事故的句子相關，把它們當獨立例會誇大確定性。應在同來源事故比較模型，檢查各領域而非只看總平均。模型改變後，重跑固定測試及新樣本，避免反覆調整逐漸把測試變開發資料。

## 7. 訓練實務遇上服務限制

應用輸入長度及計算成本不一，填補讓張量矩形，卻對人工位置花工作。Hagiwara 第 10 章把填補、排序與遮罩連到實際推論 [1]。正確損失遮罩防止填補改目標，未必防止硬體處理填補。

定義填補利用率：

$$
u=\frac{\sum_{b=1}^{B}L_b}{B\max_b L_b}.
$$

其中 $L_b$ 是請求 $b$ 的真實詞元長度；$B$ 是批次大小；$u$ 是填補位置中真實詞元比例。這是工作量診斷，不是實測加速。按相近長度組批可提高利用率，也可能讓請求等待適合批次。

```python
import numpy as np

lengths = np.array([8, 64, 12, 60, 10, 56, 14, 52])
def utilization(values):
    batches = values.reshape(-1, 4)
    real = int(batches.sum())
    padded = int((batches.max(axis=1) * 4).sum())
    return real / padded
arrival = utilization(lengths)
bucketed = utilization(np.sort(lengths))
print("Arrival-order utilization:", round(arrival, 3))
print("Length-bucketed utilization:", round(bucketed, 3))
assert bucketed > arrival
# Two cache arrays (keys and values), with a toy equal head layout.
layers, kv_heads, head_dim, cache_tokens, bytes_per_value = 4, 2, 16, 128, 4
cache_bytes = 2 * layers * kv_heads * head_dim * cache_tokens * bytes_per_value
print("Toy cache bytes:", cache_bytes)
assert cache_bytes == 131072
```

自迴歸注意力常快取先前鍵和值避免重算。簡單布局近似 $M_{\mathrm{KV}}=2N_{\mathrm{layers}}H_{\mathrm{KV}}d_hTb_v$，其中 $N_{\mathrm{layers}}$ 是層數、$H_{\mathrm{KV}}$ 是鍵／值頭數、$d_h$ 是頭維度、$T$ 是快取詞元數、$b_v$ 是每值位元組。因子二表示鍵與值。實際還有配置及中繼資料成本，也可能用不同布局。

應分開首詞元時間、後續詞元間隔、總完成時間及負載吞吐。短提示長答案與長提示短答案壓力不同，端到端要含前處理、等待、驗證與序列化。快速解碼器可以放在緩慢應用內。

按量測工作設定請求長度、輸出上限及佇列期限，報告逾時回傳部分結果、可重試錯誤或經覆核替代。反覆重試會放大過載。部署測試應含異常長輸入及同時請求，不只舒服放進記憶體的平均輸入。

## 8. 可重現服務契約與整合專題

把系統包成輸入假設及輸出明確的函數。只有模型檔無法重現預測，分詞、正規化、證據選擇、解碼、驗證及格式都影響行為。Hagiwara 部署章 [1] 提供版本、測試、訓練—服務差異與監控的實務閱讀。

下面是狹義結構的確定報告函數，不開伺服器也不使用外部服務，展示欄位驗證與追溯。事件紀錄是可信結構輸入，從原文取得並驗證紀錄屬於另一個 NLP 階段。

```python
import math

VERSION = "equipment-template-1"
def report(event):
    required = {"device", "temperature_c", "fault", "evidence_id"}
    if set(event) != required:
        raise ValueError("Unexpected input fields")
    if not isinstance(event["device"], str) or not event["device"].strip():
        raise ValueError("Missing device")
    value = event["temperature_c"]
    if isinstance(value, bool) or not isinstance(value, (int, float)) or not math.isfinite(value):
        raise ValueError("Temperature must be finite")
    if event["fault"] not in ("present", "absent", "unknown"):
        raise ValueError("Unknown fault status")
    if not isinstance(event["evidence_id"], str) or not event["evidence_id"]:
        raise ValueError("Missing evidence ID")
    phrases = {"present": "A fault was recorded.",
               "absent": "No fault was recorded.",
               "unknown": "Fault status was not recorded."}
    text = f"{event['device']} measured {value:g} C. {phrases[event['fault']]}"
    return {"text": text, "evidence_id": event["evidence_id"], "version": VERSION}
output = report({"device": "Pump A", "temperature_c": 30,
                 "fault": "absent", "evidence_id": "synthetic-event-01"})
print(output)
assert output["text"] == "Pump A measured 30 C. No fault was recorded."
assert output["version"] == VERSION
```

注意 absent 與 unknown。「沒有記錄到故障」描述紀錄證據，不表示故障不可能。編碼差別防止實現階段把缺證據升格為確定。摘要與翻譯也要保留限定、範圍與不確定性。

替換成學得模型時，文字旁要回傳模型版本與已驗證證據 ID，保存前處理版本及解碼設定。紀錄應能診斷，卻不必無謂保留私密原文。受控語料可能只需文件 ID 與可重現授權查找；適當保留政策取決於應用。

新版本先服務有限比例請求，用相同錯誤類別與穩定版比較，同時看延遲、完成率與證據正確。回復應簡單：儲存套件能一起選回舊模型、分詞器與驗證規則。舊模型混新分詞器可能產生各元件單獨未出現的錯誤。

整合專題是具書面契約、合成觀察、擷取基準、結構模板及錯誤表的小型報告應用。加入改寫、否定、矛盾時間、未知欄位與長輸入，明說支援哪些案例。有明確限制的受控應用，比只用漂亮示例評無限制生成器更能展現理解。

## 現代觀點

當代生成研究改架構、調適與服務技術，上面任務問題仍必要。以下來源是互補地圖，證據查證至 2026 年 10 月 4 日。

**Li 等人的預訓練生成綜述 [9]** 依輸入表示、架構與最佳化整理方法，涵蓋應用及評估。這有助定位變化：檢索改可用證據，編碼器—解碼器改條件架構，調適改參數或目標。本章綜合是先定位失敗階段再選更強模型。綜述早於部分後續系統，應配較新評估與部署證據閱讀。

**Schmidtova 等人的人類評估綜述 [10]** 檢查研究如何定義與評幻覺，指出術語不一致及方法報告缺失。實務重點是分開來源支持、世界知識與嚴重度，公開標註與歧見處理。判斷程序清楚，人工分數才可解讀；綜述不是替某自動偵測器認證。

**WMT25 評估結果 [11]** 分開片段品質預測、錯誤區段標註與品質導向修正，指出系統及片段評估可能偏好不同方法，語言多樣仍困難。跨語料排名兩模型不代表能拒絕某個錯誤輸出，翻譯品質評量與自動接受需要不同驗證。

**Kwon 等人的 PagedAttention [12]** 研究服務中快取配置與共享，處理浪費及記憶體允許的批次大小，替前面快取計算提供系統觀點。論文提升只屬其工作負載與比較，本機微型計算無法重現。採服務設計前，先量請求長度、並行與延遲目標。

| 設計軸 | 比較選項 | 所需證據 |
|---|---|---|
| 內容 | 選擇、改寫、結構轉文字 | 必需內容與來源支持錯誤 |
| 條件 | 原文、檢索、對話、結構紀錄 | 來源、相關性與上下文涵蓋 |
| 模型使用 | 固定預訓練、調適、狹義確定基準 | 保留任務表現與維護成本 |
| 解碼 | 貪婪、搜尋、受控取樣 | 完整度、變化與語意錯誤 |
| 評估 | 重疊、學得分數、主張檢查、人工覆核 | 與應用失敗類別的一致性 |
| 服務 | 組批、快取、佇列政策 | 端到端延遲、記憶體與完成行為 |

這些閱讀的綜合是從生成合理句子，轉向經營可量測應用。強模型擴大涵蓋，也讓流暢錯誤更難察覺；好服務容許更大工作量，卻不直接改善語意有效性。穩健比較要把模型變更與穩定契約、記錄的負載配對。

開放問題包含長上下文稀少限制保留、低資源語言評估、偵測無支持而不壓制有用回答，以及可負擔的可靠人類判斷。評估模型可能與生成器共享錯誤，尤其訓練資料相近。把接受完全交給另一模型前，應測獨立證據檢查與雙語覆核。

研究筆記應以具體不確定性收尾：「驗證器能抓技術報告的否定反轉嗎？」或「長度組批能滿足佇列期限嗎？」教科書提供建模語言，綜述提供替代地圖，受控實驗決定應用可以支持哪個主張。

## 重點整理

- 生成需要內容契約、文字實現策略與支持意義評估。
- 擷取保留句子來源，仍可能漏上下文或必需事實。
- 教師強制概似、解碼品質與應用正確量測不同事物。
- 翻譯必須保留實體、關係、數字、否定、範圍與目標要求。
- 重疊及學得指標仍需主張檢查與明訂人工評估。
- 填補利用率與快取大小是工作量診斷，實際服務要另外量。
- 整個前處理—模型—解碼—驗證套件都要版本化，回復也要可重現。
