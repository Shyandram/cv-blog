## 先看全貌

**自然語言處理**（natural language processing, NLP）研究如何讓系統處理人類語言：搜尋文件、分類客訴、辨識人名、翻譯、回答問題或產生回覆。這些任務可以共用表示，但需要不同的輸出與不同的評估方式。

影像模型讀取像素；文字模型讀取離散符號的序列。兩者都能使用嵌入、注意力與共用的預訓練表示，這也是 [ML 系列](/zh-tw/learn/ml/ml-04-vision-transformers/)中許多機制可以直接沿用的原因。語言也有自己的難題：同一個詞可能有好幾個意思，改變語序可能反轉一句話的意思，而一個完全流暢的句子也可能陳述錯誤的事實。

<Callout type="tip" title="用最簡單的話說">
語言模型在玩猜字遊戲：「請打開那扇」後面接什麼？「門」是好答案，「香蕉」就不太對。它從大量例子中學會哪些接法比較可能。要玩這個遊戲，它得先把文字切成它認得的小片段（token），再把每個片段變成一串數字（嵌入）。不過，一個有用的助理不能只會猜字：它還要聽懂要求、找到正確的資訊，並確認自己的回答真的有根據。
</Callout>

一定要先定義任務。「理解評論」可能是情緒分類、抽取產品缺陷，也可能是整理常見抱怨。在選模型之前，先寫下預期的輸入、輸出與可接受的錯誤。

## 把文字當資料

**白話版。** 電腦把文字存成一串字元編碼。模型使用之前，我們必須決定單位是什麼，並給每個單位一個編號。這些決定本身就是模型的一部分。

### 字元、Unicode 與正規化

文字以 Unicode 碼位儲存，並編碼成位元組（通常是 UTF-8，一個字元佔一到四個位元組）。同一個看起來一樣的字串可能有不只一種編碼；例如帶重音的字母，可以是一個預先組合的碼位，也可以是基本字母加上組合用重音符號。**Unicode 正規化**（例如 NFC）會把這些變體統一成一種形式。其他正規化選擇則是有代價的建模決策：

- 轉成小寫會把「Apple」（公司）與「apple」（水果）、「US」與「us」合併。
- 移除標點會抹掉問號、小數點與表情符號。
- 去掉重音符號在許多語言中會改變意思。

保留原文、記錄每一個轉換，而使用預訓練模型時，務必採用它訓練時的正規化方式。

### Token、type 與詞彙表

**Token** 是序列中的一次出現；**type** 是詞彙表中一個不同的項目。以空白切分「a cat and a dog」，有五個 token、四個 type。**Token ID** 是詞彙表的索引：它是一個名字而不是數量，所以 ID 7 並不比 ID 3「多」。

以空白切分英文適合教學，但標點、縮寫、程式碼、網址以及書寫時不用空白分隔的語言，都需要更細心的處理。中文文字一般無法靠空白切成詞，甚至「詞」在哪裡結束本身就是一個有多種答案的語言學問題。這也是現代系統從資料中學習切分單位的原因之一。

## 斷詞：詞、字元與子詞

**白話版。** 用完整的詞，詞彙表會非常龐大，而且新詞一律不認得。用單一字元，序列會變得非常長。子詞介於兩者之間：常見詞保持完整，罕見詞則用較小、可重複使用的片段拼出來。

### 開放詞彙問題

使用詞彙表時，任何訓練中沒看過的詞都會變成同一個未知 token，例如 `<unk>`，關於它的資訊全部遺失。字元或位元組詞彙表永遠不會有未知詞，但序列會長好幾倍，而注意力的成本會隨長度快速增加。Mielke 等人從前神經時代到神經時代回顧了這個取捨，結論是沒有一種方案適用於所有應用 [5]。

### 位元組對編碼（BPE）

Sennrich 等人把**位元組對編碼**（byte-pair encoding, BPE）用在神經機器翻譯上，讓罕見詞與沒見過的詞能以子詞單位的序列表示 [2]。訓練是一個貪婪迴圈：

1. 從單一字元組成的詞彙表開始，並加上詞尾標記，讓合併遵守詞的邊界。
2. 計算語料庫中每一對相鄰符號的出現次數，以詞頻加權。
3. 把出現最多次的一對合併成新符號，加入詞彙表。
4. 重複，直到詞彙表達到想要的大小。

要切分新文字時，依學到的順序套用這些合併規則。

```python
from collections import Counter

corpus = ("low low low low low lower lower newest newest newest newest newest "
          "newest widest widest widest").split()
# Start from characters; "_" marks the end of a word so merges respect boundaries.
words = Counter(tuple(w) + ("_",) for w in corpus)

def pair_counts(words):
    pairs = Counter()
    for symbols, freq in words.items():
        for a, b in zip(symbols, symbols[1:]):
            pairs[a, b] += freq
    return pairs

def merge(words, pair):
    out = Counter()
    for symbols, freq in words.items():
        s, i = [], 0
        while i < len(symbols):
            if i + 1 < len(symbols) and (symbols[i], symbols[i + 1]) == pair:
                s.append(symbols[i] + symbols[i + 1]); i += 2
            else:
                s.append(symbols[i]); i += 1
        out[tuple(s)] += freq
    return out

merges = []
for step in range(10):
    pairs = pair_counts(words)
    best = max(pairs, key=lambda p: (pairs[p], p))   # most frequent; ties broken by symbol order
    merges.append(best)
    words = merge(words, best)
print("merges:", [a + b for a, b in merges])

def tokenize(word):                   # apply the learned merges in order
    symbols = list(word) + ["_"]
    for pair in merges:
        symbols = list(merge(Counter({tuple(symbols): 1}), pair))[0]
    return symbols

for w in ["lowest", "newer", "wider"]:
    print(w, "->", tokenize(w))
```

輸出：

```text
merges: ['t_', 'st_', 'est_', 'ow', 'low', 'west_', 'ne', 'newest_', 'low_', 'wi']
lowest -> ('low', 'est_')
newer -> ('ne', 'w', 'e', 'r', '_')
wider -> ('wi', 'd', 'e', 'r', '_')
```

「lowest」從未在語料中出現，卻能以兩個有意義的片段 `low` 與字尾 `est_` 表示。「newer」與「wider」則退回較小的片段，因為它們的結尾從沒頻繁到被合併。由於單一字元永遠在詞彙表中，不會有任何詞是未知的。實務上的 tokenizer 常對**位元組**而非字元執行 BPE，因此任何輸入（包括表情符號與沒見過的文字系統）都能用固定的 256 個基本符號編碼。

### WordPiece

**WordPiece** 由 Schuster 與 Nakajima 為日文與韓文語音搜尋提出 [3]，並因 Google 神經機器翻譯系統而廣為人知；該系統把詞切成有限的一組常見子詞單位（「wordpieces」）來處理罕見詞 [4]。WordPiece 和 BPE 一樣以合併擴充詞彙表，但它挑選的不是出現最多次的一對，而是分數 $\mathrm{freq}(ab)/\bigl(\mathrm{freq}(a)\,\mathrm{freq}(b)\bigr)$ 最高的一對，偏好那些組成部分很少單獨出現的組合；而且它只保存最終詞彙表，不保存有順序的合併清單 [37]。延續同一個詞的片段會加上 `##` 前綴，例如「unbelievable」可能被切成 `un`、`##believ`、`##able` [37]。BERT 釋出的模型使用 WordPiece 詞彙表 [16]。

### Unigram 語言模型與 SentencePiece

Kudo 的 **unigram 語言模型** tokenizer 方向相反：先從一個很大的候選詞彙表開始，為每個片段指定機率，再反覆移除那些對語料概似影響最小的片段 [6]。由於它為每一種可能的切分都定義了機率，訓練時也可以對同一個詞**取樣**不同的切分，Kudo 稱這種正則化為**子詞正則化**（subword regularization）[6]。**SentencePiece** 是一個直接從原始文字訓練 BPE 或 unigram 模型的函式庫，它把空白當成一般符號（顯示為 `▁`），因此不需要針對特定語言的預先切分，也能精確還原原始文字 [7]。

Hugging Face Tokenizers 等工具把整個流程組織成正規化、預先切分、子詞模型與後處理（例如加入分類用的特殊 token）的管線 [8]。

**實務原則。** 使用預訓練模型時，一定要載入它自己的 tokenizer 與特殊 token 慣例；只換 tokenizer 卻保留嵌入表，會改變每一個 ID 的意義。訓練新的 tokenizer 時，只能在訓練資料上擬合。同樣的內容在不同語言中的 token 數不同，這會影響成本與可用的上下文長度。

## 詞嵌入

**白話版。** 給每個詞一小串數字，讓用在相似上下文的詞得到相似的數字。「觀其友，知其人」：貓和小貓都會喝牛奶、追東西，所以它們的向量最後會很接近。

### 從 one-hot 向量到稠密向量

詞 $i$ 的 **one-hot** 向量長度為 $|V|$（詞彙表大小），只有第 $i$ 個位置是 1。任意兩個不同的 one-hot 向量距離都一樣，所以它們不帶任何相似性資訊。**嵌入表** $E\in\mathbb R^{|V|\times d}$ 把 token ID $i$ 換成它的那一列 $E_i$，一個維度為 $d$（通常是數百）的稠密向量。one-hot 向量乘上 $E$ 就是選出那一列，所以嵌入層其實只是查表。

### 計數上下文：PPMI 與 SVD

**分布式**方法從共現次數建立向量。令 $C_{wc}$ 計算上下文詞 $c$ 出現在詞 $w$ 周圍小視窗內的次數。**逐點互資訊**（pointwise mutual information, PMI）把它與獨立時的預期比較：

$$
\mathrm{PMI}(w,c)=\log\frac{P(w,c)}{P(w)\,P(c)},\qquad
\mathrm{PPMI}(w,c)=\max\bigl(\mathrm{PMI}(w,c),0\bigr),
$$

其中 $P(w,c)=C_{wc}/\sum C$，$P(w)$ 與 $P(c)$ 是對應的邊際機率。正 PMI（PPMI）只保留比隨機更強的關聯。對 PPMI 矩陣做截斷奇異值分解，就得到稠密向量。

```python
import numpy as np

sentences = """the cat drinks milk . the dog drinks water . a cat chases a mouse .
a dog chases a cat . the kitten drinks milk . the puppy drinks water .
a kitten chases a ball . a puppy chases a ball . the car needs fuel .
the truck needs fuel . a car drives on the road . a truck drives on the road .""".split(".")
tokens = [s.split() for s in sentences if s.strip()]
vocab = sorted({w for s in tokens for w in s})
idx = {w: i for i, w in enumerate(vocab)}

# 1) Co-occurrence counts within a +-2 word window.
C = np.zeros((len(vocab), len(vocab)))
for s in tokens:
    for i, w in enumerate(s):
        for j in range(max(0, i - 2), min(len(s), i + 3)):
            if j != i:
                C[idx[w], idx[s[j]]] += 1

# 2) Positive pointwise mutual information.
total = C.sum()
pw, pc = C.sum(1, keepdims=True) / total, C.sum(0, keepdims=True) / total
with np.errstate(divide="ignore"):
    pmi = np.log((C / total) / (pw * pc))
ppmi = np.maximum(pmi, 0)

# 3) Truncated SVD gives dense 8-dimensional embeddings.
U, S, _ = np.linalg.svd(ppmi)
E = U[:, :8] * S[:8]
E /= np.linalg.norm(E, axis=1, keepdims=True)

def nearest(word, k=3):
    sims = E @ E[idx[word]]
    order = [vocab[i] for i in np.argsort(-sims) if vocab[i] != word]
    return [(w, round(float(sims[idx[w]]), 2)) for w in order[:k]]

for w in ["cat", "puppy", "truck", "milk"]:
    print(w, "->", nearest(w))
```

輸出：

```text
cat -> [('kitten', 0.96), ('puppy', 0.88), ('dog', 0.88)]
puppy -> [('dog', 1.0), ('kitten', 0.98), ('cat', 0.88)]
truck -> [('car', 1.0), ('needs', 0.6), ('the', 0.47)]
milk -> [('water', 0.97), ('a', 0.62), ('chases', 0.51)]
```

只用十二個句子、沒有任何標籤，動物就和動物聚在一起，車輛和車輛聚在一起。注意「milk」與「water」幾乎相同：在這個語料中兩者都是被喝的東西。嵌入相似度量的是**共享的上下文**，這通常、但不總是對應到相似的意思；例如「熱」與「冷」這類反義詞也會共享上下文。

### word2vec 與 GloVe

Mikolov 等人用簡單的對數線性模型，讓嵌入學習快到足以處理數十億個詞：**CBOW** 從上下文預測詞，**skip-gram** 從詞預測上下文詞 [9]。後續論文加入了**負取樣**（negative sampling）與高頻詞的子取樣 [10]。對詞 $w$ 與一個觀察到的上下文詞 $c$，帶負取樣的 skip-gram 最大化

$$
\log\sigma\bigl(\mathbf u_c^\top\mathbf v_w\bigr)+\sum_{k=1}^{K}\mathbb E_{c_k\sim P_n}\Bigl[\log\sigma\bigl(-\mathbf u_{c_k}^\top\mathbf v_w\bigr)\Bigr],
$$

其中 $\mathbf v_w$ 是詞的輸入向量，$\mathbf u_c$ 是上下文的輸出向量，$\sigma$ 是 logistic sigmoid，$c_1,\dots,c_K$ 是從雜訊分布 $P_n$ 抽出的 $K$ 個「負」詞。模型學的是分辨真實的（詞，上下文）配對與隨機配對。

Pennington 等人的 **GloVe** 以加權最小平方目標，直接把向量擬合到全域共現次數 $X_{ij}$ [11]：

$$
J=\sum_{i,j}f(X_{ij})\bigl(\mathbf w_i^\top\tilde{\mathbf w}_j+b_i+\tilde b_j-\log X_{ij}\bigr)^2,
$$

其中 $\mathbf w_i,\tilde{\mathbf w}_j$ 是詞向量與上下文向量，$b_i,\tilde b_j$ 是偏差，$f$ 是限制極罕見與極常見配對影響力的權重函數。以計數為基礎的方法（PPMI–SVD、GloVe）與以預測為基礎的方法（word2vec）其實密切相關；兩者都以不同方式分解一個共現統計矩陣。

**fastText** 擴充了 skip-gram，把每個詞表示為一袋字元 $n$-gram，因此能為訓練中沒看過的詞建立向量 [12]。

### 靜態與情境化

**靜態**嵌入在「河岸（river bank）」與「銀行帳戶（bank account）」中給「bank」同一個向量。**情境化**表示則依句子為每一次出現計算不同的向量。ELMo 從深層雙向語言模型的內部狀態產生這種向量，加入現有模型後改善了六項 NLP 任務 [13]。本章後面的所有模型都是情境化的。

## 語言模型

**白話版。** 語言模型一次預測一個 token，依據的是前面已經出現的 token，以此給整個序列一個機率。

### 鏈式法則與 n-gram

對 token $w_1,\ldots,w_T$，機率的鏈式法則給出

$$
p(w_1,\ldots,w_T)=\prod_{t=1}^{T}p(w_t\mid w_1,\ldots,w_{t-1}).
$$

這個等式是精確的。**n-gram** 模型以最後 $n-1$ 個 token 近似歷史；**bigram** 模型（$n=2$）只用前一個 token。開始標記 `<s>` 作為第一個詞的上下文，結束標記 `</s>` 則被預測，用來表示句子邊界。

令 $c(h,w)$ 為訓練中 $w$ 接在上下文 $h$ 後面的次數，$V$ 為預測詞彙表。最大概似估計 $c(h,w)/\sum_v c(h,v)$ 會給任何沒看過的配對零機率，而只要一個零，整個句子就變成不可能。**加法平滑**以 $\alpha>0$ 解決這個問題：

$$
p(w\mid h)=\frac{c(h,w)+\alpha}{\sum_{v\in V}c(h,v)+\alpha|V|}.
$$

加法平滑刻意保持簡單；更好的平滑方法（與低階模型做內插或退回）以及神經模型，能更有效地共享統計資訊。

### 程式碼：訓練、評分與取樣一個 bigram 模型

這個完整範例不需要下載資料或 GPU。語料是為教學編寫的；測試句子與訓練句子分開。測試中任何不在訓練詞彙表內的詞，都對應到同一個未知 token。

```python
from collections import Counter, defaultdict
import math
import random

train = [
    "the cat sleeps", "the dog sleeps", "the cat runs",
    "the dog runs", "a cat eats", "a dog eats",
    "the bird sings", "a bird sleeps",
]
test = ["the cat eats", "a dog runs", "the bird sleeps", "a robot runs"]
START, END, UNK = "<s>", "</s>", "<unk>"
words = {w for sentence in train for w in sentence.split()}
vocab = sorted(words | {END, UNK})       # START is context, never predicted
alpha = 0.2
counts = defaultdict(Counter)
unigrams = Counter()

def encode(sentence):
    return [w if w in words else UNK for w in sentence.split()] + [END]

for sentence in train:
    tokens = [START] + encode(sentence)
    for h, w in zip(tokens, tokens[1:]):
        counts[h][w] += 1
        unigrams[w] += 1

def bigram(h, w):
    row = counts.get(h, {})
    return (row.get(w, 0) + alpha) / (sum(row.values()) + alpha * len(vocab))

def unigram(h, w):
    return (unigrams[w] + alpha) / (sum(unigrams.values()) + alpha * len(vocab))

def perplexity(sentences, probability):
    nll, n = 0.0, 0
    for sentence in sentences:
        tokens = [START] + encode(sentence)
        for h, w in zip(tokens, tokens[1:]):
            nll -= math.log(probability(h, w))
            n += 1
    return math.exp(nll / n)

for h in [START] + vocab:
    assert abs(sum(bigram(h, w) for w in vocab) - 1) < 1e-10
print("unigram test perplexity:", round(perplexity(test, unigram), 3))
print("bigram test perplexity:", round(perplexity(test, bigram), 3))
assert UNK in encode(test[-1])

rng = random.Random(7)
h, sample = START, []
for _ in range(20):                     # cap length for this demonstration
    w = rng.choices(vocab, weights=[bigram(h, v) for v in vocab])[0]
    if w == END:
        break
    sample.append(w)
    h = w
print("sample:", " ".join(sample))
```

輸出：

```text
unigram test perplexity: 10.382
bigram test perplexity: 3.573
sample: a bird sings
```

assert 檢查每一個條件分布加總為一，以及「robot」被對應到未知 token。bigram 模型對測試句子的「驚訝程度」遠低於 unigram 模型，因為詞序帶有資訊。取樣仍可能產生彆扭的字串：機率大於零不代表合乎文法。長度上限只是讓示範停下來，並不改變評分所用的機率。

### 損失與困惑度

對 $N$ 個被預測的 token（這裡包含結束標記），平均負對數概似與**困惑度**（perplexity）為

$$
\mathcal L=-\frac1N\sum_{i=1}^{N}\log p(w_i\mid h_i),
\qquad
\operatorname{PPL}=\exp(\mathcal L),
$$

其中 $h_i$ 是第 $i$ 個被預測 token 的上下文。困惑度等於一個同樣令人驚訝的均勻選擇的大小：把機率平均分給 11 個符號的模型，困惑度就是 11。困惑度越低，代表模型給**這份**已斷詞的測試資料越高的機率。它不衡量事實正確性、有用程度或檢索是否成功。用不同 tokenizer 算出的困惑度無法互相比較，因為被預測事件的數量與種類 $N$ 改變了。

### 神經語言模型

Bengio 等人以神經網路取代計數表，同時學習每個詞的分散式表示與機率函數，使得由相似詞組成、沒看過的詞組合，仍能得到高機率 [14]。「一起學嵌入與預測器」這個想法，是以下所有模型的基礎。

## 從 RNN 到 Transformer

**白話版。** n-gram 模型會忘記幾個詞之外的所有東西。循環網路沿著句子攜帶記憶。注意力讓每個詞都能直接看向其他每個詞。Transformer 幾乎完全由注意力構成。

### 循環網路與 LSTM

**循環神經網路**（recurrent neural network, RNN）一次讀入一個 token 嵌入 $\mathbf x_t$，並更新隱藏狀態：

$$
\mathbf h_t=\tanh\bigl(W\mathbf h_{t-1}+U\mathbf x_t+\mathbf b\bigr),\qquad
p(w_{t+1}\mid w_{\le t})=\operatorname{softmax}(V\mathbf h_t),
$$

其中 $W$、$U$、$V$ 與 $\mathbf b$ 是學習得到的參數。理論上 $\mathbf h_t$ 概括了整個前綴。實務上，梯度經過許多步後會消失或爆炸，因此一般 RNN 難以處理長距離依賴。**長短期記憶**（long short-term memory, LSTM）加入一個細胞狀態，以及乘法式的輸入、遺忘與輸出閘門，讓資訊與梯度能跨越長距離流動 [15]。[ML 03a](/zh-tw/learn/ml/ml-03a-recurrent-recursive-networks/) 詳細介紹這些架構。

### 序列到序列與注意力

Sutskever 等人用兩個 LSTM 把輸入序列映射到輸出序列：**編碼器**把來源句子壓縮成固定長度的向量，**解碼器**再從它產生目標句子 [17]。Bahdanau 等人主張這個固定長度向量是瓶頸，讓解碼器在每一個輸出步驟都能對所有編碼器狀態做（軟性）搜尋 [18]。這就是**注意力**：對來源表示做一個學習得到、依輸入而變的加權平均。

### Transformer

Vaswani 等人完全拿掉了循環結構 [19]。每一層先做**縮放點積注意力**，再接一個逐位置的前饋網路，並使用殘差連接與正規化。對堆疊成 $X\in\mathbb R^{T\times d}$ 的 $T$ 個向量：

$$
Q=XW_Q,\quad K=XW_K,\quad V=XW_V,\qquad
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\Bigl(\frac{QK^\top}{\sqrt{d_k}}+M\Bigr)V,
$$

其中 $W_Q,W_K,W_V$ 是學習得到的投影，$d_k$ 是 key 的維度，$M$ 是**遮罩**：允許注意的位置為 $0$，禁止的位置為 $-\infty$。softmax 的第 $t$ 列是一個機率分布，表示 token $t$ 從其他每個 token 讀取多少資訊。多個這樣的「頭」平行運作。由於注意力本身忽略順序，所以要把**位置資訊**加進嵌入。每個位置都能平行處理，這讓在超大語料上訓練變得可行。

```python
import numpy as np

rng = np.random.default_rng(0)
T, d = 5, 8                                   # 5 tokens, 8-dimensional embeddings
X = rng.normal(size=(T, d))                   # token embeddings (+ positions)
Wq, Wk, Wv = (rng.normal(size=(d, d)) / np.sqrt(d) for _ in range(3))

def attention(X, causal):
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    scores = Q @ K.T / np.sqrt(d)             # (T, T) query-key similarities
    if causal:                                # position t may only look at <= t
        scores = np.where(np.tri(T, dtype=bool), scores, -np.inf)
    w = np.exp(scores - scores.max(axis=1, keepdims=True))
    w /= w.sum(axis=1, keepdims=True)         # softmax over keys
    return w @ V, w

out, w = attention(X, causal=True)
print(np.round(w, 2))

# Changing the LAST token must not change any earlier causal output...
X2 = X.copy(); X2[-1] += 5.0
out2, _ = attention(X2, causal=True)
print("causal: earlier outputs unchanged:", np.allclose(out[:-1], out2[:-1]))
# ...but in a bidirectional encoder every position can see it.
b1, _ = attention(X, causal=False); b2, _ = attention(X2, causal=False)
print("bidirectional: earlier outputs unchanged:", np.allclose(b1[:-1], b2[:-1]))
```

```text
[[1.   0.   0.   0.   0.  ]
 [0.88 0.12 0.   0.   0.  ]
 [0.42 0.29 0.29 0.   0.  ]
 [0.28 0.24 0.29 0.19 0.  ]
 [0.34 0.06 0.24 0.11 0.26]]
causal: earlier outputs unchanged: True
bidirectional: earlier outputs unchanged: False
```

### 使用 Transformer 的三種方式

- **因果解碼器**依前綴預測下一個 token，可以生成文字。GPT 系列是解碼器。
- **雙向編碼器**同時讀取左右上下文，適合分類與標註等理解任務，但無法直接由左至右生成。BERT 是編碼器。
- **編碼器–解碼器**以雙向方式編碼來源序列，以因果方式生成目標序列，並透過**交叉注意力**讀取來源。翻譯與摘要屬於這種模式；T5 使用這種架構。

## 預訓練語言模型

**白話版。** 先用大量未標註的文字，教一個大模型一般的語言能力，再用少量標註資料把它調適到你的任務，或者乾脆用文字描述任務。

- **GPT**（Radford 等人，2018）顯示，先在未標註文字上對 Transformer 語言模型做生成式預訓練，再針對每個任務做判別式微調，能在語言理解基準上帶來大幅進步 [20]。
- **BERT**（Devlin 等人）以**遮罩語言模型**目標預訓練深層雙向編碼器：部分輸入 token 被隱藏或替換，模型從兩側上下文預測原本的 token。只加一層輸出層再微調，就在十一項任務上創下新的最佳成績 [16]。遮罩語言模型並不為整個句子給出正規化的由左至右機率；它是一個表示學習器。
- **T5**（Raffel 等人）把每一項任務（包括分類）都當成以編碼器–解碼器進行的文字到文字生成，並系統化比較預訓練目標、架構、資料集與遷移方法 [21]。
- **GPT-3**（Brown 等人）把自迴歸模型擴大到 1,750 億個參數，並顯示它常常能以**少樣本**（few-shot）方式執行新任務：只在提示中放入少量例子，不做任何梯度更新 [22]。在此之前，Kaplan 等人發現語言模型的損失會隨模型大小、資料量與算力，以冪律方式下降，橫跨許多數量級 [23]。
- **遵循指令。** Ouyang 等人先用標註者撰寫的示範對 GPT-3 做監督式微調，再以來自人類對輸出排序的強化學習（RLHF）進一步微調，得到 InstructGPT；在人工評估中，13 億參數的 InstructGPT 的輸出比 1,750 億參數的 GPT-3 更受偏好 [24]。受人偏好並不保證事實正確。
- **檢索增強生成**（retrieval-augmented generation, RAG）把挑選出的外部段落提供給生成器，讓回答能引用訓練後才更新的文件 [25]。檢索仍可能取回不相關或過時的文字，生成器也可能忽略它，因此要檢查檢索涵蓋率，以及每一個最終陳述是否真的由引用的段落支持。

各種調適方式在資料、算力與可控性之間取捨：凍結編碼器加小型分類器、完整微調、參數高效率的轉接器（見 [ML 09](/zh-tw/learn/ml/ml-09-foundation-models/)），以及完全不更新參數的提示。

### 一定要跑的傳統基準

許多文字任務根本不需要生成。詞袋（bag-of-words）或 **TF–IDF** 特徵加上邏輯迴歸，是很快的 CPU 基準：每份文件變成加權詞頻的稀疏向量，線性分類器預測 $p(y\mid x)$。詞項 $t$ 在文件 $d$ 中的 TF–IDF 權重為

$$
\operatorname{tfidf}(t,d)=\operatorname{tf}(t,d)\cdot\log\frac{N}{\operatorname{df}(t)},
$$

其中 $\operatorname{tf}(t,d)$ 是 $t$ 在 $d$ 中的次數，$N$ 是訓練文件數，$\operatorname{df}(t)$ 是包含 $t$ 的文件數（函式庫會再加上平滑與正規化）。詞袋會失去詞序，而詞序對否定句很重要。

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline

train = [
    ("the battery is good", 1), ("good screen and good sound", 1),
    ("the camera is great", 1), ("great value , works well", 1),
    ("the battery is not good", 0), ("not great , the screen broke", 0),
    ("the sound is bad", 0), ("bad camera and bad battery", 0),
    ("works well , not bad at all", 1), ("not good , not worth it", 0),
]
test = ["the screen is not good", "the sound is not bad", "great battery"]
texts, labels = zip(*train)

for name, ngrams in [("unigrams", (1, 1)), ("uni+bigrams", (1, 2))]:
    clf = make_pipeline(TfidfVectorizer(ngram_range=ngrams, token_pattern=r"\S+"),
                        LogisticRegression(C=10.0))
    clf.fit(texts, labels)                    # vocabulary + IDF fitted on train only
    probs = clf.predict_proba(test)[:, 1]
    print(f"{name:12s}", [f"{t!r}: {p:.2f}" for t, p in zip(test, probs)])
```

輸出（正面評論的機率）：

```text
unigrams     ["'the screen is not good': 0.43", "'the sound is not bad': 0.11", "'great battery': 0.61"]
uni+bigrams  ["'the screen is not good': 0.20", "'the sound is not bad': 0.18", "'great battery': 0.56"]
```

加入 bigram 特徵後，模型學到「not good」是負面的，那個測試句從 0.43 降到 0.20。但「not bad」仍被判為負面：它在訓練資料中只出現一次，太少，壓不過「bad」。局部 n-gram 能修補部分詞序效應；情境化模型則從多得多的資料中學會這些。在真實任務中，調校良好的 TF–IDF 基準有時出乎意料地難以超越，而且永遠很便宜。

## 評估 NLP 系統

**白話版。** 量測你真正在乎的任務，用模型從沒見過的資料，並對每個系統使用相同的評估協定。

### 資料切分與洩漏

相關的電子郵件、重複的文章以及同一段對話中的訊息，都可能在隨機切分時洩漏。當符合部署情況時，依文件家族、對話、作者或時間切分。詞彙表、TF–IDF 統計與 tokenizer 只能在訓練資料上擬合，並記錄資料集版本與去重規則（[ML 10](/zh-tw/learn/ml/ml-10-evaluation-deployment/) 深入討論資料洩漏與信賴區間）。對網路規模的預訓練模型，另一個風險是**資料污染**：公開的測試集可能已經出現在預訓練資料中。

### 依任務選指標

| 任務 | 有用的量測 | 要檢查的錯誤 |
|---|---|---|
| 分類 | Macro-F1、各類別召回率、校準 | 罕見類別被併入多數類別 |
| 實體擷取 | 片段層級的精確率與召回率 | 實體詞正確但邊界錯誤 |
| 語言建模 | 在同一 tokenizer 下的保留資料對數損失／困惑度 | 罕見詞涵蓋不足或上下文洩漏 |
| 翻譯、摘要 | BLEU、ROUGE，加上人工判斷 | 正確的改寫被算成錯誤 |
| 檢索 | 截斷位置的召回率、排序指標 | 支持段落從未送到生成器 |
| 開放式生成 | 任務正確性、證據支持、拒答 | 流暢卻沒有根據的陳述 |

**BLEU** 透過修正後的 $n$-gram 精確率 $p_n$（每個候選 $n$-gram 最多只計入它在參考譯文中出現的次數），比較候選譯文與參考譯文 [26]：

$$
\mathrm{BLEU}=\mathrm{BP}\cdot\exp\Bigl(\sum_{n=1}^{N}w_n\log p_n\Bigr),\qquad
\mathrm{BP}=\begin{cases}1,&c\gt r\\ e^{\,1-r/c},&c\le r\end{cases}
$$

其中 $w_n$ 是權重（通常 $N=4$、$w_n=1/N$），$c$ 是候選長度，$r$ 是參考長度；簡短懲罰 BP 防止很短的輸出拿到很高的精確率。**ROUGE** 是一系列以召回率為主的摘要重疊指標，例如 ROUGE-N（對參考摘要的 $n$-gram 召回率）與 ROUGE-L（最長共同子序列）[27]。兩者都獎勵表面重疊：正確的改寫可能分數很低，而一個只錯了一個事實的流暢句子可能分數很高。

**基準**把多個任務打包。GLUE 收集了多樣的既有自然語言理解任務（其中一些訓練資料非常少），加上人工設計的診斷測試集，以鼓勵能跨任務共享知識的模型 [28]。對大型語言模型，Chang 等人依「評估什麼、在哪裡評估（哪些基準）、如何評估（自動指標或人工判斷）」整理評估方法 [32]。無論用哪個指標，都要在看系統輸出之前先定好人工評估準則，記錄哪位評估者看過哪些例子，並與品質一起報告延遲、記憶體以及長輸入被截斷的情況。

## 語言與視覺的交會

**白話版。** 讀詞 token 的 Transformer 也能讀影像區塊。訓練一個文字模型和一個影像模型，讓它們對「哪個說明配哪張圖」達成一致，就得到一個能比較文字與影像的共同空間。把影像編碼器接到語言模型上，就得到一個能談論圖片的助理。

- **把影像當 token。** Vision Transformer 把影像切成固定大小的區塊，像詞一樣嵌入每個區塊，再套用標準的 Transformer 編碼器；經過大規模預訓練後，它與強大的卷積網路表現相當 [29]。[ML 04](/zh-tw/learn/ml/ml-04-vision-transformers/) 有詳細說明。
- **對比式影像–文字學習。** CLIP 在 4 億組影像–說明配對上訓練影像編碼器與文字編碼器，預測哪個說明配哪張圖，並能以零樣本方式遷移到新的分類任務：把影像與「a photo of a dog」這類文字提示比較 [30]。對一批 $B$ 組配對、正規化後的嵌入 $\mathbf i_k$ 與 $\mathbf t_k$，損失是在相似度矩陣 $S_{jk}=\mathbf i_j^\top\mathbf t_k/\tau$（溫度為 $\tau$）上的對稱交叉熵：

$$
\mathcal L=-\frac1{2B}\sum_{k=1}^{B}\Bigl[\log\frac{e^{S_{kk}}}{\sum_j e^{S_{kj}}}+\log\frac{e^{S_{kk}}}{\sum_j e^{S_{jk}}}\Bigr].
$$

- **視覺語言助理。** LLaVA 把預訓練的視覺編碼器接到大型語言模型上，並以純語言模型產生的多模態指令遵循資料，對整個組合做指令微調 [31]。[ML 09](/zh-tw/learn/ml/ml-09-foundation-models/) 把這些模型放在其他基礎模型的脈絡中介紹。
- **共同的分解方式。** 以下一個 token 預測來生成文字與生成影像，用的正是上面 bigram 模型的同一條鏈式法則，只是套用在不同的 token 上；見 [ML 08](/zh-tw/learn/ml/ml-08-autoregressive-vision/)。

對視覺領域的實務工作者而言，結論是：這裡學到的斷詞、嵌入、遮罩、預訓練目標與評估陷阱，可以直接套用到本站其他章節的影像與影片模型，包括[深度學習系列](/zh-tw/learn/deep-learning/dl-01-deep-learning-for-image-processing/)。

## 現代觀點

**綜述。** Mielke 等人追溯開放詞彙建模與斷詞的歷史，從詞層級模型、詞與字元的混合方法，到學習出的子詞切分與位元組層級處理，並主張沒有一種粒度適合所有應用 [5]。Qiu 等人以四個面向的分類法綜述 NLP 的預訓練模型，並討論如何把它們調適到下游任務 [33]。Bommasani 等人提出**基礎模型**（foundation models）一詞，指在廣泛資料上大規模訓練、可調適到許多任務的模型，並分析其能力、技術原理、應用與社會風險 [34]。Zhao 等人持續更新的大型語言模型綜述，依預訓練、調適微調、使用方式與能力評估四個面向組織 [35]。Minaee 等人回顧主要的 LLM 家族（GPT、LLaMA、PaLM）、建構與增強 LLM 的技術、資料集與評估指標 [36]。Chang 等人依評估什麼、在哪裡評估與如何評估，綜述 LLM 的評估 [32]。

**2023–2026 年的現況。** 主流做法是在網路規模的文字上以下一個 token 預測預訓練大型的純解碼器 Transformer，接著做指令微調與基於偏好的後訓練，並常與檢索結合 [22], [24], [25], [35], [36]。子詞 tokenizer（BPE 或 unigram，常為位元組層級）仍是標準 [5]。模型越來越常透過接到語言模型上的編碼器接受影像與其他模態 [30], [31]。規模化研究則指引算力如何在模型大小與資料量之間分配 [23]。

**開放問題。**

- **事實性與依據。** 流暢的輸出可能沒有根據；量測並確保證據支持仍然困難。
- **評估。** 公開基準遭到污染、對提示措辭的敏感性，以及人工判斷的成本與可靠度，都讓比較變得複雜 [32]。
- **斷詞。** 不同語言與文字系統的 token 數不同，影響成本、上下文長度與公平性；字元與位元組層級的替代方案則以序列長度為代價 [5]。
- **效率。** 注意力成本隨序列長度增加；長文件與長對話會壓迫記憶體與延遲。
- **低資源語言。** 大部分的資料、基準與工具仍集中在少數高資源語言。

## 重點整理

- 斷詞與正規化定義了預測問題；預訓練模型一定要搭配它自己的 tokenizer 使用。
- 子詞 tokenizer（BPE、WordPiece、unigram／SentencePiece）提供開放詞彙，同時讓序列長度保持在可控範圍。
- 嵌入讓用在相似上下文的詞彼此接近；靜態向量無法區分詞義，情境化模型可以。
- 語言模型以鏈式法則分解序列機率；困惑度衡量的是對已斷詞測試資料的貼合程度，不是真實性或有用程度。
- RNN 一步一步攜帶記憶；注意力讓每個 token 讀取其他每個 token；遮罩決定什麼是允許的，這正是 GPT 式解碼器與 BERT 式編碼器的差別。
- 預訓練加上調適（微調、提示、指令微調、檢索）是現代做法，但 TF–IDF 基準仍值得一跑。
- BLEU 與 ROUGE 這類重疊指標有用，卻看不見改寫與事實錯誤；要在乾淨、無洩漏的切分上評估你真正需要的任務。
- 同樣的 token–嵌入–注意力機制也驅動 ViT、CLIP 與視覺語言助理，把本系列與本站其他部分連在一起。

## 練習

1. **平滑。** 在 bigram 程式中把 $\alpha$ 改成 0.01、0.2 與 1.0。比較保留資料的困惑度，並說明沒看過的轉移機率會怎樣變化。為什麼在這四個測試句子上最好的值並不是可靠的選擇？

<details>
<summary>提示</summary>

大量平滑會讓每個條件分布趨向均勻（困惑度趨近 $|V|=11$）；平滑很少時，沒看過的配對幾乎沒有機率，所以只要遇到一個就代價很高。四個句子遠不足以得出可靠的超參數結論；應在獨立的驗證集上選擇 $\alpha$。

</details>

2. **字元與詞。** 在 bigram 模型中把詞 token 換成字元。在比較兩個模型的分數之前，哪些量必須保持固定？

<details>
<summary>提示</summary>

字元預測產生多得多、而且不同種類的事件，所以每個 token 的困惑度不在同一個單位上。應比較同一段測試文字在兩個模型下的總對數概似（例如由兩個模型算出的每字元或每位元組位元數），並使用相同的正規化與相同的未知詞處理方式。

</details>

3. **手算 BPE。** 對語料「hug hug hug pug pug bun」（含詞尾標記）手動執行三次 BPE 合併。然後切分沒看過的詞「bug」。用 BPE 程式檢查答案。

<details>
<summary>提示</summary>

以頻率加權計算配對：`u g` 出現 5 次，`g _` 5 次，`h u` 3 次。依程式的平手規則，第一次合併是最高頻配對中符號順序較大的那一個。合併後，「bug」應該會重用學到的字尾片段 `ug_`，並把 `b` 保留為單一字元。

</details>

4. **嵌入稽核。** 在 PPMI 範例中把句子「the cat drinks water」加入五次。預測「milk」與「water」之間、以及「cat」與「dog」之間的餘弦相似度會怎樣變化，然後實際執行。

<details>
<summary>提示</summary>

實際執行後，milk–water 從 $0.97$ 升到約 $1.00$，但 cat–dog **下降**，從 $0.88$ 降到 $0.58$，而「cat」的最近鄰變成「drinks」：同一句話的五個複本主導了 cat 的上下文分布。嵌入反映語料統計，包括重複與偏差，這也是訓練前要先去重的另一個理由。

</details>

5. **設計資料切分。** 你有一份客服資料集，每段對話有多則訊息，還有許多重複的範本回覆。設計訓練／驗證／測試切分與去重規則。

<details>
<summary>提示</summary>

讓每段對話只落在一個切分中；切分前偵測完全重複與近似重複的範本，並把同一個範本家族放在同一側；如果產品會隨時間改變，考慮使用較晚時間的測試集。tokenizer 與任何 TF–IDF 統計都只在訓練切分上擬合。

</details>

6. **RAG 失敗分析。** 設計一個能區分檢索失敗與無依據生成的實驗。其中包含一個正確答案不在已索引文件中的案例。

<details>
<summary>提示</summary>

在為最終答案評分之前，先評估是否取回了支持段落。把完整系統與「直接給生成器正確段落」（理想檢索）的版本比較。對沒有任何已索引依據的問題，正確行為是拒答；量測系統仍然作答的頻率。

</details>
