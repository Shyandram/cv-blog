## 你將學到

- 把序列機率分解成因果的下一詞元預測。
- 解釋因果、遮罩與條件生成目標之間的差別。
- 推導縮放內積注意力，檢查其可見性遮罩。
- 不下載資料，訓練小型 Transformer 式語言模型。
- 量測保留資料的負對數概似，測試未來詞元洩漏。
- 區分預訓練、任務調適、偏好學習與解碼。

## 先看全貌

語言模型依指定上下文替文字配置機率。這個簡單定義連結拼字補全、句子生成與可重用的上下文表示，但各種用途並沒有相同輸出契約。預測可能的延續與驗證事實回答是不同工作。流暢延續可能反映常見文字模式，卻不適合某個特定任務。

Hagiwara 第 5 章討論語言模型，第 8 章介紹注意力與 Transformer，第 9 章說明預訓練模型調適 [1]。McRoy 第 6 章透過合語法性、情感、相似度與推論等任務，強調語言模型評估 [2]。本章把機率模型連到這些實際評估，只訓練微小合成模型；大型預訓練系統則透過已驗證的原始論文與綜述討論。

<Callout type="tip" title="用最簡單的話說">
想像一個猜詞遊戲：看到句子開頭，再猜下一個詞。因果模型只能看已經揭露的詞；遮罩填詞則允許你看被藏起來的詞兩側。兩種遊戲都能學模式，但在第一種遊戲偷看句子後面的答案，就是作弊。
</Callout>

三個決策組織這個主題：訓練目標決定預測什麼；注意力模式決定哪些輸入位置可見；部署程序決定預測如何變成使用者輸出。比較模型時要分開。改變取樣溫度會改變輸出分布，不會改變已學到哪些事實，也不會驗證產生的主張。

## 因果序列機率

**直觀說法。** 依前面的詞元逐一預測，就能建立序列機率。訓練時雖然看得到完整序列，每次預測仍必須遵守可見性規則。

由機率鏈式法則：

$$
p_\theta(x_1,\ldots,x_T)=\prod_{t=1}^{T}p_\theta(x_t\mid x_{\lt t}).
$$

其中 $x_t$ 是位置 $t$ 的詞元；$T$ 是序列長度；$x_{\lt t}$ 是 $t$ 之前的前綴；$\theta$ 是模型參數。起始詞元可提供第一個普通詞元的明確上下文，結束詞元則讓模型替停止配置機率。鏈式法則是精確等式，學得的條件分布則近似資料生成過程。

對含有 $N$ 個受監督詞元位置的語料，平均負對數概似為：

$$
\mathcal L_{\mathrm{causal}}=-\frac{1}{N}\sum_{n=1}^{N}\log p_\theta(x_n\mid c_n).
$$

其中 $\mathcal L_{\mathrm{causal}}$ 是訓練目標；$n$ 遍歷所有範例的有效預測位置；$x_n$ 是目標詞元；$c_n$ 是允許使用的前綴；$N$ 不包含填補位置及其他刻意不監督的位置。自然對數使損失單位為每詞元的 nat。若批次平均把填補也計入，就改變了目標，可能獎勵模型預測人造填補符號。

教師強制（teacher forcing）在訓練時使用觀察到的前綴預測每個詞元。架構若強制因果遮罩，就能平行評估所有位置。生成時，前綴改為先前生成的詞元，錯誤可能影響後續預測。因此，即使權重相同，訓練目標與逐步生成行為仍需要不同診斷。

輸入與目標要錯開一個位置。完整序列若是起始、the、robot、moves、結束，模型輸入就是起始、the、robot、moves，目標則是 the、robot、moves、結束。若直接由未位移表示預測輸入詞元本身，就建立了與下一詞元預測無關的捷徑。後面的程式明確寫出位移。

## 遮罩與條件目標

**直觀說法。** 不是每個預訓練語言模型都預測下一詞元。遮罩目標使用周圍內容，條件生成則根據另一個輸入預測輸出序列。

BERT 的遮罩語言目標藏起選定位置，再使用雙向上下文預測原詞元 [3]。簡化描述如下：

$$
\mathcal L_{\mathrm{mask}}=-\frac{1}{|M|}\sum_{i\in M}\log p_\theta(x_i\mid\widetilde{\mathbf x}).
$$

其中 $M$ 是受監督遮罩位置集合；$|M|$ 是集合大小；$x_i$ 是原詞元；$\widetilde{\mathbf x}$ 是受損輸入序列。波浪號表示損壞，不是獨立抽出的文件。這個式子描述遮罩預測部分，沒有重現原 BERT 訓練程序的每個細節。

遮罩預測器適合上下文表示、分類與區段任務，其損失卻不會自動成為一般由左到右序列的對數機率。把各自讀取句子兩側的預測相乘，通常不會得到與因果分解相同的正規化聯合分布。因此，遮罩目標分數與因果困惑度不能直接互換。

條件序列生成則寫成：

$$
p_\theta(\mathbf y\mid\mathbf x)=\prod_{t=1}^{U}p_\theta(y_t\mid y_{\lt t},\mathbf x).
$$

其中 $\mathbf x$ 是來源序列；$\mathbf y$ 是目標序列；$U$ 是包含結束詞元的目標長度；$y_{\lt t}$ 是目標前綴。來源可以完整可見，目標仍保持因果。T5 把多種 NLP 任務整理成文字到文字架構，並研究 Transformer 編碼器—解碼器的遷移學習 [4]。

這些區別有助選模型。完整句子已知時，分類器可使用雙向編碼器；串流延續則必須排除未來輸出。翻譯可以在來源全部抵達後讀取完整來源，但同步翻譯需要更嚴格的來源可見性契約。應由任務可取得的資訊決定遮罩，而非因為某個模型名稱熟悉就選它的遮罩。

## 上下文表示與位置

**直觀說法。** 注意力比較詞元表示，位置資訊則告訴模型詞元在哪裡。詞元身分本身不會說明它是主詞還是最後一個詞。

使用學得的嵌入與位置表：

$$
\mathbf h_i^{(0)}=E[x_i]+P[i].
$$

其中 $\mathbf h_i^{(0)}\in\mathbb R^d$ 是位置 $i$ 的初始表示；$E$ 是詞元嵌入表；$E[x_i]$ 選取詞元 $x_i$ 的列；$P$ 是學得的位置表；$P[i]$ 選取位置列；$d$ 是表示寬度。本例使用這種簡單設計。其他位置設計也存在，但示範因果預測並不需要它們。

學得的位置表也限制支援的最遠位置。超過範圍的序列不是普通長輸入，而是非法索引。服務契約應記錄上下文限制。擴充位置表或改變位置行為屬於模型變更，需要評估，不能直接假定長文件表現維持不變。

網路由詞元與位置輸入計算上下文表示，所以同一詞元在不同句子能得到不同向量。這支持跨任務重用，但必須配對分詞器、詞彙表與前處理規則。嵌入列只在該模型詞元 ID 的定義下有意義。未調適權重就換分詞器，可能讓形式合法的數字代表不相關符號。

## 縮放內積注意力

**直觀說法。** 每個位置詢問其他哪些位置含有有用資訊。注意力把比較轉成權重，再組合相應的值向量。

對單一注意力頭：

$$
Q=HW_Q,\quad K=HW_K,\quad V=HW_V,\qquad
A=\operatorname{softmax}_{\mathrm{row}}\left(\frac{QK^\top}{\sqrt{d_k}}+B\right),\quad O=AV.
$$

其中 $H\in\mathbb R^{T\times d}$ 包含輸入表示；$W_Q,W_K\in\mathbb R^{d\times d_k}$ 是學得的查詢與鍵投影；$W_V\in\mathbb R^{d\times d_v}$ 是值投影；$Q,K,V$ 是投影矩陣；$d_k,d_v$ 是鍵和值的寬度；$B\in\mathbb R^{T\times T}$ 是加法可見性遮罩；$A$ 包含按列正規化的注意力權重；$O\in\mathbb R^{T\times d_v}$ 是輸出。每個查詢列分別套用 softmax。這是 Transformer 論文介紹的機制 [5]。

因果自注意力在 $j\leq i$ 時令 $B_{ij}=0$，否則令 $B_{ij}=-\infty$。其中 $i$ 是查詢位置，$j$ 是候選鍵位置。目標已位移，所以目前輸入位置仍是允許的前綴詞元，對角線可見。完整雙向自注意力允許所有真實輸入位置，但仍可阻擋填補位置。

<Figure src={maskFig} alt="因果注意力允許三角形的位置集合，雙向注意力則允許所有真實詞元" caption="圖 1 — 可見性是任務定義的一部分。列是發出查詢的位置，欄是它們可以讀取的位置。" />

在常見初始化假設下，縮放因子避免內積只因鍵向量維度增加而變大。它不會把注意力權重變成校準後的語意重要性。高權重表示經過學得投影後，在這次計算有較大貢獻；不會證明該詞元造成最終答案，也不會證明它支持生成的陳述。

多頭注意力執行多組學得投影，再結合輸出。原 Transformer 還使用殘差連接、正規化與逐位置前饋層 [5]。本章微型模型只有一頭、一個區塊，讓形狀容易檢查；它保留核心可見性與殘差機制，並不主張符合正式大型語言模型的架構或訓練配方。

直接儲存注意力分數會隨序列長度平方成長。專用實作可避免實體化每個中間矩陣，但哪些位置需要互動的建模問題仍在。教學序列很短，因此清楚比核心運算速度重要。部署時，應按實際上下文長度量測記憶體與延遲，不能由短句直接外推。

## 可執行的因果模型

**直觀說法。** 小模型可以學會合成語言模式，卻對沒見過的組合泛化很差。我們還測試低損失不能證明的性質：未來詞元不得影響較早預測。

以下獨立 CPU 範例使用自訂等長句子。訓練與測試句不同，但每個普通詞彙都曾出現在訓練中。程式沒有填補、預訓練權重或資料下載，刻意作為機制實驗而非語言基準。

實作使用 AdamW 最佳化 [11]、前饋區塊中的 GELU 活化函數 [12]，以及注意力和前饋轉換之前的層正規化（layer normalization）[13]。這些選擇定義小型實驗，不是重現原 Transformer 的所有細節。研究因果遮罩時保持它們固定，避免最佳化或活化函數的改變干擾比較。

```python
import math
import torch
from torch import nn
from torch.nn import functional as F

torch.manual_seed(11)
torch.set_num_threads(1)
train_text = [
    'the red robot moves', 'the blue robot waits',
    'a red sensor waits', 'a blue sensor moves',
    'the red sensor moves', 'a blue robot waits',
]
test_text = ['a red robot moves', 'the blue sensor waits']
vocab = ['<bos>', '<eos>'] + sorted(set(' '.join(train_text).split()))
index = {word: i for i, word in enumerate(vocab)}
def encode(rows):
    return torch.tensor([[index[w] for w in ['<bos>'] + s.split() + ['<eos>']] for s in rows])
train, test = encode(train_text), encode(test_text)

class TinyCausalModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.token = nn.Embedding(len(vocab), 16)
        self.position = nn.Embedding(5, 16)
        self.norm1, self.norm2 = nn.LayerNorm(16), nn.LayerNorm(16)
        self.q, self.k, self.v = [nn.Linear(16, 16, bias=False) for _ in range(3)]
        self.output = nn.Linear(16, 16)
        self.ff = nn.Sequential(nn.Linear(16, 32), nn.GELU(), nn.Linear(32, 16))
        self.head = nn.Linear(16, len(vocab))
    def forward(self, ids):
        length = ids.shape[1]
        h = self.token(ids) + self.position(torch.arange(length))
        z = self.norm1(h)
        scores = self.q(z) @ self.k(z).transpose(-1, -2) / math.sqrt(16)
        blocked = torch.ones(length, length, dtype=torch.bool).triu(1)
        weights = scores.masked_fill(blocked, float('-inf')).softmax(dim=-1)
        h = h + self.output(weights @ self.v(z))
        h = h + self.ff(self.norm2(h))
        return self.head(h)

model = TinyCausalModel()
optimizer = torch.optim.AdamW(model.parameters(), lr=0.01)
def loss(rows):
    logits = model(rows[:, :-1])
    return F.cross_entropy(logits.reshape(-1, len(vocab)), rows[:, 1:].reshape(-1))
initial = loss(train).item()
for _ in range(180):
    optimizer.zero_grad()
    objective = loss(train)
    objective.backward()
    optimizer.step()
model.eval()
with torch.no_grad():
    train_nll, test_nll = loss(train).item(), loss(test).item()
    original = train[:1, :-1]
    changed = original.clone()
    changed[0, -1] = index['blue']
    gap = (model(original)[:, :-1] - model(changed)[:, :-1]).abs().max().item()
assert train_nll < initial and gap < 1e-6
print('initial/train/test NLL:', *(round(x, 3) for x in [initial, train_nll, test_nll]))
print('held-out perplexity:', round(math.exp(test_nll), 3))
print('future-token perturbation gap:', gap)
```

執行會印出初始、最終訓練與保留資料損失。斷言檢查訓練損失下降，不要求保留損失改善特定幅度。保留句把熟悉詞語組成訓練未包含的組合。大的訓練—測試落差說明，學會觀察到的模式不代表有組合泛化能力。

未來詞元擾動測試改變最後輸入詞元，再比較所有較早位置的 logits。因果注意力應讓這個變動對較早預測不可見。測試直接對準可見性契約，但通過不代表所有資料隔離都成立：跨切分重複文件、使用禁止的測試資料建詞彙表，或未來中繼資料，都能造成其他洩漏。

模型沒有 dropout，因此本例評估模式不會改變隨機層；仍明確呼叫它，因為真實模型必須區分訓練與評估。損失函數展平批次及位置維度，保留詞彙維度作為類別。若不小心交換這些軸，程式可能照樣執行，卻最佳化錯誤問題。

每個序列等長，位置表也涵蓋五個模型輸入位置，因此排除了填補與截斷。擴充成可變長資料，要分別加入注意力與損失遮罩。注意力遮罩控制表示可讀什麼；損失遮罩控制哪些目標對目標函數有貢獻。兩者處理不同問題，需要獨立測試。

## 困惑度與有意義的比較

**直觀說法。** 困惑度總結保留詞元預測表現，但數值取決於詞元定義與評估位置。

平均負對數概似為 $\mathcal L$ 時：

$$
\mathrm{PPL}=\exp(\mathcal L).
$$

其中 $\mathrm{PPL}$ 是困惑度（perplexity）；$\exp$ 是自然指數；$\mathcal L$ 對同一組評估位置使用自然對數。較低困惑度表示模型在該評估契約下，對觀察到的詞元配置較高平均機率，不是事實正確、實用性或合語法性的直接指標。

只有分詞與輸入慣例相容時才比較困惑度。一個詞可能在某詞彙表是單一詞元，在另一個表被拆成多個詞元，平均每詞元損失便使用不同單位。還應記錄是否評分起始與結束符號、文件如何分段、上下文長度，以及評估視窗是否重疊。重複計算目標位置會改變權重。

評估文件應與訓練及其衍生文件獨立。把同一文件相鄰段落分到不同集合，可能暴露風格、事實與幾乎相同措辭。具有時間相依性的應用應採適當時間切分，並保留文件版本。單一名稱或短語沒見過，不能證明周圍文件獨立。

McRoy 的基準觀點提醒我們，序列預測之外還要評估任務行為 [2]。分類器需要類別表現，擷取器需要區段與受支持關係，生成器需要意義保留與遺漏評估。困惑度較低的模型仍可能把「沒有移動」改成「移動」而失敗。評估要對準使用者真正的結果。

## 預訓練、調適與提示

**直觀說法。** 預訓練學習廣泛表示或延續模式；調適改變任務行為；提示則改變提供的輸入，不一定改權重。

監督任務調適對標註例子最小化任務損失。分類器可在預訓練表示後加分類頭，條件生成器則能學習回覆格式。繼續在領域文字上訓練語言模型會改變所建模的分布，卻不會自動教會應用標籤政策。熟悉領域與理解任務指令是兩種不同調適。

上下文內例子直接出現在輸入中，可在該次請求不更新參數的情況下示範格式或行為。效果取決於例子選擇、次序與任務相容性。若例子包含私密答案或測試標籤，評估就可能失效。提示在開發案例剛好表現不錯，仍必須在最終測試前凍結。

低秩調適（Low-Rank Adaptation，LoRA）固定基礎權重矩陣，訓練受限更新 [6]：

$$
W'=W+BA.
$$

其中 $W\in\mathbb R^{m\times n}$ 是固定矩陣；$A\in\mathbb R^{r\times n}$ 與 $B\in\mathbb R^{m\times r}$ 是學得因子；$r$ 是選定的秩；$W'$ 是有效調適矩陣。簡化式省略可選縮放。減少可訓練參數能降低調適成本，但不能取代代表性標籤、資料隔離與任務評估。

基礎模型版本、分詞器、調適權重與設定應一起儲存。針對某基礎檢查點訓練的調適，不保證能套用到同家族另一檢查點。比較時要報告哪些參數改變、用了哪些資料。只說「有微調」不足以重現結果。

## 指令與偏好

**直觀說法。** 學習遵循指令與學習人們偏好的回覆，是相關但不同的訊號；兩者都不直接保證真實。

InstructGPT 論文先研究監督指令例子，再以人類回饋進行偏好訓練 [7]，因而區分基礎延續模型與朝請求行為調適的模型。偏好來源很重要：標註者依政策平衡實用性、格式與其他目標。較受偏好的回覆仍可能有事實錯誤。

直接偏好最佳化（Direct Preference Optimization，DPO）結合偏好與不偏好的回覆，以及參考政策 [8]。代表性目標如下：

$$
\mathcal L_{\mathrm{DPO}}
=-\log\sigma\!\left(
\beta\left[
\log\frac{\pi_\theta(y^+\mid x)}{\pi_{\mathrm{ref}}(y^+\mid x)}
-\log\frac{\pi_\theta(y^-\mid x)}{\pi_{\mathrm{ref}}(y^-\mid x)}
\right]\right).
$$

其中 $x$ 是提示；$y^+$ 與 $y^-$ 是偏好及不偏好的回覆序列；$\pi_\theta$ 是可訓練政策；$\pi_{\mathrm{ref}}$ 是固定參考政策；$\beta$ 是正縮放參數；$\sigma$ 是 logistic sigmoid；$\mathcal L_{\mathrm{DPO}}$ 是單一偏好對的損失。序列機率是回覆詞元條件機率的乘積，提示提供上下文，不是受監督回覆詞元。

目標提高偏好回覆相對於另一回覆的概似，並以參考政策為基準。它假設偏好對是有用訓練證據。若資料獎勵自信但無支持的答案，最佳化可能強化這種行為。因此，評估除總體偏好勝率外，還要包含來源支持、不確定性與任務失敗案例。

這個式子是閱讀輔助，不是要求對微型語料訓練偏好模型。小型合成練習無法證明大型模型對齊。重點是辨識訓練訊號及限制：指令遵循、偏好一致與事實支持是不同性質，需要不同證據。

## 解碼改變輸出分布

**直觀說法。** 訓練模型產生分數；解碼器決定選最強詞元，還是取樣其他選項。

對 logit $z_v$ 與正溫度 $\tau$：

$$
q_\tau(v)=\frac{\exp(z_v/\tau)}{\sum_{u\in V}\exp(z_u/\tau)}.
$$

其中 $v$ 是候選詞元；$V$ 是詞彙表；$u$ 遍歷分母候選；$z_v$ 是模型未正規化分數；$\tau$ 是溫度；$q_\tau$ 是所得取樣分布。低溫集中在高分詞元，高溫則分散機率。貪婪選擇直接取最高分詞元，不做取樣。

<Figure src={temperatureFig} alt="溫度改變四個合成候選詞元的機率，但原 logits 不變" caption="圖 2 — 固定合成 logits 下，溫度改變取樣分布。更集中的輸出不會自動更正確。" />

生成還需要停止政策與長度預算。模型可能太早停止，也可能持續輸出重複內容，這些都是相對於契約的錯誤。[NLP 08](/zh-tw/learn/nlp/nlp-08-generation-deployment/) 會討論條件搜尋、摘要限制與翻譯評估。比較模型回覆時，應記錄解碼設定。

重複取樣能顯示變異，但樣本一致不是主張的獨立驗證。它們共享模型，也往往共享訓練偏誤。檢索或工具結果能提供外部證據，前提是檢查來源與權限。這也引出下一章。

## 可重現的語言模型實驗

**直觀說法。** 別人能知道哪些文字、詞元與決策產生結果，結果才有用。應以契約記錄實驗，而非只存權重檔。

先記錄文件切分與理由。獨立合成句子可能適合隨機切分，客服助理則可能需要按客戶或時間隔離。寫清楚是否允許用無標籤開發文字建詞彙表。本例詞彙只來自訓練句，測試組合也刻意全部使用已知詞，因而隔離一個狹義的組合泛化問題。

接著記錄分詞、序列邊界、目標位移、最大上下文與損失分母。程式評分每個下一詞元目標，包括結束詞元，但不把起始詞元當目標。這些細節讓困惑度能被解讀。若別的實驗排除停止預測，或讓不同長度句子等權，其數字回答的就是不同問題。

最後區分選擇與報告。若目標是公平最終測試，應在開發資料上選架構、訓練長度與解碼行為。本例固定短訓練預算作教學，沒有競爭性主張。正式比較需要聲明選擇程序，在不穩定性重要時重複執行，並只在選擇凍結後檢視保留集合。

保存足以解釋失敗的資訊：前處理版本、模型設定、種子、允許的輸入上下文與輸出設定。敏感原文件應放在適當存取控制下，而非複製到不受限制的紀錄。以文件識別碼與版本建立精簡紀錄，可支援重現而不必把底層文字公開給每位讀者。

## 現代觀點

**直觀說法。** 當代語言模型結合預訓練、調適、評估與系統整合。綜述若能釐清選擇，而非壓縮成單一排名，就特別有用。

Zhao 等人的綜述更新至 2026 年，並發表於 Frontiers of Computer Science，依預訓練、調適、使用與能力評估組織大型語言模型 [9]。這有助區分更多訓練資料、指令微調與不同使用方式。Chang 等人的評估綜述區分評什麼、在哪裡評與如何評 [10]。兩者共同支持任務專屬評估，而非依賴單一通用分數。

分類圖譜不能當成普遍性能主張。因果解碼器、雙向編碼器與編碼器—解碼器提供不同介面與資訊可見性，原 BERT 與 T5 論文就是例子 [3, 4]。比較應取決於使用者需要詞元區段、類別、檢索段落還是生成文字。能以低延遲和簡單覆核滿足任務時，小型專用模型可能是更好的工程選擇。

開放問題包含評估集合污染、長上下文穩健性、多語涵蓋、穩定不確定性，以及指令遵循和來源支持正確性的關係。較大視窗允許更多輸入，卻不能證明模型可靠使用了所有相關部分。長答案看似完整，仍可能遺漏來源的重要限定。

實務學習可維持四份報告：序列預測契約、任務品質、挑戰案例錯誤與資源成本。最終保留集合要與模型、提示及解碼選擇分開。應用改變時，先修訂契約與評估，再比較新檢查點。機率模型是強大的元件，完整語言應用仍是需要設計與測試的系統。

## 重點整理

- 因果預測使用較早詞元，遮罩預測可以使用選定位置兩側。
- 注意力可見性與監督損失遮罩有不同用途。
- 明確位移目標，測試未來詞元無法改變較早 logits。
- 困惑度比較需要相容分詞與評估位置。
- 預訓練、領域調適、任務微調與提示是不同操作。
- 偏好學習不能取代事實支持評估。
- 解碼設定是可重現生成結果的一部分。
