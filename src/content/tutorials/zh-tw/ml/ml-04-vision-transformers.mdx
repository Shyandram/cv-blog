## 你將學到

- 自注意力（self-attention）如何算出一個隨輸入而變的加權平均；query、key、value 各自扮演什麼角色；為什麼分數要除以 $\sqrt{d_k}$。
- 多頭注意力（multi-head attention）、因果遮罩（causal mask）與交叉注意力（cross-attention）怎麼建構，並用程式碼與 PyTorch 逐一比對。
- 為什麼注意力需要位置資訊，以及正弦、可學習、相對與旋轉（rotary）位置編碼如何提供它。
- Transformer 區塊如何組合注意力、MLP、LayerNorm 與殘差連接。
- Vision Transformer（ViT）如何把影像變成 patch token、為什麼它需要那麼多資料，以及 DeiT、Swin 與 CNN–Transformer 混合設計如何回應這個問題。
- 注意力為什麼昂貴；FlashAttention、視窗與 token 合併各自改變了什麼；Mamba 與 Mamba-2 和注意力的差異，以及影像掃描順序如何影響全域上下文與方向偏差。

## 先看全貌

CNN（[ML 03](/zh-tw/learn/ml/ml-03-convolutional-networks/)）讓資訊透過固定的局部鄰域傳遞：一個像素要經過很多層，才能「聽到」遠處像素的消息。**注意力**（attention）則讓每個位置根據自己目前的內容，自行決定要讀取哪些其他位置，而且一步就到。要辨認一隻鳥，含有鳥頭的 patch 可以直接參考遠處含有翅膀的 patch。

<Callout type="tip" title="用最簡單的話說">
想像一間教室，每個小朋友手上拿著一片拼圖。每個人都對自己那一片提出一個問題（「我這片有藍色的邊，誰有天空？」），其他人則各自舉起一張卡片，描述自己手上那一片。每個小朋友會最專心聽那些卡片最符合自己問題的同學，然後更新自己對這片拼圖的想法。接著大家用更新後的想法再來一輪。注意力就是這個「聽誰說話」的規則；Transformer 則是重複很多輪聆聽，中間再穿插一點自己思考的時間。
</Callout>

注意力的想法來自用循環網路做的機器翻譯：[ML 03A](/zh-tw/learn/ml/ml-03a-recurrent-recursive-networks/) 說明了它如何移除編碼器–解碼器 RNN 的單一向量瓶頸。Vaswani 等人的 Transformer [1] 走得更遠，完全拿掉循環結構，編碼器與解碼器都只由注意力和逐 token 的小型網路組成。Dosovitskiy 等人的 Vision Transformer（ViT）[2] 則幾乎原封不動地把 Transformer 編碼器套用到影像 patch 序列上。Bishop 與 Bishop [10] 提供了現代的教科書式推導，而現代觀點一節討論的綜述 [3]、[11]、[12] 則整理了眾多視覺變體。讀完本篇之後，[DL 02](/zh-tw/learn/deep-learning/dl-02-image-classification/) 會在實務上比較 CNN 與 Transformer 骨幹在分類上的表現，[ML 05](/zh-tw/learn/ml/ml-05-representation-learning/) 則說明這些骨幹如何在沒有標註的情況下預訓練。

## 自注意力：query、key 與 value

**白話版。** 每個 token 產生三個向量：**query**（「我在找什麼？」）、**key**（「我含有什麼？」）以及 **value**（「如果你聽我的，我要傳出什麼？」）。一個 token 的輸出，就是所有 value 的平均，權重取決於它的 query 與每個 key 的吻合程度。

**精確版。** 把 $N$ 個 token 疊成矩陣 $X\in\mathbb{R}^{N\times D}$ 的各列，其中 $D$ 是模型寬度。三個可學習的矩陣將它們投影：

$$
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V,
$$

其中 $W_Q,W_K\in\mathbb{R}^{D\times d_k}$、$W_V\in\mathbb{R}^{D\times d_v}$。**縮放點積注意力**（scaled dot-product attention）[1] 為

$$
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}_{\text{row}}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V=AV .
$$

$QK^\top$ 是一個 $N\times N$ 的**分數**矩陣：第 $(i,j)$ 項是 query $i$ 與 key $j$ 的點積，衡量 token $j$ 對 token $i$ 有多相關。逐列的 softmax 把每一列轉成非負且總和為一的權重，得到**注意力矩陣** $A$。輸出 $Y=AV\in\mathbb{R}^{N\times d_v}$ 每個 token 一列：第 $i$ 列是 $\sum_j A_{ij}v_j$，也就是 value 向量的加權平均。

**為什麼要三個不同的投影？** 如果 query 和 key 是同一個向量，每個 token 都會和自己最吻合，而且相關性被迫是對稱的。分開的 $W_Q$ 與 $W_K$ 讓「我要找的東西」可以不同於「我能提供的東西」（眼睛的 patch 可以去找鼻子，而不必自己就是鼻子）；分開的 $W_V$ 則讓「我能提供的東西」不同於「我實際傳出的內容」。

**為什麼要除以 $\sqrt{d_k}$？** 若 query 與 key 的各分量互相獨立、平均為零、變異數為一，則點積 $q\cdot k=\sum_{l=1}^{d_k}q_lk_l$ 的平均為零、變異數為 $d_k$。不縮放的話，頭越寬分數就越大，softmax 會飽和（幾乎所有權重集中在一個 token 上），梯度也會變得極小。除以 $\sqrt{d_k}$ 讓變異數回到一。這是一種尺度慣例，並不是把每個 query 正規化成單位長度。

**決定誰跟誰交談的是內容，而不是位置。** 卷積的權重綁定在相對位置上；注意力的權重則是在執行時由資料算出來的。由此衍生一個性質：自注意力是**排列等變**（permutation-equivariant）的。把輸入 token 打亂，輸出也會以相同方式被打亂，因為公式裡沒有任何東西涉及 token 的順序。下面的程式碼同時檢查形狀與這個對稱性。

```python
import torch

torch.manual_seed(0)
X = torch.randn(5, 8)                   # N=5, D=8
Wq, Wk, Wv = [torch.randn(8, 4) for _ in range(3)]
def attention(x):
    q, k, v = x @ Wq, x @ Wk, x @ Wv
    a = (q @ k.T / q.shape[-1]**.5).softmax(dim=-1)
    return a @ v, a
y, a = attention(X)
perm = torch.tensor([3, 0, 4, 1, 2])
yp, _ = attention(X[perm])
assert torch.allclose(a.sum(-1), torch.ones(5), atol=1e-6)
assert torch.allclose(yp, y[perm], atol=1e-5)
print("output shape:", tuple(y.shape))
```

這個對稱性很適合處理集合，但影像不是一堆 patch 的集合：眼睛長在嘴巴下面的臉，就不是一張臉。下面介紹的位置資訊會打破這個對稱性。

## 多頭注意力

**白話版。** 平行執行好幾個注意力運算，每個都有自己較小的投影，讓不同的頭可以追蹤不同的關係（鄰近紋理、同一個物體、對稱的部位）。最後把它們的輸出串接起來再混合。

**精確版。** 有 $h$ 個頭時，第 $r$ 個頭有自己的 $W_Q^{(r)},W_K^{(r)},W_V^{(r)}\in\mathbb{R}^{D\times d_k}$，通常取 $d_k=d_v=D/h$：

$$
\operatorname{head}_r=\operatorname{Attention}\!\left(XW_Q^{(r)},XW_K^{(r)},XW_V^{(r)}\right),\qquad
\operatorname{MHA}(X)=\big[\operatorname{head}_1,\dots,\operatorname{head}_h\big]\,W_O,
$$

其中方括號把 $h$ 個寬度為 $D/h$ 的輸出串接回寬度 $D$，$W_O\in\mathbb{R}^{D\times D}$ 再把它們混合。由於每個頭寬度只有 $D/h$，多頭注意力的成本與一個全寬度的頭差不多，所有投影合計 $4D^2$ 個權重（另加偏差）。各個頭不保證會學到人類看得懂的角色；有些頭是多餘的，可以被剪除。

下面的實作把投影切成多個頭、逐頭計算分數、串接後再投影，結果與 `nn.MultiheadAttention` 完全一致。它也示範了**因果遮罩**：在 softmax 之前把禁止的分數設為 $-\infty$，這些位置的權重就會恰好為零。

```python
import torch
from torch import nn

torch.manual_seed(0)
B, N, D, h = 2, 6, 16, 4
mha = nn.MultiheadAttention(D, num_heads=h, batch_first=True, bias=False)
X = torch.randn(B, N, D)

def multi_head(x):
    Wq, Wk, Wv = mha.in_proj_weight.chunk(3)          # each D x D (rows = outputs)
    q, k, v = x @ Wq.T, x @ Wk.T, x @ Wv.T              # B x N x D
    split = lambda t: t.view(B, N, h, D // h).transpose(1, 2)   # B x h x N x d_k
    q, k, v = split(q), split(k), split(v)
    scores = q @ k.transpose(-2, -1) / (D // h) ** 0.5  # B x h x N x N
    A = scores.softmax(dim=-1)
    heads = A @ v                                       # B x h x N x d_k
    concat = heads.transpose(1, 2).reshape(B, N, D)     # put the heads side by side
    return concat @ mha.out_proj.weight.T, A

ours, A = multi_head(X)
ref, _ = mha(X, X, X)
print("matches nn.MultiheadAttention:", torch.allclose(ours, ref, atol=1e-5))
print("attention tensor:", tuple(A.shape), "| parameters:",
      sum(p.numel() for p in mha.parameters()), "= 4 * D^2 =", 4 * D * D)

# Causal mask: query i may only read keys j <= i
causal = torch.triu(torch.ones(N, N, dtype=torch.bool), diagonal=1)   # True = forbidden
out_c, w_c = mha(X, X, X, attn_mask=causal)
print("no weight on the future:", torch.all(w_c[:, causal] == 0).item())
```

輸出為 `True`、形狀 `(2, 4, 6, 6)` 的注意力張量（批次、頭、query、key）、`1024 = 4 * D^2 = 1024`，以及因果檢查的 `True`。正式的程式碼請呼叫 `torch.nn.functional.scaled_dot_product_attention`，它計算的是同一件事，並會在裝置、資料型別與形狀允許時，自動改用融合（fused）、省記憶體的核心 [7]。

## 連接 token 的三種方式

**白話版。** 一個 query 可以讀取哪些 token，是模型設計的一部分，以分數矩陣上的遮罩來表達。

| 機制 | query 可讀取 | 典型用途 |
|---|---|---|
| 雙向自注意力 | 同一序列中的所有 token | ViT 及其他影像編碼器 |
| 因果（遮罩）自注意力 | 只有自己與更早的位置 | 下一個 token 的生成、自迴歸影像模型 |
| 交叉注意力 | 來自另一個序列的 token | 解碼器讀取編碼器；影像 token 讀取文字 |

<Figure src={masksFig} alt="三個 8 × 8 矩陣：無限制注意力全為藍色；因果遮罩只有下三角為藍色；兩個局部視窗則是對角線上的兩個藍色區塊。" caption="圖 1 — 注意力遮罩：藍色表示允許，白色表示禁止。因果生成還會把輸入平移一個位置，讓目標無法被直接複製。" />

在**交叉注意力**中，query 來自一個序列 $X$，key 與 value 則來自另一個序列 $Z$：$Q=XW_Q$、$K=ZW_K$、$V=ZW_V$。分數矩陣的形狀是 $N_X\times N_Z$，輸出每個 query 一列。原始 Transformer 的解碼器就是這樣讀取編碼器；影像描述模型這樣讀取影像特徵；文字生成影像的擴散模型也這樣讀取文字提示（[ML 07](/zh-tw/learn/ml/ml-07-diffusion-flow-matching/)），而不需要在影像 patch 上做自迴歸。

注意力權重是計算的一部分，並不自動等於一種解釋。很大的權重可能乘上一個毫無資訊的 value，而殘差與 MLP 路徑也會影響輸出。

## 位置資訊

**白話版。** 注意力不理會順序，所以我們必須告訴模型每個 token 在哪裡。最簡單的方法是在第一層之前，為每個 token 加上一個與位置有關的向量；更精緻的方法則把相對位置直接注入注意力分數。

**正弦位置編碼。** 原始 Transformer [1] 在位置 $pos$ 的 token 上加一個固定向量 $p_{pos}\in\mathbb{R}^D$：

$$
p_{pos,\,2i}=\sin\!\left(\frac{pos}{10000^{2i/D}}\right),\qquad
p_{pos,\,2i+1}=\cos\!\left(\frac{pos}{10000^{2i/D}}\right),\qquad i=0,\dots,\tfrac{D}{2}-1 .
$$

每一對維度 $(2i,2i+1)$ 都是一個以角頻率 $\omega_i=10000^{-2i/D}$ 繞圓旋轉的點，頻率從很快（每個位置一弧度）到非常慢都有。由三角函數的和角公式可得兩個性質。第一，對任一固定位移 $k$，都有 $p_{pos+k}=p_{pos}R_k$，其中 $R_k$ 是一個與 $pos$ 無關的區塊對角旋轉矩陣；因此一個線性層就能學會「往後看 $k$ 個位置」。第二，$p_{m}\cdot p_{n}=\sum_i\cos\big(\omega_i(m-n)\big)$ 只與位移 $m-n$ 有關（圖 2 中）。

<Figure src={posFig} alt="左：正弦位置編碼的熱圖，橫軸為位置、縱軸為 128 個維度，低維度振盪快、高維度振盪慢。中：位置 20 的編碼與所有位置的點積，在 20 處達到峰值並隨距離下降。右：14 × 14 網格依二維（列加行）編碼與星號 patch 的相似度著色，在星號附近以及其所在的列與行最亮。" caption="圖 2 — 正弦位置編碼。左：每一對維度以各自的頻率振盪。中：編碼之間的相似度只取決於位移。右：把列與行的編碼串接起來，就得到 14 × 14 patch 網格的二維編碼。" />

```python
import numpy as np

def sinusoidal(n_pos, D):
    pos = np.arange(n_pos)[:, None]
    omega = 1.0 / 10000 ** (np.arange(0, D, 2) / D)    # one frequency per sin/cos pair
    pe = np.zeros((n_pos, D))
    pe[:, 0::2] = np.sin(pos * omega)
    pe[:, 1::2] = np.cos(pos * omega)
    return pe, omega

pe, omega = sinusoidal(100, 16)
k = 7                                                 # a fixed offset
# block-diagonal rotation that maps p_pos to p_{pos+k}, the same for every pos
R = np.zeros((16, 16))
for i, w in enumerate(omega):
    c, s = np.cos(w * k), np.sin(w * k)
    R[2 * i:2 * i + 2, 2 * i:2 * i + 2] = [[c, -s], [s, c]]
print("p[pos+k] == p[pos] @ R for all pos:", np.allclose(pe[:-k] @ R, pe[k:]))
print("dot products depend only on offset:",
      np.isclose(pe[10] @ pe[17], pe[50] @ pe[57]))
```

兩項檢查都印出 `True`。

**其他做法。**

- **可學習的絕對位置嵌入**：每個位置一個可訓練的向量，ViT [2] 就是如此。ViT 依光柵（raster）順序編號的一維可學習嵌入，效果與明確的二維嵌入差不多；訓練後，同一列或同一行的 patch 嵌入會變得相似，代表模型自己學會了網格結構。換到新的解析度時，先用二維內插調整嵌入網格的大小，再進行微調。
- **相對位置表示**（Shaw 等人 [17]）在 token $i$ 與 $j$ 的分數上，加一個取決於位移 $j-i$ 的可學習項。Swin [5] 則在每個視窗的分數上加一張可學習的**相對位置偏差**（relative position bias）表。
- **旋轉位置嵌入**（rotary position embedding, RoPE；Su 等人 [16]）把每個 query 與 key 依其位置旋轉一個成比例的角度，使用的正是上面程式碼中的那種旋轉。於是分數 $q_m^\top k_n$ 只透過 $m-n$ 依賴位置。RoPE 已是大型語言模型的標準配備，在視覺中也越來越常見，做法是對影像的兩個軸分別旋轉。
- **不加明確編碼**：網路內部的卷積（如 CvT [19]），或邊界的零填補，本身就可能洩漏足夠的位置資訊。

## Transformer 區塊

**白話版。** 一個區塊交替做兩件事：注意力讓 token 互相交換資訊；接著一個小型 MLP 分別處理每個 token。殘差連接與正規化讓整個堆疊保持穩定。

**精確版。** ViT 與大多數現代模型使用的**前置正規化**（pre-norm）區塊為

$$
U=X+\operatorname{MHA}\!\big(\operatorname{LN}(X)\big),\qquad
Y=U+\operatorname{MLP}\!\big(\operatorname{LN}(U)\big),\qquad
\operatorname{MLP}(u)=W_2\,\operatorname{GELU}(W_1u+b_1)+b_2 .
$$

$\operatorname{LN}$ 是**層正規化**（layer normalization）[14]：它把每個 token 的 $D$ 個特徵標準化為平均零、變異數一，再套用可學習的縮放與平移；與 BatchNorm 不同，它不依賴同一批次中的其他樣本。MLP 把每個 token 從 $D$ 擴展到通常 $4D$ 個隱藏單元，套用 GELU 非線性 [26]（$\operatorname{GELU}(z)=z\,\Phi(z)$，$\Phi$ 為標準常態分布的累積分布函數），再投影回去。殘差相加代表每個子層只需學習一個修正量，與 ResNet 完全相同。

<Figure src={blockFig} alt="由左至右的區塊圖：X、LayerNorm、多頭自注意力、加法節點、LayerNorm、D 到 4D 再到 D 並使用 GELU 的 MLP、加法節點、Y；兩條橘色弧形箭頭分別把 X 繞過注意力分支、把中間結果繞過 MLP 分支，送到加法節點。" caption="圖 3 — 前置正規化的 Transformer 區塊。注意力在 token 之間混合資訊；MLP 分別轉換每個 token；殘差路徑（橘色）把輸入繞過每個分支。" />

原始 Transformer 把 LayerNorm 放在每次殘差相加**之後**（後置正規化，post-norm）。Xiong 等人 [15] 證明，使用後置正規化時，初始化階段靠近輸出的梯度很大，這正是它需要學習率暖身（warm-up）的原因；前置正規化則讓梯度保持穩定，可以不用暖身就訓練。所以只說「一個 Transformer」並不完整，還得說明正規化放在哪裡。每個區塊的權重數：注意力 $4D^2$、MLP $8D^2$，合計約 $12D^2$，其中三分之二在 MLP。

## Vision Transformer（ViT）

**白話版。** 把影像切成方形 patch，把每個 patch 變成向量，加上位置資訊，然後送進標準的 Transformer 編碼器。答案從一個額外的特殊 token 讀出。

**切成 patch。** 對一張 $H\times W$ 像素、$C$ 個通道的影像，若 patch 大小 $P$ 能整除 $H$ 與 $W$，就有 $N=HW/P^2$ 個 patch。把每個 patch 攤平成 $x_i^{\text{patch}}\in\mathbb{R}^{P^2C}$，再做線性投影：

$$
z_0=\big[\,x_{\text{cls}};\;x_1^{\text{patch}}E;\;\dots;\;x_N^{\text{patch}}E\,\big]+E_{\text{pos}},
$$

其中 $E\in\mathbb{R}^{P^2C\times D}$ 是可學習的 **patch 嵌入**，$x_{\text{cls}}\in\mathbb{R}^D$ 是加在序列最前面的可學習**類別 token**（class token），$E_{\text{pos}}\in\mathbb{R}^{(N+1)\times D}$ 存放可學習的位置嵌入。經過 $L$ 個區塊後，對類別 token 的輸出套用一個 LayerNorm 與線性分類頭，就得到 logits。把所有 patch 的輸出取平均（mean pooling）也是同樣常見的替代做法。

<Figure src={patchFig} alt="縮放成 224 × 224 的太空人測試影像，疊上 7 × 7 的白色格線；右側依光柵順序列出前十二個 patch 的小圖，接著是四個編號步驟：切成 patch、攤平並乘上 E、加上位置嵌入並可選擇加上 CLS token、把 N × D 序列送進編碼器。" caption="圖 4 — 切成 patch。為了清楚起見這裡畫的是 32 像素的格子；ViT-Base 使用 16 × 16 的 patch，把 224 × 224 的影像變成 196 個 token。" />

對不重疊的 $P\times P$ patch 套用線性映射，恰好等於核大小與步幅都是 $P$ 的卷積，實作上也正是這樣寫：

```python
import torch
from torch import nn

torch.manual_seed(0)
B, C, H, W, P, D = 2, 3, 32, 32, 8, 48
x = torch.randn(B, C, H, W)

# 1) explicit: cut into P x P patches, flatten each, multiply by E
patches = x.unfold(2, P, P).unfold(3, P, P)                 # B, C, H/P, W/P, P, P
patches = patches.permute(0, 2, 3, 1, 4, 5).reshape(B, -1, C * P * P)   # B, N, P*P*C
E = torch.randn(C * P * P, D) * 0.02
tokens_explicit = patches @ E                                # B, N, D

# 2) the same linear map written as a convolution with kernel = stride = P
conv = nn.Conv2d(C, D, kernel_size=P, stride=P, bias=False)
conv.weight.data = E.T.reshape(D, C, P, P)
tokens_conv = conv(x).flatten(2).transpose(1, 2)             # B, N, D

print("tokens:", tuple(tokens_conv.shape), "| identical:",
      torch.allclose(tokens_explicit, tokens_conv, atol=1e-5))
```

輸出為 16 個寬度 48 的 token，以及 `True`。

**模型大小。** 標準設定有 ViT-Base（12 個區塊、$D=768$、12 個頭、約 8,600 萬個參數）、ViT-Large（24 個區塊、$D=1024$、16 個頭）與 ViT-Huge（32 個區塊、$D=1280$、16 個頭）[2]。「ViT-B/16」代表使用 $16\times16$ patch 的 Base 模型。**patch 大小是最主要的運算量旋鈕**：$P$ 減半，$N$ 變成四倍，注意力分數的數量變成十六倍。小 patch 保留細節；大 patch 便宜，但比 patch 還細的資訊都會遺失，而且後面任何一層都救不回來。

**資料的教訓。** Dosovitskiy 等人 [2] 發現，只在 ImageNet-1k（約 130 萬張影像）上訓練的 ViT，表現略遜於規模相當的 ResNet；但若先在 ImageNet-21k（1,400 萬張）或 JFT-300M（3 億張）上預訓練再微調，它就能追平甚至超越 ResNet，而且預訓練成本更低。他們的解釋是**歸納偏置**（inductive bias）：CNN 在每一層都假設局部性與平移等變性，而 ViT 只在 patch 嵌入內是局部的，空間關係必須從資料中**學出來**。Raghu 等人 [18] 比較了 ViT 與 ResNet 的內部表徵，發現 ViT 各層的表徵更加一致、較低層同時兼顧局部與全域的注意力，而且要在早期層學到局部注意力，需要大規模的預訓練。

### 程式碼：在手寫數字上訓練一個小型 ViT

這個完整範例在與 [ML 03](/zh-tw/learn/ml/ml-03-convolutional-networks/) CNN 相同的 $8\times8$ 手寫數字資料上訓練一個小型 ViT，使用 $2\times2$ 的 patch（16 個 token）、一個類別 token、可學習的位置嵌入，以及四個前置正規化區塊。在 CPU 上約半分鐘即可跑完。

```python
import copy
import numpy as np
import torch
from torch import nn
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

torch.manual_seed(0)
torch.set_num_threads(1)

class TinyViT(nn.Module):
    def __init__(self, img=8, patch=2, chans=1, D=64, depth=4, heads=4, classes=10):
        super().__init__()
        N = (img // patch) ** 2
        self.patch = nn.Conv2d(chans, D, kernel_size=patch, stride=patch)   # patchify + E
        self.cls = nn.Parameter(torch.zeros(1, 1, D))                       # [CLS] token
        self.pos = nn.Parameter(torch.randn(1, N + 1, D) * .02)             # learned positions
        layer = nn.TransformerEncoderLayer(D, heads, dim_feedforward=4 * D, dropout=0.1,
                                           activation="gelu", batch_first=True,
                                           norm_first=True)                 # pre-norm block
        self.blocks = nn.TransformerEncoder(layer, depth, enable_nested_tensor=False)
        self.norm, self.head = nn.LayerNorm(D), nn.Linear(D, classes)

    def forward(self, x):
        t = self.patch(x).flatten(2).transpose(1, 2)                         # B, N, D
        t = torch.cat([self.cls.expand(len(t), -1, -1), t], dim=1) + self.pos
        return self.head(self.norm(self.blocks(t))[:, 0])                    # read [CLS]

d = load_digits()
X = torch.tensor(d.images[:, None] / 16.0, dtype=torch.float32)
y = torch.tensor(d.target)
train, test = train_test_split(np.arange(len(y)), test_size=.2, stratify=d.target,
                               random_state=0)
train, val = train_test_split(train, test_size=.2, stratify=d.target[train], random_state=1)
model = TinyViT()
opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.05)
best = (float("inf"), None)
for epoch in range(30):
    model.train()
    for idx in torch.tensor(train)[torch.randperm(len(train))].split(64):
        loss = nn.functional.cross_entropy(model(X[idx]), y[idx])
        opt.zero_grad(); loss.backward(); opt.step()
    model.eval()
    with torch.no_grad():
        v = nn.functional.cross_entropy(model(X[val]), y[val]).item()
    if v < best[0]:
        best = (v, copy.deepcopy(model.state_dict()))
model.load_state_dict(best[1]); model.eval()
with torch.no_grad():
    acc = (model(X[test]).argmax(1) == y[test]).float().mean().item()
print("parameters:", sum(p.numel() for p in model.parameters()))
print("best validation loss:", round(best[0], 4), "| held-out accuracy:", round(acc, 4))
```

在我們的執行中，它約有 202,000 個參數，保留測試集準確率約 95%；而 ML 03 的 CNN 在相同的資料切分下，只用不到 10,000 個參數就達到約 96%。在小型資料集上，CNN 內建的局部性大約值二十倍的參數量。這是「資料的教訓」的縮影，而不是對大規模效能的定論。

## 訓練配方：DeiT 及其後續

**白話版。** 早期 ViT 與 CNN 在 ImageNet 規模資料上的差距，很大一部分其實來自訓練方式，而不是架構。

DeiT（Touvron 等人 [4]）**只用 ImageNet-1k** 就把 ViT 訓練到具競爭力，靠的是強力的資料擴增（RandAugment、Mixup、CutMix、隨機抹除）、大量正則化（stochastic depth、label smoothing）以及較長的訓練排程。它還引入了**蒸餾 token**（distillation token）：一個類似類別 token 的額外可學習 token，其輸出被訓練去符合一個預訓練 CNN 教師模型的預測。CNN 的歸納偏置因此透過它的預測轉移過來。後來的 DeiT III [27] 證明，一個更簡單但仔細調校的監督式配方（輕量的「3-Augment」擴增、簡單的裁切，以及二元交叉熵損失函數）能讓純 ViT 更強。Steiner 等人 [25] 對資料、擴增與正則化做了大規模研究（「AugReg」），發現擴增、正則化與運算量的適當組合，可以追上用大約十倍資料訓練的模型。

一般性的教訓與 [ML 03](/zh-tw/learn/ml/ml-03-convolutional-networks/) 討論 ConvNeXt 時相同：只有在資料、擴增、解析度、訓練排程與運算量都對齊的情況下，比較架構才有意義。

## Swin 與階層式 Transformer

**白話版。** 對數千個 token 做全域注意力很昂貴，而且純 ViT 從頭到尾維持同一個粗解析度，不利於偵測與分割。Swin 把注意力限制在局部視窗內，在層與層之間平移視窗讓資訊仍能擴散，並合併 patch 來建立類似 CNN 的金字塔。

**視窗。** Swin [5] 把 token 網格切成互不重疊、每個 $M\times M$ 個 token 的視窗（通常 $M=7$），只在每個視窗內部計算自注意力。對 $h\times w$ 的 token 網格、$C$ 個通道，論文給出的成本為

$$
\Omega(\text{global MSA})=4hwC^2+2(hw)^2C,\qquad
\Omega(\text{window MSA})=4hwC^2+2M^2hwC,
$$

其中 $4hwC^2$ 是四個投影的成本，第二項則是計算分數與加權的乘法。全域成本對 token 數 $hw$ 是二次方；固定 $M$ 時，視窗成本是線性的。

**平移視窗。** 若視窗固定不動，不同視窗的 token 永遠不會互動。Swin 讓一般視窗與在兩個方向各平移 $\lfloor M/2\rfloor$ 個 token 的視窗交替出現。在第 $\ell$ 層位於視窗邊界附近的 token，到第 $\ell+1$ 層會與相鄰視窗的 token 同在一個視窗，資訊因此得以跨越邊界（圖 5）。高效率的實作會把特徵圖做循環平移，並用遮罩避免從對側邊緣繞過來的 token 互相注意。

<Figure src={swinFig} alt="左：8 × 8 的 token 網格分成四個彩色的 4 × 4 視窗。中：同一網格的視窗邊界平移兩個 token，形成九個大小不一的區域。右：8 × 8 的圖中，左上角 4 × 4 視窗為深藍色，向右與向下再延伸兩個 token 的 L 形帶狀區域為淺藍色，紅色星號標出一個靠近視窗邊緣的 token。" caption="圖 5 — Swin 在 8 × 8 token 網格上的一般視窗與平移視窗。兩層之後，星號 token 的資訊會到達深色視窗（第 ℓ 層），再加上平移視窗帶來的淺色帶狀區域（第 ℓ+1 層）。" />

**階層結構。** 在各階段之間，**patch 合併**（patch merging）把每 $2\times2$ 組相鄰 token 串接後做線性投影，使解析度減半、通道數加倍，就像步幅卷積一樣。四個階段分別產生輸入解析度 $1/4$、$1/8$、$1/16$、$1/32$ 的特徵圖，與 ResNet 的金字塔相同，因此 Swin 可以在偵測與分割框架中直接取代 CNN 骨幹。每個視窗的分數也會加上可學習的**相對位置偏差**。Swin V2 [32] 用殘差後置正規化、縮放餘弦注意力（scaled cosine attention），以及連續、對數間隔的位置偏差來擴大規模，後者在不同視窗大小與解析度之間的遷移效果更好。

## CNN–Transformer 混合模型

**白話版。** 卷積擅長在資料少時處理局部細節；注意力擅長長距離互動。混合模型讓兩者各自在適合的地方發揮。

- **卷積起始層（stem）。** 原始 ViT 論文就已測試過一種「混合」版本，其 patch 取自 ResNet 的特徵圖而不是原始像素 [2]；在較小的運算預算下有幫助。
- **在注意力裡放卷積。** CvT [19] 在每個階段使用卷積式 token 嵌入，並用深度可分離卷積產生 query、key、value 的投影，藉此內建局部性，也因此可以省去明確的位置嵌入。
- **依階段堆疊。** CoAtNet [20] 在前期放深度卷積階段（此時解析度高、局部模式為主），後期放相對注意力階段；它在各種資料規模下都報告了強勁的結果，因為卷積階段在資料有限時提供了歸納偏置。
- **行動裝置混合模型。** MobileViT [28] 在 MobileNet 風格的網路中插入小型 Transformer 區塊，以行動裝置等級的成本加入全域脈絡。
- **反方向。** ConvNeXt（見 [ML 03](/zh-tw/learn/ml/ml-03-convolutional-networks/)）把 Transformer 時代的設計選擇引進純 CNN，並追平了 Swin。

## 成本與高效率注意力

**白話版。** 全域注意力要把每個 token 和其他每個 token 比較，所以影像邊長加倍，工作量就變成十六倍。高效率方法要嘛讓精確注意力跑得更快，要嘛限制哪些 token 互動，要嘛減少 token 數量。

對 $N$ 個寬度為 $D$ 的 token，每層分數矩陣約需 $N^2D$ 次乘加，投影與 MLP 約需 $12ND^2$ 次。單純的實作會為每個頭儲存一個 $N\times N$ 矩陣。固定 patch 大小時，影像高與寬各加倍，$N$ 變成四倍，成對分數變成十六倍。

<Figure src={costFig} alt="patch 大小 16、影像邊長 224、448、896 時的相對成對分數數量：全域注意力成長到 256 倍，而 7 × 7 視窗注意力只成長到 16 倍。" caption="圖 6 — 成對分數的成長趨勢，並非實測的執行時間。投影、MLP、記憶體存取與核心實作品質也會影響延遲。" />

主要的方法家族：

- **精確但更快。** FlashAttention [6] 把計算切成區塊（tiling），讓 query、key、value 的區塊留在快速的晶片內記憶體中，並且從不把完整的 $N\times N$ 矩陣寫到較慢的 GPU 記憶體，藉此計算**精確**的注意力；FlashAttention-2 [29] 進一步改善了工作切分方式。算術量仍是二次方，但記憶體用量變成線性，實際執行時間也大幅下降。PyTorch 的 `scaled_dot_product_attention` 在可行時會自動選用這類核心 [7]。
- **限制連接方式。** 視窗（Swin）或其他稀疏模式減少了成對的數量，代價是需要好幾層才能達成全域溝通。
- **減少 token。** Token Merging（ToMe）[21] 在預訓練好的 ViT 內，以快速的配對步驟逐步合併相似的 token，不需重新訓練就能提高吞吐量。較大的 patch、token 剪枝與池化階段則以更粗略的方式達到相同效果。
- **更小的模型。** Papa 等人的綜述 [13] 把高效率 ViT 分為精簡架構、剪枝、知識蒸餾與量化四類，並提出「Efficient Error Rate」指標，用來在參數量、位元數、FLOPs 與模型大小之間比較模型。

## 狀態空間模型與混合模型

**白話版。** 不必比較每一對 token，而是像循環網路（[ML 03A](/zh-tw/learn/ml/ml-03a-recurrent-recursive-networks/)）一樣，讓一個精簡的狀態沿著序列傳遞。成本隨 token 數線性成長。

對 token 序列，一個簡化的狀態空間遞迴為

$$
h_t=\bar A_t\,h_{t-1}+\bar B_t\,x_t,\qquad y_t=C_t\,h_t,
$$

其中 $h_t$ 是固定大小的隱藏狀態，$\bar A_t$、$\bar B_t$、$C_t$ 是（離散化後的）狀態空間矩陣。在 Mamba 這類**選擇性**（selective）模型中，寫入／讀取係數與步長取決於輸入 $x_t$；底層連續轉移可以保持固定，離散化後的係數卻會改變。輸入選擇與仿射狀態更新使平行掃描（parallel scan）成為可能 [33]。影像沒有天然的一維順序，因此視覺版本必須選擇**掃描順序**：Vision Mamba（Vim）[30] 加上位置嵌入，對 patch 序列做正向與反向掃描；VMamba [31] 則沿著二維網格的四個方向掃描。Visual Mamba 綜述 [8] 回顧了 200 多篇論文，並指出掃描方式是視覺應用中最關鍵的設計決策。

MambaOut [9]（CVPR 2025）是一個有用的反例。作者主張 Mamba 適合長序列與因果（自迴歸）結構的任務，並在保留閘控卷積區塊的同時拿掉狀態空間元件，建立了 MambaOut 模型。他們的模型在 ImageNet 分類上勝過視覺 Mamba 模型，顯示 Mamba 在這裡並非必要；而對於涉及長 token 序列的偵測與分割，他們認為狀態空間模型仍值得探索。更廣泛的重點在於方法論：要把某個結果歸功於某種機制（注意力、掃描、卷積）之前，必須先把它與閘控、正規化、訓練配方和參數預算分開來看。

### 影像掃描是一種歸納偏置

Mamba [33] 提供高效率的序列運算，但不會替我們決定影像的幾何結構。Vim [30] 使用 patch 序列、位置嵌入與正向／反向處理；VMamba [31] 則把四條路徑的選擇性掃描放進階層式視覺骨幹中。單靠模型名稱，無法判斷感受野的影響強度、解析度行為或執行時間。狀態維度、掃描路徑、局部運算與降取樣階段都會影響結果。

在固定掃描順序下，影像中相鄰的兩個像素，可能在序列中相隔許多步。反過來，一列最後的像素與下一列第一個像素，雖然在空間上相距甚遠，卻在序列中連續。局部卷積可以先提供鄰近證據，再由掃描把上下文傳得更遠。多條路徑提供額外的傳遞方式，但不會自動恢復所有幾何對稱性。位置嵌入也能編碼有用的位置，卻讓移轉到不同網格成為另一個需要處理的設計問題。

可以用數學明確呈現這個選擇：

$$
Y^{(r)}=P_r^{-1}\mathcal S_r(P_rX),\qquad
Y=\frac1m\sum_{r=1}^{m}Y^{(r)}.
$$

其中 $X$ 包含展平後的影像 token，$r$ 索引 $m$ 條路徑中的一條，$P_r$ 把 token 排列成該路徑的順序，$\mathcal S_r$ 執行該路徑的序列循環，$P_r^{-1}$ 還原影像座標，$Y$ 對產生的特徵取平均。這是概念性的路徑融合模型。可學習的視覺區塊可以使用不同投影或融合規則；這裡選擇平均，是為了讓實驗容易解讀。

### CPU 實驗：量測方向偏差

下一個範例使用單一純量狀態，每條路徑的衰減係數都相同。先比較正向／反向的逐列掃描，以及加入逐欄掃描的四條路徑；接著把輸入旋轉 90 度、處理後再把輸出轉回來。全部使用合成的 $6\times6$ 脈衝，不下載權重或影像。這個實驗單獨檢查排序，並不重現訓練好的 Vim 或 VMamba。

```python
import numpy as np

def scan_image(image, four=False):
    ids = np.arange(image.size).reshape(image.shape)
    row, col = ids.ravel(), ids.T.ravel()
    orders = [row, row[::-1]]
    if four:
        orders += [col, col[::-1]]
    outputs = []
    for order in orders:
        h = 0.0
        out = np.zeros(image.size)
        for i in order:
            h = 0.8 * h + 0.2 * image.ravel()[i]
            out[i] = h
        outputs.append(out.reshape(image.shape))
    return np.mean(outputs, axis=0)

image = np.zeros((6, 6))
image[1, 4] = 1.0
errors = []
for four in [False, True]:
    original = scan_image(image, four=four)
    rotated_back = np.rot90(scan_image(np.rot90(image), four=four), -1)
    error = np.max(np.abs(original - rotated_back))
    errors.append(error)
    print('four routes:', four, 'rotation discrepancy:', round(error, 6))
assert 0.0 < errors[1] < errors[0]
```

兩條路徑的最大差異為 `0.063622`，四條路徑則為 `0.026738`。在這個範例中，增加路徑減少方向偏差，但剩餘差異並非零。旋轉逐列路徑時，其中一個遍歷軸會反向；變換後的路徑未必屬於原本四條路徑的集合。因此，即使係數共用且以平均融合，也不保證旋轉等變性。可學習的方向投影、位置資訊與局部運算又引入更多選擇。應直接測試需要的性質，而不是從「二維掃描」推定它存在。

<Figure src={scanFig} alt="兩條與四條路徑之純量影像掃描的脈衝響應" caption="圖 7 — 紅色外框標示輸入脈衝。兩條逐列路徑不均勻地傳遞上下文；加入逐欄路徑後，影響圖會改變。這些合成響應使用範例中的相同循環，並非學得的注意力圖或訓練好的 VMamba 活化值。" />

資訊能沿著完整掃描傳遞，因此循環可以具有全域感受野。這表示依賴關係可能存在，並不代表它在所有距離都保持強大影響。純量衰減為 $0.8$ 時，攜帶的貢獻每經過一步就再乘上 $0.8$。[ML 03A](/zh-tw/learn/ml/ml-03a-recurrent-recursive-networks/) 推導的選擇性轉移可以改變這種保留方式，但訓練仍須學會哪些資訊值得保存。即使可以讀取遠處上下文，狀態壓縮或降取樣仍可能遺失細緻邊界與小物件。

### Mamba-2 改變了什麼，又該如何評估

Mamba-2 [34] 以結構化狀態空間對偶性與高效率的分塊計算，重新安排選擇性序列混合器。它改變轉移結構與區塊參數投影，並沒有讓任意影像 patch 序列都等同於 Transformer。具有結構的因果係數矩陣可以用類似注意力的方式解讀，但標準 softmax 注意力仍保有不同的表達與計算性質。應用到影像時，仍須指定方向與融合方式。因此，對偶性回答的是計算問題，並未消除幾何問題。

公平的視覺比較應區分三種實驗：在共用區塊中只替換混合器；在對齊的訓練預算下比較完整骨幹；以及在目標硬體上量測部署模型。固定資料、資料增強、token 解析度與下游預測頭。除了參數量，也記錄狀態大小，並在不同影像解析度與批次大小下量測延遲及記憶體峰值。token 數的線性項可以同時伴隨昂貴的投影、路徑排列與小型運算核心的額外成本。上面的 Python 迴圈無法支持 GPU 吞吐量的宣稱。

對密集任務，檢查邊界附近、小型結構與不同長寬比下的錯誤；對影片，區分離線雙向編碼器與因果即時處理。除了分布內分類，也應納入旋轉／裁切敏感度與更長網格的評估。MambaOut [9] 提供重要的移除混合器消融實驗。結果支持依任務比較，並不是證明所有影像問題都不需要掃描的定理。Xu 等人 [8] 依骨幹、掃描機制，以及影像／影片／點雲／多模態應用整理視覺 Mamba。在已核實的紀錄中，這篇綜述仍是 2024 年預印本。其分類架構有助於選擇控制變因的實驗；提出的變體數量並不能確立普遍的贏家。

## 現代觀點

**綜述文獻。** Khan 等人 [3]（*ACM Computing Surveys*，2022）從基礎（自注意力、大規模預訓練、雙向編碼）談起，接著綜覽 Transformer 在辨識、生成模型、視覺問答等多模態任務、影片、低階視覺與三維分析上的應用，最後列出開放問題。Han 等人 [11]（*IEEE TPAMI*，2023）依任務整理視覺 Transformer（骨幹、偵測與分割等中高階視覺、低階視覺、影片），也涵蓋高效率 Transformer 方法。Liu 等人 [12]（*IEEE TNNLS*，2024）回顧了一百多個用於影像、點雲與視覺–語言資料之分類、偵測與分割的視覺 Transformer，並提出三個未來方向。在效率方面，Papa 等人 [13]（*IEEE TPAMI*，2024）最有系統。狀態空間視覺模型請參考 Xu 等人 [8]。教科書式的推導則見 Bishop 與 Bishop [10]。

**2023–2026 年的最新發展。** 純 ViT 已成為預設的**基礎模型**（foundation model）骨幹。ViT-22B [24]（ICML 2023）把 ViT 擴大到 220 億個參數，並需要一些架構修改（例如對 query 與 key 做正規化）才能在這個規模下穩定訓練。DINOv2 [23]（TMLR 2024）以自監督方式在大型精選影像集合上訓練 ViT，得到的通用特徵在凍結狀態下就能用於分類、分割與深度估計（[ML 05](/zh-tw/learn/ml/ml-05-representation-learning/)）。Darcet 等人 [22]（ICLR 2024）發現大型 ViT 會把資訊量低的背景 patch 挪作內部暫存空間，在注意力圖中產生高範數的假影 token；加入少數額外的**暫存器 token**（register tokens）就能消除這些假影，並改善密集預測。視覺–語言基礎模型（[ML 09](/zh-tw/learn/ml/ml-09-foundation-models/)）與擴散 Transformer（[ML 07](/zh-tw/learn/ml/ml-07-diffusion-flow-matching/)）都建立在同樣的區塊上。與此同時，階層式與混合設計在高解析度的密集任務上仍很常見；在預算對齊時，現代化的 CNN 依然具有競爭力（ML 03）；而狀態空間與線性注意力模型仍持續被探索，用於影片這類非常長的 token 序列。

**開放問題。** 高解析度與長影片下的二次方成本；純 ViT 對資料與運算量的龐大需求；能在不同解析度與長寬比之間泛化的位置編碼；如何解讀注意力而不過度詮釋；以及在注意力、卷積與狀態空間機制之間，做出運算量對齊的公平比較。

## 重點整理

- 自注意力是一個可學習、隨輸入而變的加權平均：$\operatorname{softmax}(QK^\top/\sqrt{d_k})V$。除以 $\sqrt{d_k}$ 讓分數維持單位變異數，softmax 才不會飽和。
- 多頭注意力以約等於一個頭的成本，平行執行 $h$ 個較窄的頭；遮罩（因果、視窗）與交叉注意力決定誰讀取誰。
- 注意力是排列等變的，因此必須注入位置資訊：正弦、可學習絕對、相對偏差或旋轉編碼。
- 前置正規化的 Transformer 區塊先做 $X+\operatorname{MHA}(\operatorname{LN}(X))$，再做 $U+\operatorname{MLP}(\operatorname{LN}(U))$；注意力混合 token，MLP 轉換每個 token。
- ViT = 切成 patch（步幅為 $P$ 的卷積）+ 位置嵌入 + 類別 token + Transformer 編碼器。它的歸納偏置弱，需要大規模預訓練或強力的訓練配方（DeiT、AugReg）。
- Swin 透過平移視窗與 patch 合併找回局部性與階層結構；CvT、CoAtNet、MobileViT 等混合模型結合了卷積與注意力。
- FlashAttention 讓精確注意力更快，但不改變其二次方的算術量；視窗、token 合併與狀態空間掃描則改變了實際計算的內容。比較機制時一定要對齊預算。

- Vision Mamba 與 VMamba 把選擇性狀態空間應用到影像序列。多條路徑會改變影響傳遞方式，但不自動保證旋轉等變性，也不保證保留所有遠處細節。

## 練習

1. **Token 預算。** 對一張 $512\times512$ 的影像，分別計算 patch 大小為 16 與 8 時的 token 數，以及每個頭的注意力分數個數。patch 大小減半時，分數個數增加幾倍？

<details>
<summary>提示</summary>

$N=(512/16)^2=1024$ 與 $(512/8)^2=4096$ 個 token；$N^2=1{,}048{,}576$ 與 $16{,}777{,}216$ 個分數。patch 大小減半，$N$ 乘以 4，分數乘以 16。

</details>

2. **縮放檢查。** 對 $d_k=4,64,1024$，隨機產生各分量為獨立標準常態的 query 與 key。分別量測有無除以 $\sqrt{d_k}$ 時 $q\cdot k$ 的變異數，以及在 100 個 key 上 softmax 的最大權重。不縮放時，softmax 會發生什麼事？

<details>
<summary>提示</summary>

原始點積的變異數接近 $d_k$；縮放後接近 1。不縮放時，在 $d_k=1024$ 下 softmax 幾乎把所有權重都放在單一個 key 上（近乎 one-hot），流經其他 key 的梯度因此消失。

</details>

3. **移除位置資訊。** 在 TinyViT 程式碼中，把位置嵌入設為零、拿掉類別 token 改用平均池化，然後在送進區塊之前打亂 patch token 的順序，並在評估模式下比較 logits。解釋結果，並說明這對一個沒有位置資訊的影像分類器意味著什麼。

<details>
<summary>提示</summary>

logits 在浮點誤差範圍內相同，因為每個區塊都是排列等變的，而平均池化是排列不變的。記得關掉 dropout（`eval()`），並打亂 token 而不是 patch 內的像素。這樣的模型無法分辨一張臉和用相同 patch 拼湊出來的亂序臉。

</details>

4. **交叉注意力的形狀。** 在一個文字生成影像的模型中，256 個寬度 320 的影像 token 讀取 77 個寬度 768 的文字 token，使用 8 個寬度 40 的頭。寫出 $W_Q$、$W_K$、$W_V$、單一個頭的分數矩陣以及輸出的形狀。

<details>
<summary>提示</summary>

$W_Q\in\mathbb{R}^{320\times320}$（8 個頭 × 40），$W_K,W_V\in\mathbb{R}^{768\times320}$。每個頭的分數為 $256\times77$。輸出跟隨 query：經過輸出投影後為 $256\times320$。key 與 value 的長度必須彼此相同，而不必與 query 長度相同。

</details>

5. **Swin 的算術。** 利用成本公式，比較 $56\times56$ 的 token 網格、$C=96$、$M=7$ 時的全域注意力與視窗注意力。兩種情況各由哪一項主導？

<details>
<summary>提示</summary>

$hw=3136$。全域：$4\cdot3136\cdot96^2\approx1.16\times10^8$ 加上 $2\cdot3136^2\cdot96\approx1.89\times10^9$，由二次方項主導。視窗：同樣的 $1.16\times10^8$ 加上 $2\cdot49\cdot3136\cdot96\approx2.95\times10^7$，由投影主導。此例中視窗版本約便宜 14 倍。

</details>

6. **公平比較。** 你有 2,000 張標註影像，以及預訓練好的 CNN、ViT 與視覺 Mamba 骨幹。設計一個實驗來決定要部署哪一個骨幹，並列出必須固定的條件。 納入移除混合器的消融實驗，以及解析度／旋轉測試。

<details>
<summary>提示</summary>

先在凍結的特徵上比較線性探測（linear probe），再在驗證集上以對齊的預算、為各模型分別調校學習率來做微調。記錄預訓練資料、輸入解析度、參數量、FLOPs，以及在目標裝置上實測的延遲。拿預訓練的 ViT 去比從頭訓練的 CNN，測到的是預訓練，而不是架構。 對掃描骨幹，記錄狀態大小，並測試保留閘控與局部卷積、移除混合器後，優勢是否仍存在。解析度與旋轉測試要使用一致的前處理。

</details>
