## 先看全貌

影片就是一疊間隔不到一秒拍下的照片。每張照片都很小、有點模糊，但相機或物體在兩次拍攝之間會稍微移動。影片超解析度把附近所有影格看到的東西合在一起，讓這樣的片段變得更清楚、更大。

<Callout type="tip" title="用最簡單的話說">
想像你隔著紗窗看一幅畫。紗窗的細線擋住了一部分畫面，所以看一眼只能看到片段。現在把頭稍微移動一點再看一次：這次被擋住的是*不同*的部分。頭移動幾次之後，你就幾乎看遍整幅畫，前提是你記得每次移動了多遠。VSR 模型做的正是這件事：它算出每個東西在影格之間移動了多遠（也就是「記得移動了多遠」這一步），再用其他影格補上被擋住的部分。如果它忘了移動量，補上的部分就會落在錯的位置，畫面就糊成一團。
</Callout>

為什麼重要：人們看的像素大多來自影片。頻寬不足時串流會降到低解析度，老電影與家庭影片原本就是以低解析度錄製，手機、監視攝影機、衛星與顯微鏡拍下的也是小而有雜訊的影像序列。好的 VSR 模型能讓這些影片更清楚，又不會像逐影格處理的影像模型那樣出現畫面閃爍。VSR 也是許多現在影片模型常見想法的發源地：以光流對齊特徵、可變形對齊、長距離循環傳播與影片 Transformer。

本篇建立在 [DLCV 09](/zh-tw/learn/deep-learning/image-restoration/) 之上；那一篇談退化模型、用合成配對訓練、損失函數與通用的影像指標，我們直接連結過去，不再重複。單張影像超解析度（輸入一個影格、輸出一個影格的設定）在 [DLCV 09A](/zh-tw/learn/deep-learning/super-resolution/) 討論。這裡我們專注在時間多帶來了什麼。

## 為什麼影片不只是很多張影像

**白話版。** 逐影格獨立放大會忽略鄰近量測，也未要求細節在時間上穩定。

### 子像素位移帶來新資訊

假設相機用一組粗糙的像素格取樣場景。在某一個影格中，落在取樣點之間的細節會遺失（更糟的是，會被折疊成錯誤的低頻圖樣，稱為**混疊**，aliasing）。如果下一個影格中場景位移了四分之一個像素，同一組像素格就會在不同的位置取樣場景。位移 $0, \tfrac14, \tfrac12, \tfrac34$ 個像素的四個影格，合起來對場景的取樣密度是其中任何一個的四倍（圖 1 是一維情形；在二維中，倍率 $s$ 需要 $s^2$ 種不同的位移）。這就是多影格超解析度能勝過單張影像超解析度的基本原因：多出來的影格是新的量測，而不是複本 [1]。

必須同時滿足兩個條件。第一，運動必須是**子像素**的：位移整數個低解析度像素，會取到相同的位置，只多了雜訊平均的效果。第二，我們必須**知道運動**，而且準確到足以把每個取樣放到正確的位置。真實的運動不是整體平移：物體各自移動、旋轉、變形、出現與消失。估計並補償這些運動是 VSR 的核心問題，本篇大部分內容都圍繞著它。

### 時間上的冗餘

相鄰影格也高度冗餘：場景的大部分會被再看一次。獨立的雜訊在重複觀察中會被平均掉，模型也可以重複利用處理先前影格時做過的工作。影片編碼器利用的是同樣的冗餘：用運動向量由前一個影格預測每個影格（見 [IP 08](/zh-tw/learn/image-processing/compression-watermarking/#預測編碼) 的運動補償預測）。

### 時間一致性與閃爍

單張影像模型逐影格套用時，每個影格都會獨立做出許多小決定。凡是它捏造紋理的地方（草地、頭髮、水面、類似雜訊的細節），捏造出的紋理在每個影格都不同，影片就會**閃爍**（flicker），或像水沸騰般波動。即使每個影格單獨看都沒問題，這種時間瑕疵還是看得出來。VESPCN [2] 與 FRVSR [3] 都把時間一致性列為共同處理影格、而不是各自獨立處理的主要動機。所以 VSR 模型有兩個目標：每個影格要忠實而清晰，而且相鄰影格只應隨場景改變而改變。

## 影片退化模型

**白話版。** 每個低解析度影格，都是那一刻的高解析度影格經過模糊、縮小、加雜訊，通常還經過壓縮的結果。影格之間的差異來自場景在移動。

### 每個影格一個方程式

把 [DLCV 09](/zh-tw/learn/deep-learning/image-restoration/#一個問題許多面貌退化模型) 的超解析度模型延伸到由 $T$ 個高解析度（HR）影格組成的片段 $\{x_t\}_{t=1}^{T}$，得到

$$
y_t = \mathcal C\bigl( (x_t * k)\downarrow_s + n_t \bigr), \qquad t = 1, \dots, T,
$$

其中 $y_t$ 是時間 $t$ 的低解析度（LR）影格，$k$ 是模糊核（相機光學、感測器積分、抗混疊濾波器），$*$ 是二維卷積，$\downarrow_s$ 在每個方向上每隔 $s$ 個像素保留一個（$s$ 是放大倍率，基準測試通常是 4），$n_t$ 是每個影格都全新產生的雜訊，$\mathcal C$ 是有失真的影片壓縮（在乾淨的基準測試中是恆等映射）。運動進入模型的方式是：每個 $x_t$ 都是其鄰近影格移動後的版本。在影格 $t$ 附近可以寫成

$$
x_{t+j} \approx \mathcal W_{t \to t+j}(x_t),
$$

其中 $\mathcal W_{t \to t+j}$ 是從影格 $t$ 到影格 $t + j$ 的運動（扭曲），$j$ 是小的影格偏移量，而 $\approx$ 藏起了運動解釋不了的部分：被遮擋的區域、進入畫面的物體、光照變化。把兩個式子合起來，

$$
y_{t+j} \approx \mathcal C\bigl( (\mathcal W_{t \to t+j}(x_t) * k)\downarrow_s + n_{t+j} \bigr),
$$

所以每個鄰近的 LR 影格，都是同一個未知量 $x_t$ 的一次*不同的*量測。VSR 從 $y_{t-K}, \dots, y_{t+K}$（寬度 $2K+1$ 個影格的視窗）或整段片段來估計 $x_t$。

### 多影格重建是一個反問題

如果運動、模糊與倍率都已知，而且沒有壓縮，就能用最小平方法求出 $x_t$：

$$
\hat x_t = \arg\min_x \; \frac{1}{2K+1} \sum_{j=-K}^{K} \bigl\| D B \, \mathcal W_{t \to t+j}(x) - y_{t+j} \bigr\|_2^2 ,
$$

其中 $B$ 是用 $k$ 做的模糊，$D$ 是降取樣 $\downarrow_s$，總和遍及視窗中的各個影格。只有一個影格時，這個問題嚴重欠定（$s = 4$ 時，每個 LR 像素對應 $s^2 = 16$ 個未知的 HR 像素）。有許多位於不同子像素位置的影格時，它就變得好解得多。對這個目標函數做梯度下降，會反覆由目前的估計模擬出 LR 影格，與觀測到的影格比較，再把誤差分攤回 HR 格點；這就是 Irani 與 Peleg 提出的經典**迭代反向投影**（iterative back-projection）想法 [4], [1]，它也啟發了後面會談到的 RBPN 架構 [5]。

*選讀：[傳統多影格超解析度](#傳統多影格超解析度)（見「補充資料」頁）。在細緻格點上融合已配準的取樣、穩健（中位數）融合，以及多影格問題何時是良置的。*

### 玩具實驗：對齊帶來什麼

這段程式碼用一張 `skimage` 照片，加上隨機的子像素相機位移、高斯模糊、$\times 4$ 子取樣與雜訊，造出一段 16 個影格的 LR 影片。接著比較第一個影格的四種重建：只用該影格的三次內插；不對齊就把所有上取樣影格平均；只用第一個影格的上述最小平方求解器；以及用全部 16 個影格、分別搭配真實位移與**由 LR 影格估計出的位移**（以子像素相位相關法 [6]）的同一個求解器。它在筆電 CPU 上大約十秒跑完。

```python
import numpy as np
from scipy import ndimage as ndi
from skimage import data, color
from skimage.registration import phase_cross_correlation

rng = np.random.default_rng(0)
s, T, blur, noise = 4, 16, 1.2, 0.01                       # scale, frames, blur sigma (HR px), noise std
hr = color.rgb2gray(data.astronaut())[64:320, 128:384]     # 256 x 256 ground-truth frame, values in [0, 1]
shifts = rng.uniform(0, s, size=(T, 2)); shifts[0] = 0     # sub-pixel camera motion of each frame (HR px)

def degrade(x, d):                                         # y_t = D B W_t x : shift, blur, keep every s-th pixel
    return ndi.gaussian_filter(ndi.shift(x, d, order=3, mode="reflect"), blur)[::s, ::s]
def degrade_T(r, d):                                       # adjoint: zero-fill, blur, shift back
    z = np.zeros((r.shape[0] * s, r.shape[1] * s)); z[::s, ::s] = r
    return ndi.shift(ndi.gaussian_filter(z, blur), -d, order=3, mode="reflect")
def upsample(y):                                           # cubic-spline interpolation on the HR grid
    u, v = np.mgrid[0:y.shape[0] * s, 0:y.shape[1] * s] / s
    return ndi.map_coordinates(y, [u, v], order=3, mode="nearest")
def psnr(x):
    c = (slice(8, -8), slice(8, -8))                       # skip a border, as benchmarks do
    return 10 * np.log10(1 / np.mean((np.clip(x, 0, 1)[c] - hr[c]) ** 2))

lr = np.stack([degrade(hr, d) + noise * rng.standard_normal((64, 64)) for d in shifts])
print("LR video:", lr.shape)

def reconstruct(frames, ds, iters=20):
    """Multi-frame least squares by gradient descent (iterative back-projection)."""
    x = np.mean([ndi.shift(upsample(f), -d, order=3, mode="reflect") for f, d in zip(frames, ds)], 0)
    for _ in range(iters):
        grad = np.mean([degrade_T(degrade(x, d) - f, d) for f, d in zip(frames, ds)], 0)
        x -= s * s * grad
    return x

# shifts estimated from the LR frames themselves (sub-pixel phase correlation), in HR pixels
est = np.array([-s * phase_cross_correlation(lr[0], f, upsample_factor=100)[0] for f in lr])
print(f"mean shift error: {np.abs(est - shifts).mean():.2f} HR px")

print(f"single frame, cubic interpolation {psnr(upsample(lr[0])):.2f} dB")
print(f"average of frames, no alignment   {psnr(np.mean([upsample(f) for f in lr], 0)):.2f} dB")
print(f"single frame, same solver         {psnr(reconstruct(lr[:1], shifts[:1])):.2f} dB")
print(f"{T} frames, true shifts            {psnr(reconstruct(lr, shifts)):.2f} dB")
print(f"{T} frames, estimated shifts       {psnr(reconstruct(lr, est)):.2f} dB")
# LR video: (16, 64, 64)
# mean shift error: 0.13 HR px
# single frame, cubic interpolation 25.50 dB
# average of frames, no alignment   20.99 dB
# single frame, same solver         25.81 dB
# 16 frames, true shifts            30.30 dB
# 16 frames, estimated shifts       29.33 dB
```

這次玩具實驗有三個教訓（所有數字都來自我們自己的執行，不是來自任何論文）。第一，**不對齊就平均，比只用一個影格更糟**（20.99 對 25.50 dB）：錯位的影格會把影像抹糊，正是比喻中「忘了移動多遠」的失敗。第二，進步來自**影格，而不是求解器**：同一個最小平方求解器只用一個影格，勉強勝過內插（25.81 dB），用 16 個影格則有 30.30 dB。第三，運動可以直接**由 LR 影格本身估計**，平均誤差約為八分之一個 HR 像素，仍保住大部分進步（29.33 dB）。圖 2 顯示裁切結果，以及 PSNR 如何隨影格數增加。

## 運動：光流與扭曲

**白話版。** 光流估計影格間的像素對應，扭曲則依對應重新取樣，使內容對齊。

### 光流

經典的出發點是**亮度恆定**（brightness constancy）：一個點在移動時保持它的亮度，

$$
I(u + \delta u,\, v + \delta v,\, t + 1) = I(u, v, t),
$$

其中 $I(u, v, t)$ 是第 $u$ 欄、第 $v$ 列、時間 $t$ 的強度，$(\delta u, \delta v)$ 是該點在影格 $t$ 與 $t+1$ 之間的位移。所有像素位移所構成的場，就是**光流**（optical flow）$F(p) = (\delta u(p), \delta v(p))$，對每個像素 $p$ 各有一組。每個像素只有一個方程式，無法決定兩個未知數（這是「孔徑問題」：沿著一條直邊，只看得到垂直於邊的運動），所以每種方法都要加入「相鄰像素的運動相近」這個假設。Horn 與 Schunck [8] 加上整體平滑度的懲罰；OpenCV 內建的 Farnebäck 方法 [9] 則對每個鄰域擬合二次多項式，再由多項式如何移動來估計位移。

深度光流估計器從資料中學習這個映射。SPyNet [10] 以由粗到細的方式估計大的運動：在影像金字塔的每一層，先用目前的光流扭曲其中一張影像，再由一個小網路預測剩下的小幅更新；它很精簡，是 BasicVSR [7] 的光流模組。RAFT [11] 建立所有像素配對之間的相關體（correlation volume），並用循環單元反覆改進光流場。例如 BasicVSR 從預訓練的 SPyNet 出發，與模型其餘部分一起微調 [7]。

*選讀：[亮度恆定與傳統光流求解器](#亮度恆定與傳統光流求解器)（見「補充資料」頁）。線性化的光流方程式、孔徑問題，以及整體（Horn–Schunck）、局部視窗與多項式展開（Farnebäck）求解器各自加了什麼。*

### 以雙線性取樣做反向扭曲

要把影格 $t+1$ 對齊到影格 $t$，我們使用從 $t$ 到 $t+1$ 的光流，並把值**拉**過來：對參考影格的每個像素 $p$，找出該點在另一個影格中的位置，並讀取那裡的值，

$$
\hat I_{t+1 \to t}(p) = I_{t+1}\bigl(p + F_{t \to t+1}(p)\bigr),
$$

其中 $\hat I_{t+1 \to t}$ 是被扭曲到影格 $t$ 座標系的影格 $t+1$，$F_{t \to t+1}(p)$ 是像素 $p$ 的位移。這就是**反向扭曲**：每個輸出像素都恰好得到一個值，沒有空洞。（前向扭曲是把每個來源像素推到它的新位置，會留下空洞與碰撞。）位置 $q = p + F(p)$ 通常不在像素格點上，所以要用周圍四個像素做**雙線性**內插：

$$
I(q) = (1 - a)(1 - b)\, I_{00} + a(1 - b)\, I_{10} + (1 - a)\, b\, I_{01} + a\, b\, I_{11},
$$

其中 $q = (u_0 + a,\, v_0 + b)$，$(u_0, v_0)$ 為整數，$a, b \in [0, 1)$ 為小數部分，$I_{ij}$ 是位置 $(u_0 + i,\, v_0 + j)$ 的值。雙線性取樣對影像值與光流都可微分，所以網路可以透過扭曲端到端地學習光流；這個「雙線性取樣器」是空間轉換網路（spatial transformer networks）[12] 的核心，也是每個以光流為基礎的 VSR 模型的核心。

下面的程式碼手寫了反向扭曲，並與 `cv2.remap` 比對；它造出兩個影格，其中背景移動 $(1.5, -2)$ 個像素，一個有紋理的方塊移動 $(6, 4)$ 個像素；然後分別用真實光流與 OpenCV 的 Farnebäck 光流，把第二個影格扭曲到第一個影格上。

```python
import numpy as np, cv2
from scipy import ndimage as ndi
from skimage import data, transform

def bilinear_warp(img, flow):
    """Backward warping: out(p) = img(p + flow(p)), bilinear sampling. flow[..., 0] = dx, flow[..., 1] = dy."""
    H, W = img.shape
    yy, xx = np.mgrid[0:H, 0:W].astype(np.float64)
    x = np.clip(xx + flow[..., 0], 0, W - 1); y = np.clip(yy + flow[..., 1], 0, H - 1)
    x0 = np.minimum(np.floor(x).astype(int), W - 2); y0 = np.minimum(np.floor(y).astype(int), H - 2)
    ax, ay = x - x0, y - y0                                   # fractional parts = bilinear weights
    return ((1 - ay) * ((1 - ax) * img[y0, x0] + ax * img[y0, x0 + 1])
            + ay * ((1 - ax) * img[y0 + 1, x0] + ax * img[y0 + 1, x0 + 1]))

# two frames: the background moves by (dx, dy) = (1.5, -2.0) px, a textured square moves by (6, 4) px
bg = transform.resize(data.camera() / 255.0, (256, 256), anti_aliasing=True)
obj = transform.resize(data.coins() / 255.0, (60, 60), anti_aliasing=True)
def frame(t):
    f = ndi.shift(bg, (-2.0 * t, 1.5 * t), order=3, mode="reflect")   # ndi.shift takes (rows, cols)
    r, c = 90 + 4 * t, 100 + 6 * t
    f[r:r + 60, c:c + 60] = obj
    return f
I0, I1 = frame(0).astype(np.float32), frame(1).astype(np.float32)

# true backward flow from frame 0 to frame 1: where is pixel p of frame 0 found in frame 1?
flow = np.zeros((256, 256, 2), np.float32); flow[..., 0], flow[..., 1] = 1.5, -2.0
flow[90:150, 100:160] = (6.0, 4.0)
mine = bilinear_warp(I1, flow)
H, W = I0.shape; yy, xx = np.mgrid[0:H, 0:W].astype(np.float32)
ocv = cv2.remap(I1, xx + flow[..., 0], yy + flow[..., 1], cv2.INTER_LINEAR, borderMode=cv2.BORDER_REPLICATE)
print(f"max |ours - cv2.remap| = {np.abs(mine - ocv)[5:-5, 5:-5].max():.4f}")

u8 = lambda a: (np.clip(a, 0, 1) * 255).round().astype(np.uint8)        # Farneback expects 8-bit images
est = cv2.calcOpticalFlowFarneback(u8(I0), u8(I1), None, pyr_scale=0.5, levels=4, winsize=21,
                                   iterations=5, poly_n=7, poly_sigma=1.5, flags=0)
m0 = np.zeros((H, W), np.float32); m0[90:150, 100:160] = 1          # square in frame 0
m1 = np.zeros((H, W), np.float32); m1[94:154, 106:166] = 1          # square in frame 1
occl = (bilinear_warp(m1, flow) > 0) & (m0 == 0)                  # background of frame 0 hidden in frame 1
inner = (slice(8, -8), slice(8, -8))
for name, img in [("no alignment", I1), ("warped, true flow", mine), ("warped, Farneback", bilinear_warp(I1, est))]:
    e = np.abs(img - I0)
    print(f"{name:18s} mean |error| {e[inner].mean():.4f}   on occluded pixels {e[occl].mean():.4f}")
print("Farneback median flow (dx, dy): square", np.median(est[100:140, 110:150], axis=(0, 1)).round(2),
      " background", np.median(est[200:240, 20:60], axis=(0, 1)).round(2))
# max |ours - cv2.remap| = 0.0000
# no alignment       mean |error| 0.0562   on occluded pixels 0.2367
# warped, true flow  mean |error| 0.0089   on occluded pixels 0.2617
# warped, Farneback  mean |error| 0.0133   on occluded pixels 0.1733
# Farneback median flow (dx, dy): square [6. 4.]  background [ 1.42 -1.88]
```

用真實光流扭曲，把兩個影格之間的平均差異降低到約六分之一，而 Farnebäck 的估計已經達到大部分效果（我們的執行結果）。但請看**被遮擋的像素**：就是在影格 $t+1$ 中被方塊蓋住的那一條背景。在那裡，即使是*真實的*光流也有很大的誤差，因為那些內容根本不在影格 $t+1$ 裡，它們被藏在方塊後面。任何光流都救不了這一點。VSR 模型必須學會在扭曲後的影格一致時相信它，不一致時就忽略它（圖 4）。

## 對齊策略

**白話版。** 對齊可使用顯式光流、學得的可變形取樣位置，或對對應內容的注意力。

### 顯式對齊：以光流扭曲

最直接的做法是估計每個鄰近影格到參考影格的光流，再用它扭曲鄰近影格。

- **VESPCN** [2]（CVPR 2017）端到端訓練一個快速的多解析度空間轉換運動補償模組，搭配子像素卷積（pixel shuffle）網路 ESPCN [13] 的時空版本。
- **TOFlow** [14]（IJCV 2019）把光流網路與復原網路一起訓練，所以光流是**以任務為導向**的：它會移動任何能讓輸出最好的東西，即使這與實際的物理運動不同。這篇論文也提出了 Vimeo-90K。
- **影像扭曲與特徵扭曲。** 早期的方法扭曲 LR *影像*。不準確的光流會產生模糊或錯誤的扭曲影像，而損失的細節之後就無法挽回。後來的方法在影像上計算光流，卻扭曲*特徵圖*，讓後續各層能修正小幅的錯位；BasicVSR 的消融實驗發現，特徵扭曲優於影像扭曲 [7]。

以光流為基礎的對齊可解釋，在中等運動下效果很好。它的弱點是光流網路的成本、遮擋與運動邊界處的誤差，以及每個像素只有一個光流向量，只能指向一個位置。

### 隱式對齊：可變形卷積

一般的 $3 \times 3$ 卷積，是在每個像素周圍固定的格點上讀取輸入。**可變形卷積**（deformable convolution）[15] 則為每個取樣位置加上一個學得的偏移：

$$
y(p) = \sum_{i=1}^{K} w_i \; x\bigl(p + p_i + \Delta p_i(p)\bigr),
$$

其中 $y(p)$ 是像素 $p$ 的輸出，$K$ 是卷積核的取樣點數（$3 \times 3$ 時為 9），$w_i$ 是第 $i$ 個取樣點的權重，$p_i$ 是它固定的格點位置（例如 $(-1, -1)$），$\Delta p_i(p)$ 是由一個小網路為每個像素與每個取樣點預測的實數偏移，$x(\cdot)$ 以雙線性取樣讀取。DCNv2 [16] 另外把每個取樣點乘上一個落在 $[0, 1]$ 的學得調變權重，讓這一層能壓低不可靠位置的權重。

用於對齊時，偏移由參考影格與鄰近影格的特徵預測，可變形卷積則套用在鄰近影格的特徵上。**TDAN** [17] 以這種方式在特徵層級把每個支援影格對齊到參考影格，不需要計算光流。**EDVR** [18] 在**金字塔、串接與可變形（Pyramid, Cascading and Deformable, PCD）**模組中套用可變形對齊，在特徵金字塔上由粗到細處理大的運動，再用**時間與空間注意力（temporal and spatial attention, TSA）**融合對齊後的特徵；它拿下了 NTIRE 2019 影片復原挑戰賽的全部四個賽道。

Chan 等人 [19] 證明，可變形卷積可以拆解成數個空間扭曲（每個取樣點一個，各有自己的偏移場），再接一個卷積。所以可變形對齊是光流扭曲的推廣：用數個光流場取代一個；這種**偏移多樣性**（offset diversity）正是它對齊得更好的原因。同一項研究與 BasicVSR++ [20] 都回報，可變形對齊訓練起來不穩定：偏移可能變得非常大（「偏移溢位」，offset overflow）。因此 BasicVSR++ 把可變形偏移預測成**疊加在光流上的殘差**（光流引導的可變形對齊），結合光流的穩定性與可變形取樣的多樣性。

*選讀：[可變形卷積即「扭曲加卷積」](#可變形卷積即扭曲加卷積)（見「補充資料」頁）。用兩行寫出這個拆解、一個測試過的範例，以及為什麼多個偏移場在遮擋處有幫助。*

### 不需顯式運動步驟的對齊

有些模型完全跳過運動估計，讓網路自行吸收運動。**DUF** [21] 為每個輸出像素，從輸入影格的時空鄰域預測一個動態上取樣濾波器與一個殘差，所以運動是由依內容而變的濾波器隱式處理的。**PFNL** [22] 逐步融合影格，並用非區域（non-local）運算（它把每個位置與其他每個位置比較）取代運動估計與補償。在（時間、高度、寬度）上做 3-D 卷積是第三種選擇。這些方法避開了光流的誤差，但有效搜尋範圍受限於感受域，所以大的運動較難處理。

### 注意力與 Transformer

注意力讓每個位置能與其他影格中許多候選位置比較，並對最佳匹配取加權平均，這是運動搜尋的軟式、學習版本。**VRT** [23] 把影片切成短的片段，並使用**時間互相自注意力（temporal mutual self-attention, TMSA）**：兩個影格之間的互相注意力執行聯合的運動估計、對齊與融合，自注意力則負責擷取特徵；片段的切分在相鄰層之間會位移，讓資訊能跨越片段邊界，另有一個**平行扭曲**（parallel warping）模組，額外加入鄰近特徵的光流扭曲。VRT 應用於影片 SR、去模糊、去雜訊、影格內插與時空 SR。**RVRT** [24] 使用**引導式可變形注意力**（guided deformable attention）：從光流出發，在前一個片段中預測數個相關位置，並以注意力權重聚合它們的特徵。

## 依時間設計分類的架構

**白話版。** 一旦影格能夠對齊，問題就變成：每個輸出能看到哪些影格，以及資訊如何沿著影片傳遞。主要有四種答案，如圖 5 所示。

### 滑動視窗

**滑動視窗**（sliding-window）模型取 $2K + 1$ 個連續的 LR 影格，產生一個 HR 影格（中間那一個），然後把視窗移動一個影格。VESPCN、DUF、TDAN 與 EDVR 都是滑動視窗模型。它簡單又可平行，誤差也不會隨時間累積。FRVSR [3] 指出兩個弱點：每個輸入影格要被處理與扭曲 $2K + 1$ 次，而且每個輸出都是獨立估計的，限制了時間一致性。固定的視窗也無法利用更遠處的資訊；BasicVSR 的作者測量到，把測試序列切成較短的獨立片段會降低 PSNR，而且在片段末端降得最多 [7]。

### 循環

**循環**（recurrent）模型保有一個概括過去的隱藏狀態 $h_t$，並逐影格更新它：

$$
h_t = F\bigl(y_t,\; \mathcal W(h_{t-1}, F_{t \to t-1})\bigr), \qquad \hat x_t = U(h_t),
$$

其中 $F$ 是一個網路，把目前的 LR 影格 $y_t$ 與被光流 $F_{t \to t-1}$ 扭曲到影格 $t$ 的前一個狀態結合起來（扭曲 $\mathcal W$ 就是上一節的反向扭曲），而 $U$ 是重建與上取樣的輸出頭。因為狀態在重複使用之前已經對齊，資訊可以用每個影格固定的成本傳遞許多個影格。（關於一般的循環網路，請見 [ML 04](/zh-tw/learn/ml/recurrent-recursive-networks/)。）**FRVSR** [3] 把*前一個 HR 輸出*經光流扭曲並重新排列成 LR 大小後，餵給下一個影格的網路，這有助於產生時間一致的結果，而且每一步只需要一次扭曲。**RBPN** [5] 是混合式：在視窗內，它用受反向投影啟發的循環編碼器–解碼器，一次整合一個鄰近影格，並把估計出的運動當作輸入餵進去，而不是扭曲影格。

單向循環模型只看得到過去。早期的影格得到的資訊很少，而狀態中的誤差（來自不好的光流、遮擋或場景切換）會被帶進後面的影格：這就是**誤差累積**（error accumulation）。

### 雙向循環

**BasicVSR** [7] 執行兩條循環分支，一條沿時間向前，一條沿時間向後：

$$
h^b_t = F_b\bigl(y_t,\, y_{t+1},\, h^b_{t+1}\bigr), \qquad h^f_t = F_f\bigl(y_t,\, y_{t-1},\, h^f_{t-1}\bigr), \qquad \hat x_t = U\bigl(h^f_t,\, h^b_t\bigr),
$$

其中 $h^b_t$ 與 $h^f_t$ 是影格 $t$ 的後向與前向特徵，$F_b$ 與 $F_f$ 是兩條分支（各自用 SPyNet 在它的兩個輸入影格之間估計光流，用它扭曲傳播而來的特徵，再以殘差區塊改進），$U$ 則把兩種特徵串接起來，並用 pixel shuffle 上取樣。現在每個輸出都看得到整段片段，包括過去與未來。論文的消融實驗發現，單向版本在早期影格的 PSNR 明顯下降，而不做對齊則下降更多，這支持了它的配方：雙向傳播加上以光流為基礎的特徵對齊，就足以成為強大的基線。它的延伸版本 **IconVSR** 加入一個*資訊補充*（information-refill）模組，從稀疏的關鍵影格重新擷取特徵，以限制遮擋與邊界處的誤差累積；以及*耦合傳播*（coupled propagation），把後向分支的輸出餵給前向分支。

代價是延遲：後向分支需要*未來*的影格，所以在第一個輸出之前，必須先取得整段片段（或一大段）。這適合離線處理，以及有緩衝區的串流，但不適合即時影片。

*選讀：[BasicVSR 與 IconVSR](#basicvsr-與-iconvsr)（見「論文導讀」頁）。四元件分析呈現了什麼、要看哪些消融實驗，以及這個設定的限制。*

### 網格與二階傳播

**BasicVSR++** [20] 從兩方面讓傳播更豐富。**網格傳播**（grid propagation）以交替方式把特徵向後、向前傳遞數次，讓每個影格的特徵一再地用整段序列的資訊改進。**二階連接**（second-order connections）讓影格 $t$ 的狀態同時使用影格 $t-1$ *與* $t-2$（二階馬可夫鏈，而不是一階），使資訊能繞過一個壞掉的影格，這對遮擋與細緻結構有幫助。搭配前面描述的光流引導可變形對齊，BasicVSR++ 在相近的參數量下，回報比 BasicVSR 高 0.82 dB 的 PSNR，並在 NTIRE 2021 影片超解析度與壓縮影片增強挑戰賽中拿下三個賽道的第一名、一個賽道的第二名 [20]。

### Transformer 與循環–Transformer 混合

VRT [23] 以多個尺度的長距離時間注意力，**平行**處理所有影格，威力強大但很吃資源。RVRT [24] 直接描述了這個取捨：平行模型能把時間資訊融合得很好，但模型大、記憶體用量高；循環模型在各影格之間共用參數，所以精簡，但長距離建模較弱，也較難平行化。RVRT 在整體循環的框架*內*，把相鄰影格當成一個片段平行處理，用推論出的前一個片段來估計下一個，並以引導式可變形注意力做片段到片段的對齊。

## 真實世界影片與壓縮

**白話版。** 基準測試的 LR 影片是用一套乾淨、已知的配方做出來的。真實的影片有雜訊、以未知的方式模糊，最重要的是還被壓縮過。用乾淨配方訓練的模型，常常把壓縮瑕疵銳化了，而不是場景。

### 壓縮是真實世界最主要的退化

大部分影片都以 H.264/AVC [25] 這類以區塊為基礎的編碼器儲存與串流；它們用運動向量由先前的影格預測每個區塊，並把殘差量化。由此產生的瑕疵（區塊效應、振鈴、模糊的紋理、邊緣周圍的蚊式雜訊）在影格之間各不相同：不參考其他影格而編碼的影格（內部影格，intra frame）看起來與預測影格不同，品質也隨位元率改變。這些瑕疵不是獨立的雜訊，而且會隨內容移動，所以 VSR 模型可能把它們誤認為真實細節並傳播下去。**COMISR** [26] 為壓縮輸入設計 VSR，用雙向循環扭曲、保留細節的光流估計，以及拉普拉斯增強模組，把內部影格的位置等壓縮特性納入考量，並在一系列壓縮率下評估。

### 真實世界 VSR：RealBasicVSR

**RealBasicVSR** [27]（CVPR 2022）發現，對輕微退化有幫助的長期傳播，會**放大嚴重的瑕疵**：雜訊與壓縮瑕疵會與有用的資訊一起被傳播與放大。它的解法是在 BasicVSR 網路之前，對每個影格先套用一個影像**預清理**（pre-cleaning）模組。它也提出了 **VideoLQ**，這是一組沒有真實標準答案的真實低品質影片，以無參考指標與視覺比較來評估。

*選讀：[RealBasicVSR](#realbasicvsr)（見「論文導讀」頁）。它找出的三個取捨，以及如何閱讀它的實驗。*

這些退化流程是 [DLCV 09](/zh-tw/learn/deep-learning/image-restoration/#深度學習的問題設定) 中盲退化流程的影片版：隨機模糊、縮放、雜訊與壓縮，另外還要選擇對片段的所有影格套用相同或不同的參數。

### 以擴散模型為基礎的 VSR

預訓練的文字生成影像擴散模型，能為真實世界影像 SR 產生非常逼真的紋理（見 [DLCV 09](/zh-tw/learn/deep-learning/image-restoration/#超解析度super-resolution-sr)）。在影片中，它們的隨機性是個問題：逐影格獨立取樣，會讓每個影格的紋理都不同，這是最嚴重的閃爍。因此近期的方法在預訓練的生成模型上加入時間機制：時間層加上光流引導、跨序列的潛在變數傳播（Upscale-A-Video [28]，CVPR 2024）、引導取樣路徑的運動引導損失（MGLD-VSR [29]，ECCV 2024）、本來就會建模運動的文字生成*影片*模型（STAR [30]，ICCV 2025）、可處理任意長度與解析度影片的擴散 Transformer（SeedVR [31]，CVPR 2025），以及降低成本的一步蒸餾（DLoRAL [32]，NeurIPS 2025）。

*選讀：[以擴散模型為基礎的 VSR 模型](#以擴散模型為基礎的-vsr-模型)（見「補充資料」頁）。這五個模型各在預訓練的擴散模型上加了什麼，來維持影片的一致性。*

這些模型在真實影片上給出最令人信服的紋理，但它們承襲了影像層級的**捏造細節**（hallucinated detail，合理但從未存在於場景中的內容）風險，並多了影片層級的風險：每個影格看起來都合理，但影格之間不一致的細節。它們也比 CNN 或 Transformer 的 VSR 貴得多。

## 訓練 VSR 模型

**白話版。** 訓練與影像復原相同，只是每個訓練樣本是一小段影片，而不是單一影像。

配對的做法是用上述模型把 HR 影片片段退化：基準測試用雙三次（BI）或模糊後降取樣（BD）配方（見「評估」），或用隨機化的真實世界流程。每一步取樣一小段片段，並在所有影格的同一位置隨機裁切；翻轉與旋轉對所有影格做相同處理，影格順序也可以反轉當作時間上的資料擴增（BasicVSR 就這樣反轉 Vimeo-90K 的 7 影格序列 [7]）。循環模型用較長的片段訓練（BasicVSR 在 REDS 上的設定使用 15 個影格的輸入），好讓傳播確實被練到；RealBasicVSR 發現較長的序列勝過較大的批次，指向同一個方向 [27]。在 BasicVSR 中，預訓練的光流網路與特徵擷取器在前 5,000 次迭代中是凍結的，之後光流網路以比其餘部分更小的學習率訓練 [7]。

損失函數通常是在每個輸出影格上的 L1 類型像素損失（BasicVSR 使用平滑版本 $\rho(z) = \sqrt{z^2 + \varepsilon^2}$，其中 $\varepsilon$ 是一個小常數，$z$ 是輸出與真實像素之間的差 [7]），真實世界模型再加上感知與對抗項；[DLCV 09](/zh-tw/learn/deep-learning/image-restoration/#損失函數) 討論了這些。有些方法加入**時間損失**，懲罰經運動補償後連續輸出之間的差異，例如 Lai 等人 [33] 的短期扭曲損失，它把每個輸出影格與經光流扭曲的前一個輸出比較，並在扭曲不可靠的地方遮罩掉。

## 評估

**白話版。** 把每個影格都與真實標準答案比較評分，將分數平均，並明確說明 LR 影格是怎麼做出來的。然後觀看實際播放的影片，因為逐影格的分數看不到閃爍。

### 逐影格保真度：Y 通道 PSNR 與 SSIM

大多數 VSR 論文回報在**亮度（Y）通道**上的 PSNR 與 SSIM [34]（定義見 [DLCV 09](/zh-tw/learn/deep-learning/image-restoration/#評估指標)）；每個影格各自計算，先對片段內的影格平均，再對片段平均。Y 通道依循 ITU-R BT.601 [35]：由 $[0, 1]$ 中經過 gamma 校正的 RGB 算出亮度 $E_Y = 0.299 E_R + 0.587 E_G + 0.114 E_B$，並以 8 位元的「studio」刻度量化為 $Y = 219 E_Y + 16$。這個慣例並不通用：在 BasicVSR 與 BasicVSR++ 的比較表中，除了 REDS4 是算在 RGB 上之外，所有結果都算在 Y 上 [7], [20]。混用不同的慣例會讓數字差好幾 dB，下面的程式碼就是例子。

```python
import numpy as np
from skimage import data, color

def rgb_to_y(rgb):
    """BT.601 luma on the 8-bit studio scale: Y = 16 + 219 * (0.299 R + 0.587 G + 0.114 B), RGB in [0, 1]."""
    return 16 + 65.481 * rgb[..., 0] + 128.553 * rgb[..., 1] + 24.966 * rgb[..., 2]

def psnr(a, b, peak=255.0):
    return 10 * np.log10(peak ** 2 / np.mean((a.astype(np.float64) - b) ** 2))

rng = np.random.default_rng(0)
gt = np.stack([np.roll(data.astronaut(), 2 * t, axis=1) for t in range(5)]) / 255.0   # 5 ground-truth frames
out = np.clip(gt + rng.normal(0, 0.02, gt.shape) * np.array([1.0, 0.3, 1.5]), 0, 1)  # unequal error per channel

y_scores = [psnr(rgb_to_y(o), rgb_to_y(g)) for o, g in zip(out, gt)]
rgb_scores = [psnr(255 * o, 255 * g) for o, g in zip(out, gt)]
print("matches skimage rgb2ycbcr:", np.allclose(rgb_to_y(gt[0]), color.rgb2ycbcr(gt[0])[..., 0]))
print(f"Y-channel PSNR, mean of frames: {np.mean(y_scores):.2f} dB")
print(f"RGB PSNR,       mean of frames: {np.mean(rgb_scores):.2f} dB")
# matches skimage rgb2ycbcr: True
# Y-channel PSNR, mean of frames: 43.74 dB
# RGB PSNR,       mean of frames: 33.94 dB
```

同一個輸出在 Y 上的分數比在 RGB 上高約 10 dB（我們的執行結果），一部分是因為 Y 是三個通道的加權平均，獨立的通道誤差會部分抵消，另一部分是因為 Y 只涵蓋 255 個階層中的 219 個，而公式中的峰值仍是 255。務必說明所用的通道、邊界裁切，以及影格是否已四捨五入成 8 位元。

### 退化設定：BI 與 BD

兩種 LR 配方主導了乾淨的基準測試，而且在它們之下的結果不能直接比較：

- **BI（雙三次，bicubic）：** 用 MATLAB 的 `imresize` 把每個 HR 影格縮小 $\times 4$，它先用三次濾波器模糊，再做子取樣。Vimeo-90K SR 基準測試就是這樣建立的 [14]。
- **BD（模糊後降取樣，blur-downsampling）：** 先用標準差 $\sigma = 1.6$ 的高斯函數模糊每個 HR 影格，再每隔四個像素保留一個，如 BasicVSR [7] 所規定。

BD 包含更強而且已知的模糊，所以模型除了上取樣，還必須去模糊。BasicVSR 的表格中，REDS4 只回報 BI，UDM10 只回報 BD，而 Vimeo-90K-T 與 Vid4 兩者都有 [7]。閱讀比較表時，先檢查每一欄的設定。

### 時間一致性

逐影格的 PSNR 看不到閃爍：每個影格隨機變動的誤差，可能和穩定的誤差得到相同的平均 PSNR。常用的指標有三類：

- **扭曲誤差**（warping error）[33]：用光流把輸出影格 $t+1$ 扭曲到影格 $t$，並量測加上遮罩的差異，

$$
E_{\text{warp}}(V_t, V_{t+1}) = \frac{1}{\sum_i M_t^{(i)}} \sum_{i=1}^{N} M_t^{(i)} \bigl\| V_t^{(i)} - \hat V_{t+1}^{(i)} \bigr\|_2^2 ,
$$

其中 $V_t^{(i)}$ 是輸出影格 $t$ 的像素 $i$，$\hat V_{t+1}$ 是被扭曲到影格 $t$ 的影格 $t+1$，$N$ 是像素數，$M_t^{(i)} \in \{0, 1\}$ 是非遮擋遮罩；影片的分數是對所有連續配對取平均。它的弱點是：模糊、毫無細節的影片非常穩定，分數也很好。
- **tOF 與 tLP**（TecoGAN [36]）比較輸出與真實標準答案的時間行為，而不是要求完全不變：

$$
\mathrm{tOF} = \bigl\| \mathrm{OF}(b_{t-1}, b_t) - \mathrm{OF}(g_{t-1}, g_t) \bigr\|_1 , \qquad \mathrm{tLP} = \bigl| \mathrm{LP}(b_{t-1}, b_t) - \mathrm{LP}(g_{t-1}, g_t) \bigr| ,
$$

其中 $b_t$ 與 $g_t$ 是輸出與真實標準答案的影格，$\mathrm{OF}$ 是用 Farnebäck 方法估計的光流，$\mathrm{LP}$ 是 LPIPS 感知距離 [37]。TecoGAN 的作者提出它們，是因為單純的扭曲差異指標「很容易被欺騙」，例如被雙三次內插這類模糊的結果騙過。
- **時間剖面**（temporal profile）：取一列像素沿時間追蹤，堆疊成一張影像；斑點與條紋會顯露閃爍。VESPCN 用它做質化比較 [2]。

下面的程式碼造出一個運動已知的玩具場景和四種「輸出」：每個影格獨立捏造的紋理、沿運動方向遞迴平滑的同一批輸出、忽略運動的同樣平滑，以及一個模糊的輸出。閃爍的量測精神近似 tOF：輸出在運動補償後的時間變化，減去真實標準答案的時間變化。

```python
import numpy as np
from scipy import ndimage as ndi
from skimage import data, transform

rng = np.random.default_rng(0)
T, v = 12, (1, 2)                                         # 12 frames, the scene moves 1 px down and 2 px right per frame
base = transform.resize(data.camera() / 255.0, (256, 256), anti_aliasing=True)
gt = np.stack([np.roll(base, (v[0] * t, v[1] * t), axis=(0, 1)) for t in range(T)])
warp_prev = lambda f: np.roll(f, v, axis=(0, 1))          # exact motion compensation for this toy scene

def fake_detail():                                        # zero-mean "hallucinated texture", new every frame
    n = ndi.gaussian_filter(rng.standard_normal(base.shape), 0.8)
    return 0.03 * n / n.std()

per_frame = gt + np.stack([fake_detail() for _ in range(T)])  # each frame restored independently
smoothed, unaligned, blurry = per_frame.copy(), per_frame.copy(), np.stack([ndi.gaussian_filter(g, 1.5) for g in gt])
for t in range(1, T):
    smoothed[t] = 0.3 * per_frame[t] + 0.7 * warp_prev(smoothed[t - 1])   # recursive filter along the motion
    unaligned[t] = 0.3 * per_frame[t] + 0.7 * unaligned[t - 1]           # same filter, motion ignored

c = (slice(None), slice(16, -16), slice(16, -16))          # ignore borders (np.roll wraps around)
def psnr(out):
    return np.mean([10 * np.log10(1 / np.mean((o - g) ** 2)) for o, g in zip(out[c], gt[c])])
def flicker(out):
    """Mean |temporal change of output - temporal change of ground truth| after motion compensation."""
    d_out = out[1:] - np.stack([warp_prev(f) for f in out[:-1]])
    d_gt = gt[1:] - np.stack([warp_prev(f) for f in gt[:-1]])
    return np.abs(d_out - d_gt)[c].mean()

for name, out in [("per-frame", per_frame), ("aligned smoothing", smoothed),
                  ("unaligned smoothing", unaligned), ("blurry output", blurry)]:
    print(f"{name:20s} PSNR {psnr(out):5.2f} dB   flicker {flicker(out):.4f}")
# per-frame            PSNR 30.50 dB   flicker 0.0338
# aligned smoothing    PSNR 36.40 dB   flicker 0.0082
# unaligned smoothing  PSNR 21.74 dB   flicker 0.0223
# blurry output        PSNR 25.99 dB   flicker 0.0000
```

把這四行合起來讀（都來自我們的玩具實驗）。**沿著運動**傳播資訊，會降低閃爍，在這個玩具中 PSNR 也提高了，因為捏造的紋理是零平均的雜訊，會被平均掉；真實的捏造紋理不是這樣，所以不要期待 PSNR 有這麼大的進步。**不對齊**就傳播，會讓移動中的場景產生鬼影：PSNR 崩落，閃爍仍然很高。而**模糊的輸出**閃爍為零，但 PSNR 很差，這就是縮小版的 TecoGAN 警告：時間指標務必*與*保真度或感知指標一起回報。圖 6 以經過運動補償的時間剖面顯示同樣的效應。

| **UDM10** | 與 PFNL [22] 一起釋出的十段測試序列 | BD 下的測試 |
| **VideoLQ** [27] | 沒有真實標準答案的真實低品質影片 | 真實世界評估（無參考指標、視覺） |

Liu 等人的綜述指出，隨著方法瞄準更複雜的運動與場景變化，測試影片從 Vid4 逐漸演變到 REDS [40]；BasicVSR 則把 REDS4 描述為包含大而複雜的運動 [7]。由於 Vimeo-90K-T 的序列只有七個影格，長距離傳播在那裡沒有太多可發揮的空間：BasicVSR 在 Vimeo-90K-T 上回報的分數略低於 EDVR 等滑動視窗方法，並把原因歸於序列太短 [7]。

### 挑戰賽

NTIRE（CVPR）與 AIM（ECCV）研討會的挑戰賽建立了資料集，並追蹤最新技術水準。**NTIRE 2019** 提出了 REDS [38]；它的影片 SR 挑戰賽 [41] 有一個雙三次賽道與一個含真實運動模糊的賽道，EDVR 當年拿下了全部四個影片復原賽道 [18]。**NTIRE 2021** 影片 SR [42] 有一個復原品質賽道與一個較低影格率賽道，後者把問題變成時空 SR（同時提高解析度與影格率）；BasicVSR++ 回報在那次挑戰賽與壓縮影片增強挑戰賽合計拿下三個第一名與一個第二名 [20]。**效率挑戰賽**評斷每單位運算量的品質：Mobile AI & AIM 2022 報告 [43] 要求在手機的神經處理單元上即時進行 ×4 VSR，以 REDS 訓練，並以執行時間與耗電評比；AIM 2024 的壓縮內容高效率 VSR 挑戰賽 [44] 則針對串流，要求把 540p 以 ×4 放大到 4K，以及把 360p 以 ×3 放大到 1080p。

## 效率與串流

**白話版。** 影片模型必須對每個影格都執行，常常要即時，而且常常在未來影格還不存在時就得輸出。這些限制對架構的影響不亞於準確度。

- **每個影格的成本。** 除非快取特徵，滑動視窗會把每個輸入影格處理 $2K + 1$ 次；循環模型每個影格只處理一次並攜帶一個狀態，所以每個影格的成本不會隨影片長度增加 [3]。
- **延遲與因果性。** 雙向與網格傳播需要未來的影格，所以第一個輸出得等到整段片段結束。即時影片（通話、遊戲串流）只容許因果設計或短的前瞻緩衝區，品質會有所損失（BasicVSR 的單向消融實驗 [7]）。長影片要分段處理，品質會在段落末端下降，如 BasicVSR 的分段實驗所示。
- **記憶體。** 像 VRT 這樣的平行 Transformer，會在多個尺度上跨許多影格做注意力；它們的模型大小與記憶體用量是 RVRT 以片段層級的循環要解決的缺點 [24]。擴散式 VSR 更貴，這也是推動一步模型的動機 [32]。
- **部署。** 效率挑戰賽為手機與串流設定了目標：少量參數與運算、即時影格率與低耗電，品質則與內插基線而不是最大的模型相比 [43], [44]。

## 失效模式

**白話版。** VSR 會在它的主要假設不成立的地方失敗：這個假設是，相鄰影格顯示的是同樣的內容，只是稍微移動過。

- **遮擋與去遮擋。** 在鄰近影格中被藏起來的內容（圖 4）沒有額外的量測；模型若在那裡相信扭曲後的特徵，就會產生鬼影或雙重邊緣。調變遮罩與注意力權重讓模型能壓低這些區域的權重 [20]。
- **大而複雜的運動。** 快速的非剛體運動與動態模糊會讓對齊不準確；由粗到細的對齊（EDVR 的 PCD、SPyNet 的金字塔）有幫助，但不能消除問題。REDS 正是用來對這一點施加壓力 [18]。
- **誤差累積。** 在循環模型中，錯誤的狀態會被往前帶，尤其是在遮擋或場景切換之後；IconVSR 的關鍵影格補充與 BasicVSR++ 的二階連結，都是直接的對策 [7], [20]。長距離傳播也會放大嚴重的輸入瑕疵，RealBasicVSR 以預清理來對付 [27]。
- **閃爍。** 在單張影像模型或擴散取樣中，獨立的逐影格決策會造成時間上的不穩定，而逐影格指標看不到。
- **捏造的細節。** GAN 與擴散式 VSR 可能創造出從未存在的合理紋理、文字或人臉，而在影片中，捏造的內容還可能漂移。對於監視、鑑識、醫療或科學影片，請優先選用以保真度為導向的模型，並說明輸出是由哪一種模型產生的。
- **領域差距。** 用 BI 或 BD 退化訓練的模型，沒有考慮壓縮與真實雜訊 [26], [27]。

## 現代觀點

### 綜述論文

- **Liu 等人，「Video Super-Resolution Based on Deep Learning: A Comprehensive Survey」（Artificial Intelligence Review，2022）** [40]。回顧 37 個深度 VSR 方法，依**如何利用影格間資訊**分成七個子類別：*有對齊*（運動估計與補償、可變形卷積）或*無對齊*（2-D 與 3-D 卷積、循環 CNN、非區域運算、其他），並在基準測試上比較。重點：這個領域從對齊的短視窗，走向混合的設計與長序列，REDS 取代 Vid4 成為嚴格的測試集。
- **Tu 等人，「Optical Flow for Video Super-Resolution: A Survey」（Artificial Intelligence Review，2022）** [45]。涵蓋指標以及傳統與深度的光流式 VSR，並分析代表性的深度方法。重點：稠密的子像素光流是最常用的運動補償工具之一，所以理解光流，就是理解 VSR 對齊的一大部分。
- **Baniya 等人，「A Survey of Deep Learning Video Super-Resolution」（IEEE Transactions on Emerging Topics in Computational Intelligence，2024）** [46]。一套元件分類法（輸入、對齊、融合、改進與重建、上取樣），加上損失函數、品質與效率評估、應用，以及線上、真實世界、資源受限與時空 VSR 等趨勢。重點：設計選擇常由基準測試的進步所驅動，而不是被解釋清楚，實務情境值得更多關注。

### 2023–2026 年的最新進展

1. **傳播加對齊是以保真度為導向的 VSR 的核心。** 帶光流引導可變形對齊的雙向或網格循環傳播（BasicVSR++），以及平行或片段循環的 Transformer（VRT、RVRT），是本篇的參考設計，在準確度與記憶體、延遲之間取捨。
2. **真實世界 VSR 轉向生成式先驗。** 繼 RealBasicVSR 等以 CNN 為基礎的真實世界模型之後，出現了建立在影像擴散模型上的擴散式 VSR（Upscale-A-Video、MGLD-VSR），接著是建立在影片擴散模型與擴散 Transformer 上的（STAR、SeedVR），時間一致性是核心的技術問題。
3. **生成式 VSR 的降低成本。** 一步擴散（DLoRAL）走的路，與一步影像 SR 相同。
4. **效率與壓縮成為一級目標**，挑戰賽中有針對行動硬體與壓縮串流內容的賽道 [43], [44]。

### 尚未解決的問題

- **忠實與合理。** 在影片中量測並控制幻覺仍未解決，因為捏造的細節在時間上也可能不穩定。
- **時間評估。** 扭曲誤差可以靠模糊鑽漏洞，tOF 與 tLP 依賴光流與特徵估計，沒有公認的時間品質感知指標，而使用者研究又很昂貴。
- **真實退化與編碼器。** 合成流程仍然漏掉了真實的相機處理與編碼器行為；真實影片很少有標準答案。
- **長影片、線上處理與場景切換。** 要把雙向與全域模型的品質，與因果、固定記憶體的處理結合起來，仍然困難。
- **遮擋與大的運動。** 在快速的非剛體運動與去遮擋下，對齊仍是弱點。
- **生成式 VSR 的成本**，對於長的高解析度影片，仍遠高於 CNN 與 Transformer 的 VSR。

## 重點整理

- 次像素運動可能提供額外場景量測，逐影格獨立放大會忽略它們。
- 合併前須對齊對應內容，遮擋區域可能沒有有效匹配。
- 光流、可變形取樣與注意力提供不同對應機制及成本。
- 循環會傳遞資訊，也會傳遞錯誤；雙向處理還需要未來影格。
- 壓縮偽影與生成紋理可能隨時間累積或閃爍。
- 同時報告退化、色彩、邊界協定及空間、時間指標；單靠模糊也能顯得穩定。

### 傳統多影格超解析度

**白話版。** 在深度學習之前，多影格超解析度被當成估計問題來解：先把影格配準，把它們的取樣放到細緻的格點上，再求出能解釋所有取樣的 HR 影像，並用先驗補上仍然缺少的部分。

**精確版。** 對於整體平移 $d_j$、已知的模糊 $B$ 與降取樣 $D$，觀測模型是 $y_j = D B S_{d_j} x + n_j$，影格 $j = 1, \dots, M$，其中 $S_{d}$ 把影像位移 $d$。Farsiu 等人 [1] 觀察到，對於純平移與空間不變的模糊，模糊與位移運算子可交換，$B S_{d_j} = S_{d_j} B$，所以問題可以分成兩步：(1) 由 LR 影格估計模糊後的 HR 影像 $z = Bx$，做法是把每個已配準的 LR 取樣複製到它在 HR 格點上的位置，並結合落在同一個 HR 像素上的取樣；(2) 對 $z$ 去模糊以得到 $x$。使用 L2 資料項時，第 1 步是對每個 HR 像素的取樣取平均；Farsiu 等人則改為最小化 L1 資料項，$\min_x \sum_j \| D B S_{d_j} x - y_j \|_1 + \lambda\, \Phi_{\text{BTV}}(x)$，其中 $\Phi_{\text{BTV}}$ 是他們保留邊緣的「雙邊 TV」（bilateral TV）正則項，$\lambda > 0$ 是它的權重。L1 版本讓第 1 步變成**逐像素的中位數**，對離群的影格以及運動與模糊估計的誤差都很穩健。Irani 與 Peleg [4] 提出的迭代反向投影，就是對資料項做最陡下降，如同正文的程式碼。

**何時是良置的。** 數一數未知數，$\times s$ 的 SR 至少需要 $s^2$ 個具有不同子像素相位的影格；隨機位移需要更多，因為有些相位會重複，有些則缺少。模糊設下第二道限制：被 $B$ 壓到接近零的頻率，不管有多少影格都無法還原，只能靠先驗。這是圖 2 中玩具實驗的進步隨影格增加而放慢的原因之一。

**程式碼。** 把位移四捨五入到 HR 格點的第 1 步，顯示兩個效應：影格少時，許多 HR 像素完全沒有取樣；而且融合後的影像接近的是*模糊*影像 $Bx$，而不是 $x$，所以仍需要第 2 步。

```python
import numpy as np
from scipy import ndimage as ndi
from skimage import data, color

rng = np.random.default_rng(0)
s, blur = 4, 1.2
hr = color.rgb2gray(data.astronaut())[64:320, 128:384]
def fuse(T):
    shifts = rng.uniform(0, s, size=(T, 2)); shifts[0] = 0
    acc, cnt = np.zeros_like(hr), np.zeros_like(hr)
    i, j = np.mgrid[0:64, 0:64]
    for d in shifts:
        y = ndi.gaussian_filter(ndi.shift(hr, d, order=3, mode="reflect"), blur)[::s, ::s]
        u, v = np.rint(s * i - d[0]).astype(int), np.rint(s * j - d[1]).astype(int)
        ok = (u >= 0) & (u < 256) & (v >= 0) & (v < 256)
        np.add.at(acc, (u[ok], v[ok]), y[ok]); np.add.at(cnt, (u[ok], v[ok]), 1)
    z = acc / np.maximum(cnt, 1)
    err = np.abs(z - ndi.gaussian_filter(hr, blur))[cnt > 0].mean()
    return (cnt > 0).mean(), err
for T in (4, 16, 64):
    cov, err = fuse(T)
    print(f"{T:3d} frames: {100 * cov:5.1f}% of HR pixels filled, mean |z - Bx| on filled pixels {err:.4f}")
#   4 frames:  18.4% of HR pixels filled, mean |z - Bx| on filled pixels 0.0052
#  16 frames:  66.9% of HR pixels filled, mean |z - Bx| on filled pixels 0.0061
#  64 frames:  97.7% of HR pixels filled, mean |z - Bx| on filled pixels 0.0030
```

在 $s = 4$ 時有 16 種子像素相位，所以在我們的執行中，即使 16 個隨機位移也只填滿 HR 格點的約三分之二，需要 64 個才能填滿幾乎全部。剩下的小誤差來自把位移四捨五入成整個 HR 像素。

**限制。** 這些方法依賴簡單運動模型下的準確配準，以及已知的模糊；局部的非剛體運動與遮擋會破壞運算子可交換的論證，這正是學習式對齊接手的地方。現代的後繼者是連拍攝影：Wronski 等人 [47] 利用手部自然的顫動，取得一組偏移很小的原始（raw）影格連拍，再把它們對齊並合併成全彩影像，不需要另外的去馬賽克步驟，並且對局部運動、遮擋與場景變化保持穩健。

### 亮度恆定與傳統光流求解器

**白話版。** 光流求解器假設一個點在移動時保持亮度，而且相鄰的點一起移動。第一個假設給出每個像素一個方程式；第二個則補上缺少的方程式。

**精確版。** 對亮度恆定 $I(u + \delta u, v + \delta v, t + 1) = I(u, v, t)$ 做一階泰勒展開線性化，得到**光流約束式**

$$
I_u\, \delta u + I_v\, \delta v + I_t = 0,
$$

其中 $I_u, I_v$ 是強度在該像素的空間導數，$I_t$ 是時間導數。這是兩個未知數的一個方程式：只有沿著梯度 $(I_u, I_v)$ 方向的運動分量被決定（孔徑問題），而且線性化只在位移很小時才成立，這就是實用的求解器要在影像金字塔上由粗到細運作的原因。Horn 與 Schunck [8] 在整張影像上最小化

$$
\iint \bigl(I_u\, \delta u + I_v\, \delta v + I_t\bigr)^2 + \alpha^2 \bigl( \|\nabla \delta u\|^2 + \|\nabla \delta v\|^2 \bigr)\, du\, dv,
$$

其中 $\alpha > 0$ 是光流場平滑度懲罰的權重；結果是稠密的，但在運動邊界上會被抹糊。局部方法則假設在小視窗內光流為常數，並以最小平方法對視窗內所有像素求解約束式。Farnebäck [9] 以二次多項式近似每個鄰域，$I(\mathbf z) \approx \mathbf z^\top A \mathbf z + \mathbf b^\top \mathbf z + c$，其中 $\mathbf z$ 是局部座標，$A$ 是對稱矩陣，$\mathbf b$ 是向量，$c$ 是由資料擬合出的純量；一個位移 $\mathbf d$ 的純平移會保持 $A$ 不變，並把 $\mathbf b$ 變成 $\mathbf b - 2A\mathbf d$，所以 $\mathbf d$ 可由 $\mathbf b$ 的變化得出，再在鄰域上取平均並在金字塔上改進。這就是正文程式碼所用的求解器，也是 TecoGAN tOF 指標中的光流估計器 [36]。

**為什麼在 VSR 中被學習式光流取代。** 傳統求解器在亮度改變、大的運動、遮擋與無紋理區域下會失效，而且沒有針對下游任務最佳化。學習式估計器（SPyNet [10]、RAFT [11]）更準確，也能端到端微調，而 TOFlow [14] 顯示，對復原最有幫助的光流，不一定是物理上正確的那一個。

### 可變形卷積即「扭曲加卷積」

**白話版。** 有 $K$ 個取樣點的可變形卷積，行為就像 $K$ 個一般的扭曲（各有自己的小光流場），再接一個 $1 \times 1$ 式的加權總和。所以它可以同時「看」好幾個位置，而光流扭曲只看一個。

**精確版。** 對單一輸入通道，把正文的可變形卷積改寫成

$$
y(p) = \sum_{i=1}^{K} w_i\, \tilde x_i(p), \qquad \tilde x_i(p) = x\bigl(p + p_i + \Delta p_i(p)\bigr),
$$

其中 $\tilde x_i$ 是被光流場 $p_i + \Delta p_i(\cdot)$ 反向扭曲的輸入，每個取樣點 $i$ 有一個光流場。每個 $\tilde x_i$ 都是 $x$ 經光流扭曲的複本，而 $y$ 是這 $K$ 個扭曲複本的學習式加權總和。Chan 等人 [19] 用這個拆解證明，以光流為基礎的對齊，是所有偏移場都等於同一個光流（不計固定的取樣點位置）的特例，而可變形對齊額外的**偏移多樣性**才是改善結果的原因。例如在遮擋處，有些取樣點可以取遮擋物一側的背景，另一些則取另一側的背景。

**程式碼。** 這個拆解可以用正文的 `bilinear_warp` 函式做數值驗證：

```python
import numpy as np
from scipy import ndimage as ndi
from skimage import data, transform

def bilinear_warp(img, flow):
    H, W = img.shape
    yy, xx = np.mgrid[0:H, 0:W].astype(np.float64)
    x = np.clip(xx + flow[..., 0], 0, W - 1); y = np.clip(yy + flow[..., 1], 0, H - 1)
    x0 = np.minimum(np.floor(x).astype(int), W - 2); y0 = np.minimum(np.floor(y).astype(int), H - 2)
    ax, ay = x - x0, y - y0
    return ((1 - ay) * ((1 - ax) * img[y0, x0] + ax * img[y0, x0 + 1])
            + ay * ((1 - ax) * img[y0 + 1, x0] + ax * img[y0 + 1, x0 + 1]))

rng = np.random.default_rng(0)
x = transform.resize(data.camera() / 255.0, (128, 128), anti_aliasing=True)
w = rng.normal(size=9)                                            # 3x3 kernel weights
taps = [(dx, dy) for dy in (-1, 0, 1) for dx in (-1, 0, 1)]
# (a) all offsets zero: deformable conv = ordinary (correlation-style) convolution
zero = np.zeros((128, 128, 2))
y_def = sum(wi * bilinear_warp(x, zero + np.array(t)) for wi, t in zip(w, taps))
y_conv = ndi.correlate(x, w.reshape(3, 3), mode="nearest")
print("zero offsets match ndi.correlate:", np.allclose(y_def[2:-2, 2:-2], y_conv[2:-2, 2:-2]))
# (b) every tap shares one flow f: deformable conv = warp by f, then ordinary convolution
f = np.zeros((128, 128, 2)); f[..., 0], f[..., 1] = 3.0, -2.0     # integer flow keeps the check exact
y_shared = sum(wi * bilinear_warp(x, f + np.array(t)) for wi, t in zip(w, taps))
y_warp_conv = ndi.correlate(bilinear_warp(x, f), w.reshape(3, 3), mode="nearest")
print("shared offsets = warp then conv:", np.allclose(y_shared[6:-6, 6:-6], y_warp_conv[6:-6, 6:-6]))
# zero offsets match ndi.correlate: True
# shared offsets = warp then conv: True
```

情況 (a) 是一般的卷積，情況 (b) 是光流扭曲後接一般的卷積；一般的可變形卷積則讓九個取樣點各有自己的偏移場。

**為什麼訓練不穩定。** 偏移 $\Delta p_i$ 是不受限制的迴歸輸出。訓練初期，它們可能漂移到非常大的值，指向遠離相關區域的地方（「偏移溢位」），產生無用的特徵。Chan 等人加入了偏移保真度損失，讓偏移接近光流 [19]；BasicVSR++ 則把偏移預測成疊加在光流上的殘差，並把每個取樣點乘上 sigmoid 調變遮罩，這同時也當作扭曲複本上的注意力圖 [20]。

### 以擴散模型為基礎的 VSR 模型

**白話版。** 所有擴散式 VSR 模型都從一個已經知道自然影像（或影片）長什麼樣子的生成器出發，以 LR 影片為條件，再加上某種東西，讓產生的細節在影格之間保持一致。它們的差別在於各自加了什麼。

**精確版。**

- **Upscale-A-Video** [28] 是文字引導的潛在擴散模型。在局部，它在 U-Net 與 VAE 解碼器中插入時間層，讓短序列內保持一致；在整體，一個免訓練的**光流引導循環潛在變數傳播**模組，會在整段序列中傳播並融合潛在變數。文字提示可以引導紋理的產生，可調整的雜訊程度則在復原與生成之間取捨。
- **MGLD-VSR** [29] 用由 LR 影片的時間動態算出的**運動引導損失**，引導預訓練潛在擴散模型的潛在取樣路徑，並以序列導向的損失微調插入解碼器的時間模組。
- **STAR** [30] 從本來就會建模運動的文字生成影片擴散模型出發，並在全域注意力區塊之前加入一個局部資訊增強模組（豐富局部細節並抑制退化瑕疵），以及一個動態頻率損失，在不同的擴散步驟強調不同的頻率成分（以維持保真度）。
- **SeedVR** [31] 是用於一般影片復原、可處理任意長度與解析度的擴散 Transformer，建立在位移視窗注意力之上，在空間與時間邊界使用大小可變的視窗，並搭配因果式影片自編碼器與影像加影片的混合訓練。
- **DLoRAL** [32] 以兩個 LoRA 分支訓練一步模型：一條一致性分支，用跨影格檢索模組由退化輸入學得；一條細節分支，隨後訓練，在維持於一致性分支的時間表徵之內，加入空間細節。兩者都合併進擴散模型，做單步推論。

**如何比較它們。** 檢查比較用的是有標準答案的合成資料（保真度指標）、真實影片（無參考指標、使用者研究），還是 AI 生成的影片，以及是否在逐影格品質之外也回報時間一致性指標；生成式模型可能拿其中一項去換另一項。

### BasicVSR 與 IconVSR

#### 挑戰

到了 2020 年，VSR 方法已變得複雜而且彼此差異很大（EDVR 的多尺度可變形對齊加注意力、RBPN 的多個投影模組），這讓它們很慢、難以重新實作，也很難公平比較。BasicVSR [7] 問的是：哪些元件真正重要？

#### 方法

把 VSR 方法分解成四個功能：**傳播、對齊、聚合與上取樣**，並用最精簡的設計測試每個功能的各種選項。論文的表 1 就是這樣分類現有方法的（局部、單向或雙向傳播；無對齊、光流或可變形對齊；以串接為基礎的聚合；pixel shuffle 上取樣）。BasicVSR 本身是效果最好的最簡單組合：雙向傳播、以光流（SPyNet）對*特徵*做對齊、串接與 pixel shuffle。

#### 結果

消融實驗是這篇論文的核心，這裡的數字是論文自己的。把測試序列切成獨立片段會降低 PSNR，在片段末端降得最多，這支持長距離傳播（它的圖 3）。單向版本在早期影格明顯較差，整體而言比雙向模型差約 0.5 dB（圖 4）。移除對齊損失 1.19 dB，而扭曲影像而不是特徵損失 0.17 dB。延伸版 IconVSR 加入關鍵影格的資訊補充與耦合傳播以減少誤差累積，回報比 BasicVSR 最多高 0.31 dB。

#### 判讀證據

從表 1 與 3.1 節讀起，兩者合起來就是這個領域的精簡地圖。在主要的比較表中，要檢查：(a) 每一欄的退化（REDS4 只有 BI，UDM10 只有 BD，Vimeo-90K-T 與 Vid4 兩者都有）；(b) 通道（除了用 RGB 的 REDS4 之外，都用 Y）；(c) 每一欄背後的訓練集（REDS4 用 REDS，其餘用 Vimeo-90K）；(d) 執行時間，它取決於硬體與 LR 大小。在消融實驗中，要注意每一個都是修改 BasicVSR 的某個變體，所以下降的幅度衡量的是該元件在這個設計內的價值，而不是一般情況下的價值。

#### 限制與問題

雙向傳播需要整段序列，所以 BasicVSR 是離線方法。以光流為基礎的對齊會承襲大運動與遮擋下的光流誤差，BasicVSR++ 用光流引導的可變形對齊來處理這一點 [20]。這項研究是在乾淨的 BI/BD 退化上進行的；RealBasicVSR [27] 顯示，同樣的長距離傳播可能放大嚴重的真實世界瑕疵。

#### 結論

它提供了本篇通篇使用的詞彙，也是 BasicVSR++、RealBasicVSR 與數個擴散式 VSR 模型所建立的基線。

### RealBasicVSR

#### 挑戰

用 BI 或 BD 退化訓練的模型，在真實影片上會失效，而單純用隨機的真實世界退化來訓練 BasicVSR 類型的模型，又會引發先前研究忽略的新取捨 [27]。

<Figure src={paperRealbasicvsrSource} alt="先清理各影格，再雙向傳播，避免退化沿時間反覆累積；動態細化可重複清理階段。" caption="原論文圖 3 — 先清理各影格，再雙向傳播，避免退化沿時間反覆累積；動態細化可重複清理階段。" />

*圖片來源: [27], Published paper PDF, PDF 第 4 頁. [原始 PDF](https://openaccess.thecvf.com/content/CVPR2022/papers/Chan_Investigating_Tradeoffs_in_Real-World_Video_Super-Resolution_CVPR_2022_paper.pdf).*

#### 方法

這篇論文找出三個取捨，並為每一個提出簡單的解法。(1) *細節合成與瑕疵抑制*：長期傳播在散播細節的同時也散播雜訊與瑕疵，所以在 BasicVSR 網路傳播之前，先由一個**影像預清理模組**（一疊殘差區塊）獨立地清理每個 LR 影格。它用一個額外的*清理損失*訓練，把它的輸出與降取樣後的真實標準答案比較；測試時，*動態改進*機制會反覆套用它，直到變化降到門檻以下。論文顯示，循環式的清理模組，或沒有清理損失，都無法去除瑕疵。(2) *訓練中的速度與表現*：載入許多長的、退化的片段會讓訓練變慢，所以**隨機退化機制**只載入每段序列的一半並在時間上翻轉它，並讓退化參數以隨機漫步的方式逐影格變化，以維持資料多樣性；這在品質不下降的情況下，最多把訓練時間減少 40%。(3) *批次與長度*：在固定的記憶體預算下，較長的序列比較大的批次更有效地利用時間資訊，也讓推論更穩定。

#### 結果

RealBasicVSR 是帶有清理模組的 BasicVSR，並以感知與對抗損失微調（清理模組與這兩個損失分離），在真實影片上，它的品質與效率優於真實世界的影像與影片 SR 模型。這篇論文也釋出 **VideoLQ** 這個真實低品質影片資料集，作為共同的基準測試。

#### 判讀證據

從清理模組的分析（對未清理的輸入套用傳播時會發生什麼）與批次對長度的實驗開始，因為它們解釋了這個設計。對於 VideoLQ，要檢查比較用的是無參考指標與視覺結果，因為沒有標準答案；並閱讀視覺比較，看更清晰的紋理與捏造的瑕疵之間的取捨。

#### 限制與問題

VideoLQ 上的無參考指標與人類判斷的關聯只算薄弱，所以比較有一部分要靠視覺範例。退化模型是合成的，所以它之外的編碼器與相機流程仍可能讓模型失效。清理模組若移除太多，也會連真實細節一起移除。

#### 結論

它解釋了為什麼真實世界 VSR 不能直接沿用乾淨基準測試的配方，也是 Upscale-A-Video 等擴散式 VSR 論文拿來比較的標準非擴散基線 [28]。
