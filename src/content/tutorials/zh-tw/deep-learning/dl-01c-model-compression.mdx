## 你將學到

- 視覺模型的「成本」指什麼（參數量、乘加運算、記憶體流量、尖峰記憶體、延遲、吞吐量）、為什麼這些數字彼此不一致，以及**屋頂線**（roofline）的觀點如何告訴你某一層是受限於運算還是受限於記憶體。
- **剪枝**：移除單一權重與移除整個通道的差別、量值準則、剪枝加微調的排程、半結構化的 2:4 稀疏，以及**樂透彩券假說**（lottery ticket hypothesis）主張了什麼、沒有主張什麼。
- **量化**：每個符號都定義清楚的均勻仿射方案、為什麼整數核可以把尺度提到外面、逐張量與逐通道尺度的差別、訓練後量化與使用直通估計器的量化感知訓練、混合精度，以及為什麼離群值與激活值是最容易出問題的地方。
- **知識蒸餾**超越 logit 損失的部分：特徵與注意力的模仿，以及決定蒸餾有沒有用的實務規則（相同的視角、長時間的訓練、不要差太遠的教師）。
- **低秩分解**與「一開始就設計得小」的替代做法（高效率區塊、結構重參數化、考慮硬體的架構搜尋），以及把小模型變成快模型的部署步驟（運算子融合、批次正規化折疊、整數核）。
- 分類器、偵測器、影像復原網路、視覺 Transformer 與擴散模型中，哪些部分對壓縮敏感，只舉已驗證的例子。

## 先看全貌

訓練好的網路，對於某個特定裝置上的某個特定工作，通常比需要的更大、更慢。**模型壓縮**（model compression）是一組在訓練之後（或訓練期間）移除這些多餘部分的技術，而**高效推論**（efficient inference）則是讓較小的模型在真實硬體上真的跑得更快的工程。兩者並不相同，這個領域裡大多數的失望都來自把它們混為一談。

<Callout type="tip" title="用最簡單的話說">
想像你要從大房子搬進小公寓。你可以丟掉從來不用的東西（剪枝）。你可以把衣服折得更緊，讓同樣的衣服占更少空間（量化）。你可以請一位已經住在小公寓的朋友告訴你哪幾樣東西真正重要，然後照著他的選擇做（蒸餾）。或者一開始就買可折疊的家具（設計小型網路）。但搬家公司是照箱子的重量與趟數收費，不是看你清單寫得多整齊。同樣地，電腦在意的是它要搬多少位元組，以及有沒有合適的工具打開這些箱子，而不是你的模型在紙面上看起來有多小。
</Callout>

**為什麼重要。** 大部分部署的視覺模型都在預算之下運作（手機相機、每秒 60 張影格的工廠產線、靠電池的機器人），壓縮決定了模型放不放得進這個預算。壓縮也會改變模型：量化或剪枝後的網路是另一個函數，可能在原本不會出錯的地方出錯。因此整章只有一條規則：**在目標裝置上量測成本，並在部署資料上量測壓縮後的準確率**。

**基礎知識在哪裡。** 本章建立在站內其他地方教過的內容上，並以連結取代重複：計算 FLOPs、記憶體帳、延遲協定、仿射量化公式與匯出執行環境，見 [ML 11](/zh-tw/learn/ml/evaluation-deployment/#效率flops記憶體與延遲)；帶溫度的 logit 蒸餾損失與經過測試的梯度檢查，見 [DLCV 01 補充資料](/zh-tw/learn/deep-learning/deep-learning-for-image-processing/notes/知識蒸餾向老師模型的軟答案學習/)；深度可分離卷積與區塊成本，見 [DLCV 02](/zh-tw/learn/deep-learning/image-classification/#mobilenet把卷積拆開) 與 [DLCV 01B](/zh-tw/learn/deep-learning/building-blocks/#瓶頸反向殘差與深度可分離卷積)；偵測器的速度量測，見 [DLCV 03A](/zh-tw/learn/deep-learning/real-time-detection/#速度量測檢查清單)。這裡所有程式碼都只用 NumPy 與 scikit-learn，在 CPU 上幾秒就跑完，並使用 scikit-learn 內建的 digits 資料集或合成資料。**我們程式碼產生的每一個準確率數字都是玩具結果**，來自 8 × 8 像素的數字辨識任務；它說明的是一個機制，而不是真實視覺模型上效果的大小。

## 「成本」是什麼意思

**白話版。** 「小」和「快」各有好幾種意思。參數較少的模型，執行時不一定用較少的記憶體；運算較少的模型，也不一定比較早跑完。壓縮任何東西之前，先決定你的預算談的是哪一個數字，然後在重要的那個裝置上量測它。

### 六個彼此不同的數字

描述執行一個網路要花多少成本的有六個數字：

- **參數量** $P$：學習到的值的數量。每個值用 $b$ 位元時，權重在磁碟與記憶體中占 $P\,b/8$ 位元組。剪枝與量化都會降低這個數字。
- **乘加運算**（multiply–accumulate, MAC）或 **FLOPs**：每張影像的運算量。一次 MAC 是一次乘法加一次加法，通常算作 2 FLOPs；各函式庫的計算方式不一致，所以要寫明你回報的是哪一種。一個從 $C_{\text{in}}$ 個通道到 $C_{\text{out}}$ 個通道、輸出為 $H' \times W'$ 的 $k \times k$ 卷積，成本是 $k^2 C_{\text{in}} C_{\text{out}} H' W'$ 次 MAC（[ML 11](/zh-tw/learn/ml/evaluation-deployment/#計算運算量)）。
- **記憶體流量**（memory traffic）：在主記憶體與運算單元之間搬動的位元組數。權重、輸入激活值與輸出激活值，至少都要被讀取或寫入一次。
- **尖峰記憶體**（peak memory）：一次前向傳遞中，同一時間存在的最大記憶體量（權重加上仍需要的激活值）。對高解析度的影像復原網路而言，它可能由激活值而不是權重主導。
- **延遲**（latency）：在目標裝置上，一個輸入從頭到尾的實際經過時間。相機管線或使用者感受到的就是這個。
- **吞吐量**（throughput）：許多影像一起處理時，每秒處理的影像數。大批次會提高吞吐量，但不會降低單張影像的延遲。

Dehghani 等人指出，這些成本指標可能互相矛盾，只回報其中一個，可能會對哪個模型比較有效率得出錯誤的結論 [1]。壓縮會讓這種不一致更嚴重，因為每種技術攻擊的是不同的數字：剪枝針對參數量與 MAC，量化針對位元組，而兩者都不會自動針對延遲。

### 運算強度與屋頂線

**白話版。** 晶片有兩個速度上限：乘法能算多快，以及從記憶體取數字能取多快。一層如果對取來的每個數字做很多運算，就會碰到第一個上限；一層如果取很多、乘得很少，就會碰到第二個上限。對一個卡在第二個上限的層縮減運算，幾乎沒有任何效果。

**精確版。** Williams、Waterman 與 Patterson 的**屋頂線模型**（roofline model）[2] 用下式限制一個計算可達到的速度：

$$
\text{attainable speed} = \min\bigl(\pi,\; \beta \cdot I\bigr),
\qquad
I = \frac{\text{operations}}{\text{bytes moved}},
$$

其中 $\pi$ 是裝置的尖峰運算速率（這裡以每秒 MAC 數計）、$\beta$ 是它的記憶體頻寬（每秒位元組數），$I$ 是該計算的**運算強度**（arithmetic intensity，每位元組的 MAC 數）。兩個上限交會處的強度 $I^\ast = \pi / \beta$ 稱為**脊點**（ridge point）：低於它時，該層**受限於記憶體**（memory-bound），高於它時則**受限於運算**（compute-bound）。單一層的簡單時間估計是

$$
t \approx \max\!\left(\frac{\text{MACs}}{\pi},\; \frac{\text{bytes}}{\beta}\right).
$$

下面的程式碼把這個式子套用到一個**虛構的**加速器（4 TMAC/s、100 GB/s；真實裝置各不相同）上的幾個層，並假設每個權重、輸入與輸出值恰好各穿過記憶體一次。真實的核會重複利用快取並讓資料傳輸與運算重疊，所以這些數字只是理想化的示意。

```python
# A made-up accelerator: 4 TMAC/s peak compute, 100 GB/s memory bandwidth.
PEAK_MACS, BANDWIDTH = 4e12, 100e9

def layer(kind, C=64, H=56, W=56, batch=1):
    """MACs and bytes moved, if weights, inputs and outputs each cross memory once."""
    if kind == "conv 3x3":
        weights, macs = 9 * C * C, 9 * C * C * H * W
    elif kind == "depthwise 3x3":
        weights, macs = 9 * C, 9 * C * H * W
    elif kind == "pointwise 1x1":
        weights, macs = C * C, C * C * H * W
    elif kind == "linear 2048x2048":
        weights, macs, C, H, W = 2048 * 2048, 2048 * 2048, 2048, 1, 1
    acts = 2 * C * H * W                                  # one input and one output tensor
    return batch * macs, weights + batch * acts

for kind, batch, nbytes in [("conv 3x3", 1, 4), ("depthwise 3x3", 1, 4), ("pointwise 1x1", 1, 4),
                            ("depthwise 3x3", 1, 1), ("linear 2048x2048", 1, 4), ("linear 2048x2048", 64, 4)]:
    macs, values = layer(kind, batch=batch)
    traffic = values * nbytes
    t_compute, t_memory = macs / PEAK_MACS, traffic / BANDWIDTH
    bound = "compute" if t_compute > t_memory else "memory"
    print(f"{kind:17s} batch {batch:2d} {8 * nbytes:2d}-bit: {macs / 1e6:7.1f} M MACs, "
          f"{macs / traffic:5.1f} MACs/byte, ~{max(t_compute, t_memory) * 1e6:6.1f} us ({bound}-bound)")
print(f"ridge point: {PEAK_MACS / BANDWIDTH:.0f} MACs/byte")
```

輸出：

```text
conv 3x3          batch  1 32-bit:   115.6 M MACs,  65.9 MACs/byte, ~  28.9 us (compute-bound)
depthwise 3x3     batch  1 32-bit:     1.8 M MACs,   1.1 MACs/byte, ~  16.1 us (memory-bound)
pointwise 1x1     batch  1 32-bit:    12.8 M MACs,   7.9 MACs/byte, ~  16.2 us (memory-bound)
depthwise 3x3     batch  1  8-bit:     1.8 M MACs,   4.5 MACs/byte, ~   4.0 us (memory-bound)
linear 2048x2048  batch  1 32-bit:     4.2 M MACs,   0.2 MACs/byte, ~ 167.9 us (memory-bound)
linear 2048x2048  batch 64 32-bit:   268.4 M MACs,  15.1 MACs/byte, ~ 178.3 us (memory-bound)
ridge point: 40 MACs/byte
```

後面會反覆出現三個教訓。第一，深度卷積層的 MAC 比稠密的 $3 \times 3$ 卷積少 64 倍，估計卻只快了約 1.8 倍，因為它受限於記憶體（這就是 [DLCV 01B](/zh-tw/learn/deep-learning/building-blocks/#瓶頸反向殘差與深度可分離卷積) 中「MAC 不等於延遲」這項警告背後的算術）。第二，把那一層改用 8 位元而不是 32 位元儲存，估計時間縮短為 1/4，而一個 MAC 都沒有變：對受限於記憶體的層，量化的好處來自搬動更少的位元組。第三，批次 64 的線性層做的工作是批次 1 的 64 倍，花的時間卻差不多，因為它的權重只讀一次就重複使用，所以大批次的吞吐量幾乎說明不了批次 1 的延遲。

### 誠實地量測

請遵循 [ML 11](/zh-tw/learn/ml/evaluation-deployment/#延遲量測協定) 的延遲協定（固定並回報裝置、執行環境、精度、批次大小、解析度與執行緒數；暖機；百分位數；在 GPU 上同步），以及 [DLCV 03A](/zh-tw/learn/deep-learning/real-time-detection/#速度量測檢查清單) 的端到端檢查清單。壓縮另外多了三條自己的規則：

1. **與公平的稠密基準比較**：一個大小相同、用相同預算訓練的稠密模型。Liu 等人發現，在他們檢驗的結構化剪枝方法中，從頭訓練剪枝後的架構，表現持平或優於微調剪枝後的權重 [3]；Blalock 等人回顧了 81 篇剪枝論文，發現基準與指標不一致，使大多數比較無從進行 [4]。
2. **在匯出之後、在你實際出貨的執行環境上量測準確率。** 匯出、量化、融合後的計算圖，在數值上是和你訓練的不同的程式。
3. **回報取捨曲線，而不是單一個點。** 在幾種壓縮程度下，準確率對延遲（與記憶體）的曲線，才能顯示一個方法是移動了整條曲線，還是只是在曲線上挑了另一個點。

## 剪枝

**白話版。** 訓練好的網路有許多權重接近零，貢獻很小。剪枝（pruning）把它們設成精確的零並移除。移除零星分布的單一權重，在移除什麼上有最大的自由度，但需要特殊軟體才能跑得更快；移除整個通道，會得到真正更小、在任何地方都跑得更快的網路，但移除什麼的自由度較小。

### 移除什麼

把網路的參數寫成向量 $\boldsymbol\theta \in \mathbb{R}^{N}$。剪枝選擇一個二元**遮罩**（mask）$\mathbf{m} \in \{0, 1\}^{N}$，並用 $\mathbf{m} \odot \boldsymbol\theta$ 取代 $\boldsymbol\theta$，其中 $\odot$ 是逐元素相乘。**稀疏度**（sparsity）是零所占的比例，

$$
s = 1 - \frac{\lVert \mathbf{m} \rVert_0}{N},
$$

其中 $\lVert \mathbf{m} \rVert_0$ 計算遮罩中非零項的個數。各種方法的差別在於遮罩的**粒度**：

- **非結構化**（細粒度）：任何單一權重都可以被移除。這在選擇移除什麼上有最大的自由度，但結果是一個形狀仍為稠密、卻充滿零星零的張量。Li 等人指出，除非有稀疏卷積函式庫，這種不規則的稀疏並不會大幅降低卷積層的成本 [5]。
- **結構化**（粗粒度）：整個濾波器、通道、注意力頭或區塊被移除。移除一個卷積的輸出通道 $j$，也會移除下一層的輸入通道 $j$，所以兩個張量都縮小，而且仍是稠密的。Li 等人正是因為這個原因，把整個濾波器連同與它相連的特徵圖一起剪掉：結果可以用一般的稠密矩陣函式庫執行 [5]。
- **半結構化**：硬體可以利用的固定小樣式。NVIDIA 的稀疏 Tensor Core 支援 **2:4 稀疏**，也就是每連續四個權重中至少有兩個零；該論文報告這種樣式的數學吞吐量是稠密單元的兩倍 [6]。

*選讀：[N:M 半結構化稀疏](#nm-半結構化稀疏)（見「補充資料」頁）。2:4 的權重如何儲存、訓練—剪枝—重新訓練的流程，以及用 NumPy 檢查這種樣式比非結構化剪枝多損失多少權重量值。*

### 該移除哪些權重：量值與其他準則

最簡單、至今仍最常用的準則是**量值**（magnitude）：移除 $|\theta_i|$ 最小的權重。它可以逐層套用（每層移除相同比例）或全域套用（整個網路用同一個閾值；小權重多的層因此損失較多）。對結構化剪枝，則改用一組權重的量值：Li 等人用每個濾波器的絕對權重和（$\ell_1$ 範數）為濾波器排名 [5]。**Network slimming** 在訓練時對批次正規化層的尺度因子 $\gamma$ 加上 $\ell_1$ 懲罰，把不重要通道的尺度推向零，然後移除 $|\gamma|$ 最小的通道 [7]。還有許多其他準則（以梯度為基礎、二階的、以資料為基礎的）；Hoefler 等人對它們做了綜述 [8]。

結構化剪枝有一個非結構化剪枝沒有的陷阱：**耦合的通道**，例如殘差相加兩側的通道，它們必須一起被移除。Fang 等人的 DepGraph 可以從計算圖自動找出這類群組 [9]。

*選讀：[剪枝耦合的通道](#剪枝耦合的通道)（見「補充資料」頁）。殘差相加、深度層、串接與注意力頭的相依規則，並以小例子逐一走過。*

### 剪枝、微調、再重複

移除權重會改變函數，所以剪枝之後要接著訓練。Han 等人描述了標準的三步驟配方：訓練網路以學出哪些連接重要、剪掉不重要的連接，並重新訓練剩下的權重；他們在 ImageNet 上報告，把 AlexNet 的參數從 6,100 萬降到 670 萬、把 VGG-16 的從 1.38 億降到 1,030 萬，而準確率沒有下降 [10]。他們的 Deep Compression 流程又在剪枝之上加入量化與 Huffman 編碼 [11]。

剪枝常被分成幾個較小的步驟，每一步之後都做一些訓練，而不是一次大幅砍掉。Zhu 與 Gupta 的**漸進式**排程，在訓練期間把稀疏度從零升到目標值，一開始升得快，接近尾聲時升得慢 [12]。他們也比較了記憶體占用相同的大而稀疏模型與小而稠密模型，發現在他們測試的各種架構上，大而稀疏的模型一致地更準確 [12]。

*選讀：[漸進式剪枝排程](#漸進式剪枝排程)（見「補充資料」頁）。三次方的稀疏度公式與每個符號的定義、一個走過的排程範例，以及它留給你決定的選擇。*

### 程式碼：小型 MLP 的非結構化與結構化剪枝

這段程式碼先在 scikit-learn 的 digits 上訓練一個 64–256–128–10 的 MLP，再用兩種方式剪枝：移除每一層最小的權重，以及移除整個隱藏單元（傳入權重的 $\ell_1$ 範數最小者，兩個隱藏層都做）。每個剪枝後的模型都微調 10 個 epoch，並在每一步最佳化器更新之後重新套用遮罩。最後，把剪得最多的結構化模型切成一個真正更小的稠密網路。

```python
import copy, warnings
import numpy as np
from sklearn.datasets import load_digits
from sklearn.exceptions import ConvergenceWarning
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier
warnings.filterwarnings("ignore", category=ConvergenceWarning)

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X / 16.0, y, test_size=0.3, random_state=0, stratify=y)
base = MLPClassifier(hidden_layer_sizes=(256, 128), max_iter=300, random_state=0).fit(Xtr, ytr)
print(f"dense: {sum(w.size for w in base.coefs_)} weights, test accuracy {base.score(Xte, yte):.3f}")

def fine_tune(net, masks, epochs=10):
    order_rng = np.random.default_rng(0)
    for _ in range(epochs):
        order = order_rng.permutation(len(Xtr))
        for i in range(0, len(Xtr), 128):
            net.partial_fit(Xtr[order[i:i + 128]], ytr[order[i:i + 128]])   # one Adam step
            for w, m in zip(net.coefs_, masks):
                w *= m                                                     # keep pruned weights at zero

def unstructured_masks(net, sparsity):          # smallest |w| in each layer -> 0
    return [np.abs(w) > np.quantile(np.abs(w), sparsity) for w in net.coefs_]

def structured_masks(net, keep):                # drop hidden units with the smallest L1 norm of incoming weights
    masks = [np.ones_like(w) for w in net.coefs_]
    for l in range(len(net.coefs_) - 1):
        norms = np.abs(net.coefs_[l]).sum(axis=0)
        dead = np.argsort(norms)[: int(round((1 - keep) * norms.size))]
        masks[l][:, dead] = 0                   # incoming weights of the unit ...
        masks[l + 1][dead, :] = 0               # ... and its outgoing weights
    return masks

for name, make, levels in [("remove weights", unstructured_masks, [0.8, 0.9, 0.95]),
                           ("keep units", structured_masks, [0.5, 0.25, 0.125])]:
    for level in levels:
        net = copy.deepcopy(base)
        masks = make(net, level)
        for w, m in zip(net.coefs_, masks):
            w *= m
        before = net.score(Xte, yte)
        fine_tune(net, masks)
        kept = int(sum(m.sum() for m in masks))
        print(f"{name} {level:6.1%}: {kept:5d} weights left, "
              f"accuracy {before:.3f} -> {net.score(Xte, yte):.3f} after fine-tuning")

# The last structured model is a genuinely smaller dense network: slice out the live units.
alive = [masks[l].any(axis=0) for l in range(2)]
small_W = [net.coefs_[0][:, alive[0]], net.coefs_[1][alive[0]][:, alive[1]], net.coefs_[2][alive[1]]]
small_b = [net.intercepts_[0][alive[0]], net.intercepts_[1][alive[1]], net.intercepts_[2]]
h = Xte
for l, (w, b) in enumerate(zip(small_W, small_b)):
    h = h @ w + b if l == 2 else np.maximum(h @ w + b, 0)
print("sliced shapes:", [w.shape for w in small_W],
      "| same predictions:", bool((h.argmax(1) == net.predict(Xte)).all()))
```

輸出（玩具結果）：

```text
dense: 50432 weights, test accuracy 0.980
remove weights  80.0%: 10087 weights left, accuracy 0.909 -> 0.974 after fine-tuning
remove weights  90.0%:  5044 weights left, accuracy 0.563 -> 0.954 after fine-tuning
remove weights  95.0%:  2523 weights left, accuracy 0.170 -> 0.885 after fine-tuning
keep units  50.0%: 17024 weights left, accuracy 0.887 -> 0.981 after fine-tuning
keep units  25.0%:  6464 weights left, accuracy 0.550 -> 0.980 after fine-tuning
keep units  12.5%:  2720 weights left, accuracy 0.402 -> 0.957 after fine-tuning
sliced shapes: [(64, 32), (32, 16), (16, 10)] | same predictions: True
```

從中能讀到什麼。**微調做了大部分的工作**：移除 90% 的權重會讓準確率掉到 0.563，十個 epoch 就把它帶回 0.954。**結構化剪枝產生了一個真正的網路**，形狀為 64–32–16–10，任何函式庫都能把它當成一般稠密矩陣來執行。而在剩下約 2,500 個權重時，小的稠密網路（0.957）勝過大的稀疏網路（0.885），這與 Zhu 與 Gupta 在大型模型上的發現相反 [12]：我們的網路對 8 × 8 的數字任務來說參數過多，讓它變窄幾乎沒有代價。不要從這個玩具往任一方向推論。

### 樂透彩券假說

**白話版。** 如果剪枝後的網路可以這麼小，為什麼不直接訓練小網路？Frankle 與 Carbin 發現，在他們的實驗中，隨機重新初始化的剪枝網路訓練效果較差，但同一個稀疏網路若**重設回它原本的初始權重**，訓練效果就和完整網路一樣好。他們提出，大型網路從一開始就含有這種幸運的稀疏子網路（「中獎彩券」，winning tickets）。

這些彩券是用**反覆量值剪枝**找到的：訓練、剪掉量值最小的權重、把留下的權重重設為初始值，然後重複；在小型 MNIST 與 CIFAR-10 網路上，這個做法一致地找到了只有原本大小 10–20% 或更小的彩券 [13]。在 ImageNet 的規模上，權重必須重設為訓練早期的值，而不是初始化時的值 [14]；Liu 等人則報告，在學習率調得好的情況下，他們的實驗中使用彩券初始化並沒有比隨機初始化更好 [3]。實務上的教訓並不誇張：這個假說談的是哪些稀疏網路是可訓練的，而不是更便宜的壓縮方法（找一張彩券要花好幾次完整訓練）。

*選讀：[樂透彩券假說（Frankle 與 Carbin，ICLR 2019）](#the-lottery-ticket-hypothesisfrankle-與-carbiniclr-2019)（見「論文導讀」頁）。實驗控制了什麼、如何讀提早停止的圖，以及這項主張的限制。*

## 量化

**白話版。** 用 32 位元浮點數訓練的網路，並不需要那麼高的精度才能做出好的預測。量化（quantization）把權重（通常還有激活值）存成小整數（8 位元，有時是 4 位元），並搭配少數幾個尺度因子。這能讓記憶體減少 4 到 8 倍，在有整數運算的硬體上還能加速計算。困難在於，一個小格點必須同時涵蓋大量的小數字與少數非常大的數字。

### 均勻仿射量化

這是最常見的方案，因為它允許有效率的定點運算 [15]，它把實數值 $x$ 映射成整數 $q$，再映射回來 [16]：

$$
q = \operatorname{clip}\!\left(\operatorname{round}\!\left(\frac{x}{s}\right) + z,\; q_{\min},\; q_{\max}\right),
\qquad
\hat{x} = s\,(q - z),
$$

其中 $s > 0$ 是**尺度**（scale，相鄰可表示值之間的間距），$z$ 是整數**零點**（zero point，精確表示實數 0 的那個整數），$[q_{\min}, q_{\max}]$ 是 $b$ 位元格式的整數範圍（例如無號 8 位元是 $[0, 255]$，對稱有號格式是 $[-127, 127]$），$\operatorname{round}$ 是四捨五入到最近的整數，$\operatorname{clip}$ 是夾進範圍內，$\hat{x}$ 是 $x$ 經過反量化後的近似值。對於包含 0 的實數範圍 $[x_{\min}, x_{\max}]$，常見的選擇是

$$
s = \frac{x_{\max} - x_{\min}}{q_{\max} - q_{\min}},
\qquad
z = q_{\min} - \operatorname{round}\!\left(\frac{x_{\min}}{s}\right).
$$

**對稱**量化固定 $z = 0$ 並使用有號範圍。精確表示 0 很重要，因為零填補與 ReLU 的輸出會產生許多精確的零 [15]。會出現兩種誤差：範圍內的值有**捨入誤差**，最多 $s/2$；範圍外的值有**截斷誤差**。範圍越大，截斷越少，但 $s$ 變大，捨入誤差也隨之變大 [15]。[ML 11](/zh-tw/learn/ml/evaluation-deployment/#量化) 有經過測試的實作與誤差對位元數的曲線。

### 為什麼整數核可以把尺度提到外面

**白話版。** 只有在一層最昂貴的部分，也就是那一長串乘積之和，能完全用整數執行時，整數才有用。如果每個權重列有一個尺度、每個激活張量有一個尺度，這些尺度就可以從和裡面提出來，只在最後套用一次。

對線性層的一個輸出 $y_i = \sum_j W_{ij} x_j$（卷積是對一個區塊做同樣的和），把權重以每個輸出通道一個尺度 $s_{w,i}$ 做對稱量化，$W_{ij} \approx s_{w,i}\,q^{w}_{ij}$，並把輸入以尺度 $s_x$ 與零點 $z_x$ 做仿射量化，$x_j \approx s_x (q^{x}_j - z_x)$。於是

$$
y_i \approx s_{w,i}\, s_x \sum_{j} q^{w}_{ij}\,\bigl(q^{x}_j - z_x\bigr),
$$

其中的和只涉及整數，並在 32 位元整數暫存器中累加；單一個乘積 $s_{w,i} s_x$ 對每個輸出只套用一次。這就是為什麼權重的逐通道尺度很便宜（每個輸出通道一個因子），而**激活值**的逐通道尺度卻不便宜：它們會落在和的裡面，每個輸入通道都需要重新縮放累加器 [15]。這也是為什麼常見的選擇是對稱的權重加上非對稱的激活值：非對稱的權重零點會為每個輸出加上一個與資料相關的項 [15]。偏置通常保留為 32 位元整數 [16]。

```python
import numpy as np

rng = np.random.default_rng(0)
W = rng.normal(0, 0.2, size=(16, 256))              # a layer: 16 outputs, 256 inputs
x = rng.normal(0.3, 1.0, size=256)                  # input activations (not centred at 0)

# Weights: symmetric int8, one scale per output channel (zero point 0).
s_w = np.abs(W).max(axis=1) / 127
W_q = np.round(W / s_w[:, None]).astype(np.int8)

# Activations: affine uint8 with a scale and an integer zero point.
lo, hi = min(x.min(), 0.0), x.max()
s_x = (hi - lo) / 255
z_x = int(np.round(-lo / s_x))
x_q = np.clip(np.round(x / s_x) + z_x, 0, 255).astype(np.uint8)
print("activation scale:", round(s_x, 5), "| zero point:", z_x)

# Integer-only inner products, accumulated in int32, then one rescale per output.
acc = W_q.astype(np.int32) @ (x_q.astype(np.int32) - z_x)
y_int = s_w * s_x * acc
y_ref = W @ x
print("max |integer result - float result|:", np.abs(y_int - y_ref).max().round(4))
print("relative error:", (np.linalg.norm(y_int - y_ref) / np.linalg.norm(y_ref)).round(4))
print("largest |accumulator|:", np.abs(acc).max(), "| int16 limit:", 2**15 - 1)
```

輸出：

```text

max |integer result - float result|: 0.0495
relative error: 0.0083
largest |accumulator|: 83167 | int16 limit: 32767
```

整數路徑重現浮點結果，誤差在約 1% 以內。累加器達到 83,167，遠超過 16 位元能容納的範圍，這就是為什麼即使輸入是 8 位元，加速器仍使用 32 位元累加器 [15]。在進入下一層之前，32 位元的結果會用下一層的尺度轉回 8 位元（「重新量化」，requantization）。

*選讀：[用定點乘數重新量化](#用定點乘數重新量化)（見「補充資料」頁）。Jacob 等人如何把合併後的實數尺度變成一次整數乘法加一次位元位移，讓推論時不留下任何浮點運算。*

### 粒度與範圍設定

**粒度**（granularity）是有多少個值共用一個尺度：每個張量一個、每個輸出通道一個，或每一小組連續權重一個。粒度越細，格點越能貼合每一組自己的範圍。**範圍設定**（range setting，也稱校準）是 $[x_{\min}, x_{\max}]$ 的選擇方式 [15]：

- **Min-max**：觀察到的最小值與最大值。沒有截斷，但一個離群值就會把所有人的格點拉寬。
- **百分位數**：忽略一小部分最極端的值。
- **MSE**：在具代表性的資料上，搜尋使 $\lVert x - \hat{x} \rVert^2$ 最小的範圍，在截斷與捨入之間取捨。

權重事先已知，不需要資料。激活值取決於輸入，所以它們的範圍是靠讓一小份未標註的**校準集**（calibration set）影像跑過網路來估計；Nagel 等人指出，500 到 1,000 張未標註影像通常就夠了 [15]。

*選讀：[選擇截斷範圍：min-max、百分位數與 MSE](#選擇截斷範圍min-max百分位數與-mse)（見「補充資料」頁）。一個經過測試的比較，顯示最佳規則會隨位元寬度改變：8 位元時保留離群值，4 位元時截斷它們。*

### 什麼會壞掉：離群值、折疊後的批次正規化與激活值

**白話版。** 當一個共用的尺度必須涵蓋大小差異極大的值時，量化就會失敗。大的值迫使格點變粗，而大量的小值全都被捨入到少數幾個整數。

典型的視覺例子是 MobileNetV2。Nagel 等人指出，它的一個深度可分離層中，不同輸出通道的權重範圍差異極大，以致一組量化參數無法服務整個張量；在折疊批次正規化並使用 8 位元逐張量量化時，他們的模型在 ImageNet 上的 top-1 準確率從 71.72% 掉到 0.12% [17]。他們的解法不需要資料或訓練：因為 $c > 0$ 時 $\operatorname{ReLU}(c\,t) = c\,\operatorname{ReLU}(t)$，所以可以把一層的某個輸出通道縮小，同時把下一層對應的輸入通道放大，函數不會改變（**跨層均衡化**，cross-layer equalization）。在把 ReLU6 換成具有這個性質的 ReLU 之後，均衡化加上偏置吸收，讓模型在 8 位元下達到 70.92% [17]。

我們的玩具重現了這個機制。我們取訓練好的 MLP，把一個隱藏單元放大 100 倍（並把下一層的權重縮小為 1/100）。浮點網路計算的仍是完全相同的函數，但它的激活值與權重範圍現在含有一個巨大的通道。

```python
import warnings
import numpy as np
from sklearn.datasets import load_digits
from sklearn.exceptions import ConvergenceWarning
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier
warnings.filterwarnings("ignore", category=ConvergenceWarning)

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X / 16.0, y, test_size=0.3, random_state=0, stratify=y)
net = MLPClassifier(hidden_layer_sizes=(256, 128), max_iter=300, random_state=0).fit(Xtr, ytr)

def q_weight(w, bits, per_channel):     # symmetric: one scale per output unit, or one per tensor
    qmax = 2 ** (bits - 1) - 1
    m = np.abs(w).max(axis=0, keepdims=True) if per_channel else np.abs(w).max()
    return np.clip(np.round(w * qmax / m), -qmax, qmax) * m / qmax

def q_act(a, hi, bits):                 # post-ReLU activations: grid on [0, hi], zero point 0
    s = hi / (2 ** bits - 1)
    return np.clip(np.round(a / s), 0, 2 ** bits - 1) * s

def run(Ws, bs, X, wbits=None, abits=None, his=None, per_channel=True, record=None):
    h = X
    for l, (w, b) in enumerate(zip(Ws, bs)):
        h = h @ (q_weight(w, wbits, per_channel) if wbits else w) + b
        if l < len(Ws) - 1:
            h = np.maximum(h, 0)
            if record is not None:
                record.append(h)
            if abits:
                h = q_act(h, his[l], abits)
    return h

acc = lambda logits: (logits.argmax(1) == yte).mean()
for c in [1, 100]:
    Ws = [w.copy() for w in net.coefs_]
    bs = [b.copy() for b in net.intercepts_]
    Ws[0][:, 0] *= c; bs[0][0] *= c; Ws[1][0, :] /= c   # same function: ReLU(c*t) = c*ReLU(t)
    calib = []
    run(Ws, bs, Xtr[:100], record=calib)                 # 100 training images calibrate the ranges
    minmax = [a.max() for a in calib]
    pct99 = [np.percentile(a, 99) for a in calib]
    print(f"unit 0 scaled by {c}: float {acc(run(Ws, bs, Xte)):.3f} | "
          f"W8A8 {acc(run(Ws, bs, Xte, 8, 8, minmax)):.3f} | "
          f"W8A4 {acc(run(Ws, bs, Xte, 8, 4, minmax)):.3f} | "
          f"W8A4 clipped {acc(run(Ws, bs, Xte, 8, 4, pct99)):.3f} | "
          f"W4 per-tensor {acc(run(Ws, bs, Xte, 4, per_channel=False)):.3f} | "
          f"W4 per-channel {acc(run(Ws, bs, Xte, 4)):.3f}")
```

輸出（玩具結果；「W8A4」表示 8 位元權重與 4 位元激活值）：

```text
unit 0 scaled by 1: float 0.980 | W8A8 0.980 | W8A4 0.978 | W8A4 clipped 0.978 | W4 per-tensor 0.983 | W4 per-channel 0.980
unit 0 scaled by 100: float 0.980 | W8A8 0.980 | W8A4 0.163 | W8A4 clipped 0.980 | W4 per-tensor 0.102 | W4 per-channel 0.978
```

兩個網路是同一個函數，但有了一個離群通道，4 位元 min-max 的激活值就崩潰到 0.163，4 位元逐張量的權重崩潰到 0.102。把激活值範圍在第 99 百分位數截斷（0.980），以及使用逐單元的權重尺度（0.978），都能解決。這裡截斷剛好不花任何代價；當離群通道攜帶真正的資訊時就會有代價，這就是為什麼會有移動或隔離離群值的方法。

同樣的模式在更大的規模上，推動了 Transformer 的量化研究：Dettmers 等人在大型語言模型中發現系統性的離群特徵維度，並把它們保留在 16 位元 [18]，而 SmoothQuant 用等價的逐通道重新縮放，把難度從激活值轉移到權重，與跨層均衡化屬於同一類想法 [19]。

### 訓練後量化與量化感知訓練

**白話版。** 你可以只用一點校準資料就量化一個已完成的模型（快、不需要標籤），或者在訓練模型的同時讓它「感受」到捨入，讓它學到能經得起捨入的權重（慢一些，但在低位元寬度下更準確）。

**訓練後量化**（post-training quantization, PTQ）取一個訓練好的浮點模型，只用一小份校準集來轉換。Nagel 等人建議的流程是：跨層均衡化；對稱的權重量化器與非對稱的激活量化器（若硬體支援，權重逐通道）；以 MSE 為基礎的權重範圍；然後在有校準資料時使用 **AdaRound**（學習每個權重該向上還是向下捨入 [20]），否則使用解析式的偏置校正；最後設定激活值範圍 [15]。

**量化感知訓練**（quantization-aware training, QAT）在前向傳遞中插入「偽量化」（先量化、再立刻反量化），並照常訓練。困難在於 $\operatorname{round}$ 幾乎處處梯度為零。**直通估計器**（straight-through estimator, STE）[21] 在反向傳遞中把捨入視為恆等映射。對於對稱量化器 $\hat{x} = s\,\operatorname{clip}(\operatorname{round}(x/s), q_{\min}, q_{\max})$，這給出

$$
\frac{\partial \hat{x}}{\partial x} \approx
\begin{cases}
1, & q_{\min} \le x/s \le q_{\max},\\
0, & \text{otherwise},
\end{cases}
$$

所以梯度會原封不動地通過範圍內的值，並在被截斷的值處停止 [15]。被更新的是浮點的「影子」權重，而前向傳遞永遠使用它們量化後的版本。

何時用哪一種：在白皮書的實驗中，PTQ 足以處理 8 位元的權重與激活值（所有測試的模型都在浮點結果的 0.7% 以內），而更低的位元寬度，特別是 4 位元激活值，就需要 QAT；使用深度可分離層的網路，即使做了 QAT 仍然是最難的 [15]。

*選讀：[超越四捨五入：AdaRound、BRECQ 與 LSQ](#超越四捨五入adaroundbrecq-與-lsq)（見「補充資料」頁）。三項改進：學習每個權重該向上或向下捨入、重建整個區塊，以及在 QAT 中學習尺度本身。*

### 混合精度與其他數字格式

並非所有層都同樣敏感，所以**混合精度量化**（mixed-precision quantization）讓不同的層使用不同的位元寬度：HAWQ 根據二階（Hessian）資訊選擇 [22]，HAQ 則根據硬體模擬器回饋的延遲與能耗，並發現邊緣與雲端加速器的最佳策略並不相同 [23]。整數不是唯一的選擇：8 位元浮點編碼（E4M3 與 E5M2）[24] 把位元花在指數上，能容忍更寬的數量級範圍，代價是步階更少。

不要把這和**混合精度訓練**（[DLCV 01A](/zh-tw/learn/deep-learning/training-practice/#混合精度與損失縮放)）混淆，後者保留一份 32 位元的權重主副本，並用 16 位元計算以加快訓練。混合精度量化談的是部署後的模型。

## 知識蒸餾

**白話版。** 訓練一個小的**學生**（student）去模仿大的**教師**（teacher），而不只是模仿正確的標籤。教師的完整輸出（它認為哪些錯誤類別也有可能）以及它的中間特徵，每個範例帶有的資訊比一個標籤更多，所以學生從同樣的影像可以學到更多。

Hinton 等人帶溫度 $T$ 與 $T^2$ 因子的回應式損失，已在 [DLCV 01 補充資料](/zh-tw/learn/deep-learning/deep-learning-for-image-processing/notes/知識蒸餾向老師模型的軟答案學習/)中推導並測試，並在 [ML 11](/zh-tw/learn/ml/evaluation-deployment/#知識蒸餾) 中摘要 [25]；這裡不重複。用一行來說：學生最小化 $(1-\alpha)\,\mathrm{CE}(y, \sigma(\mathbf{z})) + \alpha\,T^2\,\mathrm{CE}(\sigma(\mathbf{v}/T), \sigma(\mathbf{z}/T))$，其中 $\mathbf{z}$ 與 $\mathbf{v}$ 分別是學生與教師的 logits，$y$ 是標籤，$\sigma$ 是 softmax，$\mathrm{CE}$ 是交叉熵，$\alpha \in [0, 1]$ 是軟項的權重。Hinton 等人指出，像 Ba 與 Caruana 那樣用 L2 損失迴歸 logits 來匹配它們 [26]，是這個損失在高溫下的極限 [25]。

### 程式碼：把玩具 MLP 蒸餾成 8 單元的學生

教師是剪枝程式碼中那個有 50,432 個權重的 MLP。學生只有一個含 8 個單元的隱藏層（592 個權重），用全批次梯度下降訓練：一次只用標籤，兩次使用蒸餾損失。

```python
import warnings
import numpy as np
from sklearn.datasets import load_digits
from sklearn.exceptions import ConvergenceWarning
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier
warnings.filterwarnings("ignore", category=ConvergenceWarning)

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X / 16.0, y, test_size=0.3, random_state=0, stratify=y)
teacher = MLPClassifier(hidden_layer_sizes=(256, 128), max_iter=300, random_state=0).fit(Xtr, ytr)
h = Xtr
for l, (w, b) in enumerate(zip(teacher.coefs_, teacher.intercepts_)):   # teacher logits
    h = h @ w + b if l == 2 else np.maximum(h @ w + b, 0)
z_teacher = h

def softmax(z, T=1.0):
    e = np.exp((z - z.max(axis=1, keepdims=True)) / T)
    return e / e.sum(axis=1, keepdims=True)

def train_student(T, alpha, hidden=8, steps=500, lr=0.2, seed=0):
    """64 -> 8 -> 10 ReLU network, full-batch gradient descent on the distillation loss."""
    rng = np.random.default_rng(seed)
    W1, b1 = rng.normal(0, np.sqrt(2 / 64), (64, hidden)), np.zeros(hidden)
    W2, b2 = rng.normal(0, np.sqrt(1 / hidden), (hidden, 10)), np.zeros(10)
    Y, p_T = np.eye(10)[ytr], softmax(z_teacher, T)
    for _ in range(steps):
        a = np.maximum(Xtr @ W1 + b1, 0)
        z = a @ W2 + b2
        # gradient of (1-alpha)*CE(y, softmax(z)) + alpha*T^2*CE(p_T, softmax(z/T)) w.r.t. z
        g = ((1 - alpha) * (softmax(z) - Y) + alpha * T * (softmax(z, T) - p_T)) / len(Xtr)
        ga = (g @ W2.T) * (a > 0)
        W2 -= lr * a.T @ g;  b2 -= lr * g.sum(0)
        W1 -= lr * Xtr.T @ ga; b1 -= lr * ga.sum(0)
    return (np.maximum(Xte @ W1 + b1, 0) @ W2 + b2).argmax(1)

print(f"teacher: {sum(w.size for w in teacher.coefs_)} weights, accuracy {teacher.score(Xte, yte):.3f}")
for T in (1, 4):
    print(f"mean top probability of the teacher on training images at T = {T}: "
          f"{softmax(z_teacher, T).max(axis=1).mean():.3f}")
for name, T, alpha in [("labels only", 1, 0.0), ("distill, T = 1", 1, 0.5), ("distill, T = 4", 4, 0.5)]:
    accs = [(train_student(T, alpha, seed=s) == yte).mean() for s in range(5)]
    print(f"student (592 weights), {name:14s}: accuracy {np.mean(accs):.3f} +/- {np.std(accs):.3f} over 5 seeds")
```

輸出（玩具結果）：

```text
teacher: 50432 weights, accuracy 0.980
mean top probability of the teacher on training images at T = 1: 0.998
mean top probability of the teacher on training images at T = 4: 0.787
student (592 weights), labels only   : accuracy 0.936 +/- 0.025 over 5 seeds
student (592 weights), distill, T = 1: accuracy 0.936 +/- 0.025 over 5 seeds
student (592 weights), distill, T = 4: accuracy 0.954 +/- 0.006 over 5 seeds
```

$T = 4$ 的蒸餾把學生的平均準確率從 0.936 提高到 0.954，並讓它對隨機種子的依賴小得多。$T = 1$ 時則毫無改變，第二行說明了原因：在自己的訓練影像上，教師幾乎是確定的（平均最高機率 0.998），所以它的軟目標實際上就是標籤。溫度才是讓教師對錯誤類別的看法顯現出來的東西。這個效果很小，而且只適用於這個玩具；能遷移的是機制，不是數字。

### 特徵與注意力蒸餾

教師的中間表示也可以被模仿。**FitNets** 訓練一個細而深的學生，讓它的某個中間層（「被引導」層）經過一個小的學習式**迴歸器**（regressor）後，去預測教師的某個中間層（「提示」層）；需要迴歸器，是因為兩個層的寬度不同，作者使用卷積迴歸器來讓它的大小保持在可控範圍 [27]。**注意力轉移**（attention transfer）模仿的是教師的特徵在哪裡活躍，而不是特徵本身：對特徵圖 $A \in \mathbb{R}^{C \times H \times W}$，它形成一張空間圖

$$
F(A) = \sum_{c=1}^{C} \lvert A_c \rvert^{p},
$$

其中 $A_c$ 是通道 $c$，$p \ge 1$ 是指數（該論文也研究了 $p = 1$ 以及對通道取最大值），並訓練學生在多個深度上匹配教師經 $\ell_2$ 正規化的圖 [28]。因為 $F(A)$ 沒有通道維度，教師與學生的寬度不需要一致。Gou 等人依傳遞的內容（回應、特徵、範例之間或層之間的關係）以及傳遞的方式（從固定教師離線、線上，或自蒸餾）來整理這個領域 [29]。

### 蒸餾有沒有用，取決於什麼

- **教師與學生必須看到相同的輸入。** Beyer 等人發現，當教師與學生拿到每張影像完全相同的擴增視角（「一致」的教學）、擴增很強，並且訓練時間很長（「有耐心」）時，蒸餾效果最好；不一致的設定在他們的實驗中停在較低的水準 [30]。
- **更好的教師不一定是更好的老師。** Cho 與 Hariharan 發現，更大、更準確的教師往往沒有產生更好的學生，他們把原因歸於容量不匹配，發現經由中等大小模型的多步蒸餾無效，並報告提早停止教師的訓練可以緩解這個問題 [31]。
- **蒸餾是一種訓練方法，不是對既有模型的壓縮**：它需要一次訓練、資料，以及事先選定的學生架構。例如 DeiT 訓練視覺 Transformer 時，加了一個向卷積教師學習的蒸餾 token（[DLCV 02](/zh-tw/learn/deep-learning/image-classification/#deit只用-imagenet-訓練-vit)）[32]。

## 低秩分解

**白話版。** 一個大的權重矩陣所含的資訊，往往比它的大小所暗示的少得多。把它寫成兩個細矩陣的乘積，就能把一個大層換成兩個小層，權重與運算都少很多。

任何 $m \times n$ 矩陣 $W$ 都有奇異值分解 $W = U \Sigma V^\top$，其中 $U$（$m \times m$）與 $V$（$n \times n$）的各行互相正交且長度為 1，$\Sigma$ 是對角矩陣，對角線上是奇異值 $\sigma_1 \ge \sigma_2 \ge \dots \ge 0$。保留最大的 $r$ 個，就得到 Frobenius 範數下最佳的秩-$r$ 近似（[ML 01A](/zh-tw/learn/ml/linear-algebra/#最佳低秩近似)）：

$$
W \approx A B, \qquad A = U_{:, 1:r}\,\Sigma_{1:r,1:r} \in \mathbb{R}^{m \times r}, \qquad B = V_{:, 1:r}^\top \in \mathbb{R}^{r \times n},
$$

其中 $U_{:,1:r}$ 是 $U$ 的前 $r$ 行，$r$ 是選定的**秩**（rank）。層 $x \mapsto W x$ 變成兩層 $x \mapsto A(Bx)$，權重數為 $r(m + n)$ 而不是 $mn$，只有當 $r \lt mn/(m+n)$ 時才會節省權重與 MAC。對於核為 $W \in \mathbb{R}^{C_{\text{out}} \times C_{\text{in}} \times k \times k}$ 的卷積，把它重塑成 $C_{\text{out}} \times (C_{\text{in}} k^2)$ 的矩陣再分解：$B$ 變成有 $r$ 個輸出通道的 $k \times k$ 卷積，$A$ 是回到 $C_{\text{out}}$ 個通道的 $1 \times 1$ 卷積。Denton 等人利用卷積濾波器中這類線性結構，在 CPU 與 GPU 上把卷積層加速約兩倍，準確率差距在 1% 以內 [33]；Jaderberg 等人建立了在空間域中秩為 1 的濾波器基底（一個 $k \times 1$ 後接一個 $1 \times k$ 的濾波器）[34]；Zhang 等人把低秩加速擴展到用於分類與偵測的非常深的網路，其最小化的是每層非線性響應的重建誤差，而不是權重的重建誤差 [35]。

```python
import warnings
import numpy as np
from sklearn.datasets import load_digits
from sklearn.exceptions import ConvergenceWarning
from sklearn.model_selection import train_test_split
from sklearn.neural_network import MLPClassifier
warnings.filterwarnings("ignore", category=ConvergenceWarning)

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X / 16.0, y, test_size=0.3, random_state=0, stratify=y)
net = MLPClassifier(hidden_layer_sizes=(256, 128), max_iter=300, random_state=0).fit(Xtr, ytr)
(W1, W2, W3), (b1, b2, b3) = net.coefs_, net.intercepts_

U, S, Vt = np.linalg.svd(W2, full_matrices=False)       # W2 is 256 x 128
energy = np.cumsum(S**2) / np.sum(S**2)
for r in [4, 8, 16, 32, 128]:
    A, B = U[:, :r] * S[:r], Vt[:r]                     # W2 ~ A @ B: a 256->r and an r->128 layer
    h = np.maximum(np.maximum(Xte @ W1 + b1, 0) @ A @ B + b2, 0)
    acc = ((h @ W3 + b3).argmax(1) == yte).mean()
    print(f"rank {r:3d}: {A.size + B.size:5d} weights instead of {W2.size} "
          f"({energy[r - 1]:.0%} of the squared singular values), accuracy {acc:.3f}")
```

輸出（玩具結果）：

```text
rank   4:  1536 weights instead of 32768 (29% of the squared singular values), accuracy 0.620
rank   8:  3072 weights instead of 32768 (47% of the squared singular values), accuracy 0.978
rank  16:  6144 weights instead of 32768 (58% of the squared singular values), accuracy 0.981
rank  32: 12288 weights instead of 32768 (72% of the squared singular values), accuracy 0.981
rank 128: 49152 weights instead of 32768 (100% of the squared singular values), accuracy 0.980
```

秩 8 保留了準確率，所用的權重不到該層的十分之一，儘管它只保留了 47% 的奇異值平方。權重的 Frobenius 誤差並不是任務誤差的好指標：重要的是這一層對它實際看到的輸入做了什麼，這就是 Zhang 等人改為最小化響應誤差的原因 [35]。最後一行顯示了損益兩平規則：滿秩時分解後的形式權重比原本更多，因為 $128 > 256 \cdot 128 / 384 \approx 85$。把一層拆成兩層，還會為中間結果多出一次記憶體往返，所以在受限於記憶體的裝置上，延遲的節省會比 MAC 的節省小。

## 一開始就設計得小

**白話版。** 與其在訓練後縮小一個大網路，你可以從一開始就選擇小而且對硬體友善的架構，不論是手工設計（高效率區塊）還是靠搜尋。實務上兩種做法會結合：設計良好的小網路再做量化，有時也做剪枝或蒸餾。

主要的手工設計家族在別處已經涵蓋，這裡只列出：**深度可分離卷積**與反向殘差（MobileNet [36]、MobileNetV2 [37]；推導與成本見 [DLCV 02](/zh-tw/learn/deep-learning/image-classification/#mobilenet把卷積拆開) 與 [ML 03](/zh-tw/learn/ml/convolutional-networks/#高效率-cnn把空間濾波與通道混合分開)）、深度／寬度／解析度的**複合縮放**（EfficientNet [38]；[DLCV 02](/zh-tw/learn/deep-learning/image-classification/#efficientnet深度寬度解析度一起放大)），以及逐區塊的成本算術（[DLCV 01B](/zh-tw/learn/deep-learning/building-blocks/#瓶頸反向殘差與深度可分離卷積)）。本章開頭的屋頂線觀點，是看待這所有家族的正確鏡頭：一個區塊要在某個裝置上有效率，就要對那個裝置而言每位元組做足夠的運算，並且在那裡有快速的核。

### 重參數化：訓練時豐富，部署時簡單

**結構重參數化**（structural re-parameterization）訓練一個有數條平行線性分支的區塊，並在部署時把它們合併成一個卷積。RepVGG 訓練的區塊含有一個 $3 \times 3$ 卷積、一個 $1 \times 1$ 卷積與一條恆等分支，每個後面都接批次正規化，部署時則是由 $3 \times 3$ 卷積與 ReLU 組成的簡單堆疊 [39]。折疊的推導與數值檢查，見 [DLCV 03A 補充資料](/zh-tw/learn/deep-learning/real-time-detection/notes/把重參數化區塊折疊成一個卷積/)；針對增強網路的版本，見 [DLCV 09C 補充資料](/zh-tw/learn/deep-learning/low-light-enhancement/notes/結構重參數化逐步說明/)。

重參數化會與量化互相影響。YOLOv6 報告指出，由於大量使用重參數化區塊，先前的 PTQ 技術無法產生好的結果；在它的 1.0 版中，YOLOv6-S 在 8 位元 PTQ 下的 COCO val AP 從 42.4 掉到 35.0，使用 RepOptimizer 訓練後則回到 40.9，因為它縮窄了激活值的分布 [40]。合併後的核加進了範圍差異很大的分支，這正是逐張量量化處理得最差的情況。

### 神經架構搜尋

**白話版。** 神經架構搜尋（neural architecture search, NAS）讓演算法選擇層的類型、寬度與核大小，並以準確率來評分候選者，在考慮硬體的形式中，還以目標裝置上量測到的延遲來評分。

Elsken 等人用三項選擇描述每一種 NAS 方法：**搜尋空間**（允許哪些架構）、**搜尋策略**（如何提出候選者）與**效能估計策略**（如何在不完整訓練的情況下為候選者評分）[41]。三個想法對壓縮很重要：

- **權重共享讓搜尋負擔得起。** 最早的強化學習方法是把每個被提出的架構分別訓練 [42]；ENAS 讓所有候選者共享同一張大圖的權重 [43]，DARTS 把離散的選擇鬆弛成連續的選擇並用梯度下降最佳化 [44]，而 Once-for-All 訓練一個網路，從中取出不同深度、寬度、核大小與解析度的子網路給不同的裝置使用，不需要重新訓練 [45]。
- **針對量測到的延遲搜尋，而不是 FLOPs。** MnasNet 把在真實手機上量測到的延遲放進目標函數 [46]；ProxylessNAS 直接在目標任務與硬體上搜尋 [47]；FBNet 的可微分搜尋出於同樣的觀察：FLOPs 不一定反映延遲 [48]。
- **保留一個隨機基準。** Li 與 Talwalkar 發現，在他們使用的兩個基準上，帶提早停止的隨機搜尋至少和 ENAS 一樣好 [49]。

## 部署：從小模型到快模型

**白話版。** 壓縮後的模型，要等到編譯器或執行環境把它變成少數幾個大的融合運算，並有支援它的數字格式與稀疏樣式的核，才會變快。論文裡的速度宣稱，常假設了你的裝置沒有的支援。

### 運算子融合與批次正規化折疊

每個獨立的運算都會從記憶體讀入它的輸入，再把輸出寫回去。**運算子融合**（operator fusion）把連續的運算（卷積、偏置、批次正規化、激活函數）合併成一個核，讓中間結果留在快速的晶片內記憶體；從屋頂線的觀點來看，它藉由去掉記憶體往返來提高運算強度。最常見的融合是**批次正規化折疊**（batch-norm folding）：推論時，帶有學習到的尺度 $\gamma_c$、平移 $\beta_c$、累積平均 $\mu_c$ 與變異數 $\sigma_c^2$ 的批次正規化 [50]，對每個輸出通道 $c$ 是一個仿射映射，所以可以被吸收進前一個卷積，

$$
W'_c = \frac{\gamma_c}{\sqrt{\sigma_c^2 + \epsilon}}\,W_c,
\qquad
b'_c = \frac{\gamma_c}{\sqrt{\sigma_c^2 + \epsilon}}\,(b_c - \mu_c) + \beta_c,
$$

其中 $W_c$ 與 $b_c$ 是輸出通道 $c$ 的核與偏置，$\epsilon$ 是一個很小的常數。經過測試的 NumPy 版本在 [DLCV 03A 補充資料](/zh-tw/learn/deep-learning/real-time-detection/notes/把重參數化區塊折疊成一個卷積/)。對壓縮而言，請注意因子 $\gamma_c / \sqrt{\sigma_c^2 + \epsilon}$：它在不同通道之間不一樣，所以折疊可能會把各通道的權重範圍拉開，這是 MobileNetV2 難以逐張量量化的原因之一 [17]。在裝置上，批次正規化是在量化之前折疊的，所以整數核看到的是折疊後的權重，而 QAT 必須正確地模擬折疊 [15]。

### 整數核與執行環境支援

只有當執行環境對計算圖中的每個運算都有整數（或低精度）核時，量化才會加速推論。[ML 11](/zh-tw/learn/ml/evaluation-deployment/#程式碼純權重-int8延遲與匯出) 展示了一個純權重 int8 的模型，它小了四倍卻*更慢*，因為每次呼叫都要把權重轉回浮點。在真實部署中，要檢查：目標是否支援逐通道的權重尺度（不是所有硬體都支援 [15]）；哪些運算子退回浮點（每次退回都會多一次反量化與量化）；以及執行環境是否讓計算圖在各層之間維持整數。匯出與執行環境工具本身（ONNX、ONNX Runtime、TensorRT、`torch.export`）在 [ML 11](/zh-tw/learn/ml/evaluation-deployment/#匯出與推論執行環境) 有說明。

### 為什麼論文的加速在裝置上會縮水

- **FLOPs 不是瓶頸。** 一個移除了受限於記憶體的層 90% MAC 的方法，幾乎不會改變它們的時間（圖 1）。
- **稀疏需要核。** 非結構化稀疏，只有在那個裝置上有針對該樣式的稀疏核時才會加速 [5]、[8]；2:4 稀疏在部分 GPU 上有專用硬體 [6]；結構化剪枝不需要任何特別的東西。
- **批次大小。** 大批次的吞吐量不是批次 1 的延遲（上面的線性層例子）。
- **管線的其餘部分。** 前處理、NMS 這類後處理（[DLCV 03A](/zh-tw/learn/deep-learning/real-time-detection/#匯出低精度與重參數化)）、縮放與資料傳輸，不會因為網路變小而變小。
- **不支援的運算子。** 單一個沒有低精度核的運算子，就可能迫使加入的轉換比省下的還貴。

## 壓縮視覺模型：哪些地方敏感

**白話版。** 視覺模型的不同部分，對壓縮的反應差異很大。每個通道權重很少的層、必須在數值上精確的輸出（框座標、像素值），以及範圍隨影像而變的激活值，是常見的弱點。

### 分類骨幹

由深度可分離層建成的網路，是最難量化的常見骨幹。在 Nagel 等人的實驗中，使用 4 位元權重與 8 位元激活值時，逐張量 PTQ 讓 MobileNetV2 與 EfficientNet-lite 的 ImageNet top-1 分別損失約 2.5 與 4.2 個點，他們推測原因是深度可分離卷積；逐通道尺度為 EfficientNet-lite 找回了 2.8 個點 [15]。各通道權重範圍差異很大的層，是最先該考慮逐通道尺度或較高精度的候選，而逐層敏感度測試（一次只量化一層並測量下降，如練習 5）可以很快找出其他的層。

### 偵測器

偵測器預測連續的框座標與分數，兩者都會受粗糙格點之害。在白皮書中，EfficientDet-D1 在浮點下達到 40.08 COCO mAP，8 位元 PTQ 下是 38.29，但 4 位元逐張量權重只有 0.31（逐通道是 35.08）；QAT 讓 4 位元權重的結果提高到 35.34 與 36.75 [15]。YOLOv6 這類重參數化的偵測器需要對量化友善的訓練（見上文）[40]。因為嚴格 IoU 下的準確率是粗糙的框座標最先傷到的，所以量化之後要檢查高 IoU 閾值的 AP，而不只是 IoU 0.5 的 AP（[DLCV 03A](/zh-tw/learn/deep-learning/real-time-detection/#匯出低精度與重參數化)）。

蒸餾對偵測器也需要小心。Wang 等人發現，把一般的蒸餾套用到偵測器只有很小的增益，因此改讓學生在物件附近的位置模仿教師的特徵（位置由錨框估計）；這在他們的實驗中改善了 KITTI、Pascal VOC 與 COCO 上的學生 [51]。

### 密集預測與影像復原

對超解析度、去雜訊與增強而言，輸出是一張影像，每個量化誤差都可能變得看得見。有兩個性質讓這些網路比分類器更難。第一，許多影像復原網路拿掉了批次正規化；Li 等人發現這會讓激活值的動態範圍大得多，破壞了假設激活值已正規化的量化方案，並提出了為每層學習最大值尺度的做法（PAMS）[52]。第二，Hong 等人觀察到，超解析度網路中每個通道的激活值分布都不同，而且還會隨輸入影像改變，並提出逐通道、感知分布的量化（DAQ）[53]。所以要用與部署內容相似的影像做校準（低光源模型就用暗景），用 [DLCV 09](/zh-tw/learn/deep-learning/image-restoration/#評估指標) 的指標在完整解析度下評估，並檢查平滑的漸層，色帶最先出現在那裡。NTIRE 高效率超解析度挑戰賽在固定的 PSNR 閾值下，把執行時間、FLOPs 與參數量分成不同賽道排名 [54]（[DLCV 09A](/zh-tw/learn/deep-learning/super-resolution/#效率)）；[DLCV 09C](/zh-tw/learn/deep-learning/low-light-enhancement/) 涵蓋高效率的增強網路。

### 視覺 Transformer 與擴散模型

在視覺 Transformer 中，softmax 與 GELU 之後的激活值遠非高斯分布，PTQ4ViT 對每個這樣的張量使用兩個範圍來處理 [55]；Liu 等人加入一個排序損失，讓量化後的注意力保留注意力分數的順序 [56]。擴散模型多了時間維度：同一個去雜訊網路要在許多雜訊等級下執行，它的激活值分布會隨時間步改變。Q-Diffusion 把這點，連同捷徑層中的雙峰激活值，視為關鍵困難，並使用感知時間步的校準 [57]；PTQ4DM 研究的是同一個多時間步校準的問題 [58]。大型分割基礎模型則靠蒸餾來壓縮：MobileSAM 蒸餾 Segment Anything Model [59] 的大型影像編碼器成一個小的（「解耦蒸餾」）[60]，EfficientSAM 則預訓練小型編碼器去重建 SAM 的特徵 [61]。

## 現代觀點

### 綜述怎麼說

- **一般壓縮。** Cheng 等人把這個領域分成四類：參數剪枝與量化、低秩分解、轉移式／緊湊卷積濾波器，以及知識蒸餾，並討論每一類的優缺點 [62]。Menghani 把高效深度學習整理成五個領域：壓縮技術、學習技術（如蒸餾）、自動化（超參數最佳化與架構搜尋）、高效架構，以及基礎設施（軟體與硬體），並附上實務者指南 [63]。
- **量化。** Gholami 等人從基礎（均勻與非均勻量化器、範圍校準、粒度、微調）到進階主題（純整數推論、混合精度、考慮硬體與蒸餾輔助的量化、極低位元量化）綜述量化 [64]；Nagel 等人的白皮書是實用的配套，有經過測試的 PTQ 與 QAT 流程以及除錯工作流程 [15]。
- **剪枝與稀疏。** Hoefler 等人整理了 300 多篇關於推論與訓練稀疏的論文，包括如何在硬體上得到真正的加速 [8]。Cheng、Zhang 與 Shi 依通用或特定加速、何時剪枝、如何剪枝，以及與其他壓縮技術的融合來整理剪枝，並涵蓋大型語言與多模態模型的剪枝 [65]。Blalock 等人仍是剪枝結果該如何回報這件事的警示性參考 [4]。
- **蒸餾。** Gou 等人依知識類型、訓練方案、教師—學生架構與演算法對蒸餾分類 [29]；Wang 與 Yoon 則聚焦於視覺，以及蒸餾為什麼有效 [66]。
- **架構搜尋。** Elsken 等人提供了上面使用的三維度分類法 [41]；White 等人在超過 1,000 篇 NAS 論文之後寫作，給出搜尋空間、演算法與加速技巧的分類法，並附上基準與最佳實務 [67]。

*選讀：[A White Paper on Neural Network Quantization（Nagel 等人，2021）](#a-white-paper-on-neural-network-quantizationnagel-等人2021)（見「論文導讀」頁）。它的流程如何建構，以及如何閱讀它的 PTQ 與 QAT 表格。*

### 2023–2026 年的最新進展

- **超大型模型的低位元權重。** 以補償誤差的捨入（GPTQ [68]）或感知激活值並保護重要通道（AWQ [69]）的方式，把權重量化到 3–4 位元，已成為大型 Transformer 的標準做法；[ML 11](/zh-tw/learn/ml/evaluation-deployment/#量化) 介紹了這兩者。SmoothQuant 把離群值從激活值遷移到權重，使語言模型的 8 位元權重與激活值變得可行 [19]。
- **4 位元的生成式視覺模型。** 繼 Q-Diffusion [57] 之後，SVDQuant 把大型擴散模型的權重與激活值都量化到 4 位元：它把激活值的離群值移進權重，再用一個小的高精度低秩分支吸收權重的離群值，並把該分支融合進低位元核，以避免額外的記憶體流量；它結合了本章的兩項技術：低秩分解與量化 [70]。
- **8 位元浮點格式**（E4M3、E5M2），在訓練與推論上作為 int8 的替代方案 [24]。
- **蒸餾後的基礎模型。** 大型視覺基礎模型的小型學生，例如分割用的 MobileSAM 與 EfficientSAM [60]、[61]，以及 [DLCV 02](/zh-tw/learn/deep-learning/image-classification/#dino-與-dinov2自我蒸餾) 討論的蒸餾版 DINOv2 骨幹。
- **適用於任何計算圖的結構化剪枝。** DepGraph 式的相依分析，讓通道剪枝能用同一個方法套用到 CNN、Transformer 與其他架構 [9]。
- **由挑戰賽推動的高效影像復原**，其中執行時間、FLOPs 與參數量是分開計分的 [54]。

### 尚未解決的問題

- **預測裝置速度。** FLOPs 與參數量仍然主導論文，但只有目標裝置上量測到的延遲才重要，而它取決於核、記憶體與批次大小 [1]。
- **公平的比較。** 大小與訓練預算相同的基準、多個種子，以及完整的取捨曲線，仍然常常缺少 [4]、[3]。
- **低位元激活值。** 4 位元權重已越來越常規；4 位元激活值，尤其是在含有深度層、注意力與隨時間變化的分布的網路中，仍然要付出準確率的代價 [15]、[57]。
- **壓縮在準確率之外改變了什麼。** 平均準確率可能掩蓋稀有類別、偏移輸入或校準上的變化；壓縮之後去量測這些，仍不是標準做法。
- **影像復原與生成模型的壓縮**，其誤差在輸出中看得見，而沒有單一指標能完整反映。

## 重點整理

- 參數量、MAC、記憶體流量、尖峰記憶體、延遲與吞吐量是不同的數字；決定你的預算談的是哪一個，並在目標裝置上從頭到尾量測它。
- 屋頂線的觀點解釋了大多數意外：受限於記憶體的層（深度層、批次 1 的線性層）從更少的 MAC 得到的好處很小，從更少的位元組得到的好處很大。
- 剪枝需要微調。非結構化稀疏在移除什麼上有最大的自由度，但需要稀疏核；結構化剪枝產生較小的稠密層，在任何地方都跑得快；2:4 稀疏是有硬體支援的折衷。
- 均勻仿射量化儲存整數加尺度；權重的逐通道尺度很便宜，激活值的逐通道尺度則不然。離群值、折疊後的批次正規化與深度層是它容易出問題的地方。
- 先用 PTQ（對視覺模型而言 8 位元通常就夠）；需要 4 位元，或 PTQ 失敗時，再用搭配直通估計器的 QAT。
- 當教師的輸出帶有標籤之外的資訊時，蒸餾才有幫助：使用溫度、讓教師與學生看到相同的視角、訓練得久一點，並且不要假設更大的教師就是更好的。
- 低秩分解與高效設計針對的是架構；它們的節省，只有在得到的層能在裝置上有效率地執行時，才會變成速度。
- 把每個壓縮後的模型，和一個大小相同、同樣仔細訓練的稠密模型比較，並在匯出之後、在你出貨的執行環境上評估。

### N:M 半結構化稀疏

這則說明稀疏 GPU 硬體使用的 2:4 樣式，以及它與非結構化剪枝相比要付出什麼代價。

在 **N:M 稀疏**中，每連續 $M$ 個權重（沿著矩陣乘法的輸入維度）最多包含 $N$ 個非零值；2:4 是 NVIDIA 稀疏 Tensor Core 所支援的情況，作者報告這種樣式讓稠密單元的數學吞吐量加倍 [6]。每組只儲存兩個非零值，另外每個儲存值加 2 位元的中繼資料，說明它在組內的位置；對 16 位元的值，一組四個用 36 位元儲存而不是 64 位元，少約 44% [6]。他們的流程是：先訓練稠密網路，把每組中量值最小的兩個權重移除而剪成 2:4，再用相同的最佳化器與排程重新訓練，同時保持樣式固定 [6]。因為這個限制是局部的，剪枝可能會損失一些相對大的權重；作者指出，剪枝前先置換輸入通道，可以保留更多權重量值，不過在他們測試的大多數網路中並不需要這樣做 [6]。

下面的程式碼在一個隨機矩陣上量測這個代價：只要四個一組中有三個大的，2:4 就必須丟掉其中一個大權重，而在同樣 50% 下的非結構化剪枝會把它留下。

```python
import numpy as np

rng = np.random.default_rng(0)
W = rng.normal(size=(256, 512))

def prune_2_4(W):
    """Keep the two largest |w| in every group of four consecutive weights along a row."""
    groups = W.reshape(W.shape[0], -1, 4)
    order = np.argsort(np.abs(groups), axis=-1)                # positions sorted by magnitude
    mask = np.ones_like(groups, dtype=bool)
    np.put_along_axis(mask, order[..., :2], False, axis=-1)     # drop the two smallest
    return (groups * mask).reshape(W.shape)

W_24 = prune_2_4(W)
W_un = W * (np.abs(W) > np.median(np.abs(W)))                    # unstructured, also 50%
kept = lambda V: (V**2).sum() / (W**2).sum()
print("zeros: 2:4", (W_24 == 0).mean(), "| unstructured", (W_un == 0).mean())
print(f"squared magnitude kept: 2:4 {kept(W_24):.3f} | unstructured {kept(W_un):.3f}")
print("every group of four has exactly two nonzeros:",
      bool(((W_24.reshape(256, -1, 4) != 0).sum(-1) == 2).all()))
```

輸出：

```text
zeros: 2:4 0.5 | unstructured 0.5
squared magnitude kept: 2:4 0.867 | unstructured 0.928
every group of four has exactly two nonzeros: True
```

對隨機高斯矩陣，2:4 樣式保留了 86.7% 的權重平方量值，非結構化剪枝在相同稀疏度下則是 92.8%；重新訓練才是彌補準確率差距的關鍵。邊界情況：這個樣式是沿著歸約維度套用的，所以對卷積而言，各組是依核的排列方式，沿著輸入通道乘以核位置展開；而加速只出現在一層中矩陣乘法的部分，且要在支援它的硬體與函式庫上。

### 剪枝耦合的通道

這則列出決定哪些通道必須一起剪的相依規則，這是結構化剪枝中錯誤的主要來源。

當某一層的輸出通道 $j$ 被移除時，每個使用或產生通道 $j$ 的張量都必須一致地改變。常見視覺區塊的規則如下：

- **連續的卷積。** 移除卷積 $\ell$ 的輸出通道 $j$，會移除它的核與偏置的第 $j$ 列、它後面任何批次正規化的對應項（$\gamma_j$、$\beta_j$、$\mu_j$、$\sigma_j^2$），以及卷積 $\ell + 1$ 的輸入通道 $j$。剪枝程式碼對 MLP 做的就是這件事。
- **殘差相加。** 在 $y = x + F(x)$ 中，$x$ 的通道 $j$ 與 $F(x)$ 的通道 $j$ 會被相加，所以它們構成一個群組：通道 $j$ 只能同時從區塊輸入、$F$ 的最後一層、區塊輸出，以及每個共用同一條殘差流的後續區塊一次移除。這個群組的重要性必須共同判斷，例如把所有成員的範數加總。$F$ 的內部通道（瓶頸的中間）則是自由的。
- **深度卷積。** 輸入通道 $j$ 與輸出通道 $j$ 是同一個濾波器，所以移除一個就會移除另一個，這會耦合前後的 $1 \times 1$ 層。
- **串接。** 在 $\operatorname{concat}(a, b)$ 之後，$b$ 的通道索引會偏移 $a$ 的寬度；移除 $a$ 的一個通道，會讓下一層輸入中 $b$ 的索引位移。
- **注意力頭。** 移除一個注意力頭，會移除它的查詢、鍵與值投影，以及輸出投影中對應的輸入片段。

Fang 等人的 DepGraph 從計算圖自動建立這些群組，並顯示在群組正確之後，即使是簡單的、以範數為基礎的準則也很有效，涵蓋 ResNe(X)t、DenseNet、MobileNet 與視覺 Transformer 等架構 [9]。任何結構化剪枝之後，一個實用的檢查是：匯出剪枝後的模型，跑一個批次，並與遮罩版（尚未切除）的模型比較；如程式碼那樣輸出完全相同，就證明切除的動作遵守了每一個相依關係。

### 漸進式剪枝排程

這則完整給出 Zhu 與 Gupta 的稀疏度排程，並說明它的參數如何塑造一次剪枝過程。

訓練步 $t$ 的稀疏度是 [12]

$$
s_t = s_f + (s_i - s_f)\left(1 - \frac{t - t_0}{n\,\Delta t}\right)^{3},
\qquad t \in \{t_0,\; t_0 + \Delta t,\; \dots,\; t_0 + n\Delta t\},
$$

其中 $s_i$ 是初始稀疏度（通常為 0），$s_f$ 是最終稀疏度，$t_0$ 是開始剪枝的訓練步，$\Delta t$ 是兩次剪枝更新之間的訓練步數，$n$ 是剪枝更新的次數。每次更新時，把每一層的權重依量值排序，並遮蔽最小的那些，直到該層達到稀疏度 $s_t$；被遮蔽的權重不會接收梯度更新，一旦達到 $s_f$，遮罩就不再改變 [12]。

**走過的範例。** 取 $s_i = 0$、$s_f = 0.9$、$t_0 = 2{,}000$、$\Delta t = 1{,}000$ 與 $n = 10$，剪枝從第 2,000 步進行到第 12,000 步。一次更新之後（$t = 3{,}000$），稀疏度是 $0.9\,(1 - 0.9^3) \approx 0.244$；五次更新之後（$t = 7{,}000$）是 $0.9\,(1 - 0.5^3) = 0.7875$，已經是目標的 87.5%；後五次更新只再增加剩下的 0.11。三次方的形狀在網路仍有大量冗餘時移除很多權重，並隨著剩下的權重變少、變重要而放慢。

**它留給你決定的選擇。** 作者報告，把 $\Delta t$ 在 100 到 1,000 個訓練步之間變動，對最終品質的影響可以忽略，但在學習率已經很小的時候剪枝，會讓訓練很難恢復；他們把剪枝排在學習率仍然相當高的階段，所以剪枝排程必須與學習率排程一起選擇 [12]。在 $t_0 + n\Delta t$ 之後也必須再訓練一段時間，讓最後一刀能被修復。

### 用定點乘數重新量化

這則說明純整數網路如何在不使用任何浮點運算的情況下，把結果從一層傳到下一層。

在整數乘積之和之後，一層必須以 8 位元整數產生它的輸出，供下一層使用，而下一層有自己的尺度 $s_y$ 與零點 $z_y$。Jacob 等人把兩個量化矩陣的實數乘積 $r_3 = r_1 r_2$（其中 $r_\alpha = s_\alpha (q_\alpha - z_\alpha)$，$\alpha = 1, 2, 3$）寫成 [16]

$$
q_3^{(i,k)} = z_3 + M \sum_{j=1}^{N} \bigl(q_1^{(i,j)} - z_1\bigr)\bigl(q_2^{(j,k)} - z_2\bigr),
\qquad
M = \frac{s_1 s_2}{s_3},
$$

其中 $q_\alpha^{(i,j)}$ 是量化矩陣 $\alpha$ 的第 $(i,j)$ 項，$N$ 是內維度，$M$ 是唯一不是整數的量。因為 $M$ 只取決於各尺度，所以可以離線算好。他們根據經驗發現 $M$ 總是落在 $(0, 1)$，並把它寫成 [16]

$$
M = 2^{-n} M_0, \qquad M_0 \in [0.5, 1),
$$

其中 $n$ 是非負整數。$M_0$ 以最接近 $2^{31} M_0$ 的 32 位元整數儲存，它至少是 $2^{30}$，因此保有至少 30 位元的相對精度；乘以 $M_0$ 變成整數乘法，乘以 $2^{-n}$ 則變成一次位元位移，並具有正確的四捨五入到最近的行為 [16]。

一個走過的範例：取 $s_1 = 0.02$、$s_2 = 0.05$ 與 $s_3 = 0.4$，$M = 0.0025$。把它帶進 $[0.5, 1)$ 的二的冪次是 $2^{8} = 256$：$0.0025 \cdot 256 = 0.64$，所以 $n = 8$、$M_0 = 0.64$，儲存為 $\operatorname{round}(0.64 \cdot 2^{31}) = 1{,}374{,}389{,}535$。兩個陷阱：位元位移必須做四捨五入，而不是截去，否則每一層都會出現系統性的負偏差；而且結果在加上 $z_3$ 之後必須夾進 8 位元範圍（融合的 ReLU 常常就是用這個夾制來實作）。逐通道的權重尺度只是讓每個輸出通道各有一對 $(M_0, n)$。

### 選擇截斷範圍：min-max、百分位數與 MSE

這則比較三種選擇量化範圍的方式，並說明最佳的選擇取決於位元寬度。

給定範圍 $[x_{\min}, x_{\max}]$ 與 $b$ 位元，步長為 $s = (x_{\max} - x_{\min})/(2^b - 1)$。範圍內的值有最多 $s/2$ 的捨入誤差；範圍外的值被截斷到兩端。三種常見的規則 [15]：

- **Min-max**：$x_{\min} = \min x$，$x_{\max} = \max x$。沒有截斷誤差；步長由極端值決定。
- **百分位數**：兩端是校準值的低百分位數與高百分位數。固定比例的值會被截斷。
- **MSE**：選擇使校準資料上的 $\frac{1}{n}\sum_i (x_i - \hat{x}_i)^2$ 最小的兩端，通常用格點搜尋。對分類器的最後一層，Nagel 等人指出，logits 上的交叉熵準則可能比 MSE 更好，因為只有少數最大 logits 的順序重要 [15]。

```python
import numpy as np

rng = np.random.default_rng(0)
x = rng.laplace(0, 1, 20_000)             # heavy-tailed, like many activations
x[:4] = 40.0                               # four rare outliers

def quantize(x, lo, hi, bits):
    s = (hi - lo) / (2**bits - 1)
    z = np.round(-lo / s)
    return s * (np.clip(np.round(x / s) + z, 0, 2**bits - 1) - z)

def mse(lo, hi, bits):
    return np.mean((quantize(x, lo, hi, bits) - x) ** 2)

shrink = np.linspace(0.05, 1.0, 39)       # candidate ends: a fraction of the min and of the max
for bits in (8, 4):
    p_lo, p_hi = np.percentile(x, [0.05, 99.95])
    errors = {(a, b): mse(a * x.min(), b * x.max(), bits) for a in shrink for b in shrink}
    a, b = min(errors, key=errors.get)
    print(f"{bits}-bit MSE: min-max {mse(x.min(), x.max(), bits):.5f} | "
          f"percentile {mse(p_lo, p_hi, bits):.5f} | "
          f"MSE search {errors[a, b]:.5f} on [{a * x.min():.1f}, {b * x.max():.1f}]")
```

輸出：

```text
8-bit MSE: min-max 0.00299 | percentile 0.21929 | MSE search 0.00295 on [-8.3, 40.0]
4-bit MSE: min-max 0.66333 | percentile 0.29765 | MSE search 0.26366 on [-4.4, 12.0]
```

在 8 位元時，格點已細到可以涵蓋離群值：min-max 基本上就是最佳的，而把四個離群值從 40 截斷到約 7 的百分位數規則，MSE 差了 70 倍。在 4 位元時，格點粗到涵蓋離群值會毀掉其他一切：min-max 變成最差的規則，而 MSE 搜尋把上端截斷在 12。兩個邊界情況：張量上的 MSE 只是任務損失的代理，所以非常罕見但重要的值（例如影像中的明亮高光）可能值得比 MSE 給的更高的權重；而且在與部署資料不匹配的校準集上估計的範圍（用白天的影像校準夜間相機），會截斷最重要的值。

### 超越四捨五入：AdaRound、BRECQ 與 LSQ

這則介紹三種改進「選一個範圍，再捨入到最近格點」這個基本配方的方法。

**AdaRound** 質疑捨入這個步驟本身。把每個權重捨入到最近的格點，會最小化每個權重各自的誤差，但不會最小化該層輸出的誤差，因為不同權重的誤差會透過輸入互相影響。Nagel 等人用泰勒展開近似任務損失，這把每個權重向上或向下的決定變成一個二元最佳化問題；他們把它簡化成該層輸出上的逐層損失，並在少量未標註資料上求解一個軟鬆弛。他們報告 ResNet-18 與 ResNet-50 的 4 位元權重，在不微調的情況下準確率與浮點相差不到 1% [20]。每個權重仍然移到它相鄰兩個格點之一，所以儲存格式不變。

**BRECQ** 重建的是區塊而不是單一層：它逐區塊量化網路，並最佳化每個量化區塊，使其輸出與浮點區塊的輸出一致。作者從二階誤差的分析主張，區塊在跨層相依性與對小型校準集過度擬合之間取得平衡，並依據近似的敏感度加上混合精度 [71]。

**LSQ** 適用於量化感知訓練。它不是用統計量設定每個量化器的尺度 $s$，而是讓 $s$ 成為可訓練的參數，並透過量化器估計它的梯度，且加以縮放，使步長相對於權重以合適的速度學習。作者報告了權重與激活值為 2、3 或 4 位元的 ImageNet 模型，其中 3 位元的模型達到全精度基準 [72]。所有可學習量化器參數共有的陷阱：Nagel 等人指出，使用 SGD 類的最佳化器時，它們的學習率必須相對於其他參數降低，而 Adam 這類自適應最佳化器可以避免這點 [15]。

## 論文導讀

這些導讀是選讀的：每篇帶你讀一篇本章依據的論文——它要解決的問題、核心想法、它呈現了什麼，以及閱讀時要檢查什麼。

### The Lottery Ticket Hypothesis（Frankle 與 Carbin，ICLR 2019）

#### 挑戰

剪枝可以移除訓練好的網路的大部分權重，但據報告，得到的稀疏架構從頭訓練的效果很差。如果最後小網路就夠了，為什麼一開始需要大網路？[13]

<Figure src={paperLotterySource} alt="沿保留權重比例比較停止時間與準確率；保留原初始化與重新隨機初始化的子網路具有不同曲線。" caption="原論文圖 1 — 沿保留權重比例比較停止時間與準確率；保留原初始化與重新隨機初始化的子網路具有不同曲線。" />

*圖片來源: [13], arXiv:1803.03635v5, PDF 第 2 頁. [原始 PDF](https://arxiv.org/pdf/1803.03635).*

#### 方法

訓練一個網路，剪掉量值最小的權重，並把留下的權重重設為它們**在初始化時**的值，保留遮罩。單獨訓練這個稀疏網路，並與完整網路比較。反覆進行（反覆量值剪枝），每一輪移除固定比例的剩餘權重 [13]。

#### 結果

對 MNIST 上的全連接網路，以及 CIFAR-10 上的卷積網路（Conv-2/4/6，VGG 的變體），重設後的子網路（「中獎彩券」）在只有 10–20% 或更少的權重時，就達到原本的測試準確率，在高於該大小時學得比原本的網路更快，而被隨機重新初始化後就失去這個能力。反覆剪枝找到的彩券比一次性剪枝更小。對於更深的 ResNet-18 與 VGG-19，這個方法需要學習率暖機，才能在較高的學習率下找到彩券 [13]。

#### 判讀證據

主要的圖把兩個量對剩餘權重的百分比畫出來：驗證損失最小的迭代（作者以提早停止準則得到的學習速度代理指標），以及該迭代的測試準確率。每條曲線都是多次試驗的平均，而承載論證的比較是中獎彩券對上同一個遮罩加隨機重新初始化，而不是彩券對上稠密網路。請注意設定表中的架構與逐層剪枝率：卷積層與全連接層的剪枝率不同 [13]。

#### 限制與問題

所有實驗都在小型資料集上；找一張彩券要花好幾次完整訓練，所以它不是更便宜的壓縮方法；Frankle 等人的後續研究發現，在 ImageNet 的規模上，權重必須倒回到訓練早期的某個迭代，而不是初始化 [14]；而 Liu 等人報告，在調過學習率後，中獎彩券的初始化在他們的結構化剪枝實驗中並未勝過隨機初始化 [3]。

#### 結論

它把剪枝重新定義為一個關於可訓練性的問題：什麼讓稀疏網路可以訓練，以及重要的結構在訓練的哪個時間點決定。

### A White Paper on Neural Network Quantization（Nagel 等人，2021）

#### 挑戰

量化對定點硬體上的高效推論是必要的，但實務者面對許多互相影響的選擇（對稱或非對稱、逐張量或逐通道、範圍設定、PTQ 或 QAT），而已發表的方法很難組合 [15]。

<Figure src={paperQuantizationSource} alt="比較有號、無號與非對稱量化格點；尺度決定間距，零點決定實數零如何對應整數碼。" caption="原論文圖 3 — 比較有號、無號與非對稱量化格點；尺度決定間距，零點決定實數零如何對應整數碼。" />

*圖片來源: [15], arXiv:2106.08295v1, PDF 第 5 頁. [原始 PDF](https://arxiv.org/pdf/2106.08295).*

#### 方法

從定點加速器如何計算矩陣乘法出發（8 位元輸入、32 位元累加器、重新量化），推導出在這種硬體上哪些量化選擇是便宜的，再組合出兩條經過測試的流程：一條給 PTQ，一條給 QAT，另外還有一套給仍然失敗的模型使用的除錯工作流程 [15]。

#### 結果

在它的實驗中，PTQ 流程讓所有測試的視覺與語言模型的 8 位元權重與激活值，都在浮點結果的 0.7% 以內；4 位元權重的 PTQ，在 ResNet 與 InceptionV3 上相差約 1% 以內，但對有深度可分離層的模型損失較多，逐通道量化在這些模型上有幫助。QAT 流程讓大多數模型的 4 位元權重與 8 位元激活值接近浮點，而 4 位元激活值對 MobileNetV2、EfficientNet-lite、DeepLabV3，尤其是 EfficientDet-D1，仍然很困難 [15]。

#### 判讀證據

「W4A8」表示 4 位元權重與 8 位元激活值。範圍設定的消融實驗只量化權重（激活值保持浮點）或只量化激活值（權重保持浮點），所以它們一次只隔離一個誤差來源。PTQ 結果是 5 次執行的平均，QAT 結果是 3 次；DeepLabV3 以 Pascal VOC 上的 mIoU 評分，EfficientDet-D1 以 COCO 上的 mAP 評分，分類器以 ImageNet top-1 評分，所以不同列的差異不在同一個尺度上。請看逐張量與逐通道的欄位：它們顯示哪些模型受限於通道範圍的不平衡。

#### 限制與問題

這篇論文對所有層只考慮一種位元寬度（沒有混合精度）、只考慮均勻整數格式，並且主要是 2021 年以前的模型；Transformer 是透過 BERT 出現的，在 PTQ 下它有一些激活值必須保留在 16 位元 [15]。

#### 結論

它是本章實務規則最直接的來源：對稱的權重與非對稱的激活值、硬體允許時權重逐通道、MSE 範圍設定、深度網路的跨層均衡化、先 PTQ，PTQ 不夠時再 QAT。
