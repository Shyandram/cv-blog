## 先看全貌

影像分類器看一張圖，說出圖裡有什麼。影片模型還得理解*發生了什麼事*：誰做了什麼、先後順序、持續多久。多出來的輸入是時間軸，也帶來影像沒有的兩個問題。第一，時間很貴：30 影格／秒的 10 秒片段就有 300 張影像。第二，時間很容易被忽略：網路常常光看球場就能猜出「打網球」，根本不必看揮拍的動作。

<Callout type="tip" title="用最簡單的話說">
看一張門的照片。有人正在開門，還是關門？你分不出來。現在把前後連續拍的幾張照片像翻頁動畫一樣翻過去，答案就很明顯了。影片模型要學的是讀這本翻頁動畫，而不是只看其中一頁。麻煩的是它常常會作弊：如果每張「游泳」的照片都有泳池，它只要找藍色的水就行，永遠不必學游泳長什麼樣子。
</Callout>

影片理解很重要，因為大部分視覺資料都是影片：手機錄影、監視器與交通攝影機、運動轉播、機器人、汽車與醫療處置。辨識動作是許多應用的基礎：搜尋影片典藏、分析運動、監控安全、協助居家生活與控制機器人。這個領域也產生了擴散到深度學習其他角落的想法，例如把預訓練的 2D 網路膨脹成 3D、把空間與時間分解開來，以及極高遮罩比例的遮罩式預訓練。

## 影片理解的任務

**白話版。** 輸入是一疊影格。輸出取決於問題：對一小段片段給一個標籤；對長影片裡的每個動作給出開始、結束與類別；對每個人在每個時刻給一個框與標籤；或是回答一個用文字寫的問題。

**精確版。** 影片是一個張量 $V \in \mathbb{R}^{T \times H \times W \times 3}$，其中 $T$ 是影格數，$H \times W$ 是影格大小，3 是色彩通道。模型很少一次看到整個 $V$，它看到的是一個**片段**（clip）$x \in \mathbb{R}^{T' \times H' \times W' \times 3}$，由 $T' \ll T$ 張取樣出來的影格組成，並已縮放與裁切成 $H' \times W'$。圖 1 畫出四類任務。

<Figure src={figTasks} alt="四個面板。(a) 一個藍色方塊向右移動的五張影格，只有一個標籤「moving right」。(b) 一條長時間軸，上面有三段橘色區間，分別標為 jump、throw、jump，並註明開始與結束時間。(c) 三張關鍵影格，各有兩個灰色人形，每個人都在一個彩色框中，標為 walk、stand 或 sit。(d) 一個文字查詢指向三段依相似度排序的片段，一個問題框則指向一個簡短的文字答案。" caption="圖 1 — 影片的主要任務：(a) 每段已裁剪片段一個標籤；(b) 對未裁剪影片中的每個動作給出開始、結束與類別；(c) 對每張關鍵影格中的每個人給一個框與動作標籤；(d) 依文字查詢對影片排序，或回答關於影片的問題。" />

1. **片段（動作）分類。** 給定一段含有單一動作的*已裁剪*片段，預測它的類別 $y \in \{1, \dots, K\}$。以交叉熵訓練，並以 top-1 與 top-5 準確率評估，與 [DLCV 02](/zh-tw/learn/deep-learning/image-classification/#評估指標top-1top-5-與其他) 完全相同。有些資料集是**多標籤**的（同時有好幾個動作），以各類別的平均精確率均值（mean average precision, mAP）評估。
2. **時序動作定位**（temporal action localization，也稱時序動作偵測）。給定一支*未裁剪*的影片，輸出一組片段 $\{(s_i, e_i, c_i, p_i)\}$，分別是開始時間 $s_i$、結束時間 $e_i$、類別 $c_i$ 與信心分數 $p_i$。這就是沿著一個維度做的物件偵測，以數個**時序 IoU**（temporal IoU）門檻下的 mAP 來評估。
3. **時空動作偵測。** 找出*誰*在*哪裡*、*何時*做了*什麼*：在每張有標註的關鍵影格中給出人物框，每個框帶一個或多個動作標籤。以固定框 IoU 門檻下的影格層級 mAP 評估。
4. **影片–語言任務。** **文字到影片檢索**（text-to-video retrieval）依影片與一個句子的相似度為影片集合排序，以 Recall@$k$ 評估（正確影片落在前 $k$ 名的查詢所占的比例）。**影片問答**（video question answering）產生簡短的答案，常是從多個選項中挑選，以準確率計分。

相鄰的問題在別處討論。在各影格之間連結同一個物件是追蹤（[DLCV 07](/zh-tw/learn/deep-learning/object-tracking/)）。預測接下來發生什麼是動作預期或世界建模（[DLCV 13](/zh-tw/learn/deep-learning/world-models/)）。替每張影格的每個像素貼標籤則是影片分割。

## 為什麼影片很難

**白話版。** 有三件事讓影片比影像更難：標籤常常取決於*順序*與*運動*、資料集讓模型可以省掉這些功夫，而且輸入量非常大。

### 時間很重要，但資料不一定逼你使用它

有些動作只能靠運動分辨：「開門」與「關門」、「把東西推向左」與「把東西推向右」、「坐下」與「站起來」。這些動作的單張影格是模稜兩可的。許多其他動作靠單張影格就能認出，因為有**場景**與**物件**：游泳池、馬、吉他。從網路蒐集的資料集裡，有很多動作屬於第二類。

這件事很早就看得出來。Karpathy 等人用 100 萬支 YouTube 影片、487 個運動類別的資料集訓練 CNN，比較了幾種跨時間融合資訊的方式；他們最好的時空網路只比單影格模型略有進步 [6]。後來的研究直接量測這個問題。Li 等人定義了資料集的**表徵偏差**（representation bias），並顯示常見的動作資料集偏向靜態線索（物件、場景與人物）；他們也建立了 Diving48，一個包含 48 種細緻跳水類別的競技跳水資料集，以降低這種偏差 [7]。Sevilla-Lara 等人請人們辨認影格被打亂順序的影片中的動作，只保留變得無法辨認的類別；模型能不能使用時間，就在這個「時序」子集上顯現出來 [8]。Something-Something 則是為了捕捉動作的細部物理面向，而不是高層概念而建立的：它的 174 個類別是像「把東西從左推到右」這樣的描述樣板 [9]，VideoMAE 的作者稱之為以運動為中心 [10]。

網路用手邊最容易的線索解決訓練任務，這個一般現象就是 [DLCV 02](/zh-tw/learn/deep-learning/image-classification/#捷徑學習) 的**捷徑學習**（shortcut learning）。在影片裡，最容易的線索通常是場景。

### 一個單張影格毫無資訊的資料集

下面的程式碼用合成片段把這件事具體化。一個小方塊向左或向右移動，標籤就是方向。方塊在中間影格的位置，在兩種標籤下分布相同，所以**單看中間影格，完全得不到標籤的資訊**。接著我們加上「場景」：背景亮度在 90% 的訓練片段中與標籤一致。三個邏輯迴歸分類器分別看到 (1) 中間影格的像素、(2) 一個運動特徵，以及 (3) 兩者。

運動特徵是經典的亮度恆常性估計（見 [DLCV 11A](/zh-tw/learn/deep-learning/depth-optical-flow/#把光流當作學習問題)）。如果某個圖樣每影格位移 $u$ 個像素，則 $I_{t+1}(x) \approx I_t(x - u)$，所以時間差分為 $I_{t+1} - I_t \approx -u\, \partial_x I_t$。對整張影格以最小平方法擬合 $u$，得到

$$
\hat{u}_t = -\frac{\sum_{x,y} \big(I_{t+1}(x,y) - I_t(x,y)\big)\, \partial_x I_t(x,y)}{\sum_{x,y} \big(\partial_x I_t(x,y)\big)^2},
$$

其中 $I_t(x, y)$ 是第 $t$ 張影格在第 $x$ 欄、第 $y$ 列的亮度，$\partial_x I_t$ 是它的水平導數，$\hat{u}_t$ 是第 $t$ 與 $t+1$ 張影格之間估計的水平運動（正值表示向右）。它是一個時間導數濾波器和一個空間導數濾波器的乘積，這正是 3D 卷積能學到的那類圖樣。

```python
import numpy as np
from sklearn.linear_model import LogisticRegression

def make_clips(n, T=8, S=20, noise=0.5, scene_bias=0.5, seed=0):
    """A 3x3 square moves 1 px/frame left (y=0) or right (y=1) on a noisy background.
    scene_bias = P(background brightness agrees with the label); 0.5 = no bias."""
    rng = np.random.default_rng(seed)
    y = rng.integers(0, 2, n)
    X = noise * rng.standard_normal((n, T, S, S))
    for i in range(n):
        step = 1 if y[i] == 1 else -1
        c_mid = rng.integers(T // 2, S - 3 - T // 2 + 1)   # middle-frame position: same for both labels
        r = rng.integers(0, S - 3 + 1)
        agree = rng.random() < scene_bias
        X[i] += 0.3 * (y[i] if agree else 1 - y[i])       # the "scene": background brightness
        for t in range(T):
            c = c_mid + step * (t - T // 2)
            X[i, t, r:r + 3, c:c + 3] += 1.0
    return X, y

def frame_features(X):     # appearance only: the pixels of the middle frame
    return X[:, X.shape[1] // 2].reshape(len(X), -1)

def motion_features(X):    # temporal difference times horizontal gradient, per frame pair
    dt = X[:, 1:] - X[:, :-1]
    dx = np.gradient(X[:, :-1], axis=3)
    u = -(dt * dx).sum(axis=(2, 3)) / ((dx ** 2).sum(axis=(2, 3)) + 1e-6)
    return u                                            # one motion estimate per frame pair

data = {"train": make_clips(2000, scene_bias=0.9, seed=1),  # scene agrees with the label 90%
        "same": make_clips(1000, scene_bias=0.9, seed=2),   # test: same distribution
        "no cue": make_clips(1000, scene_bias=0.5, seed=3), # test: scene says nothing
        "shift": make_clips(1000, scene_bias=0.1, seed=4)}  # test: scene misleads 90%
for name, f in [("one frame", frame_features), ("motion", motion_features),
                ("frame+motion", lambda X: np.c_[frame_features(X), motion_features(X)])]:
    clf = LogisticRegression(C=0.1, max_iter=5000).fit(f(data["train"][0]), data["train"][1])
    acc = {k: clf.score(f(X), y) for k, (X, y) in data.items() if k != "train"}
    print(f"{name:13s}", "  ".join(f"{k} {v:.3f}" for k, v in acc.items()))
```

```text
one frame     same 0.867  no cue 0.495  shift 0.131
motion        same 0.945  no cue 0.929  shift 0.941
frame+motion  same 0.889  no cue 0.522  shift 0.163
```

（這個區塊與圖 2 的所有數字都來自這次玩具實驗。）在與訓練相同分布的測試資料上，單影格模型看起來不錯（0.867），因為場景有 90% 的機率能預測標籤。拿掉場景線索，它就掉到隨機猜測的水準（0.495）；讓場景產生誤導，它就跌到 0.131。運動模型在每種情況下都約在 0.93–0.94，因為它用的是真正決定標籤的線索。組合模型是個警訊：它*有*運動特徵，卻學成依賴數百個亮度像素，在分布偏移下失敗（0.163）。它對場景的依賴程度，取決於特徵尺度與正則化（練習 1），但從訓練分布抽出來的基準，永遠不會暴露這個問題。

### 運算量與記憶體

對逐影格的網路，一段 $T'$ 張影格的片段，成本大約是一張影像的 $T'$ 倍；對會混合影格的模型則更多。對一個卷積，設輸入通道 $C_{\text{in}}$、輸出通道 $C_{\text{out}}$、核大小 $k_t \times k_h \times k_w$（時間 × 高 × 寬），在 $T \times H \times W$ 的輸入上用步幅 1 與「same」補零，

$$
\text{params} = C_{\text{in}}\, C_{\text{out}}\, k_t k_h k_w, \qquad \text{MACs} = \text{params} \times T H W,
$$

其中 MACs 是乘加運算（multiply–accumulate）的次數（每次一個乘法加一個加法）。因此 $3 \times 3 \times 3$ 的核，參數量與運算量都是對同樣影格施加 $3 \times 3$ 核的 3 倍。對 Transformer 來說，問題在於 token 數 $N$：自注意力要比較 $N^2$ 對查詢–鍵，而 $N$ 與影格數成線性成長。下一節的程式碼會把這兩者量化出來。

## 如何讓影像網路學會時間

**白話版。** 基本做法有五種（圖 3）：在幾張影格上執行影像網路再把答案平均；再加一個只看運動（光流）的網路；讓每個濾波器都變成三維的；以不同影格率執行兩條路徑；或把片段切成時空小塊，交給 Transformer 做跨小塊的注意力。大多數現代模型會混合這些想法。

### 逐影格網路與後期融合

最簡單的影片模型，是把影像分類器 $f$ 套用在 $K$ 張影格 $x_{t_1}, \dots, x_{t_K}$ 上，再把類別分數平均：

$$
\hat{y} = \operatorname{softmax}\Big(\frac{1}{K} \sum_{k=1}^{K} f(x_{t_k})\Big),
$$

其中 $f(x) \in \mathbb{R}^{C}$ 是單張影格的類別分數向量（logits），$C$ 是類別數。這個模型對順序視而不見：打亂影格順序，答案不變，所以它分不出「打開」與「關上」。它在偏重場景的資料集上仍是很強的基準，而且成本低，可以從任何預訓練的影像骨幹開始（[DLCV 02](/zh-tw/learn/deep-learning/image-classification/#遷移學習與微調)）。在逐影格特徵上接 LSTM [11] 這類循環網路，可以加入順序；這種設計在 [ML 04](/zh-tw/learn/ml/recurrent-recursive-networks/#循環網路在電腦視覺中的應用) 討論。

### 雙流網路：外觀加光流

**白話版。** 直接把運動交給網路。一個網路看單張彩色影格（那裡有什麼）；第二個網路看一疊光流場（東西怎麼動）。它們的預測在最後合併。

Simonyan 與 Zisserman 的雙流 ConvNet [12] 有一條**空間流**，是對單張 RGB 影格的影像 CNN，以及一條**時間流**，是輸入為 $L$ 對連續影格之稠密光流的 CNN。每個光流場 $d_t$ 有水平分量 $d_t^x$ 與垂直分量 $d_t^y$，所以影格 $\tau$ 的堆疊輸入有 $2L$ 個通道：

$$
I_\tau(u, v, 2k-1) = d^{x}_{\tau+k-1}(u, v), \qquad I_\tau(u, v, 2k) = d^{y}_{\tau+k-1}(u, v), \qquad k = 1, \dots, L,
$$

其中 $(u, v)$ 是像素位置，$d^x_t(u, v)$ 與 $d^y_t(u, v)$ 是該像素從第 $t$ 張到第 $t+1$ 張影格的水平與垂直位移。兩條流分開訓練，在後期融合：對 softmax 分數取平均，或在堆疊的分數上用線性 SVM [12]。這篇論文顯示，即使訓練資料有限，作用在堆疊光流上的 ConvNet 表現也很好，而且兩條流是互補的 [12]。

它的弱點是成本：必須在訓練前先為每張影格計算（通常還要儲存）稠密光流，用的是傳統求解器或光流網路（用光流做扭曲見 [DLCV 09A.3](/zh-tw/learn/deep-learning/video-super-resolution/#光流)）。光流也不是針對辨識任務學出來的。Temporal Segment Networks [13] 與 I3D [14] 仍使用光流流；SlowFast（見下）後來直接從原始影格端到端學出運動，不用光流，其作者在實驗上發現它比雙流方法更有效 [15]。

### 3D 卷積：C3D 與 I3D 膨脹

**白話版。** 讓每個濾波器都變成一個小立方體，不只在空間上滑動，也在時間上滑動。這樣網路就能直接從像素學到運動偵測器，例如「一條向右移動的亮邊」。

核為 $w \in \mathbb{R}^{k_t \times k_h \times k_w}$ 的 3D 卷積，對一個輸入通道與一個輸出通道，計算

$$
y(t, i, j) = \sum_{a=0}^{k_t-1} \sum_{b=0}^{k_h-1} \sum_{c=0}^{k_w-1} w(a, b, c)\, x(t + a, i + b, j + c),
$$

其中 $x(t, i, j)$ 是第 $t$ 張影格、第 $i$ 列、第 $j$ 欄的輸入（實際上會對所有輸入通道求和，邊界也要補零）。**C3D** [16] 在一個大型影片資料集上訓練了由這種層組成的網路，發現所有層都用小的 $3 \times 3 \times 3$ 核的同質架構是最好的之一；用它的特徵加線性分類器，在數個基準上都很強。

從頭訓練 3D 網路所需的資料，遠比 2015 年有的多。Carreira 與 Zisserman 在 2017 年同時解決了這兩個問題 [14]。他們提出了 **Kinetics**，一個含有 400 個人類動作類別的資料集，每個類別至少 400 段 YouTube 片段，每段約 10 秒 [17]；以及 **Inflated 3D ConvNet（I3D）**：拿一個成功的 2D 影像架構，把每個 $N \times N$ 的濾波器與池化核*膨脹*成 $N \times N \times N$。為了從 ImageNet [18] 預訓練的權重開始，他們讓膨脹後的網路在「無聊影片」（同一張影像在時間上重複）上的反應，與 2D 網路在該影像上的反應相同：把每個 2D 濾波器沿時間重複 $N$ 次，再除以 $N$ [14]。設 $w_{2D}$ 為預訓練的濾波器，

$$
w_{3D}(a, b, c) = \frac{1}{N}\, w_{2D}(b, c), \qquad a = 0, \dots, N-1,
$$

所以對於在時間上為常數的輸入，$N$ 個時間分接點加起來，恰好等於 2D 的反應。下面的程式碼用數值驗證這一點。

```python
import numpy as np
from scipy.ndimage import correlate

rng = np.random.default_rng(0)
w2d = rng.standard_normal((3, 3))            # a "pretrained" 2D filter
N = 3                                        # temporal size of the inflated filter
w3d = np.repeat(w2d[None] / N, N, axis=0)    # (N, 3, 3): copy N times, divide by N

img = rng.standard_normal((32, 32))
boring = np.repeat(img[None], 8, axis=0)     # an 8-frame "video" of one still image

r2d = correlate(img, w2d, mode="nearest")
r3d = correlate(boring, w3d, mode="nearest")  # 3D filtering over (t, y, x)
print("max |3D response on any frame - 2D response| =", np.abs(r3d - r2d[None]).max())
```

```text
max |3D response on any frame - 2D response| = 1.7763568394002505e-15
```

差異在浮點數捨入的等級。接著，訓練會在濾波器學習運動的過程中，把它們從「在時間上為常數」推開。論文的最終模型是**雙流 I3D**：一個 I3D 吃 RGB、一個吃光流，預測取平均，因為作者仍然覺得光流流很有價值 [14]。在 Kinetics 上預訓練後，I3D 在小型的 UCF101 與 HMDB51 基準上大幅進步 [14]，這讓「在 Kinetics 上預訓練、再到目標資料上微調」成為影片的標準配方。同樣的膨脹想法也出現在影片生成器中（[DLCV 12A](/zh-tw/learn/deep-learning/video-generation/#膨脹預訓練的影像模型)），而 I3D 特徵是 Fréchet Video Distance [19] 背後的特徵網路（[DLCV 12A](/zh-tw/learn/deep-learning/video-generation/#fréchet-video-distance)）。

*選讀：[Quo Vadis：I3D 與 Kinetics 資料集](#quo-vadisi3d-與-kinetics-資料集carreira-與-zisserman2017)（見「論文導讀」頁）。論文如何比較五個架構家族，以及它的遷移實驗顯示了什麼。*

### 分解式 (2+1)D 卷積

**白話版。** 立方體形的濾波器可以拆成兩個比較便宜的步驟：先用一個平面濾波器在每張影格內部看，再用一個細長的濾波器在每個位置上跨影格看。只要中間寬度選對，拆開後參數量不變，卻多了一個非線性，也比較容易訓練。

Tran 等人 [20] 在殘差網路中比較了幾種時空卷積：只用 2D、全部用 3D、混合式（只在早期層用 3D，或只在後期層用 3D），以及分解式的 **(2+1)D** 區塊。(2+1)D 區塊把 $N_i$ 個大小為 $N_{i-1} \times t \times d \times d$ 的濾波器，換成 $M_i$ 個大小為 $N_{i-1} \times 1 \times d \times d$ 的空間濾波器、一個 ReLU，以及 $N_i$ 個大小為 $M_i \times t \times 1 \times 1$ 的時間濾波器。這裡 $N_{i-1}$ 與 $N_i$ 是第 $i$ 層的輸入與輸出通道數，$t$ 與 $d$ 是時間與空間的核大小，$M_i$ 是中間空間的寬度，選擇的方式是讓參數量與 3D 層一致 [20]：

$$
M_i = \left\lfloor \frac{t\, d^2\, N_{i-1}\, N_i}{d^2\, N_{i-1} + t\, N_i} \right\rfloor .
$$

論文提出兩個好處：多出來的 ReLU 讓非線性的數量在相同參數量下加倍，而分解讓最佳化變容易，表現為比同樣大小的 3D 網路有更低的*訓練*誤差 [20]。它是影像 CNN 中深度可分離技巧（[ML 03](/zh-tw/learn/ml/convolutional-networks/#高效率-cnn把空間濾波與通道混合分開)）在影片上的對應：把一個大運算沿著不同的軸拆成較便宜的運算。

程式碼計算一個 64 到 64 通道的層，在 16 張影格的片段、$56 \times 56$ 特徵圖上的參數量與乘加次數，並順便算出影片 Transformer 的 token 數作為比較。

```python
import math

def conv_cost(c_in, c_out, kt, kh, kw, T, H, W):
    """Parameters and multiply-adds of one convolution (stride 1, 'same' padding, no bias)."""
    params = c_in * c_out * kt * kh * kw
    return params, params * T * H * W

c, t, d = 64, 3, 3                           # channels in = out, temporal and spatial kernel size
T, H, W = 16, 56, 56                         # a 16-frame clip, 56x56 feature maps
M = math.floor(t * d * d * c * c / (d * d * c + t * c))   # R(2+1)D's matched middle width

layers = {
    "2D  (1x3x3), per frame": [conv_cost(c, c, 1, d, d, T, H, W)],
    "3D  (3x3x3)":            [conv_cost(c, c, t, d, d, T, H, W)],
    f"(2+1)D, M={M}":         [conv_cost(c, M, 1, d, d, T, H, W), conv_cost(M, c, t, 1, 1, T, H, W)],
}
for name, parts in layers.items():
    p = sum(x[0] for x in parts); f = sum(x[1] for x in parts)
    print(f"{name:24s} params {p:>8,d}   GMACs {f / 1e9:5.2f}")

# a video transformer's token count with 2x16x16 tubelets on a 16x224x224 clip
n_tok = (16 // 2) * (224 // 16) ** 2
print(f"tokens {n_tok}, joint attention pairs {n_tok**2:,}, "
      f"divided (time, then space) pairs {n_tok * 8 + n_tok * 196:,}")
```

```text
2D  (1x3x3), per frame   params   36,864   GMACs  1.85
3D  (3x3x3)              params  110,592   GMACs  5.55
(2+1)D, M=144            params  110,592   GMACs  5.55
tokens 1568, joint attention pairs 2,458,624, divided (time, then space) pairs 319,872
```

在輸入與輸出寬度相等時，$M = 144$ 使 (2+1)D 區塊的參數量與運算量恰好與 3D 層相同；它的好處在表達能力與最佳化，而不在成本。選擇較小的 $M$，就可以得到更便宜的拆法。圖 4 畫出這個分解。

### 低成本的時序建模：TSN 取樣與時序位移模組

**白話版。** 兩個技巧讓普通的 2D 網路也能便宜地處理長影片。TSN 看的是分散在整支影片的幾張影格，而不是某一刻附近的許多影格。TSM 讓相鄰影格在網路內部交換少數幾個特徵通道，幾乎不花成本就能跨時間混合資訊。

**Temporal Segment Networks（TSN）** [13] 把影片分成 $K$ 個等長的區段，從每段取一小段短片段（訓練時取隨機位置），用同一個網路替每個片段打分，再用**區段共識**（segmental consensus）合併分數，例如在 softmax 之前取平均。損失是對共識計算的，所以是整支影片在監督網路，而不只是一個短視窗 [13]。論文的預設是 $K = 3$ 個區段 [13]。這種**稀疏取樣**用固定且少量的影格涵蓋長距離結構（圖 5）。

```python
import numpy as np

def tsn_indices(n_frames, K, train, rng=None):
    """TSN-style sparse sampling: split the video into K equal segments, take one frame
    per segment (random position when training, the segment centre when testing)."""
    edges = np.linspace(0, n_frames, K + 1)
    if train:
        return np.floor(edges[:-1] + rng.random(K) * np.diff(edges)).astype(int)
    return np.floor((edges[:-1] + edges[1:]) / 2).astype(int)

def dense_clip(n_frames, length, stride, start):
    """A dense clip: `length` frames, `stride` apart, starting at `start`."""
    return start + stride * np.arange(length)

rng = np.random.default_rng(0)
n = 300                                          # a 10-second video at 30 fps
print("TSN train:", tsn_indices(n, 8, True, rng))
print("TSN test :", tsn_indices(n, 8, False))
print("dense 8x8:", dense_clip(n, 8, 8, start=100))   # 8 frames, every 8th frame
# multi-view testing: 10 clip start positions spread uniformly over the video
starts = np.linspace(0, n - 8 * 8, 10).astype(int)
print("10 clip starts:", starts)
```


**時序位移模組（Temporal Shift Module, TSM）** [21] 在 2D 網路中加入真正的時間交互作用，而且完全不增加參數，也不增加乘加運算。在每個殘差區塊內，特徵張量的一部分通道沿時間向前位移一張影格，另一部分向後位移一張影格，其餘留在原處；接下來的 2D 卷積就會混合來自三張不同影格的通道。位移太多通道，延遲（資料搬移）與準確率（每張影格剩下的空間資訊變少）都會變差，所以論文位移 1/4 的通道（每個方向 1/8），並把位移放在殘差分支上 [21]。對即時影片，單向版本只從過去位移到現在的影格 [21]。

*選讀：[時序位移是一種稀疏的時序卷積](#時序位移是一種稀疏的時序卷積)（見「補充資料」頁）。一段簡短的推導與一段測試過的程式，顯示位移加上 1×1 卷積，等於一個多數權重固定為零的時序卷積。*

### SlowFast：兩種影格率

**白話版。** 東西是什麼，變化得很慢；東西怎麼動，可能變化得很快。所以用兩條路徑：一條很重、只看少數影格來理解場景；一條很輕、看很多影格來捕捉運動。

**SlowFast 網路** [15] 有一條 **Slow 路徑**，以較大的時間步幅 $\tau$ 取樣 $T$ 張影格；以及一條 **Fast 路徑**，以步幅 $\tau / \alpha$ 取樣 $\alpha T$ 張影格，所以在時間上比 Slow 路徑密 $\alpha$ 倍。Fast 路徑只有 Slow 路徑通道數的 $\beta$ 倍。典型的值是 $\alpha = 8$ 與 $\beta = 1/8$ [15]。由於一層的成本大致與通道數的平方成正比，在論文的實例中，Fast 路徑只占總運算量的大約 20% [15]。**橫向連接**（lateral connection）在每個階段把 Fast 的特徵送進 Slow 路徑；為了讓形狀匹配，它們把 $\alpha T$ 張 Fast 影格轉換成 $T$ 張，例如用時間步幅的 3D 卷積，這是論文的預設做法 [15]。

有兩個設計細節帶有通用的教訓。Slow 路徑只在最後兩個階段使用大於 1 的時間核，因為作者發現，當影格步幅很大時，早期層的時間卷積反而*有害*：除非空間感受野也很大，否則快速移動的內容在相隔很久的時間步之間幾乎沒有相關性 [15]。而且 SlowFast **不使用光流**：它直接從原始影格端到端學習運動 [15]。它在 Kinetics、Charades 與 AVA 的分類與偵測上報告了很強的結果 [15]。

*選讀：[SlowFast 網路](#slowfast-網路feichtenhofer-等人2019)（見「論文導讀」頁）。怎麼讀它對橫向連接與通道比例 β 的消融實驗。*

還有兩個相關的想法補完了 CNN 家族。**Non-local 區塊** [22] 把每個位置的反應，算成對*所有*時空位置的加權和，也就是插在 3D CNN 中的一種注意力層，用來捕捉長距離相依。**X3D** [23] 從一個很小的 2D 影像網路出發，一次沿一個軸（空間、時間、寬度與深度）擴張它，來尋找低成本且準確的網路；一個令人意外的發現是，高時空解析度的網路可以非常窄 [23]。

### 影片 Transformer：TimeSformer、ViViT、MViT 與 Video Swin

**白話版。** 把片段切成小小的時空塊，每塊變成一個 token，讓 Transformer 決定哪些塊該看哪些塊。困難在於一段片段有幾千個 token，所以各種設計主要的差別，在於每個 token 可以注意*哪些* token。

Vision Transformer [24]（[ML 05](/zh-tw/learn/ml/vision-transformers/#vision-transformervit)）把影像變成小塊。影片 Transformer 則在時空中做同樣的事。用 **tubelet 嵌入**（tubelet embedding）[25]，把互不重疊、大小為 $t \times p \times p$ 像素的管狀區塊做線性投影（等價於步幅等於核大小的 3D 卷積），於是 $T \times H \times W$ 的片段變成

$$
N = \frac{T}{t} \cdot \frac{H}{p} \cdot \frac{W}{p}
$$

個 token，其中 $t$ 是 tubelet 的影格長度，$p$ 是小塊邊長的像素數。例如 VideoMAE 的 ViT-Base，吃 $16 \times 224 \times 224$ 的片段與 $2 \times 16 \times 16$ 的方塊，得到 $8 \times 196 = 1568$ 個 token [10]。**聯合**時空注意力要比較全部 $N^2$ 對，上面的程式碼算出每層約 246 萬對。有四種設計可以馴服它：

- **TimeSformer** [26] 比較了幾種自注意力方案，發現它試過的方案中以**分離式注意力**（divided attention）最好：在每個區塊中，一個 token 先注意其他影格中相同空間位置的 token（時間注意力），再注意自己這張影格中的 token（空間注意力）[26]。在上面的設定中，這大約是 32 萬對，而不是 246 萬對。它也能處理超過一分鐘的片段 [26]。聯合與分離式注意力的成本比，在 [DLCV 12A](/zh-tw/learn/deep-learning/video-generation/#分解式或完整時空注意力) 中推導，那裡也說明了為什麼影片*生成器*常偏好完整注意力。
- **ViViT** [25] 提出四種模型：聯合時空注意力；**分解式編碼器**（對每張影格用一個空間 Transformer，再對影格嵌入用一個時間 Transformer，是一種後期融合）；每個區塊內的分解式自注意力；以及分解式點積注意力，其中一半的注意力頭注意空間，一半注意時間。它也顯示了如何正則化這些模型，並用預訓練的影像模型初始化它們，使它們可以在相對小的資料集上訓練 [25]。
- **MViT** [27] 帶回 CNN 的多尺度階層：各階段從高時空解析度、少量通道開始，逐步增加通道並降低解析度，並使用**池化注意力**（pooling attention），也就是在注意力內部對查詢、鍵與值序列做池化 [27]。
- **Video Swin Transformer** [28] 主張**局部性**：注意力只在局部 3D 視窗內計算，視窗在相鄰層之間位移，讓資訊可以跨過視窗邊界。它延伸了影像的 Swin Transformer [29]（[DLCV 02](/zh-tw/learn/deep-learning/image-classification/#swin視窗位移與階層)），並從預訓練的影像權重開始，在速度與準確率的取捨上優於全域注意力 [28]。

注意力不是建模長片段的唯一方式。**VideoMamba** [30] 把 Mamba 狀態空間模型 [31]（其成本與 token 數成線性成長）調整到影片上；底層的選擇性掃描在 [ML 04](/zh-tw/learn/ml/recurrent-recursive-networks/#mamba選擇性狀態空間與掃描) 說明。

## 不用標籤學習影片表示

**白話版。** 標註影片又慢又貴，但沒有標籤的影片非常多。所以把片段的大部分遮起來，訓練網路把它補回來；要補得好，它就必須學會東西長什麼樣子、怎麼移動。

**VideoMAE** [10] 把遮罩式自編碼（MAE [32]，見 [ML 06](/zh-tw/learn/ml/representation-learning/#遮罩建模從填空中學習)）用到影片上。它遮住時空方塊，只用 ViT 編碼可見的部分，再用輕量解碼器重建被遮住部分的像素。有兩件事是影片特有的。第一，相鄰影格高度冗餘，所以遮罩比例可以極高：90% 到 95% 仍然很有效 [10]。第二，如果每張影格獨立抽遮罩，被遮住的小塊常常可以從相鄰影格的同一位置直接複製過來，這種**資訊洩漏**（information leakage）讓任務變得太簡單。所以 VideoMAE 使用**管狀遮罩**（tube masking）：每張影格都用同一個空間遮罩 [10]。下面的片段量測這種洩漏。

```python
import numpy as np

rng = np.random.default_rng(0)
T, P, ratio = 8, 196, 0.9               # 8 token frames of 14x14 patches, 90% masked

def leak(mask):
    """Fraction of masked tokens whose same-position token in a neighbouring frame is visible."""
    vis = ~mask
    nb = np.zeros_like(mask)
    nb[1:] |= vis[:-1]; nb[:-1] |= vis[1:]
    return (mask & nb).sum() / mask.sum()

random_mask = rng.random((T, P)) < ratio                  # independent per token
tube_mask = np.repeat((rng.random(P) < ratio)[None], T, 0) # same spatial mask in every frame
print(f"random masking: {random_mask.mean():.2f} masked, leak {leak(random_mask):.2f}")
print(f"tube masking  : {tube_mask.mean():.2f} masked, leak {leak(tube_mask):.2f}")
```

```text
random masking: 0.90 masked, leak 0.16
tube masking  : 0.89 masked, leak 0.00
```

使用獨立遮罩時，大約每六個被遮住的 token 中，就有一個在相鄰影格有可見的同位置 token（對中間的影格，期望值為 $1 - 0.9^2 = 0.19$；第一張與最後一張影格只有一個鄰居）。管狀遮罩完全消除了這個捷徑，這正是重點：預訓練任務只有在它的捷徑都被堵住時才有用。VideoMAE 也報告，在只有幾千支影片的小資料集上，不需額外資料就能有很強的結果；發現對這類預訓練而言，資料品質比資料數量更重要；並指出預訓練資料與目標資料之間的領域偏移是個重要的議題 [10]。**VideoMAE V2** [33] 以**雙重遮罩**（dual masking）把這個方法擴展到十億參數的 ViT，雙重遮罩也會遮住解碼器的輸入，以節省運算。

第二條路線預測的是*特徵*而不是像素。**V-JEPA** [34] 只用特徵預測的目標來訓練影片模型，不用預訓練的影像編碼器、文字、負樣本或重建，使用大約 200 萬支影片，並用凍結的骨幹在以運動為主與以外觀為主的任務上評估它們 [34]。它的後繼者 V-JEPA 2 [35] 與 JEPA 的想法，在 [ML 06](/zh-tw/learn/ml/representation-learning/#預測特徵而不是像素jepa) 與 [DLCV 13](/zh-tw/learn/deep-learning/world-models/#預測式表示jepa-家族) 中討論。

## 影片與語言（簡介）

**白話版。** 不使用固定的動作名稱清單，而是用自由文字描述影片。把影片和句子放在同一個空間中的模型，可以用描述來搜尋影片；把影片 token 送進語言模型的模型，可以回答關於影片的問題。

**檢索。** CLIP 式的影像–文字模型 [36]（[ML 10](/zh-tw/learn/ml/foundation-models/#影像與文字的共享空間clip-與-siglip)）可以遷移到影片：**CLIP4Clip** [37] 把 CLIP 端到端地遷移到文字–影片檢索，並研究影像特徵是否足夠、在影片–文字資料上做後預訓練（post-pretraining）有什麼幫助，以及如何建模影格之間的相依關係，使用的基準如 **MSR-VTT**，這是一個包含 1 萬段網路影片片段與 20 萬組片段–句子配對的集合 [38]。**影片基礎模型**如 **InternVideo2** [39]，在一個漸進式的訓練方案中結合了遮罩式影片建模、影片–文字對比學習與下一個 token 預測，影片編碼器最大達 60 億個參數 [39]。

**問答。** 多模態大型語言模型（[ML 10](/zh-tw/learn/ml/foundation-models/#多模態大型語言模型)）接受取樣出來的影格作為視覺 token。長影片會讓它們吃力：**Video-MME** [40] 在 900 支人工標註、長度從 11 秒到 1 小時的影片（2,700 組問答配對）上評估它們，字幕與音訊是可選的輸入，並發現處理更長的序列仍是弱點 [40]。一個實務上的提醒，類比場景偏差：在把時間理解的功勞歸給模型之前，先檢查問題是否光靠單張影格、或光靠問題文字就能回答；單影格基準是很便宜的健全性檢查。

## 在時間與空間中定位動作

**白話版。** 真實的影片沒有被裁剪過。一支料理影片包含「切」、「攪拌」與「倒」，中間夾著很長的無聊片段。時序定位找出每個動作從哪裡開始、到哪裡結束；時空偵測還會說是哪個人在做。

### 時序動作定位

這個任務沿著時間軸呼應物件偵測（[DLCV 03](/zh-tw/learn/deep-learning/object-detection/)），方法也是如此。片段層級的骨幹（常常是凍結的，例如 I3D 或 SlowFast 特徵）沿時間產生一個特徵序列；定位頭再把它轉成帶分數的區段。

- **以提案為基礎（兩階段）。** 先產生不分類別的候選區段，再對它們分類。**BMN** [41] 把一個提案表示成一對開始與結束邊界，並在一張**邊界匹配信心圖**（boundary-matching confidence map）中一次為所有稠密分布的配對打分；結合動作分類器後就得到偵測結果 [41]。
- **無錨框、單階段。** **ActionFormer** [42] 對時間上的*每個時刻*分類，並迴歸到動作開始與結束的距離，不需要提案，也不需要預先定義的錨框視窗。它使用具有局部自注意力的多尺度 Transformer 與一個輕量解碼器 [42]，是 [DLCV 03](/zh-tw/learn/deep-learning/object-detection/#無錨框偵測器用點取代框) 無錨框偵測器在時間上的對應。重複的區段用時間上的非極大值抑制移除，與框的做法相同（ActionFormer 用的是軟式變體 [42]）。

**時序 IoU 與 mAP。** 對預測區段 $\hat{g} = [\hat{s}, \hat{e}]$ 與真實區段 $g = [s, e]$，

$$
\text{tIoU}(\hat{g}, g) = \frac{\max\big(0, \min(\hat{e}, e) - \max(\hat{s}, s)\big)}{(\hat{e} - \hat{s}) + (e - s) - \max\big(0, \min(\hat{e}, e) - \max(\hat{s}, s)\big)},
$$

其中分子是重疊的長度，分母是聯集的長度。對某一類別與門檻 $\theta$，把預測依分數排序；若某個預測與該類別尚未被配對的真實區段的 tIoU 至少為 $\theta$，它就是真陽性。平均精確率（average precision, AP）是所得精確率–召回率曲線下的面積，mAP 是對各類別的 AP 取平均，而**平均 mAP** 則再對多個門檻取平均。常見的有兩種慣例：THUMOS14 對 tIoU $\{0.3, 0.4, \dots, 0.7\}$ 取平均，ActivityNet 1.3 則對 $\{0.5, 0.55, \dots, 0.95\}$ 取平均 [42]。程式碼在合成的偵測結果上計算單一類別的 AP（找到 85% 的動作，帶有邊界誤差，再加上隨機的誤報）。

```python
import numpy as np

def tiou(seg, segs):
    """Temporal IoU of one segment [s, e] with an array of segments (n, 2)."""
    inter = np.clip(np.minimum(seg[1], segs[:, 1]) - np.maximum(seg[0], segs[:, 0]), 0, None)
    union = (seg[1] - seg[0]) + (segs[:, 1] - segs[:, 0]) - inter
    return inter / union

def average_precision(preds, gts, thr):
    """preds: list of (video, start, end, score); gts: dict video -> (m, 2) array.
    Greedy matching in score order; each ground truth can be matched once."""
    n_gt = sum(len(g) for g in gts.values())
    used = {v: np.zeros(len(g), bool) for v, g in gts.items()}
    tp = []
    for v, s, e, _ in sorted(preds, key=lambda p: -p[3]):
        ious = tiou(np.array([s, e]), gts[v])
        ious[used[v]] = -1                       # already matched ground truths are off limits
        j = int(np.argmax(ious))
        hit = ious[j] >= thr
        if hit:
            used[v][j] = True
        tp.append(hit)
    tp = np.array(tp, float)
    recall = np.cumsum(tp) / n_gt
    precision = np.cumsum(tp) / np.arange(1, len(tp) + 1)
    precision = np.maximum.accumulate(precision[::-1])[::-1]   # monotone envelope
    return np.sum(np.diff(np.r_[0, recall]) * precision)

rng = np.random.default_rng(0)
gts, preds = {}, []
for v in range(20):                              # 20 untrimmed videos, 1-3 actions each
    starts = np.sort(rng.uniform(0, 100, rng.integers(1, 4)))
    g = np.c_[starts, starts + rng.uniform(4, 15, len(starts))]
    gts[v] = g
    for s, e in g:
        if rng.random() < 0.85:                  # the detector finds 85% of actions...
            j = rng.normal(0, 0.2 * (e - s), 2)  # ...with boundary errors
            preds.append((v, s + j[0], e + j[1], rng.uniform(0.5, 1.0)))
    for _ in range(rng.integers(0, 3)):          # plus some false alarms
        s = rng.uniform(0, 100)
        preds.append((v, s, s + rng.uniform(3, 12), rng.uniform(0.0, 0.7)))

thrs = [0.3, 0.4, 0.5, 0.6, 0.7]
aps = [average_precision(preds, gts, t) for t in thrs]
print("AP at tIoU:", "  ".join(f"{t}: {a:.3f}" for t, a in zip(thrs, aps)))
print(f"average over [0.3:0.1:0.7]: {np.mean(aps):.3f}")
```

```text
AP at tIoU: 0.3: 0.731  0.4: 0.696  0.5: 0.696  0.6: 0.604  0.7: 0.284
average over [0.3:0.1:0.7]: 0.602
```

（玩具數字。）到 tIoU 0.5 為止，AP 主要受 15% 漏掉的動作與誤報所限制；到 0.7 時它崩落，因為約為動作長度 20% 的邊界誤差已經不夠好。動作的邊界本來就模稜兩可（「倒」是從什麼時候開始的？），這就是為什麼嚴格的門檻即使對人來說也很難，也是為什麼基準會報告多個門檻。

### 時空動作偵測

這裡模型必須說出哪個人做了哪個動作。在 **AVA** [43] 中，從 15 分鐘電影片段以 1 Hz 取樣出的關鍵影格裡，每個人都有一個框，以及來自 80 個原子動作（14 個姿勢類別、49 個人–物互動與 17 個人–人互動）的一個或多個標籤 [43]。常見的流程是偵測加上影片分類，如 SlowFast 的 AVA 偵測器 [15]：現成的人物偵測器（[DLCV 03](/zh-tw/learn/deep-learning/object-detection/)）在關鍵影格上提出框，影片骨幹為它周圍的一段片段計算時空特徵圖，對每個框內的特徵做池化，再由每個類別各一個 sigmoid 分類器給出多標籤預測，因為一個人可以同時「站著」、「對話」又「拿著東西」。指標是 **IoU 0.5 下的影格 mAP**（frame-mAP）：對所有關鍵影格偵測，逐動作類別計算 AP，偵測只有在它的框與該類別的某個真實框的 IoU 至少為 0.5 時才算數，再對各類別取平均 [43]。把偵測結果在時間上連成管狀序列，則借用追蹤的關聯方法（[DLCV 07](/zh-tw/learn/deep-learning/object-tracking/#多物件追蹤)）。

### 骨架式動作辨識

模型也可以不讀像素，而是讀**姿態**：身體關節隨時間變化的 2D 或 3D 座標，可以像 [DLCV 05](/zh-tw/learn/deep-learning/pose-keypoints/#什麼是姿態) 那樣估計，或用深度感測器擷取，例如含 60 個動作類別的 NTU RGB+D 資料集 [44]。**ST-GCN** [45] 建立一張圖，節點是每張影格中的關節，*空間*邊沿著骨頭連接，*時間*邊則連接連續影格中的同一個關節，並在這張圖上做圖卷積 [45]。骨架很精簡，不受衣著與背景影響，因此較不容易出現場景偏差：在 **Mimetics** 資料集（沒有一般的物件與場景、只做出模仿動作）上，以姿態為基礎的模型比 3D CNN 表現好得多 [46]。代價是骨架會漏掉物件（「喝」與「吃」），而且依賴姿態估計器的誤差。

*選讀：[骨架序列上的圖卷積（ST-GCN）](#骨架序列上的圖卷積st-gcn)（見「補充資料」頁）。正規化的鄰接矩陣、鄰居的劃分，以及這個卷積怎麼實作。*

## 訓練與評估影片分類器

**白話版。** 你怎麼挑影格、測試時平均多少個視角、報告在哪個資料集上，對數字的影響不亞於許多架構上的改動。比較兩篇論文之前，先讀它們的協定。

### 取樣與訓練

有三個選擇決定了輸入：**影格數** $T'$、影格之間的**步幅**（影格率），以及稠密與稀疏（TSN 式）取樣。以運動為中心的資料集獎勵稠密、細緻的取樣；以場景為中心的資料集可以容忍稀疏取樣。例如 VideoMAE 在 Something-Something V2 上使用 TSN 式均勻取樣，在 Kinetics-400 上使用稠密取樣 [10]。空間資料增強與影像相同（隨機縮放裁切、翻轉），但有一個影片特有的陷阱：**水平翻轉會改變標籤**，對與方向相關的類別，如「把東西從左推到右」就是如此。其餘訓練則依 [DLCV 02](/zh-tw/learn/deep-learning/image-classification/#訓練配方)。初始化通常來自影像模型（膨脹，或預訓練的 ViT），或來自自監督的影片模型。

### 多視角測試

測試時，一段片段很少涵蓋整支影片，所以預測會在 $V_t$ 個時間片段與 $V_s$ 個空間裁切上取平均：

$$
\hat{p}(y \mid \text{video}) = \frac{1}{V_t V_s} \sum_{i=1}^{V_t} \sum_{j=1}^{V_s} \operatorname{softmax}\big(f(x_{ij})\big)_y,
$$

其中 $x_{ij}$ 是在第 $j$ 個空間位置裁切的第 $i$ 個片段。例如 SlowFast 沿著影片均勻取樣 10 個片段，每個再取 3 個 $256 \times 256$ 的裁切，共 30 個視角，並把成本報告為**每個視角的 GFLOPs × 視角數**，同時指出一些早期工作用了超過 100 個視角 [15]。VideoMAE 在 Something-Something V2 上用 2 個片段 × 3 個裁切評估，在 Kinetics-400 上用 5 × 3 [10]。總推論成本是每個視角的成本乘以視角數，所以每個視角看起來便宜的模型，實務上可能很貴。兩者都要報告，而且只在相同協定下比較模型。

## 失效模式

**白話版。** 影片模型會以幾種可預測的方式失敗。大多數都是因為模型用了一個剛好在訓練資料上有效的線索。

1. **場景與物件偏差。** 模型從網球場預測「打網球」。證據：常見資料集偏向靜態線索的表徵偏差 [7]；模型在沒有一般物件與場景的模仿動作上失敗 [46]。補救方式包括去偏差損失，例如對抗式場景分類器，以及懲罰在人物被遮掉的影片上仍做出高信心預測的損失 [54]、以運動為中心的訓練資料 [9]，以及姿態輸入 [46]。
2. **時序捷徑。** 模型忽略影格順序。測試：打亂或反轉影格。如果準確率幾乎沒變，模型（或基準）就沒有用到時間；Sevilla-Lara 等人就是這樣建立他們的時序類別子集 [8]。
3. **時間脈絡太短。** 大多數片段模型一次只看幾秒。以分鐘計的動作（「組裝家具」）或關於整部電影的問題，需要長距離記憶，即使對大型多模態模型，這仍是弱點 [40]。
4. **領域偏移。** 第三人稱的 YouTube 影片、第一人稱的廚房、夜間監視器與醫療內視鏡看起來截然不同。在其中一種上訓練的模型，遷移到另一種時並不完美；EPIC-KITCHENS-100 用沒看過的廚房與較晚錄製的影片量測這件事 [52], [53]。[DLCV 02](/zh-tw/learn/deep-learning/image-classification/#分佈偏移imagenet-c-r-與--a) 的分佈偏移測試也適用。
5. **含糊的標籤與邊界。** 動作會重疊、開始與結束模糊，而且取決於意圖。多標籤資料集（Charades、AVA）與多個 tIoU 門檻承認了這一點；單標籤準確率則把它藏起來。
6. **不公平的比較。** 視角數、影格數、解析度與預訓練資料各不相同，讓報告的數字無法比較 [1]。務必檢查結果表中的協定那一行。

兩個便宜的診斷就能抓出大部分問題：**單影格基準**（有多少分數根本不需要時間？）與**打亂影格測試**（順序對模型有影響嗎？）。在信任影片模型之前，先把兩個都跑過。

## 現代觀點

### 綜述論文

五篇綜述從不同角度涵蓋這個領域。**Zhu 等人** [1] 回顧了超過 200 篇深度動作辨識的論文，介紹 17 個資料集，依時間順序呈現模型（早期嘗試、雙流網路、3D 卷積、高效率運算模型），在同一套協定下以公開的程式碼對常用方法做基準測試，並指出這個領域的主要挑戰：長距離時序建模、運算成本，以及因資料集與協定不同而無法比較的結果。**Kong 與 Fu** [2] 同時涵蓋辨識（為完整的動作貼標籤）與預測（從動作的前段預期動作），包含資料集與評估協定。**Selva 等人** [3] 依輸入如何 token 化、如何減少冗餘並重新引入歸納偏差、如何捕捉長期動態，以及如何訓練，來整理影片 Transformer，並發現它們在動作分類上即使運算成本較低，也勝過 3D CNN。**Madan 等人** [4] 把超過 200 個影片基礎模型分成三組來分析（改造成影片用途的影像模型、以影片為基礎的模型，以及跨模態的通用模型），並報告在大多數影片理解任務上，影像模型勝過以影片為基礎的模型，而通用的多模態模型表現最好。**Tang 等人** [5] 依影片如何送到語言模型（影片分析器、影片嵌入器，或兩者皆有），以及語言模型的角色（摘要器、管理者、文字解碼器、迴歸器或隱藏層），來分類以大型語言模型做影片理解的方法。

*選讀：[「現代觀點」綜述導讀](#現代觀點綜述導讀)（見「論文導讀」頁）。每篇綜述的組織方式，以及該先讀哪裡。*

### 2023–2026 年的最新進展

- **自監督預訓練是常見的起點。** 遮罩式影片建模（VideoMAE [10]、VideoMAE V2 [33]）與特徵預測（V-JEPA [34]）產生的編碼器，可以為下游任務微調或探測；VideoMAE V2 的作者稱規模是這類基礎模型的首要因素 [33]。
- **影片基礎模型統一了各種任務。** 如 InternVideo2 [39] 的模型，用遮罩式建模、影片–文字對比與下一個 token 預測訓練同一個編碼器，並在辨識、檢索與對話上評估。Madan 等人發現改造後的影像模型依然非常有競爭力 [4]，這提醒我們，影片理解的很大一部分仍然是外觀。
- **多模態 LLM 接手開放式理解。** 影片問答、描述生成與時序定位（grounding），越來越多由帶有視覺 token 的語言模型處理，並在 Video-MME [40] 等基準上評估。瓶頸在於長影片的視覺 token 數量。
- **高效率的長距離模型。** 成本呈線性的序列模型如 VideoMamba [30]，以及串流式設計（精神上類似線上 TSM [21]），針對的是長影片與即時影片。
- **定位建立在預訓練編碼器之上。** 時序定位器執行在預訓練影片模型的特徵上；例如 ActionFormer 在 THUMOS14 上使用在 Kinetics 上預訓練的雙流 I3D 特徵 [42]，所以更好的編碼器與更好的定位頭會一起提升結果。

### 尚未解決的問題

1. **真正的時序推理。** 光靠單張影格或語言先驗不夠的基準，以及會使用順序、因果與持續時間的模型。
2. **長影片。** 數小時影片的記憶體與 token 預算，以及對長距離理解的評估。
3. **細粒度與第一人稱動作。** 手、小物件與意圖；跨視角與環境的遷移。
4. **高效率與線上辨識。** 在裝置上的低延遲，並誠實報告成本（FLOPs × 視角數、真實延遲）。
5. **評估。** 可比較的協定、網路規模預訓練資料對基準的汙染，以及獎勵時間理解而不是外觀的指標。

## 重點整理

- 影片任務的範圍，從每段已裁剪片段一個標籤，到（開始、結束、類別）區段、人物層級的動作框，以及自由文字的答案；指標則隨任務而定（top-1/top-5、時序 IoU 下的 mAP、影格 mAP、Recall@$k$）。
- 核心的困難在於標籤常需要運動，但許多資料集靠外觀就能解；只要有機會，模型就會走場景這條捷徑，如玩具實驗所示。
- 雙流網路透過光流加入運動；3D CNN 從像素學習運動；I3D 把每個濾波器沿時間重複並除以其長度，來膨脹預訓練的 2D 網路。
- (2+1)D 分解以匹配的中間寬度，把 3D 卷積拆成空間與時間步驟：相同的參數量、多一個非線性，而且更容易最佳化。
- TSN 用少數稀疏取樣的影格涵蓋整支影片；TSM 以通道位移混合相鄰影格，且不增加運算；SlowFast 把重而低影格率的路徑，與輕而高影格率的路徑配成一對。
- 影片 Transformer 把片段 token 化成 tubelet，差別在於哪些 token 注意哪些 token：分離式（TimeSformer）、分解式（ViViT）、池化且多尺度（MViT），或視窗式（Video Swin）。
- VideoMAE 藉由重建被遮住 90–95% 的管狀區塊來預訓練；管狀遮罩堵住了獨立遮罩留下的洩漏。
- 只在相同協定（影格、視角、解析度、預訓練）下比較結果，並對每個模型做單影格基準與打亂影格的測試。

### 選擇 (2+1)D 區塊的中間寬度

這則筆記推導 R(2+1)D 的中間寬度，並看看它的邊界情況。

**設定。** 完整的 3D 層用大小為 $t \times d \times d$ 的核，把 $N_{i-1}$ 個輸入通道映射到 $N_i$ 個輸出通道。它的參數量（不含偏置）為

$$
P_{3D} = N_{i-1}\, N_i\, t\, d^2 .
$$

(2+1)D 區塊使用 $M$ 個大小為 $N_{i-1} \times 1 \times d \times d$ 的空間濾波器，再接 $N_i$ 個大小為 $M \times t \times 1 \times 1$ 的時間濾波器：

$$
P_{2+1}(M) = M\, N_{i-1}\, d^2 + N_i\, M\, t = M \,\big(d^2 N_{i-1} + t N_i\big).
$$

**匹配。** 令 $P_{2+1}(M) = P_{3D}$ 並解出 $M$，得到 $M = t d^2 N_{i-1} N_i / (d^2 N_{i-1} + t N_i)$；向下取整讓它變成整數 [20]。因為 $P_{2+1}$ 對 $M$ 是線性的，只要除不盡，向下取整就會讓區塊比 3D 層略*小*（練習 3 在 221,184 個參數中少了 384 個）。乘加次數遵循同樣的比例，因為兩個步驟都在相同的 $T \times H \times W$ 解析度上執行（步幅為 1）。

**邊界情況。**

- *寬度相等* $N_{i-1} = N_i = N$：$M = t d^2 N / (d^2 + t)$。對 $t = d = 3$，$M = 27N/12 = 2.25N$；中間層比輸入*更寬*。這就是為什麼在匹配大小下，R(2+1)D 不是壓縮技巧。
- *時間大小為 1*（$t = 1$）：$M = d^2 N_{i-1} N_i / (d^2 N_{i-1} + N_i)$，它小於 $N_i$；這個區塊變成一個空間卷積，後面接一個 $1 \times 1$ 的通道混合器，外加一個 ReLU。實務上這種層仍保持為普通的 2D 卷積。
- *步幅。* 如果 3D 層在空間或時間上降取樣，步幅就相應拆開：空間步幅放在空間步驟，時間步幅放在時間步驟 [20]。
- *更便宜的區塊。* 選擇低於匹配值的 $M$，就是用準確率換成本。取 $M = N$ 且 $t = d = 3$ 時，區塊的成本是 $N^2(9 + 3) = 12N^2$ 個參數，而不是 $27N^2$，約為 3D 層的 44%。

**為什麼多出來的非線性很重要。** 連續兩個線性映射等價於一個線性映射，但中間夾一個 ReLU，區塊就能表示單一 3D 卷積無法表示的函數，就像兩層疊起來、中間有 ReLU 的 $3 \times 3$ 卷積，比一層 $5 \times 5$ 卷積更有表達力。R(2+1)D 把一部分的進步歸功於此，另一部分歸功於更容易的最佳化，表現為在相同深度下較低的訓練誤差 [20]。

### 時序位移是一種稀疏的時序卷積

這則筆記說明，為什麼在時間上位移通道、再做 $1 \times 1$ 卷積，其實是偽裝起來的時序卷積。

**位移。** 令 $x_t \in \mathbb{R}^{C}$ 為第 $t$ 張影格在某個空間位置的特徵向量，並把通道分成三組：$A$（前 $C/8$ 個）、$B$（接下來 $C/8$ 個）與 $R$（其餘）。雙向位移產生

$$
\tilde{x}_t[A] = x_{t+1}[A], \qquad \tilde{x}_t[B] = x_{t-1}[B], \qquad \tilde{x}_t[R] = x_t[R],
$$

當 $t+1$ 或 $t-1$ 落在片段之外時補零。過程中不涉及任何乘法，只有資料搬移。

**接下來的卷積。** 權重矩陣為 $W \in \mathbb{R}^{C \times C}$ 的 $1 \times 1$ 卷積計算 $y_t = W \tilde{x}_t$。以 $W[:, A]$ 表示 $W$ 中屬於 $A$ 組的那些欄，其他依此類推，

$$
y_t = W[:, A]\, x_{t+1}[A] + W[:, B]\, x_{t-1}[B] + W[:, R]\, x_t[R] .
$$

這是核大小為 3 的時序卷積，$y_t = K_{+1} x_{t+1} + K_{-1} x_{t-1} + K_0 x_t$，它的三個核都是 $W$ 的複本，只是大多數欄被設為零：$K_{+1}$ 只保留 $A$ 組的欄，$K_{-1}$ 只保留 $B$ 組的，$K_0$ 只保留 $R$ 組的 [21]。完整的時序卷積會有 $3C^2$ 個自由權重；位移版本只有 $C^2$，也就是原本就在那裡的 $1 \times 1$ 卷積的成本。同樣的論證也適用於位移之後的 $3 \times 3$ 空間卷積，逐位置套用即可。

```python
import numpy as np

rng = np.random.default_rng(0)
T, C = 8, 16
x = rng.standard_normal((T, C))           # one spatial position: T frames, C channels
fold = C // 8                             # 1/8 of the channels in each direction

def temporal_shift(x):
    out = np.zeros_like(x)
    out[:-1, :fold] = x[1:, :fold]                 # these channels see the next frame
    out[1:, fold:2 * fold] = x[:-1, fold:2 * fold] # these channels see the previous frame
    out[:, 2 * fold:] = x[:, 2 * fold:]            # the rest stay in place
    return out

W = rng.standard_normal((C, C))           # the channel mixing of the following 1x1 convolution
y_tsm = temporal_shift(x) @ W.T

# the same result written as a temporal convolution with three sparse kernels
K_next, K_prev, K_now = np.zeros_like(W), np.zeros_like(W), np.zeros_like(W)
K_next[:, :fold] = W[:, :fold]
K_prev[:, fold:2 * fold] = W[:, fold:2 * fold]
K_now[:, 2 * fold:] = W[:, 2 * fold:]
xp = np.vstack([np.zeros((1, C)), x, np.zeros((1, C))])   # zero padding in time
y_conv = xp[2:] @ K_next.T + xp[:-2] @ K_prev.T + xp[1:-1] @ K_now.T
print("max difference:", np.abs(y_tsm - y_conv).max())
print("nonzero kernel weights:", sum((K != 0).sum() for K in (K_next, K_prev, K_now)),
      "of", 3 * C * C, "in a full temporal convolution")
```

```text
max difference: 3.552713678800501e-15
nonzero kernel weights: 256 of 768 in a full temporal convolution
```

**設計選擇與陷阱。** (1) *比例。* 位移的通道太少，時間混合不足；太多，則每張影格自己的資訊太少。論文發現對殘差版本而言，1/4（每個方向 1/8）最好 [21]。(2) *殘差與原地。* 把位移放在殘差分支上，可以讓未位移的特徵透過跳接保留下來，這比原地位移效果更好 [21]。(3) *線上使用。* 對即時影片，未來的影格拿不到，所以只用向後位移（過去到現在）；前一張影格位移出來的通道可以快取，所以每張新影格只要一次 2D 前向傳遞 [21]。(4) *感受野。* 一次位移可以在每個方向觸及一張影格；堆疊 $L$ 個位移區塊可以觸及 $L$ 張影格，所以時間脈絡隨深度成長，就像堆疊的時序卷積一樣。

### 時序定位的平均精確率，一步一步來

這則筆記用一個小例子，走過時序 AP 背後的配對規則，包括常導致錯誤的情況。

**例子。** 一支影片、一個類別、兩個真實動作 $g_1 = [10, 20]$ 與 $g_2 = [40, 50]$，以及依分數排序的四個預測：

| 名次 | 區段 | 分數 | 與 $g_1$ 的 tIoU | 與 $g_2$ 的 tIoU |
|---|---|---|---|---|
| 1 | [11, 21] | 0.95 | 0.818 | 0 |
| 2 | [12, 20] | 0.90 | 0.800 | 0 |
| 3 | [60, 70] | 0.70 | 0 | 0 |
| 4 | [42, 54] | 0.60 | 0 | 0.571 |

**在 $\theta = 0.5$ 下配對。** 第 1 名配對到 $g_1$（TP）。第 2 名也與 $g_1$ 有很好的重疊，但 $g_1$ 已被配對，而它與 $g_2$ 的重疊是 0，所以它是**重複預測**，算 FP。第 3 名沒有配對到任何東西（FP）。第 4 名配對到 $g_2$（TP）。每個名次之後的累計計數是 TP = 1, 1, 1, 2，所以精確率是 $1, \tfrac{1}{2}, \tfrac{1}{3}, \tfrac{1}{2}$，召回率是 $\tfrac{1}{2}, \tfrac{1}{2}, \tfrac{1}{2}, 1$。

**包絡線。** 每個名次的內插精確率，是該名次或之後的最大精確率：$1, \tfrac{1}{2}, \tfrac{1}{2}, \tfrac{1}{2}$。AP 把每個 TP 處的精確率乘以召回率的增量再加總：$\tfrac{1}{2} \cdot 1 + \tfrac{1}{2} \cdot \tfrac{1}{2} = 0.75$。

**在 $\theta = 0.6$ 下。** 第 4 名現在失敗了（$0.571 \lt 0.6$），所以 $g_2$ 永遠找不到；召回率停在 $\tfrac{1}{2}$，$\text{AP} = \tfrac{1}{2} \cdot 1 = 0.5$。漏掉的真實動作透過召回率軸拉低 AP；偽陽性則透過精確率軸拉低它。

**陷阱。**

- *配對到尚未配對的最佳真實動作。* 正文程式碼中的規則，取尚未配對的真實動作中 tIoU 最高的那個。如果某個實作改為取整體最佳的真實動作，並在那個已被配對時把預測算成 FP，那麼一個同時也與第二個鄰近動作重疊的預測就會被浪費。比較數字之前，先檢查基準的官方評估程式用的是哪個規則。
- *分數相同。* 分數相同時排序不是唯一的；不同實作的結果可能略有差異。使用穩定排序。
- *測試集中沒有真實動作的類別*，通常在對類別取平均時被略過；把它們算成 AP 0 或 1 會改變 mAP。
- *NMS。* AP 會懲罰重複預測，所以定位器在評估前會先做（軟式）時間非極大值抑制，就像偵測器對框所做的（[DLCV 03](/zh-tw/learn/deep-learning/object-detection/#非極大值抑制nms與-soft-nms)）。

### 骨架序列上的圖卷積（ST-GCN）

這則筆記說明 ST-GCN 為骨架式辨識所用的圖卷積。

**圖。** 一段骨架序列在 $T$ 張影格中有 $V$ 個關節。ST-GCN 沿著每張影格內的骨頭連接關節（空間邊），並把每個關節連到下一張影格中的自己（時間邊）[45]。令 $A \in \{0, 1\}^{V \times V}$ 為骨頭鄰接矩陣（若關節 $i$ 與 $j$ 共用一根骨頭，則 $A_{ij} = 1$），$I$ 為單位矩陣（自連接）。

**一個空間層。** 論文採用標準的、以度數正規化的圖卷積；單張影格、只有一個鄰居群組的層是 [45]

$$
f_{\text{out}} = \Lambda^{-\frac{1}{2}} (A + I)\, \Lambda^{-\frac{1}{2}}\, f_{\text{in}}\, W, \qquad \Lambda_{ii} = \sum_j (A + I)_{ij},
$$

其中 $f_{\text{in}} \in \mathbb{R}^{V \times C_{\text{in}}}$ 儲存每個關節一個特徵向量（起初是它的座標與姿態估計器的信心 [45]），$W \in \mathbb{R}^{C_{\text{in}} \times C_{\text{out}}}$ 是所有關節共用的學習權重矩陣，$\Lambda$ 是以鄰居數正規化的對角度數矩陣。每個關節的輸出，是它自己與鄰居的特徵經度數正規化的平均，再接一個線性映射。

**劃分鄰居。** 單一個 $W$ 把所有鄰居一視同仁，就像只有一個權重的卷積核。ST-GCN 把每個關節的鄰居分成幾個子集，並為每個子集配上自己的權重，$f_{\text{out}} = \sum_j \Lambda_j^{-1/2} A_j \Lambda_j^{-1/2} f_{\text{in}} W_j$，其中 $\sum_j A_j = A + I$ [45]。它的**空間配置**（spatial configuration）劃分使用三個子集：關節自己；比較靠近骨架重心的鄰居（向心）；以及比較遠離重心的鄰居（離心）[45]。這讓該層能區分「手肘朝身體移動」與「遠離身體」。一個可學習的遮罩 $M$ 以逐元素方式乘上每個 $A_j$，來衡量個別邊的重要性 [45]。

**時間。** 時間邊由沿影格軸、對每個關節各做一次的一般 1D 卷積處理（論文使用 9 張影格的時間核），所以一個 ST-GCN 單元就是先對關節做圖卷積、再對影格做時間卷積，與 (2+1)D 同樣是先空間後時間的分解 [45]。

**陷阱。** 座標必須正規化（論文對輸入骨架做批次正規化），讓共用權重看到所有關節相近的尺度 [45]；姿態估計器漏掉的關節必須補上或遮罩；而雙人動作需要約定哪一個身體排在前面。

### Quo Vadis：I3D 與 Kinetics 資料集（Carreira 與 Zisserman，2017）

**要解決的問題。** 2017 年時，影片架構是在 UCF101 與 HMDB51 上比較的，這兩個資料集小到大多數方法的表現都差不多，所以很難判斷哪些設計真的比較好 [14]。

**核心想法。** 兩項貢獻。第一，在大得多的 Kinetics 資料集 [17] 上重新評估主要的架構家族：頂端接 LSTM 的 CNN、從頭訓練、類似 C3D 的 3D CNN [16]、雙流網路、「3D 融合」的雙流網路，以及新的雙流 I3D。第二，透過膨脹以 ImageNet 預訓練的 Inception-V1 [55] 來建立 I3D，並用正文所述的無聊影片規則，從 2D 濾波器引導出 3D 濾波器 [14]。

**它呈現了什麼。** 不論用 RGB、光流或兩者，I3D 在三個資料集上都表現最好；雙流版本在各處都優於單流版本；在 Kinetics 上預訓練再微調，在 UCF101 與 HMDB51 上帶來大幅進步 [14]。有趣的是，光流單獨使用時，在 HMDB51 上比 RGB 強，但在 Kinetics 上比較弱，作者把這歸因於 Kinetics 中較大的相機運動 [14]，這是基準所獎勵的東西會左右結論的早期跡象。

**閱讀時要檢查什麼。** 先看架構比較表，它在每個資料集上分別訓練並測試每個模型，再看遷移表，它比較從頭訓練、凍結的 Kinetics 特徵與微調。檢查每個模型是用什麼預訓練的（除了 3D CNN 以外，全都從 ImageNet 開始）、每個模型在訓練與測試時看多少影格，以及是否使用光流：這些差異解釋了排名的大部分原因。

**它的限制。** 光流流仍需要預先計算的光流；Kinetics 的片段很短，作者自己也發現在那裡 RGB 流比光流更有鑑別力 [14]；而膨脹是繼承影像網路的設計，而不是去問影片網路應該長什麼樣子，這個問題後來由 R(2+1)D、SlowFast 與 X3D 回答 [20], [15], [23]。

**為什麼和本篇有關。** I3D 讓「膨脹預訓練的影像模型，並在 Kinetics 上預訓練」成為標準配方，它的特徵也成為常用的影片表示，包括 [DLCV 12A](/zh-tw/learn/deep-learning/video-generation/#fréchet-video-distance) 討論的 Fréchet Video Distance 的特徵網路。

### SlowFast 網路（Feichtenhofer 等人，2019）

**要解決的問題。** 影片網路應該對稱地對待空間與時間嗎？雙流網路用光流表示運動；3D CNN 則對所有東西使用同一個影格率 [15]。

**核心想法。** 使用兩種影格率。通道多而影格少的 Slow 路徑捕捉空間語意；通道少（比例 $\beta$）而影格多（多 $\alpha$ 倍）的 Fast 路徑捕捉運動；從 Fast 到 Slow 的橫向連接在每個階段把兩者融合。不使用光流 [15]。

**它呈現了什麼。** 在 Kinetics 的消融實驗中，每個 SlowFast 變體都勝過只有 Slow 的路徑；Fast 路徑單獨使用很弱，但加進去能改善 Slow 路徑，作者認為這是兩者表示的資訊大致互補的證據 [15]。在橫向連接中，時間步幅的卷積效果最好。從 $\beta = 1/32$ 到 $1/4$ 的每個通道比例，都比只有 Slow 的路徑好，其中 $1/6$ 與 $1/8$ 最好；即使 $\beta = 1/32$，只增加大約 5% 的運算量，也有幫助 [15]。同一個骨幹在 Charades 與 AVA 偵測上也有很強的結果 [15]。

**閱讀時要檢查什麼。** 先讀表 1（$\alpha = 8$、$\beta = 1/8$ 的實例，以及哪裡的時間核大於 1），再讀消融表：橫向連接的類型、通道比例，以及移除或修改路徑的變體。讀主要結果表時，注意「GFLOPs × 視角數」那一欄——這是論文為了讓推論成本可比較而引入的——以及它的觀察：一些早期方法用了超過 100 個視角 [15]。

**它的限制。** 兩個固定的影格率是人工設計的先驗；模型仍然只看幾秒；後來的 Transformer 模型如 MViT（作者有部分重疊），以注意力重新探討了多尺度的想法 [27]。

**為什麼和本篇有關。** SlowFast 是圍繞著「是什麼」與「怎麼動」之間的不對稱所設計的架構中最清楚的例子，它的評估慣例（30 個視角、每視角的 FLOPs）至今仍在使用。

### 「現代觀點」綜述導讀

這份導讀展開「現代觀點」中簡短的綜述摘要：每篇回顧涵蓋什麼、如何組織，以及該為了什麼去讀它。

**A Comprehensive Study of Deep Video Action Recognition**（Zhu 等人，2020）[1] 是進入 CNN 時代的最佳入口。它先介紹 17 個影響了模型設計的資料集，再依時間順序追溯模型：早期深度模型、雙流網路、3D CNN 與高效率運算模型。它的獨特之處，是在共同設定下以公開的程式碼對常用方法做基準測試，這回應了它一開始就點出的問題：因資料集與協定不同而無法比較的結果。先讀它的資料集一節與基準表。

**Human Action Recognition and Prediction: A Survey**（Kong 與 Fu，*IJCV*，2022）[2] 把辨識與*預測*放在一起，預測是從不完整的開頭推斷動作，這對駕駛與監控很重要。它涵蓋兩者的模型、演算法、技術困難、資料集與評估協定，並討論未來方向。

**Video Transformers: A Survey**（Selva 等人，*IEEE TPAMI*，2023）[3] 依設計問題分析影片 Transformer：影片在輸入端如何處理（token 化與嵌入）、為了減少冗餘、重新引入歸納偏差與捕捉長期動態所做的架構改動，以及包含自監督在內的訓練方式。它在動作分類上的效能比較發現，Transformer 即使運算成本較低，也領先 3D CNN。讀它可以理解正文中的各種注意力變體*為什麼*存在。

**Foundation Models for Video Understanding: A Survey**（Madan 等人，2024）[4] 分析了超過 200 個影片基礎模型，並在三個類別的 14 種影片任務上做基準測試。它的分類法（改造成影片用途的影像模型、具有影片專用編碼的影片模型，以及跨模態的通用模型）是一張有用的地圖，而它的主要發現是該記住的那一個：改造過的影像模型在大多數任務上勝過以影片為基礎的模型，而通用的多模態模型最強。

**Video Understanding with Large Language Models: A Survey**（Tang 等人，2023，依其 arXiv 紀錄已被 *IEEE TCSVT* 接受）[5] 以兩種方式整理影片 LLM：依影片資訊如何到達語言模型（產生文字的影片分析器、產生 token 的影片嵌入器，或兩者皆有），以及依語言模型扮演的角色（摘要器、管理者、文字解碼器、迴歸器、隱藏層）。它也回顧這些模型的任務、資料集、基準與評估方法。讀它之前，先讀 [ML 10](/zh-tw/learn/ml/foundation-models/#多模態大型語言模型)。
