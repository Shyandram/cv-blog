# Retrieval interface (RAG) for the course

A local, dependency-free retrieval layer over the repository's content, for research agents and RAG pipelines. It works from the
**source files**, not the website, so results point straight at the file and lines to read or edit.

## Commands

```bash
npm run rag:build                      # write .rag/chunks.jsonl and .rag/manifest.json (about a second)
npm run rag -- "query"                 # BM25 search; builds the corpus first if it is missing
npm run rag -- "query" --k 5 --lang en --track deep-learning --zone notes
npm run rag -- "超解析度 像素重排" --lang zh-tw
npm run rag -- "query" --json --full   # machine-readable results with the full chunk text
```

Options: `--k N` (default 8), `--lang en|zh-tw`, `--track <track>`, `--zone main|notes|papers|references`,
`--kind tutorial|summary|post`, `--json`, `--full`, `--rebuild`, `--dir <corpus dir>` (default `.rag`).
`node scripts/rag/build.mjs --out <dir> --max-words <n>` changes the output folder and the chunk size (default about 700 words or
the CJK equivalent).

English is tokenized into lower-case words (light stemming, stop words removed); Chinese into overlapping character bigrams,
so queries in either language work. Headings are weighted twice. `.rag/` is generated and git-ignored: rebuild it after content
changes (it reads anchors from `docs/content-index.json`, so run `npm run index` first when headings changed).

## Corpus format: `.rag/chunks.jsonl`

One JSON object per line:

| Field | Meaning |
| --- | --- |
| `id` | stable-ish id: `<lang>/<track>/<slug>#<n>` (or `#summary`, or `<lang>/blog/<slug>#<n>`) |
| `kind` | `tutorial` (a section chunk), `summary` (one per tutorial and language: title, description, prerequisites, section list) or `post` |
| `lang` | `en` or `zh-tw` (the zh-tw twin of a tutorial has the same slug, sections and reference numbers) |
| `track`, `slug` | course location, e.g. `deep-learning`, `deep-learning/dl-03b-image-segmentation` (null for posts) |
| `title` | the tutorial or post title, e.g. `DLCV 03B · Image Segmentation: …` |
| `section` | heading path inside the page, e.g. `["Panoptic segmentation", "The task and its metric"]` |
| `zone` | `main`, `notes` (Supplementary notes, served at `…/notes/`), `papers` (Paper guides, `…/papers/`) or `references` |
| `url` | site path with the exact anchor, e.g. `/en/learn/…/notes/#ransac-fitting-a-model-despite-outliers` |
| `file`, `lines` | source file and 1-based line range of the section in that file |
| `part` | `"k/n"` when a long section was split at paragraph boundaries, else null |
| `text` | the section text: MDX imports and JSX tags removed (figure captions and alt text kept as `[Figure: …]`), Markdown, KaTeX `$…$` and code blocks kept |

`.rag/manifest.json` records the chunk counts per language and zone and the chunk size used.

## Using it from code or a vector store

- Embed `title + " › " + section.join(" › ") + "\n\n" + text` for each line of `chunks.jsonl`; keep `url`, `file` and `lines` as
  metadata so answers can cite the page and an agent can open the exact source lines.
- Filter by `lang` to answer in one language, by `zone` to keep optional material (`notes`, `papers`) out of a beginner's answer,
  and by `kind: "summary"` to route a question to the right tutorial first.
- Reference lists are chunked too (`zone: "references"`), and `docs/content-index.json` has every reference entry parsed into
  number, text and URL.
