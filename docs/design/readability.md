# Site interface — 2026-11-04

Goal: apply a clear, minimalist interface across the entire bilingual website, while making the course and paper guides comfortable for beginners to read, locate and navigate on phones and desktops. The visual direction is minimalist: neutral surfaces, whitespace and typography carry the hierarchy; decoration stays secondary.

Applied skill: [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/SKILL.md). The initial broad design-system search returned a marketing/testimonial pattern unsuitable for this course. A narrower product search, `documentation knowledge base`, matched Knowledge Base/Documentation with Minimalism & Swiss Style + Accessible & Ethical. Typography searches matched bounded line length, adequate line height and balanced headings. Astro guidance confirmed preserving static/no-JS navigation. No marketing pattern or new font dependency was adopted.

Decisions:
- Apply the same visual language to home, course overview/tree, blog list/articles, playground, search, downloads, about and error pages. Use shared neutral tokens, 4px control corners and 6px contained-media corners.
- Prefer text-led lists and light separators for articles, downloads, statistics and experiments. Use underlines for active filters, and preserve visible form boundaries, keyboard focus and meaningful plot colors. Controls that were restyled retain at least 44px touch targets.
- Use white and neutral charcoal surfaces with a restrained link accent; keep track colors for identification rather than enclosing every section; test primary and secondary text against both page and surface backgrounds at 4.5:1.
- Bound prose to 40rem. Use 19px desktop / 18px phone text, 1.8 line height, and 1.85 for Traditional Chinese. The CJK system font leads Chinese paragraphs for a consistent reading texture; Latin technical names retain available system fallbacks.
- Give paper-guide h4 headings their own 20px tier and clear section spacing. Maintain independently wide figures, equations, tables and code.
- Show complete chapter titles with wrapping. Use distinct 44px disclosure targets without hit-area overlap, 44px chapter tabs, and larger mobile navigation rows.
- Align desktop contents disclosures beside their headings in a two-column grid, keeping nested lists across both columns.
- Make prerequisite information easy to find and stack previous/next links on small screens.
- Code starts folded using native HTML disclosures. Show the language and line count before opening, with a separate 44px copy button usable while closed. A persistent code toggle supports readers who want to open all examples for reading or browser search. Keep no-JS disclosure and full-code printing; restore the reader's open/closed choices after printing. These controls apply to course, optional-reading and blog prose without changing source text.
- Retain keyboard controls, fragment reveal, reduced-motion support and existing course URLs.
- Allow unusually long unbroken reference/API names to wrap within prose; keep code and wide equations in their own horizontal scrollers.
- Use a persistent compact floating console with four primary buttons: Contents, Sections, Code and Top. The grip moves the console with pointer/touch or arrow keys; Home resets its position. Contents opens an attached tray with progress, section jump, Previous/Next and position reset. The tray starts closed, while the four actions stay available during reading and outside clicks.
- Section/code toggles close all if any are open, and open all if none are open. Stable visible labels name the four tools; accessible names and tooltips name the intended action and include open/total counts and pressed states reflect partial selections. Preserve native individual disclosures and closed-code copying.
- Save only normalized console position in local storage, tolerate blocked storage, and clamp to the visual viewport and safe areas on resizing. Hide the console for print. No positioning library is needed for this draggable panel; remove the previous popover and its dependency. Without JavaScript, static navigation and native code disclosures remain available.
- Use unboxed chapter headings, underlined active tabs, plain metadata, lightly ruled optional-reading lists and previous/next links. Prerequisites and learning tips use text hierarchy instead of colored cards. The floating console uses one row of text buttons, a subtle border and shadow, without decorative icons or a colored top bar. Copy feedback distinguishes pending, success and failure and prevents overlapping writes. Motion stays optional under reduced-motion preferences.

Console interaction checks use `scripts/check-floating-tools.py`, including pointer/touch movement, keyboard operation, storage fallback and viewport clamping. Reading verification uses `scripts/check-readability.py` at 320, 375, 768, 1024, 1440 and landscape 844px in both languages and themes, plus existing course/folding/paper-guide regressions. The standalone PDF layout is unchanged by web CSS.
