# AGENTS.md — rules for anyone (human or AI) editing this repo

This is the source of **Pixels → Perception**, a bilingual (English / 繁體中文) tutorial site on
image processing, pattern recognition, machine learning, deep learning, computer vision, NLP, optimization and information theory.
Live site: <https://blog.shyandram.dev/> · Stack: Astro 7 + MDX + KaTeX + Pagefind, deployed by
Cloudflare from `main`.

These rules exist because several tools (Claude Code, Codex, subagents) edit this repo, sometimes at
the same time. Follow them exactly.

---

## 1. Collaboration and git safety

- **Assume someone else may have uncommitted work in the working tree.** Run `git status` before you
  start and before you commit.
- **Never** run commands that rewrite the shared working tree or index: no `git stash`, `git reset`,
  `git checkout -- <file>`, `git restore`, `git clean`, no branch switching with local changes.
- **Stage explicit paths only** (`git add path/a path/b`). Never `git add -A` / `git add .` /
  `git commit -a` unless you have confirmed every change in `git status` is yours.
- Commit only work that is finished and validated (section 6). Push to `main` only when the user
  asked for it; every push to `main` deploys the live site.
- To test what a commit will deploy without other people's uncommitted files, build it in a separate
  `git worktree` (symlink `node_modules`), not by stashing.
- Edit files with targeted replacements; re-read a file right before editing it. Do not reformat files
  you are not changing.
- **Shell safety:** never put prose containing backticks into an *unquoted* heredoc (`<<EOF`) or a
  double-quoted string; the shell executes them. Use quoted heredocs (`<<'EOF'`) or a file-writing tool.

## 2. Content rules (apply to every tutorial and post)

- **Never single out the site owner's identity.** Do not write "the author's own research",
  "作者自己的研究", etc. Cite the owner's papers neutrally, like any other work. The owner's own blog
  posts (`src/content/posts/`) are their writing; do not edit their original text.
  Exception: the About page (`src/pages/[lang]/about.astro`) introduces the author and links to
  https://shyandram.dev/ at the owner's request; keep personal details there and nowhere else.
- **Every named method, paper, dataset, metric, standard or challenge needs a verified reference** in
  the page's reference list: a link you actually opened (arXiv abs page, DOI, CVF open access,
  official project/dataset/standard page) with title, authors, year and venue confirmed. Publisher DOIs
  that block scripts can be confirmed via `https://api.crossref.org/works/<doi>`. Prefer the final
  published venue over arXiv when you can confirm it. **If you cannot verify a source, do not mention
  the claim.**
- **No invented numbers** (benchmark scores, dataset sizes, parameter counts, citation counts). Numbers
  in the text must come from a verified source or from code you ran.
- **Original writing only.** Never copy prose, figures or exercises from papers, textbooks or
  websites. Following a textbook's chapter arrangement is fine (the DIP series follows Gonzalez &
  Woods, 4th ed.); its text and figures are not.
- **Figures are generated by scripts in this repo** (`scripts/figures/*.py`) from `skimage.data`,
  scikit-learn toy datasets or synthetic data. Never download images or reuse figures from papers.

## 3. Tutorial standard (the "house style")

Tutorials live in `src/content/tutorials/<lang>/<track>/<slug>.mdx`, one file per language with the
**same slug**. Tracks: `foundations`, `image-processing`, `nlp`, `pattern-recognition`, `ml`,
`deep-learning`, `optimization`, `information-theory` (see `src/lib/taxonomy.ts`). Good examples to imitate:
`image-processing/dip-03-intensity-spatial-filtering.mdx`, `deep-learning/dl-05-low-light-enhancement.mdx`.

**Structure (in this order):**
1. `## What you'll learn` / `## 你將學到` — 4–6 bullets.
2. `## The big picture` / `## 先看全貌` — an ELI5 analogy in
   `<Callout type="tip" title="Explain like I'm five">` / `title="用最簡單的話說"`, and why it matters.
3. Topic sections (`##`, subsections `###`). Each topic: a **plain-language statement first**
   (1–3 sentences), then the **precise version** — definitions and KaTeX math with **every symbol
   defined right after the equation** — then a short **tested** Python snippet and a figure where
   they help.
4. `## Modern view` / `## 現代觀點` — survey of review/survey papers (what each covers, its taxonomy,
   its takeaways), the 2023–2026 state of the art, open problems. No hype.
5. `## Key takeaways` / `## 重點整理` — 5–8 bullets.
6. `## Exercises` / `## 練習` — 4–6 original exercises; hints inside `<details>` with `<summary>` on
   its **own line** (the one-line form does not compile).
7. *(optional)* `## Supplementary notes` / `## 補充資料` — concept details; see "Supplementary notes" below.
7b. *(optional)* `## Paper guides` / `## 論文導讀` — reading guides to single papers; see "Paper guides" below.
8. `## References` / `## 參考文獻` — numbered `1. Authors, "Title," Venue, Year. [link](url)`, cited
   in text as `[1]`, `[2]`. Every entry cited; every citation has an entry.

**Depth:** complete, professional, very clear. Typical English length 4,000–8,000 words of prose.
Beginner tracks build intuition carefully; deep-learning tutorials are advanced (architectures, losses,
data, metrics, datasets/benchmarks, failure modes) but still open each section in plain language.

**Frontmatter** (validated by `src/content.config.ts`):
```yaml
title: "..."            # "<PREFIX> NN · Title" / zh-tw "<PREFIX> NN・標題" (IP, PR, ML, DLCV, NLP, OPT, IT)
description: "..."      # one sentence
track: <track>
order: <int>            # position in the track
level: beginner | intermediate | advanced
prereqs: [<track>/<slug>, ...]   # must exist
tags: [...]
notebook: notebooks/...           # optional
published: YYYY-MM-DD
updated: YYYY-MM-DD               # optional
```
Files whose names start with `_` are drafts and are excluded from the build.

**Code:** every snippet must run as shown with the project venv
(`.venv/bin/python`: numpy, scipy, matplotlib, scikit-image, opencv-python-headless, PyWavelets,
scikit-learn, torch/torchvision CPU). Printed outputs quoted in the text must match a real run. No
dataset or weight downloads; keep any training under about a minute on CPU.

**Figures:** `scripts/figures/<name>.py` (re-runnable, writes only to its own folder in
`src/assets/<track>/<slug>/`), `matplotlib.use("Agg")`, white background, font size ≥ 10, `dpi=150`,
width ≤ 1600 px, each PNG < 1 MB. Text inside figures in English (no CJK font); the zh-tw page reuses
the PNG with a Chinese caption. Show figures with `<Figure src={img} alt="..." caption="Figure n — ..." />`.

**Components** (`src/components/`): `Callout`, `Figure`, `ImageCompare` (before/after slider, two
same-size images), `KernelPlayground` (live 3×3 kernel; `lang="zh-tw"` on Chinese pages). Use them
only where they teach.

**Supplementary notes.** Additional information that is optional for the main line does **not** sit in the middle of a
section. Typical items: the introduction of a named algorithm the text only uses or mentions (RANSAC, the guided
filter); a short guide to one paper (what problem it poses, the idea, what it showed, its limits, with the verified
reference; in the notes' own words, never copied from the abstract); a primer on a concept the text takes for granted;
a variant, a historical note or a longer derivation; detail that crowds the main line (long derivations, extra variants,
historical surveys, long method lists) belongs here too. It goes in a final `## Supplementary notes` / `## 補充資料`
section, placed after `## Exercises` and before `## References`, one `###` per item, opening with one sentence saying the
notes are optional. The site shows that section on a **separate page** (`/<lang>/learn/<track>/<slug>/notes/`, built by
`src/lib/rehypeSupplementZones.mjs`); the main page shows a short card that lists the notes. Write links normally: an
in-page `[…](#note-slug)` in the main text is rewritten to `notes/#note-slug` at build time (and a note's link to the main
text to `../#slug`); a link from another page to a note must point to `…/<slug>/notes/#note-slug`. The PDF keeps the notes
at the end of the chapter.

**Paper guides** are kept apart from the notes: a reading guide to a single paper or survey (the problem it poses, the idea,
what it showed, how to read its tables and comparisons, its limits, why it matters here; grounded in the paper, in the guide's
own words) goes in its own final section `## Paper guides` / `## 論文導讀`, placed after `## Supplementary notes` and before
`## References`, one `###` per paper, opening with one sentence saying the guides are optional. The site shows it on its own
page (`…/<slug>/papers/`); the pointer line reads `*Optional: [U-Net](#u-net-...) (in the Paper guides). …*` / zh-tw
`*選讀：[…](#…)（見「論文導讀」頁）。…*`. Concept details, algorithms and sub-field background stay in the Supplementary notes;
a section may be absent when a chapter has nothing of that kind. Where the main text touches the topic it leaves a single italic pointer line with a link to
the item (`*Optional: [RANSAC](#ransac-...) (in the Supplementary notes). One sentence on what it adds.*`; zh-tw
`*選讀：[…](#…)（見「補充資料」頁）。…*`). Rules:
- nothing in the main text, code, figures or exercises may depend on a note: before moving or writing one, grep for
  its terms, functions and figure names; a term the main line needs must be explained in the main line;
- the English and zh-tw files carry the same notes in the same order, each with the house structure of section 3 in
  miniature (plain statement first, then the precise version with every symbol defined, one tested snippet if useful)
  and with verified references like any other text;
- "What you'll learn", "Key takeaways" and "Exercises" are never moved into the notes, and the notes stay
  shorter than the main text (a few items per tutorial).

**Titles and link text:** tutorials are named by track prefix and two-digit number, e.g. `IP 05`,
`ML 03a`, `DLCV 04` — never "Chapter 5" / "第 5 章" (the image-processing series follows a textbook's
chapter order, but the site calls them IP 01–13). Link text to a tutorial uses the same name.

**Links:** internal links are absolute with a trailing slash, e.g.
`/en/learn/image-processing/dip-05-restoration-reconstruction/`; the target must exist. When you
remove or rename a page, add a redirect in `astro.config.mjs` (`redirects`) and update every link to
it. Do **not** also add `public/_redirects`: Cloudflare's deploy step already turns the Astro redirects
into 301 rules, and duplicate rules make the deploy fail ("Duplicate rule for path").

## 4. Language

- **English:** clear, professional, plain; short sentences; define jargon at first use.
- **繁體中文:** natural Traditional Chinese with **Taiwanese terminology** — 影像、像素、資料、資料集、
  網路、模型、訓練、演算法、參數、最佳化、損失函數、卷積、濾波器、頻域、直方圖、雜訊、解析度、取樣、量化.
  **No Simplified characters or mainland terms** (数据、图像、网络、算法、视频、信息、默认、质量、采样…).
  Keep model/paper/dataset names in English and give the English term in parentheses at first use,
  e.g. 直方圖等化（histogram equalization）.
- The zh-tw page mirrors the English one: same sections, figures, code and reference numbers.

## 5. MDX / KaTeX gotchas

- A literal `{` or `}` in prose starts a JS expression: escape as `\{` `\}` or move it into code/math.
- A literal `<` in prose must be `&lt;`; inside math use `\lt`. A literal `$` must be `\$`
  (remark-math is on, also in `.md` posts).
- Comments are `{/* ... */}`, never `<!-- -->`.
- Multi-line math uses `\begin{aligned} ... \end{aligned}`.
- Blank line before and after every component, list, table and display-math block.
- Chinese bold/italic next to CJK punctuation (`**粗體**（…）`) works because `remark-cjk-friendly` is
  enabled in both the site and `scripts/check-mdx.mjs`; do not add workaround spaces.
- No CJK inside `\mathrm{}` or `\operatorname{}` (KaTeX warns); use `\text{位置}`.

## 6. Validation before committing

```bash
export PATH=$HOME/.nvm/versions/node/v22.23.3/bin:$PATH
node scripts/check-mdx.mjs <changed .md/.mdx files>   # syntax, KaTeX render errors, frontmatter
npm run build                                          # astro build + Pagefind index
npx astro check                                        # must report 0 errors, 0 warnings
```
Also: check new reference links respond (or confirm DOIs via Crossref); grep zh-tw files for
Simplified characters; confirm imported images exist and are < 1 MB; for layout changes, screenshot
at 1440 px and 375 px (Playwright is installed in `.venv`) and make sure nothing scrolls horizontally.
